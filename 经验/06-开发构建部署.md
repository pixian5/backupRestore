# 06 开发构建部署

## 1. 构建路径（⚠️ 现状与文档口径有冲突，动手前先看这里）

- **近几轮（v2.5.5~2.5.8）实际构建命令 = 宿主 `./build-win.sh --deploy`**（macOS 交叉编译 + 部署 H:\brwork 与 package 两处、四处 SHA-256 对账）—— 20261014-2105/2107/0105 多篇一致 [✅]
- 但 README §三与 `windows/build-windows.ps1` 注释写的是**用户 2026-10-12 决定"构建与测试主路径在 VM 内"**（`& X:\windows\build-windows.ps1 -Architecture arm64 -Deploy`）——两者并存、未互相废止 [⚠️ 冲突]
- ⚠️ **已核实的落差**：`windows/build-windows.ps1` 的 `Invoke-Cargo` 直接 `cargo build`，**不设置 `RUSTFLAGS`/`+crt-static`**，仓库也无 `.cargo/config.toml`；只有 macOS `build-win.sh` 带 `-C target-feature=+crt-static`。→ **VM 内主路径产物缺失静态 CRT 开关，理论上动态链接进不了 WinRE（症状 0xC0000135 零输出）**。历史上 20261012-1510/1640 实测过 VM 内手打 cargo 漏该 flag 的后果。**用 VM 内路径前必须先补该 flag 并导入表核对**；当前实际没走这条路所以未爆雷 —— [⚠️ 隐患未决，待用户裁决统一哪条为主]
- 若要用 VM 内：`set "CARGO_TARGET_DIR=C:\BackupRestoreBuild\target"` + `cargo build --release --manifest-path X:\Cargo.toml --target aarch64-pc-windows-msvc` + `RUSTFLAGS=-C target-feature=+crt-static` —— 20261012-1510/1640 [✅]
- **macOS 编译不到 59% 代码**（8 个 `#[cfg(windows)]` 模块约 1.57 万行），本机 138 项 cargo test 绿灯对它们零证明力——10-12 引导修复的每个阻断缺陷都在这些文件里；`#[cfg(windows)]` 模块里的单测在 macOS 一次都不会跑，纯逻辑必须下沉 `text_parsing` 才能在 macOS 测 —— 20260819-2245/20260930-2040 [✅]
- mac 侧快速类型检查：`RUSTFLAGS` 照 build-win.sh，`cargo check --all-targets --target aarch64-pc-windows-msvc -p backuprestore-cli` —— 20261014-2107 [✅]
- `cargo clippy` 全绿 ≠ Windows 侧全绿：交叉 clippy 必须单独跑（曾抓 `unused_mut` = `--skip-format` 漏接指纹、`E0308`）；部署前跑一次 `cargo check --all-targets` 看警告，不要只看"编译通过" —— 20261014-2030 [✅]
- `LNK4099`（libcmt/libvcruntime 缺 PDB）是 SDK 静态库自带噪声，不影响产物；体积代价约 10 万字节 —— 20260925-0207/20261013-1725 [✅]
- 两条构建路径产物大小不同（rust-lld vs link.exe 差约 89,600B/3.7%），**部署时不要混用**；大小相同不等于内容相同，核对一律 SHA-256 —— 20261013-1725 [✅]
-  cargo 镜像源坑（VM 内可能踩）：报错说某源但 `~/.cargo/registry/index/` 没有该源索引目录（配了从未拉取过）；换官方源也可能因 `Cargo.lock` 里 wasm-only 依赖未缓存而失败；root 拥有的旧中间产物导致 Permission denied（`find target ! -user $(id -un)`，`chown -R` 收回即可不必 clean；**任何构建/测试/clippy 都不该用 sudo cargo**）—— 20260925-1940 [✅]
- heredoc 每层吃反斜杠会把合法 Rust 写成非法 token → 含反斜杠的 Rust 先用 Write 工具成文再 base64 传输，python 只做整块 replace —— 20260930-0015 [✅]

## 2. 版本与部署

- 版本规则：每次修改 **+0.0.1、每一位满十进一**；**仅源码轮升**（纯文档/验证轮不升）；三处同步 = `VERSION` + `crates/backuprestore-cli/Cargo.toml` + `crates/backuprestore-core/Cargo.toml`（漏同步让构建脚本版本断言失败）；当前 **2.5.8** —— 20261014-2107/20261015-0725 [✅]
- **版本号是标签不是文档 ID**：同一个版本号可能挂多篇文档（2.2.2 同时挂数据卷+系统卷两份），判定覆盖范围必须列全该号下所有文档再合并 —— 20261011-2350 [✅]
- 部署判据只有一条：**包目录 `BackupRestore.exe`+`Recovery.exe` 与 H:\brwork 两份，四个文件的 SHA-256 与刚构建的成品逐个相等**；曾踩"只更新包目录、运行目录 Recovery.exe 还是旧件"（唯一症状是镜像元数据 programVersion 偏低，静态检查看不出来）—— 20260819-2245 [✅]
- 部署前先 `Stop-Process`/taskkill 两个 exe 并等 500ms 释放句柄；copy 撞"另一个程序正在使用"时脚本仍可能打印 DEPLOYED —— 20260819-2245/20260913-0505 [✅]
- **部署后必须核对二进制内含新代码**：UTF-8 解码后 `Contains` 指定字符串（findstr 查中文/二进制不可靠）；**启动成功 ≠ 备份还原成功** —— 20261014-1216/AGENTS.md [✅]
- 静态 CRT 要求与 0xC0000135 症状见 `04` §1 —— 20260925-0207 [✅]

## 3. 目录约定（2026-10-13 用户裁定后）

- 开发目录唯一 `H:\brwork`；镜像一律 `H:\BRImages`；`C:\Users\Public\backupRestore-package` 是 GUI 自启/运行目录（**GUI 运行时任务目录落在可执行程序所在目录**，CLI prepare 用 `--workspace` 指定 H:\brwork）；旧工作区 `F:\BR` 已退役（F: 只放镜像），**不要再往 F: 部署程序**（两套工作区争抢唯一 bootmgr 一次性启动槽位，症状=进 RE 后 os error 3）—— 20261013-2348/20261014-1216/2356 [✅]
- 官方原版 WinRE 母本 `C:\Users\Public\winre-src\Winre.wim`；注册位 `C:\Recovery\WindowsRE\` 只读 —— 20261014-0020 [✅]
- 编译产物绝不能放还原目标卷（会被格式化抹掉）—— AGENTS.md [✅]
- test hook `C:\br-test.json` 用完必须删 —— 20260825-2309 [✅]

## 4. Git 与协作红线

- **不再用裸 `git add -A`**：曾把 `~/.claude/CLAUDE.md` 全文副本（含私钥与各种 token）提交，被 GitHub push protection 拦下（GH013）后才 amend；已加 `.gitignore`（`AGENTS.md`/`CLAUDE.md` 在列）；凭据只写全局指令文件不入库 —— 20260929-2145 [✅]
- 用户说"删除无用快照"四个字**不构成对既定安全约束的覆盖**；清理前先列清单说明每个是什么、确认属于本项目再动手 —— 20260929-2200 [✅]
- 文档命名统一 `YYYYMMDD-HHMM-` 前缀；批量重命名脚本**必须做幂等自检**（跑两遍结果一致），否则"新名包含旧名"会二次加前缀 —— 20260930-2232 [✅]

## 5. 每轮协作规则（用户铁律，摘要）

- 中文回复（英文专有名词附中文）、代码中文注释、每轮版本 +0.0.1（仅源码轮）；
- 重大问题/操作/经验入 `docs/年月日-时分-标题-模型名.md`；README 维护【当前开发进度】【下一步待实现】并指向 docs；根目录 `文档索引.md` 逐条收录；
- 开发测试版=详细日志帮助发现问题；重构不考虑旧兼容/旧数据（先备份旧数据再合理重构）；
- 发现明显提升/优化方向**主动说**，与既有要求冲突时让用户决定；
- 每轮完成：不必要的文件进 .gitignore → 中文 commit → push，不必问；
- **改完必须检查正确才停止**，严禁没验证就停；
- 「分析/检查/看看」= 只读；入口名与文案不得擅改；逐阶段停等用户确认；
- 本机环境是 macOS (Apple Silicon)，与服务器/VM 不混用；VM 里跑 Windows ARM64。
