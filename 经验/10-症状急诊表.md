# 10 · 症状急诊表（出了事，先看哪里）

> **这是什么**：[`09-按问题找文档`](09-按问题找文档.md) 是「我想知道…」→ 答案；
> 这张是「我**看到**…」→ 三分钟内先做什么。两种入口，配合使用。
>
> **分诊第一原则**：先分辨 **「读不到」** 和 **「不满足」**。
> 通道抽风（`prlctl exec` 约 1/8 不执行）会伪装成「产品坏了」——
> 判据红时**先证明读数那一侧是对的**，再怀疑被测对象。
>
> **分诊第二原则**：先看**机器**再看**产品**。今天踩过的坑里，一半是环境脏了
> （夹具多一个任务、盘符被占、注册表被人改回去），症状全都像产品 bug。

* * *

## A. 界面上看到的东西

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| 每次登录弹「位置不可用 / **无法访问 X:\**」 | `tools/vm/baseline.sh check` | ①explorer **登录还原上次窗口**（`PersistBrowsers` 被改回 1）②该盘符有**幽灵记录** | 基线要 `pass`；再查 `reg query HKLM\SYSTEM\MountedDevices` 有无该字母 → 有就 `reg delete` |
| GUI **一启动就消失**、点一下就没了 | 看 `H:\brwork\logs` 里 `panicked at` | 窗口过程 panic = **整个进程 abort**（典型：按字节截断多字节字符） | 有 panic 栈就照栈改；见 [09 §六](09-按问题找文档.md) 多字节那条 |
| GUI 有窗口但**一片空白**、按钮不响应 | 截图 + 查 GUI 日志尾部 | 卡在某个命令上（等 DISM / 等 bcdedit） | 看日志最后一条是什么；别急着杀进程，先留现场 |
| 界面语言中英混杂 | 查设置里语言项 + 日志 | 语言层只在**启动时**灌一次 | 重启 GUI 再看；仍混就是硬编码文案漏了 |

## B. 门禁（`tools/test/ignored-acceptance.sh`）不对劲

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| `STEP 0` 报 `BASELINE=fail` | 看是哪个 `ITEM=`，`remanual=1` 吗 | 注册表三项可自动修；**夹具根/`S:` 盘符需人工** | 注册表：`baseline.sh ensure`；目录类：看 `got=` 是 `2`（多一个）还是 `MISSING` |
| `STEP 0` 报 `BASELINE=error` | 重跑一次 | **仪器故障**（读不到注册表/SID），不是环境不满足 | 连红两次才当故障查；见「C. 通道类」 |
| 某条 `CASE=...=SKIP` | 看 `reason=missing_env` 缺哪个 | 没导出环境变量（ACK/GUID/根路径） | **SKIP ≠ 通过**；补齐 env 重跑，或明确记录「本轮不验」 |
| 门禁红了，手工重跑就绿 | 先 `del` 结果文件、清 `.fault-*.triggered`，连跑两次 | ①陈旧结果文件 ②陈旧注入标记 ③`prlctl` 偶发不执行 | 两次结果**一致**才算复现；不一致记「通道抽风」，别记成产品缺陷 |
| `ERROR: 编译未完成，或 deps 里找不到测试产物` | 手工 `dir /b /o-d H:\br-target\debug\deps\backuprestore_cli-*.exe` | 多半是「命令没跑」而不是真没产物（门禁已带 3 次重试） | 手工能列出来 = 仪器问题；真没有 = 看 `H:\br-test-build.log` 尾部 |

## C. 通道类（`prlctl` / PowerShell / 编码）

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| 命令**好像没执行**（返回空、无副作用） | 重试，并给命令加哨兵 `& echo __END__` | `prlctl exec` 约 **1/8 调用不执行** | 连哨兵都没有 = 没执行；有哨兵无数据 = 真没有 |
| `prlctl exec` 报 **has finished booting** | `prlctl capture` 截图 | 机器已在 **RE/PE**，exec 通道不可用 | ★ **只能截图，绝不重启**（RE 内灌图中重启会 1235） |
| PowerShell 读文本**换行全没了** | 改 `-Encoding UTF8` 或 `[IO.File]::ReadAllText` | PS 5.1 对无 BOM 文件按 **GBK** 解码，UTF-8 全角字符末字节吞掉 `\n` | 读文本一律显式 UTF8 |
| PowerShell 输出**整段空白**、什么都不打印 | 去掉 `Select-String` 过滤，直接看全量 | 原生命令写 stderr 被当成 `NativeCommandError`，管道输出被吞 | ★ **「没输出」既不能当成功也不能当失败**，另找证据（哈希/文件） |
| `grep 中文` 结果诡异 / `tr: Illegal byte sequence` | 加 `LC_ALL=C`，只留 ASCII | 输出是 GBK/混合编码 | 判据**只认结构化字段**，绝不用中文文案当判据 |
| 返回的路径里带上了盘符、后面的步骤用不了 | 看日志里是否分配了新盘符 | 字母会**逸出**到返回路径/落盘方案 | 查 `grep hold_for_process` 那 3 处；必要时 `main()` 收尾统一撤 |

## D. 备份 / 还原跑起来之后

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| 捕获**开头长时间零输出**、镜像恒 208 字节 | 看日志 `CAPTURE_HEARTBEAT` / `CAPTURE_STALL`；看 CPU | DISM **先全卷预扫**、扫完才写第一字节——**开头零字节是正常** | 心跳阈值 600s；超过且 CPU 也趴下才算卡死 |
| 还原后**进不去恢复环境** | 查 `status.json` 的 `errorCodeText` | 缺 `reagentc.exe`/`SYSTEM` → 现在应当**任务失败 `BR-RE-047`** | ★ 若这种情况下**报成功**，才是缺陷（v2.6.73 起必须失败） |
| `bcdboot`/`bcdedit` 报 **`c0000043`**，改什么都失败 | **别再试了**，直接重启 | `bcdedit /import` **毒化**了 BFSVC 已打开的存储 | 重启即恢复；以后拿 import 只做验证、不做回退 |
| 还原后系统起来了但**盘符全乱** | 记下当前盘符，别格式化 | 盘符重启重排（**不能用盘符当卷身份**） | 判据要用卷 GUID / 分区 GUID / 序列号 |
| 任务**卡在某个 stage** 不动 | 读 `status.json` 的 `stage` + 日志尾 | 命令挂住 / 等交互确认 | 别直接杀；先抓日志与当前阶段，再决定重试 |

## E. 构建 / 部署

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| 部署了却**行为没变** | 比对 `H:\brwork\BackupRestore.exe` 与产物**哈希** | ①exe 被占用导致 Copy 失败 ②起的不是 `H:\brwork` | 哈希相等 + GUI 标题版本一起看；见 [09 §七](09-按问题找文档.md) |
| `cargo` 报 **`os error 87`** | 检查是否漏了 `-CargoTargetDir H:\br-target` | target 落在 `X:\`（9p 共享卷） | 一律指到 `H:\br-target` |
| 编译说 **`can't find crate for 'core'`** | 看 `rust-toolchain.toml` 的 `targets` | 工具链少写了 `aarch64-pc-windows-msvc` | 补 `targets` 再 `rustup update` |
| 交付包装好了但**手册还是旧的** | 查包内手册版本头 | 打包前没 commit 文档 | 先 commit 再 `pack-dist.sh`；验收走 `release-check.sh` |

## 三条「别做」清单（比「该做什么」更省时间）

1. **别用中文文案当判据**——它随语言环境变，而语言环境是最容易变的变量。
2. **别把「空输出」当结论**——先问「命令跑了吗」，再问「结果是空吗」。
3. **别在 RE/PE 里重启**——停在那里就截图取证，重启会把证据和半截状态一起搅烂。
