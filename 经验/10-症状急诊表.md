# 10 · 症状急诊表（出了事，先看哪里）

> **这是什么**：[`09-按问题找文档`](09-按问题找文档.md) 是「我想知道…」→ 答案；
> 这张是「我**看到**…」→ 三分钟内先做什么。两种入口，配合使用。
>
> **分诊第一原则**：先分辨 **「读不到」** 和 **「不满足」**。
> 通道抽风（`prlctl exec` 约 1/8 不执行）会伪装成「产品坏了」——
> 判据红时**先证明读数那一侧是对的**，再怀疑被测对象。
>
> **分诊第二原则**：先看**机器**再看**产品**。今天踩过的坑里，一半是环境脏了
> （夹具多一个任务、盘符被占、注册表被人改回去），症状全都像产品 bug。

## C. 通道类（`prlctl` / PowerShell / 编码）

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| 在落盘的客体日志副本里搜不到某行**中文** | 先看这份副本是怎么落盘的：经 `vrun` / `ascii` 落盘的都删光了非 ASCII 字符 | 中文行只剩残片，**搜不到不等于没有** | 要读原文就经共享盘原样拷出来；下否定性结论前，先搜一个明知存在的同类行做对照 |
| 命令**好像没执行**（返回空、无副作用） | 重试，并给命令加哨兵 `& echo __END__` | `prlctl exec` 约 **1/8 调用不执行** | 连哨兵都没有 = 没执行；有哨兵无数据 = 真没有 |
| **所有 `prlctl` 命令一起挂住**、几十分钟不返回 | `prlctl list -a` 看状态一栏 | 虚拟机被「空闲自动暂停」（距最后一次键鼠注入满 30 分钟；`prlctl exec` 不算活动） | 状态是 `paused` → `prlctl resume "Windows 11"`，探测通道后接着跑。★ **不许用 `prlctl set … --pause-idle off` 去关它**——用户 2026-11-24 明令不改虚拟机设置，见 [02 §19](02-VM操作与传输纪律.md) |
| `preflight.sh` 报 **`deploy_exe status=error reason=probe_failed`** | 直接重跑一次看是否转绿 | **读数侧抽风**，不是部署过期（真过期是 `status=fail`） | 带 `attempts=3 raw=[…]` = 通道没执行，**别据此重构建** |
| 虚拟机桌面**糊满一叠空黑窗**、越跑越多 | 数 `conhost.exe`：`tasklist` 或 CIM 里看**父进程还在不在** | 提权探测漏下的**孤儿控制台宿主**（Win11 默认终端是 Windows Terminal，一次探测一对） | `tools/vm/postflight.sh` 看 `orphan_console`；`… clean` 只杀孤儿；见 `docs/20261031-2357` |
| 脚本**一报错就什么都不打印**，或少打一个值 | 查那行 `$VAR` 后面是不是紧跟中文/全角字符 | bash 3.2 **按字节**把首字节吞进变量名（`set -u` 下直接崩） | 一律写 `${var}`；跑 `tools/test/source-guard.sh` 第 D 节 |
| `prlctl exec` 报 **has finished booting** | `prlctl capture` 截图 | 机器已在 **RE/PE**，exec 通道不可用 | ★ **只能截图，绝不重启**（RE 内灌图中重启会 1235） |
| PowerShell 读文本**换行全没了** | 改 `-Encoding UTF8` 或 `[IO.File]::ReadAllText` | PS 5.1 对无 BOM 文件按 **GBK** 解码，UTF-8 全角字符末字节吞掉 `\n` | 读文本一律显式 UTF8 |
| PowerShell 输出**整段空白**、什么都不打印 | 去掉 `Select-String` 过滤，直接看全量 | 原生命令写 stderr 被当成 `NativeCommandError`，管道输出被吞 | ★ **「没输出」既不能当成功也不能当失败**，另找证据（哈希/文件） |
| `grep 中文` 结果诡异 / `tr: Illegal byte sequence` | 加 `LC_ALL=C`，只留 ASCII | 输出是 GBK/混合编码 | 判据**只认结构化字段**，绝不用中文文案当判据 |
| 返回的路径里带上了盘符、后面的步骤用不了 | 看日志里是否分配了新盘符 | 字母会**逸出**到返回路径/落盘方案 | 查 `grep hold_for_process` 那 3 处；必要时 `main()` 收尾统一撤 |
| 界面脚本说「控件 2003 不是取消按钮」、中文比对全部对不上 | 看原始字节：`取消` 是不是 `c8 a1 cf fb` | 常驻助手回传的控件文字是**系统本地编码（GBK）**，脚本按通用编码读成了替换字符 | 逐行先按通用编码、解不开按 GBK **严格**解码再比对；见 [02 §21](02-VM操作与传输纪律.md) |
| 长任务「启动了」却一直没有结果 | 立刻看它的日志文件在不在、进程在不在 | 根本没启动：空参数被命令行吃掉、共享盘 `X:` 映射随重启丢失、脚本「等结束标记」的循环在空等 | 启动后马上核对「真的在跑」；见 [02 §21](02-VM操作与传输纪律.md) |
| 连着跑第二个界面脚本，被「有人在用虚拟机」拦下 | 看上一次输入是不是自己刚才的自动化 | 自己的模拟点击也算键鼠输入；守卫分不出是谁在敲 | 等空闲满 120 秒再跑，**不要调低阈值**；`tools/vm/user-idle.sh` |

## D. 备份 / 还原跑起来之后

| 症状 | 3 分钟内先做 | 最可能是 | 判据 / 下一步 |
| --- | --- | --- | --- |
| 捕获**开头长时间零输出**、镜像恒 208 字节 | 看日志 `CAPTURE_HEARTBEAT` / `CAPTURE_STALL`；看 CPU | DISM **先全卷预扫**、扫完才写第一字节——**开头零字节是正常** | 心跳阈值 600s；超过且 CPU 也趴下才算卡死 |
| 还原后**进不去恢复环境** | 查 `status.json` 的 `errorCodeText` | 缺 `reagentc.exe`/`SYSTEM` → 现在应当**任务失败 `BR-RE-047`** | ★ 若这种情况下**报成功**，才是缺陷（v2.6.73 起必须失败） |
| 点了「立刻重启进入恢复环境」，机器**闪一下就回 Windows**、任务状态几乎没动 | `dir /b /ad C:\BackupRestore-logs`（也看 F:/H: 根） | ①RE **根本没起来**（引导链）②RE **起来了但极早期退出**（失败策略 auto-escape 清理后 `wpeutil reboot`） | **三态判据**：会话目录不存在=①；只有 `session.log`/`BackupRestore-escape.log`=②；有 `Recovery.log` 的 `STEP n/4`=真跑了（问题在任务）。★ 别用「画面一样」下结论 |
| `bcdboot`/`bcdedit` 报 **`c0000043`**，改什么都失败 | **别再试了**，直接重启 | `bcdedit /import` **毒化**了 BFSVC 已打开的存储 | 重启即恢复；以后拿 import 只做验证、不做回退 |
| 还原后系统起来了但**盘符全乱** | 记下当前盘符，别格式化 | 盘符重启重排（**不能用盘符当卷身份**） | 判据要用卷 GUID / 分区 GUID / 序列号 |
| 任务**卡在某个 stage** 不动 | 读 `status.json` 的 `stage` + 日志尾 | 命令挂住 / 等交互确认 | 别直接杀；先抓日志与当前阶段，再决定重试 |
| 备份的**校验一步（第 3/4 步）好几分钟没动** | 搜恢复环境日志里 `Image hash computed: backend=` 那一行 | 旧版本（2.10.6 及以前）用纯软件哈希，速度随环境大幅波动（实测 55–480 MB/秒，最慢一次 39.9 GB 用了 727 秒） | 有那一行且 `backend=bcrypt` → 是新路径，40 GB 约 25–30 秒，再慢就看磁盘；**没有那一行** → 是旧版本，慢是正常现象不是卡死，别重启。见 `docs/20261124-1645-镜像哈希…` |
| 「还原数据到非 C 盘」选离线、进恢复环境，三次确认后弹「任务准备失败…restore-existing target must be the active Windows volume」 | 看界面标题的版本号 | **v2.10.7 及以前的缺陷 1**：10-18 加的准备期安全闸拦得太宽。**v2.10.8 已修** | 升级到 v2.10.8 及以后；旧版本上失败是干净的（没有任务、没有写入、没有重启），改用在线方式可以完成。记录 `docs/20261124-1645-离线数据卷还原缺陷复核…`，修复 `docs/20261125-0010-离线数据卷还原等四处修复…` |
| 「还原数据到非 C 盘」选离线被拒，错误码 `BR-IMG-009` 或 `BR-IMG-010` | 看错误文字：是不是「这是一份完整 Windows 镜像」 | **不是故障**：拿一份完整 Windows 镜像当数据镜像写进数据卷，v2.10.8 起会被拒（看镜像自己的副档，或只读挂载）。`BR-IMG-010` = 判断不了镜像性质 | 要还原系统盘用「还原系统到 C 盘」，要装到另一块盘用「新增非 C 盘第二系统」。副档丢了的大镜像会被挂载探测（40 GB 约 3 分钟），不是卡死 |

## 三条「别做」清单（比「该做什么」更省时间）

1. **别用中文文案当判据**——它随语言环境变，而语言环境是最容易变的变量。
2. **别把「空输出」当结论**——先问「命令跑了吗」，再问「结果是空吗」。
3. **别在 RE/PE 里重启**——停在那里就截图取证，重启会把证据和半截状态一起搅烂。
