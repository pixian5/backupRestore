# 02 VM 操作与传输纪律

> 本节全部来自多轮实机踩坑，可信度以标注为准。坐标/分辨率/空闲**每轮重新实测**。

## 1. prlctl 通道三态

- `prlctl exec "<VM名>" cmd /c "命令"`（**多参数姿势**，不加 `--`）= **SYSTEM+管理员**；把整个 `cmd /c ...` 当一个引号串会静默失败(被当程序名) —— 20260927-0016 [✅]
- `--current-user` = Session 1 中等完整性令牌：GUI 会话可见，但跨完整性读控件/UIPI 拦键鼠；**冷启无登录会话时返回固定占位 `p8b6\x`，不是通道坏**，判活看 SYSTEM 模式 `whoami` 是否干净 —— 20260927-0016 [✅]
- 全功能 WinRE 内 `prlctl exec` **可用**（刚进 RE 瞬时报 `Unable to open new session`，稍后重试即恢复，别据此断定没代理）；裸 WinPE 内不可用 —— 20261013-2115 [✅]
- **VM 名必须带空格完整形式或用 UUID**；间歇抖动（`Invalid argument`/打不开会话）等 3-5s 重试即可，不是客体故障 —— 20261014-1216 [✅]
- `prlctl restart` 对无 Tools 的 PE 无效，需 `stop --kill` + `start`；卡锁屏时 `stop --force` + 8s + `start`（约 16s 就绪）—— 20260911-0102/20261013-2115 [✅]
- 长 `-EncodedCommand` 会整体超时；**复合长脚本过 prlctl 会神秘挂起且 0 字节输出——拆单步逐个验证** —— 20261014-1216/2107 [✅]

## 2. 会话隔离与键鼠注入

- `prlctl exec` 跑在 Session 0 服务窗口站，GUI 在 Session 1：**SYSTEM 通道结构性 EnumWindows 不到主窗口**（GetLastError 1400 类）→ GUI 操作用计划任务 `Interactive+Highest`（`restart-gui-plain.ps1`/`restart-gui-h.ps1`）或 VM 内 TCP agent —— 20260927-0016/20261014-1315 [✅]
- **唯一可靠键鼠路线 = VM 内 TCP agent**（`tools/win-clicker/br-agent-tcp.sh` → 提权+Session1+高完整性，真实 `SetCursorPos`/`mouse_event`/`SendInput`）；Win32 消息级（SendMessage/BM_CLICK）不可行（UIPI + 自绘按钮不响应）—— 20261014-0126 [✅]
- 端口 9124；VM IP 段 10.211.55.x；空闲 900s 自退；agent 的 exec 与 agent 同进程，脚本里写 `exit N` 会把 agent 一起杀掉——一律用 `return` —— 20260927-0016/20261014-0126 [✅]
- 判注入是否生效**只信 `GetLastInputInfo` tick 前后对比**，不信退出码 —— 20260927-0016 [✅]
- F 键/组合键用 `prlctl send-key-event --scancode`（`--key enter` 是无效键名、退出码 255 且静默无效；Enter=28 Tab=15 Insert 等需 scancode）—— 多篇一致 [✅]
- 键盘注入半瘫根因：`keybd_event` 扫描码传 0 且不置扩展键标志 → Home/End/Insert/Delete/PageUp/方向键被标准 EDIT 忽略（Backspace 不是扩展键所以一直正常）。修法 `MapVirtualKeyW` 取真扫描码 + 扩展键表置 `KEYEVENTF_EXTENDEDKEY` —— 20261014-0126 §4 [✅]
- 标准 EDIT **本身不支持 Ctrl+A**（RichEdit 特性）；可靠全选 = `End(0x23)`→`Shift+Home` —— 20261014-0126 [✅]
- ⚠️ `tools/win-clicker/vmkey.sh space` 疑有键码 bug：路由门按数值区间 59-88 走 scancode，`space`(-k 65) 落入该区间被发成 scancode 65=F7；09-30 的"修复"只改了 f7 数值没动路由门，F7/F8/F9/F10 映射疑均错位。**用 f7-f10 前先现场打条短命令截图核对** —— 代理静态核验 [🔸 未实证]
- SmartMouse 卡死（连宿主光标都动不了）按 Ctrl+Alt 释放；根治关 SmartMouse 但 `MouseSync`/`MouseVtdSync` 必须保持 1 —— 20260927-0016 [✅]
- **prlctl 无鼠标注入接口**；macOS AX/computer-use 合成鼠标事件不转发进 guest —— 20260913-1408/20260916-0759 [✅]

## 3. 编码链（踩过 N 次的元凶）

- `prlctl exec` stdout 是 **GBK**：宿主侧 `iconv -f GBK -t UTF-8` 或 python `decode('gbk')` —— 20260927-0016 [✅]
- **中文 cmd 管道会静默漏字段行**：`bcdedit /enum {bootmgr} /v | findstr /R default displayorder resumeobject` 只命中 default——字段名本身是英文，是 GBK 字节流与模式不匹配；**根治 = 管道前 `chcp 437`** —— 20261015-0708 实测 [✅]
- 写进客体的 `.ps1` 必须纯 ASCII 或 UTF-8 带 BOM（PS5.1 按 GBK 读 UTF-8 here-string，C# 段里任何中文注释都会吞行致 Add-Type 失败）—— 20260916-0759 [✅]
- DISM/BCDBoot 原生输出按系统代码页；产品用 `decode_windows_bytes` 按字节嗅探（UTF-8 失败则 MultiByteToWideChar CP_OEMCP/CP_ACP）—— 20260819-implementation-notes/20260930-1530 [✅]
- **二进制内含新代码核对**：Rust 字符串字面量在 exe 里是 **UTF-8**（不是 UTF-16）——`[Text.Encoding]::UTF8.GetString(ReadAllBytes)` 后 `Contains`；`findstr` 查中文/二进制不可靠 —— 20261014-1216/0126 [✅]
- GBK 陷阱：`read_to_string` 读 GBK 控制台输出解码失败会被当成"无输出"；快照/`cmd >` 重定向文件读用 `GetEncoding(936)` —— 20261005-1050/20261015-0021 [✅]
- zsh `echo` 把 `\c` 当抑制输出——写 batch 一律 `printf '%s\n'` —— 20261015-0010 [✅]
- PowerShell 5.1：`ConvertFrom-Json` 处理不了仅大小写不同的键→验收用 python 标准 JSON；`$_`/`\` 会被 exec 吃掉→复杂参数走 `-File` 或 base64 —— 20260930-2130/20260927-0016 [✅]

## 4. 共享盘与 UNC

- `X:` = 共享目录，**只在 VM 交互会话可见**；SYSTEM 会话用 UNC `\\Mac\backupRestore`（prlctl exec 传 UNC 要双反斜杠转义）—— 20261013-1725/20261015-0105 [✅]
- `powershell -File` **不吃 UNC 路径**——先 copy 进 VM 再跑 —— 20261015-0105 [✅]
- 共享盘"坏"的真因是 Tools 降级+无交互登录会话（prl_fs 只有 console 登录才建通道）；`net view` 报 1702 是假警报，判好坏直接 `dir \\Mac\backupRestore\VERSION`；`if exist \\Mac\...\NUL` **恒假** —— 20260928-0658/20261013-1725 [✅]
- 共享目录**不同步 `.` 开头隐藏文件**（计划任务静默不执行）；共享不同步同名文件覆盖有 >12s 缓存（用唯一文件名）—— 20260927-0016 [✅]
- 共享盘重启后必掉：`net use X: \\Mac\backupRestore /persistent:no` 是唯一解，`--shf-host off/on` 无效 —— 20261012-1510 [✅]

## 5. 截图、判活、取证

- 截图动作名是 `prlctl capture`（不是 screenshot）；**拿到图立刻看**——只算哈希不看图会在报错画面干等（多轮教训）—— 20261014-2315/2107 [✅]
- 读黑底终端/低清截图用视觉模型不可靠；判定执行结果必须有画面证据（"操作成功完成"字样）或 `prlctl exec` 硬验证；本机 Read 工具对 1024×768 PNG 反复失效时可退化 PIL 主色统计 —— 20261014-2244/0021 [✅]
- RE 里 prlctl exec 不可用时，判断 RE 是否真在干活 = 看宿主 `.pvm` 快照层 `.hds` 的 mtime/size 变化，而非看画面（无头执行画面静止属正常）—— 20261014-2107 [✅]
- 逐键输入铁律：命令打完→截图核对完整→才回车（未核对曾把残缺命令当成功执行）—— 20261014-2244 [✅]
- **改启动顺序/启动设备前，必须先截图判断当前界面在什么状态**——2026-10-16 我在 **UEFI 固件界面**时误当成「已在『按任意键从 DVD 启动』」那一步，对着固件猛发空格白费时间；**用户手动在 UEFI 里选光驱才进的 PE** —— 20261016-1413 [✅ 用户当场纠正]
- **`--device-bootorder` 对 UEFI 不实测生效**：`"cdrom0 hdd0"`（双设备）无效、`config.pvs` 的 `BootingOrder` 对 UEFI 无效；进 PE 实测是**在 UEFI 里手选光驱** —— 20261016-1413 [✅]
- **`type_text.sh` 不支持 `\n`**：`"diskpart\nlist volume"` 换行被丢弃 → 屏幕成 `diskpartlist volume`。**一条命令一次执行**：先 `type_text.sh "<cmd>"`，再单独 `./vmkey.sh enter` —— 20261016-1413 [✅]
- **RE 内 `prlctl exec` 不可用**（WinRE 无 Parallels Tools）；取证只能读磁盘持久日志（`C:\BackupRestore-Recovery-early.log`、镜像卷 `Recovery.log`、任务目录），键盘注入用 `vmkey.sh`/`type_text.sh` —— 20261016-1413 [✅]
- **RE 内 `Esc` 能取消产品错误框，但不清 `bootsequence`**：取消后载荷重跑、又失败 → **重启死循环回 RE**；须走 PE 通道从外部改 BCD 才能逃出 —— 20261016-1413 [✅]

## 6. 宿主空间（CoW 模型，2026-10-15 用户纠正）

- **快照走 CoW：只记相对父快照的增量，不会整份复制磁盘**。层数多的真正代价 = 各快照增量各自累积、**删除前不释放**；10-12 吃满怀因 = 多轮大量写入的旧块增量累积。估算按「写入量 × 保留层数」，**不按「磁盘大小 × 层数」** —— AGENTS.md/20261015-0710 [✅ 用户拍板]
- 纪律不变：改 BCD/默认项/一次性启动/WinRE 注册/PE 部署**不拍整机快照**（用 BCD 文件级备份）；确需回滚才拍且**全程最多 1 个**；跑 87GB 级还原前宿主空闲 ≥ 镜像 × 2.5；跑完立刻 `df -h /System/Volumes/Data`；有快照时 `prl_disk_tool compact` 无效（先删层）—— AGENTS.md [✅]
- **删快照必须由旧到新**（Parallels 删快照 X 是把子快照增量合并进 X；反向删会让小文件吸收大增量，仅剩 646MB 时极可能 ENOSPC）；zsh 不做单词切分，`for id in $LIST` 要写 `LIST=(...)` + `"${LIST[@]}"` —— 20260929-1948 [✅]
- `tools/vm-snapshot.sh` 用 `set -euo pipefail` 且输出重定向进记录文件→**快照创建失败时一声不出**；排查读 `.test-artifacts/snapshots/<stamp>-<label>.txt` 的 `VERIFIED_SNAPSHOT=` —— 20260929-2040 [✅]
- `\Mac disk` 是磁盘气球：宿主越满越写大气球的正反馈死循环，停 Tools Service 瞬间消失（禁用服务期间 exec 通道也断，失败分支必须 `net start` 拉回）；它必须进 Capture 排除表（始终被独占，/Apply-Image 撞 0x80070020）—— 20260928-2215/2247 [✅]
- 一天积累 39 个快照约 180GB；清理后宿主 646MB→186GB。实验快照设上限，先建一个明确命名的干净基线长期保留 —— 20260929-1948 [✅]
- 快照对 suspended VM 必失败：先 `resume; sleep 8; stop --kill` 再建；`PRL_ERR_REVERT_IMPERSONATE_FAILED` 常伪装成权限问题，真因是 Mounter 占锁（kill pid + umount /Volumes/.PEVolumes/*）—— 20260925-0424 [✅]

## 7. 其它会咬人的小坑

- 停 Tools 前的 vssadmin/DISM 在线命令只输出版权信息 → 用 `schtasks /create /tr ... /ru SYSTEM /rl HIGHEST /f` + `/run`，用完删任务 —— 20260913-0021 [✅]
- `schtasks /it` 不启动 PowerShell；沙箱策略会拦 `schtasks /delete /f` 与 `del`（判为不可逆删除）→ 用同名 `/f` 覆盖创建、用 `>` 覆盖写输出 —— 20260913-0021/20260925-1940 [🔸]
- 客体删大文件别用 cmd `del /f /q`（会谎报"找不到"而文件仍在），用 `Remove-Item -LiteralPath -Force`；全盘 `Get-ChildItem -Recurse` 遇单个目录拒绝访问会整体中止，改分目录 `cmd dir /s /b` —— 20261013-2348/0020 [✅]
- 目录含保留设备名文件 `nul`（历史脚本 `copy nul` 忘加 `>` 真创建了 0 字节文件）会让删目录报"不是空的"—— `[System.IO.Directory]::Delete("\\?\path",$true)` 绕过 —— 20260913-0021 [✅]
- 提权会话看不到共享盘 X: 但看得到 UNC；提权进程 `GetFolderPath('Desktop')` 可能返回 `C:\Mac\Home\Desktop`（Parallels 重定向）—— 20260925-0424/20260911-0102 [⚠️]
- `--pause-idle off`：VM 窗口非活跃+无窗口程序会被自动暂停，exec 报 `Unable to open new session`（是睡了，`resume` 而非重启）；用完 VM 最稳是 `prlctl suspend` —— 20261009-0830 [✅]
- 测试期温控：`prl_vm_app` 92-104% CPU + ~6.8GiB 时 WindowServer ~60%、无 thermal warning —— 20260819-impl-notes [🔸]
- PD27 vs PD26.4.2：ramdisk 引导在 PD27.x EFI 固件崩溃触发 VM 复位（~6.4s 必现、静默复位非 0xc00000xx），PD26.4.2 同 VM 同 WIM 成功——故障与固件版本绑定，与文件系统/WIM 大小无关；ISO 引导成败也与 PD 版本绑定。宿主当前版本以实际为准 —— 20260925-0025/0424 [⚠️ 时点敏感]
