## 6. 配置类功能的核查纪律（2026-10-17 实机确立，两个真实缺陷换来）

> 触发场景：产品里任何"`设置窗口/ini/env` 里写了一个值 → 某处代码读它"的功能。
> 本节来自 v2.6.10 独立复核查出的**两个**静默失效缺陷（`20261017-0116`）。

- **「写进去了」不等于「读出来了」——必须沿取值函数反查写入方。** 验收配置项时，
  先找到**消费它的那个函数**（这里是 `dism_timeout::wait_ms()` / `recovery_progress::pause_total_timeout()`），
  再问"谁给它赋的值"。只验 ini 内容正确 = 弱信号，会放过整类缺陷 —— 20261017-0116 [✅]
- **两个缺陷的共同形状**：写入方存在、读取方存在，但**不是同一个键**或**不是同一个进程**：
  - 键不一致：读取方写裸字符串 `"BACKUPRESTORE_PAUSE_TIMEOUT_SECS"`，全仓**零写入方** → 恒为默认值；
  - 进程不一致：`wait_ms()` 只读进程环境变量，而唯一赋值点在 `recover_env`（恢复环境专用），
    于是**在线还原**与 **图形用户界面安装预安装环境** 两条路径永远读不到用户在设置里配的值 —— 20261017-0116 [✅]
- **规则：任何跨模块传递的键名一律提为单一来源常量**（`PAUSE_TIMEOUT_ENV_VAR`）。
  裸字符串各写各的时，"只有读取方、没有写入方"这件事编译器不会提醒你 —— 20261017-0116 [✅]
- **「默认 0 = 不限制」类开关的验收必须做三组对照，缺一不算通过**：
  ① 不配置 → 应为默认（零回归）；② 配置 → 应为配置值；③ 同时有显式 env 与 ini →
  **显式必须赢**（否则会破坏"任务级值优先"的无人值守契约）—— 20261017-0116 [✅ 实机三组]
- **优先找"调用前就写日志"的取证点**：`online_operation::dism` 在**调用 DISM 之前**就把等待上限
  写进 `Online.log`，所以哪怕 DISM 必然失败（用 310 MB 的 `S:` 卷做源、退出码 32），
  这一行也能直接证明"配置是否被读到"——**失败不影响取证**，零风险拿到强信号 —— 20261017-0116 [✅]
- **`cfg` 门控要跟着模块走**：`mod dism_timeout` 是 `cfg(any(windows, test))`，在 `main()` 里裸调用它，
  macOS 的非测试构建立即编译失败。新增调用点前先看模块声明的 cfg —— 20261017-0116 [✅]
- **给只被 Windows 路径调用的函数/常量加 `#[cfg_attr(not(windows), allow(dead_code))]`**，
  否则 macOS 构建多出 `dead_code` 告警，破坏"clippy 零新增"的对照基线 —— 20261017-0116 [✅]

## 12. `#[ignore]` 安全测试的门禁化（2026-10-27 实机确立）

- **★ 在 mac 上 `cargo test` 只看到 1 个 ignored，实际有 7 个**——另外 6 个都在 `cfg(windows)` 文件里，
  编译器根本不打开（「零信息」坑在**安全判据**上的表现）。而其中 3 处直接守破坏性安全
  （不往源卷写、改启动菜单能回滚），此前「只在有人记得手跑时才跑」。
- **★ ignore 的理由可能是错的**：`disposable_vhd_preflight_and_index_two_apply` 写着
  「需要 Windows 管理员」，实测在管理员下跑到 `pe_safety::run_restore` 时以
  `BR-IMG-001`（reagentc 需 PE）提前退出——**它真正需要的是 Windows PE/RE**。
  更要紧的是这条测试**把两类属性塞进了一个函数**：前半（真实 DISM 捕获、数据索引应用、
  全部拒绝路径都不写源卷 + 卷序列号不变）在 Windows 管理员下就能验，后半（格式化后引导
  失败的回滚）必须进 PE。混在一起 → 整条永远 skip → **最该自动化的「不往源卷写」一次没跑过**。
- **拆法**：一个函数 → `..._reject_without_write`（Windows，进常规门禁）+
  `..._boot_failure_rollback_in_pe`（PE，保留 ignore 但理由写准）+ `create/teardown_disposable_vhd_fixture`
  两个 helper。**验收标准是断言对账，不是变绿**：原测试 25 条 assert，拆分后两侧合计 25 条，
  `MISSING=0 EXTRA=0`（变量名 `dir.join`→`fx.dir.join` 归一化后逐条匹配）。
- **门禁脚本 `tools/test/ignored-acceptance.sh`**：8 条用例，三态 PASS / FAIL / SKIP，
  SKIP **必须写出缺什么**（`reason=missing_env: BR_...` / `requires_windows_pe_or_re`）。
  实测 `pass=3 fail=0 skip=5 ran=3`；**一条都没真跑时退出 2**（缺夹具不等于通过）。
- **★ 两条通道不能混**：编译必须用**用户会话**（`--current-user`）——源码在 `X:`，那是用户会话里的
  共享映射，**SYSTEM 账户看不到 X:**（`cd /d X:\` 静默失败）；运行必须用 **SYSTEM**——创建 VHD /

## 13. 图形界面判据的「仪器三坑」与客户区尺寸（2026-10-27 v2.6.67 实机确立）

**背景**：S2 给「任务与证据」窗口写的几何驱动首跑成功、之后稳定 `GUI_NOT_FOUND`，
当时记成「疑窗口站/桌面差异」。本轮查实**通道一直是好的**，坏的是脚本自己。

- **★ 先量读数侧，别先怀疑被测对象**：写一份**只诊断不判判据**的探针
  （`tools/win-clicker/_diag-enum-ctx.ps1`），打印 `PID / PROC_SESSION / WINSTA / DESKTOP /
  USER / INTERACTIVE / PROC_COUNT / TOP_LEVEL / GUI_CLASS_MATCH`。本轮读数：
  `SESSION=1 WINSTA=WinSta0 DESKTOP=Default TOP_LEVEL=96 GUI_CLASS_MATCH=1` → 通道健康。
  **判据红时，先让仪器自证环境**，否则「读不到」会被误记成「被测对象失败」。
- **★ 坑 1：钩子文件过期会安静地跑错的脚本**。`H:\brwork\gui-token-body.txt` 里还是上一个脚本名，
  结果文件根本不生成（或被旧内容骗）。固化成 `tools/smoke/run-body.sh`：
  **写钩子 → `type` 回读核对 → 删旧结果 → 启动 → 轮询 `DONE`**，不一致时报 `HOOK_MISMATCH`（退出 2）。
  同时把「跑完 vs 仪器没工作」用退出码分开（0 有 DONE / 1 无 DONE / 2 仪器故障）。
- **★ 坑 2：C# 里写 `[ref] RECT` 会让 `Add-Type` 编译失败，症状伪装成「找不到窗口」**。
  `[ref]` 是 **PowerShell** 语法，C# 必须写 `ref RECT`。而 PS 5.1 的 `Add-Type` 失败是
  **非终止错误**：类型没定义、脚本继续跑 → 委托回调里 `[RS3]::Cls(...)` 抛异常被吞 →
  `EnumWindows` 看似返回 0。所以：C# 块一律 `try { Add-Type @'…'@ } catch { 落 ADDTYPE_ERROR_* }`，
  类型建不起来就 **exit 4**（仪器坏了 ≠ 判据不满足）。**症状与真因完全不像，这是最贵的一坑。**
- **★ 坑 3：固定 `sleep N` 读结果会读到「写了一半」的文件**。冒烟 `run_case` 原来固定等 7 秒，
  新用例断言少几行就假红 → 改成**轮询到 `DONE`（或超时）**。
- **★ `CreateWindowExW` 的 width/height 是整窗尺寸，不是客户区**。上一版注释写反，
  于是 720×480 的窗口实测客户区只有 **704×441**，按 720×480 摆的控件右边界到 708、
  提示条下边界到 448 → **4 个控件被裁 4~7 px**（`OUTSIDE_COUNT=4`）。
  修法：`AdjustWindowRectEx` 由目标客户区反推整窗尺寸；修后 `CLIENT_W=720 CLIENT_H=480`、
  `OUTSIDE=0`。★ 差 4 px 肉眼几乎看不出，**只有几何判据能抓**。
- **★ 存在性基线必须与几何判据配对**：控件**根本没创建**时，重叠/越界/塌缩三条全是 0
  （没东西可重叠），项数判据也可能照样绿。真值用签入的
  `control-baseline-taskadmin.txt`（`id|class`，8 条），**两个方向都验**：
  基线多一条 → `MISSING_CONTROLS=1`、少一条 → `BASELINE_STALE=1`、class 改 → `CLASS_MISMATCH=1`
  （三次变异各自单红）。主窗口与子窗口各用一份基线文件，别混。
- **★ 项数对账要用两条独立代码路径**：`CB_GETCOUNT`（窗口内）与磁盘目录数（文件系统）
  都为 50 才算 T1 通过——同源读数只能证明仪器自洽。
- **★ 模态窗口的驱动脚本必须自己关窗**（`WM_CLOSE` + 轮询确认），否则后面所有用例都被挡住，
  对用户等于程序卡死。
