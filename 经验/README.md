# 经验库（docs/ 全量合并提炼，2026-10-15 建库 · 2026-10-22 滚动更新）

> **本库是什么**：把 docs/ 全部过程文档（截至 2026-10-22 20:30 共 **281 份**顶层 md，含 README/SOP）合并为「后续还会反复用到的经验」，按主题分 8 篇。
> **铁律：docs 不代表正确**。过程文档写于不同时间、不同 AI 之手，多份结论互相矛盾或已被实机推翻。
> 本库每条都标了可信度，与 docs 原文冲突时**以本库为准**；拿不准的先查 `07-墓碑与争议清单.md`。
>
> **可信度图例**：
> - ✅ 已由源码或多条独立实机证据交叉证实
> - ⚠️ 部分可信/表述不严谨（已注明范围）
> - 🔸 单一来源、未能交叉验证
> - ❌ 墓碑（已被推翻，只记录"别信什么"）
>
> **通用引用规则**（来自 20261011-2350 方法论，✅）：
> 1. **版本号是标签不是文档 ID**——同一个版本号可能挂多篇文档，判定"某版本覆盖了什么"必须列全该号下所有文档再合并范围。
> 2. `file:line` **一律会漂移**，引用前先 grep 符号名。
> 3. 图形用户界面坐标、磁盘布局、空闲空间**必须带时点**，跨轮照抄必错。
> 4. "当前状态"类信息只认最后实机日期（本库状态类以 **2026-10-22 20:30** 为基准时点）。
> 5. 旧版本线的待办/README 横幅/任务列表**都会陈旧**——每轮收尾连 `经验/` 一起刷新（2026-10-20 用户再次强调的文档治理三项判据，见 `06` §5）。
> 6. ★ **改了行为，就在同一轮里 `grep 经验/` 相关词并订正**，不要等「下次刷新」。
>    2026-10-28 的教训：v2.6.73 删掉「降级跳过」后漏了同步，`05`/`08` 仍把它当现行行为，
>    而代码里那条路已不存在——**权威源误导比 docs 过期更危险**（详见 `07` §6）。
