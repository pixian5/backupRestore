## 2. 半错/需修正理解的结论（⚠️ 引用要带修正）

- **20261014-2315「0fa52c1d 唯一失败点」**：失败步骤归因（cleanup 删不存在的 GUID 报 exit 1）经错误签名+`main.rs` 代码注释双重证实**是对的**；但「唯一」误导——同一 v2.5.4 还并存 resumeobject 不对称 bug（阶段 3 的 95ab0a7f 撞的是那个）。正确表述：**两个任务各撞一个**。
- **20261015-0021 §2.1 对 2315 的纠错本身纠错错了**（可信度地图自己犯了它防的错误）：说 0fa52c1d 主因是 resumeobject 不对称——与错误串 `invalid task: bcdedit.exe failed with exit code: 1`（resumeobject 路径永远返回 `Boot Manager default or secondary display order could not be preserved`）矛盾。**地图其余部分可用**。
- 20261015-0105 §6 未拍快照的空间理由仍用旧「整份复制一层」模型——决策本身（C:→C: 自替换+BCD 基线+同 WIM 可再还原）有验算价值，**空间论据不可引**。
- 20261012-1510「中文 bcdedit 字段名本地化」：本地化字段名确实要兼容（源码 OR 语义在），但「本地化导致匹配失败」的归因不严——真正咬人的是**管道代码页**（`chcp 437`）。
- 2159 §3 称 `CB_SETCURSEL`+补发 WM_COMMAND 可靠，与 0010/0105 两轮独立实机否定冲突——**按 0010/0105 口径**（不能 CB_SETCURSEL）。
- 文档里的磁盘布局/空闲/菜单 GUID 全是时点快照（1216 写 E: 270G、1436 实为 F: 349.9G；容量 289/279/279G 三种说法）——**引用必须带时点或重新实测**。
- 20260916-0759 分节读：二节 BCD 丢 Windows 条目录因仍有效；其余多节已推翻——不能整篇采信或整篇作废。
- 「bootsequence 时消费时不消费」（0913/0916）vs「每次都被消费」（0925）冲突——统一表述：**消费行为与固件版本相关、不可依赖，以 /enum 回读为准**。

## 4. 10-19/10-20 新增（叙述性误差与覆盖缺口）

- **「`restore-existing` 可以拿任意非 C 卷当目标验 P2」**——错。A 入口 target 必须 = source = 活动系统卷（`windows_prepare.rs:2416`「single-system restore target must equal source」硬闸），`--target-drive F` 会被挡在 P2 检查**之前**。验 P2 硬拒只能用 `create-secondary --target-drive <非活动 Windows 卷> --skip-format`。出处：`20261019-1226` §3 的示例命令对 A 入口不成立（对当时还是数据卷的 F: 更只是设想）—— 20261020-0915 实证 [✅]
- **「机器重启回原 C: 系统」（20261020-0230 §4.4 的叙述）**——字面误导。实测 C: 序列号 `48D5-196E` = **V2 还原出的新系统**（相对 B 键测试前的「原 C:」倒没错，但读者按字面理解会找错卷）。**纪律：任何「回到 X 系统」的叙述前必须 `vol` 对序列号 + `bcdedit /enum {current}`** —— 20261020-0915 [✅]
- **「任务列表显示还有 7 项 pending」**——陈旧列表。10-17 轮（v2.6.9 时代）的 #3/#27–#32 实际已在 `d3cc6a6`/`dd49996`/`31c0954` 完成；回答「还剩什么」之前先逐条对 commit —— 20261020-0915 [✅]
- **「文档索引已覆盖全部文档」**——`文档索引.md` 到 10-20 上午实际**缺 10-18 起 13 篇**（§一「当前与权威」最新只到 10-17）；两套索引（根目录 `文档索引.md` 与 `docs/README.md`）更新不同步。**每轮收尾必须滚动补两处** —— 20261020 本轮已补 [✅]

## 5. 2026-10-20 新增墓碑

- **「有 VHD 附加时 `/Mount-Wim` 一律报 87」**（`20261013` 记录、被多处引用）——**归因不成立/至少证据被污染**。真因是 `wim_mount_markers` 把 `/ImageFile` 传给 `/Mount-Wim`（`/Mount-Wim` 只认 `/WimFile`），该错误自 `50ab69f`（v2.4.2）引入起一直存在 → 任何环境下都报 87。**因此「本机挂载探测不可用」的一切推论作废；"挂载失败 → 降级启发式" 实际是常态而非异常** —— 20261020-1025 实证（`/WimFile` EXIT 0 + 双标记 YES）[✅]
