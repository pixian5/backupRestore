## 1. 项目定位（理解一切的钥匙）

- BackupRestore = **系统自带 WinRE 的自动化包装器**：GUI 准备任务→一次性 BCD 启动项→重启进 WinRE→自动跑 `Recovery.exe`（离线捕获/应用 WIM、修复引导）→清理→回 Windows —— 20261011-2350 [✅]
- 技术栈：Rust 双 crate（约 3.2 万行），**零 .NET/dotnet/C# 运行时依赖**；自绘 Win32 GUI + CLI；构建目标 Windows ARM64 静态 CRT —— 20261011-2350 [✅]
- **必须离线走 WinRE 是逼出来的**：系统卷在线被占用不能 Capture/格式化；VSS 不在 V1；测试机 WinRE 注册在 C: 本身 —— 20261011-2350 [✅]
- V1 范围边界：只做 Windows 10/11 + UEFI+GPT + NTFS + WIM + DISM + BCDBoot/BCD + Windows 自带 WinRE（或自定义 PE）。**明确不做**：分区重构、网络备份、增量/差异、Legacy BIOS、自动 BitLocker，不要擅自扩成 Ghost/PE 工具 —— 20261011-2350 + README [✅]
- **实现硬边界**：第二系统盘符绑定只支持 GPT（MBR blob 12 字节走不了 `gpt_mapping()`）——见 `03` §3 [✅]

## 2. 三入口与操作映射（入口名=用户拍板全称，不得擅改）

| tab 名（全称） | operation | 语义 | 通道 |
| --- | --- | --- | --- |
| 备份 | backup | 从源卷 DISM 捕获 WIM | 智能分流 |
| **还原系统到 C 盘**（A） | `restore-existing` | 还原到当前系统盘，目标锁 `%SystemDrive%` | **必离线** |
| **还原数据到非 C 盘**（B） | `restore-data` | 数据卷还原，镜像不够完整也放行 | 默认在线 |
| **还原系统到非 C 盘**（C） | `restore-system-other`（CLI 归一 `create-secondary`） | 第二系统/他盘系统 | 默认在线，可选离线 |
| 新增第二系统 | `create-secondary` | 旧入口，实质流程与 C 重复 | — |
| 安装 PE | `install-pe-entry` | PE 部署，RAM 版/硬盘版 | — |

- A/B 复用 `restore-existing`、C 复用 `create-secondary`，底层 core/prepare/RE **零改动**；入口规则：A 目标锁定+源卷行隐藏；B 目标≠系统盘且≠已有 Windows 卷；C 需菜单名 —— 20261014-1253 [✅]
- 格式化选项：勾选(默认)=diskpart 快速格式化+校验成功；取消=**覆盖式应用**（镜像内没有的文件保留）；**离线通道恒格式化**，复选框只对在线生效 —— 20261014-1336/1351 [✅]
- GUI 按「受影响卷 == `%SystemDrive%`」分流（判据是 %SystemDrive% 不是"含 Windows 的卷"）—— 20261011-2350 [✅]

| 副档生产 | ✅ | ✅ | ❌ |

- 三条纪律（项目灵魂，✅）：**①不信外部命令退出码 ②写完必须回读 ③元数据簿记必须与镜像实际内容同步**——20260930-2130 起立，GUI 在线路径曾一条都没套用。
- 在线还原 = 应用/覆盖模式：不格式化（除非勾选）、不动引导、无 VSS，镜像里没有的旧文件可能还在目标上 —— 20260930-2130 [✅]
