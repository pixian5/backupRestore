## 1. 项目定位（理解一切的钥匙）

- BackupRestore = **系统自带恢复环境的自动化包装器**：图形用户界面准备任务 → 一次性启动配置数据启动项 →
  重启进恢复环境 → 自动跑 `Recovery.exe`（离线捕获/应用镜像、修复引导）→ 清理 → 回 Windows。
- 技术栈：Rust 双 crate，**零 .NET/dotnet/C# 运行时依赖**；自绘 Win32 图形用户界面 + 命令行；
  构建目标 Windows ARM64 静态 CRT（`+crt-static` 是硬要求，理由见 `04` §1）。
- **必须离线走恢复环境是逼出来的**：系统卷在线被占用不能 Capture/格式化；VSS 不在 V1；
  测试机恢复环境注册在 C: 本身。
- V1 范围边界：只做 Windows 10/11 + UEFI+GPT + NTFS + 镜像 + DISM + BCDBoot/启动配置数据 +
  Windows 自带恢复环境（或自定义预安装环境）。**明确不做**：分区重构、网络备份、增量/差异、
  Legacy BIOS、自动 BitLocker。不要擅自扩成 Ghost/预安装环境工具。
- **实现硬边界**：第二系统盘符绑定只支持 GPT（MBR 盘 blob 是 12 字节，走不了 `gpt_mapping()`）——见 `03` §2。

## 2. 三入口与操作映射（入口名=用户拍板全称，不得擅改）

| tab 名（全称） | operation | 语义 | 通道 |
| --- | --- | --- | --- |
| 备份 | backup | 从源卷 DISM 捕获镜像 | 智能分流 |
| **还原系统到 C 盘**（A） | `restore-existing` | 还原到当前系统盘，目标锁 `%SystemDrive%` | **必离线** |
| **还原数据到非 C 盘**（B） | `restore-data` | 数据卷还原，镜像不够完整也放行 | 默认在线 |
| **还原系统到非 C 盘**（C） | `restore-system-other`（命令行归一 `create-secondary`） | 第二系统/他盘系统 | 默认在线，可选离线 |
| 新增第二系统 | `create-secondary` | 旧入口，实质流程与 C 重复 | — |
| 安装预安装环境 | `install-pe-entry` | 预安装环境部署，内存版/硬盘版 | — |

- A/B 复用 `restore-existing`、C 复用 `create-secondary`，底层 core/prepare/恢复环境**零改动**；
  入口规则：A 目标锁定+源卷行隐藏；B 目标≠系统盘且≠已有 Windows 卷；C 需菜单名。
- **A 入口的硬闸**：`target` 必须 = `source` = 活动系统卷（`windows_prepare.rs` 里
  `single-system restore target must equal source`），所以**不能用 A 去验别的卷**；验「目标非法」硬拒
  只能用 `create-secondary --target-drive <非活动 Windows 卷>`。
- 格式化选项：勾选(默认)=diskpart 快速格式化+校验成功；取消=**覆盖式应用**（镜像内没有的文件保留）；
  **离线通道恒格式化**，复选框只对在线生效。
- 图形用户界面按「受影响卷 == `%SystemDrive%`」分流（判据是 `%SystemDrive%`，不是"含 Windows 的卷"）。

## 3. 架构与模块地图（`crates/`）

```
backuprestore-core     任务模型/11 Stage 状态机/载荷契约/副档/SHA-256/错误类型
backuprestore-cli/src/
  main.rs              入口与任务分发、恢复环境全流程
  native_gui.rs        自绘 Win32 GUI（最大技术债，未拆）
  windows_prepare.rs   在线准备：校验/注入载荷/一次性启动（近百项校验）
  boot_entry.rs        自建 BCD 条目/ramdisk 规格/任务载荷隔离 ★
  boot_menu.rs         引导修复/菜单/default_policy ★
  secondary_registry.rs 盘符绑定（MountedDevices / DMIO:ID:）★
  online_operation.rs  在线还原/备份事务与回读
  pe_operation.rs      预装 PE 路径（pe-requests/*.json）
  winre_registration.rs 系统还原后 WinRE 注册与恢复关联核验
  windows_command.rs   作业对象约束的命令与进程树管理
  recovery_progress.rs 恢复环境/PE 进度上报（含 cmd 后台化、B 键回退）
  wimlib_apply.rs      wimlib 应用通道（`--no-acls` 覆盖式还原）
  text_parsing.rs      本地化输出解析（DISM/bcdedit/mountvol）——**纯逻辑，macOS 也编译可单测** ★★★
```

- ★ **行数不要写在这里**（会漂移）。要数量就 `wc -l`，要符号位置就 grep 符号名，见 `08` §2。
- ★ 纯逻辑必须下沉 `text_parsing`：`#[cfg(windows)]` 模块里的单测在 macOS 一次都不会跑，
  等于「写了测试但永远不执行」。

## 4. 恢复环境任务链 vs 在线 vs 预装预安装环境（能力差异，不随时间变）

| 能力 | 恢复环境任务链 | 在线路径 | 预装预安装环境 |
| --- | --- | --- | --- |
| 11 Stage 状态机+断电续跑 | ✅ | ❌ | ❌ |
| 载荷哈希五件套信任链 | ✅ | ❌ | ❌ |
| keep_indexes 保留策略 | ✅ | ❌ | ❌ |
| 格式化+BCDBoot+恢复环境注册| ✅ | ✅（修复引导有） | 简化 |
| 副档生产 | ✅ | ✅ | ❌ |

- 三条纪律（项目灵魂）：**①不信外部命令退出码 ②写完必须回读 ③元数据簿记必须与镜像实际内容同步**。
  图形用户界面在线路径曾一条都没套用——每个 bug 都是违反它的产物。
- 在线还原 = 应用/覆盖模式：不格式化（除非勾选）、不动引导、无 VSS，镜像里没有的旧文件可能还在目标上。
