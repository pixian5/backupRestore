## 2. 第五项落地：WinRE 注册缺组件从「整个任务失败」改为「降级跳过」

### 2.1 裁定内容（用户 2026-10-16 拍板）

`winre_registration` 的 preflight 在**镜像铺完、引导修好之后**运行。此前只要目标卷缺
`reagentc.exe` 或 `SYSTEM` 注册表，就硬失败——而失败点在链路末端，一失败则前面全部工作作废
（DISM 应用、格式化、bcdboot 都白做）。裁定：**这种情况记警告 + 跳过注册 + 照常报任务成功**；
系统可正常启动，只是不含恢复环境（日后无法从恢复环境检修该系统）。

**安全闸门维持硬失败不动**：身份不符（镜像与目标卷不匹配）、ESP/活动 BCD 加载器不一致、
目标不是恢复环境、固件类型不符——这些仍是真错误，不许降级。

### 2.2 代码改动（`crates/backuprestore-cli/src/winre_registration.rs`）

- 新增两个枚举承载降级语义：
  - `enum Preflight { Proceed, Skip(String) }`——preflight 返回值从「放行」扩展为「放行 / 带原因跳过」；
  - `pub(crate) enum RegistrationOutcome { Registered, Skipped(String) }`——`run()` 及三个 repair
    入口的返回值。
- `Backend::preflight` 签名改 `Result<Preflight, TaskError>`；WindowsBackend::preflight 的组件探测
  （`pe_safety::probe_file` 查 `Windows\System32\reagentc.exe` 与 `Windows\System32\config\SYSTEM`）
  由硬失败改为返回 `Preflight::Skip(reason)`，并先 `append_log` 记 `WinRE registration skipped: …`。
- `run()` 收到 Skip 时：`backend.checkpoint("registration-skipped")?` 后直接返回
  `Ok(RegistrationOutcome::Skipped(reason))`，**不触碰 info/register/enable/verify 四步**。
- `repair` / `repair_secondary` / `repair_with_mode` 均改返回 `RegistrationOutcome`；失败路径
  （Err）维持原有 sdi 回滚逻辑不变——**只有「缺组件」这一类从 Err 降级，其余失败照旧炸**。
- 调用方两处适配：
  - `pe_operation.rs`：`match repair(...)? { Registered => log("引导与恢复环境关联已回读；…"), Skipped(reason) => log("恢复环境注册已按裁定降级跳过：{reason}") }`；
  - `main.rs`（离线通道）：Skipped 时 `append_log(log, "恢复环境注册已按裁定降级跳过：{reason}")`。
- 单测：Fake backend 加 `skip: bool` 字段（5 处构造补齐），新增
  `registration_degrades_when_components_missing`——断言降级时任务报成功、返回原因、
  且调用链只有 `["preflight"]`（证明 register/enable/verify 一步没跑）。

## 2.4 实机降级实测（OS 级，2026-10-16 当日补做）

问题：P5 裁定的核心假设是「系统可正常启动，但不含恢复环境」——用实机验证这句话。

方法（全部可逆，先 `bcdedit /export` 留回滚保障）：

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | `reagentc /info` 基线 | **Enabled**；位置 `\\?\GLOBALROOT\device\harddisk0\partition4\Recovery\WindowsRE`；BCD id `f530b9e0-…`；版本 10.0.26100.8031 |
| 2 | `bcdedit /export` + `bcdedit /enum {bootmgr} /v` 留档 | 操作成功；default `{41326e72}`、resumeobject `{41326e71}` |
| 3 | `reagentc /disable` | 成功；`/info` 翻转为 **Disabled**、位置空、BCD id 清零 `00000000-…` |
| 4 | `prlctl restart` 重启 | LastBootUpTime 8:49:34；exec 10 秒内恢复响应 |
| 5 | 桌面验证 | explorer 8:49:41 起来；**截图 `p52-desktop-with-winre-disabled.png`：正常进桌面，BackupRestore GUI 应用本身也照常运行** |
| 6 | `reagentc /enable` 复原 | 成功；Enabled + 同位置 + 同版本 |
| 7 | BCD 核对 | `{bootmgr}` 逐字节一致（`fc /L`：找不到差异）；全店扫描旧 GUID `f530b9e0` **零命中**（无悬挂引用）；新恢复序列 `a6c31a81` 正常挂为 recoverysequence |

**结论**：不注册 WinRE，系统照常启动进桌面、应用照常运行——P5 裁定的假设成立。
**如实标注**：`reagentc /disable+/enable` 会重建恢复序列条目（BCD id `f530b9e0` → `a6c31a81`），
这是 reagentc 自身管理的条目，`{bootmgr}` 三行（default/resumeobject/displayorder）未动；
经由本程序代码路径（还原到缺组件目标卷）的端到端降级实测未做。

**顺带发现的环境现象**：VM 重启后约 13 秒，`C:\Users\Public\backupRestore-package\BackupRestore.exe`
会被自动拉起（父进程短逝，已排除计划任务/服务/Run 键/启动文件夹/Parallels autostart/watchdog 脚本，
机制未查明）。**测试纪律**：每次验收前先 `taskkill /F /IM BackupRestore.exe` 清场，再按需起 H: 副本。

## 3. P4 盘符精确判定的实机验证（v2.6.4 代码，v2.6.5 补证）

背景：v2.6.4 把「安装 PE」入口的 `== 'C' || == 'S'` 字面量判定改为三把精确尺子——
`system_drive_letter()`（读 `%SystemDrive%`，取不到返回 None、**不退回 C**）、
`is_efi_system_partition()`（按分区类型 GUID `{c12a7328-…}`，**与字母无关**）、
`is_program_drive()`（可执行目录首字母比较）。本轮把四个场景逐个实机走完：

### 3.1 场景 A：C: 是系统盘 → 必拦

v2.6.4 轮次已有铁证（GUI 选 C: 点创建任务被拦），本轮未重跑。
判定依据：`%SystemDrive%` = C。

### 3.2 场景 B：ESP 按 GUID 认，与字母无关（本轮补齐）

现场编排：本机 ESP 原本挂在 S:。用 diskpart 把 ESP 的字母**移到 R:** 后：

- `mountvol` 确认 `\\?\Volume{d08d796f-…}` 挂在 R:\，且明确输出「EFI 系统分区装载在 R:\」；
- CLI `list-volumes` 仍只返回 C/F/H/T——**ESP 换了字母照样进不了可选列表**
  （`discover_drives` 按 `is_reserved_partition()` 的 GUID 过滤，ESP 永远不出现在 GUI 列表里）；
- 单测 `esp_is_judged_by_partition_type_guid_not_letter` 锁住行为：S: 上是 ESP → 认得出；
  S: 上是基本数据分区 → 不误拦；ESP 换到 M: → 照样认出；卷信息缺失 → 判「不是」不猜。

**结论**：旧代码 `== 'S'` 拦不住「ESP 不在 S」；新代码与字母完全解耦。

### 3.3 场景 C1：S: 是数据盘 → 不误拦（本轮补齐，铁证）

现场编排：本机有一个 5 GiB 测试卷（原 T:，`\\?\Volume{950bd694-…}`），用 diskpart
`select volume T → assign letter=S` 把它的字母移成 S:（T: 暂时无字母）。然后 GUI 测试钩子
选中 S: 点「创建任务」，日志：

```
GUI action started: create task; operation=install-pe-entry
GUI action blocked: target partition free space < 2GB
```

**关键点**：拦住它的是「空间不足 2GB」（该卷只剩 34.6 MiB），而空间检查排在三道精确判定
**之后**——系统盘/ESP/程序卷三把尺子全部放行，才轮到空间检查。截图
`v2.6.5-p4c-s-data-volume.png` 显示弹窗「目标分区 S: 可用空间不足 2GB (34.6 MiB)」。

### 3.4 场景 C2：C: 是数据盘 → 不误拦

**本机无法构造**：C: 就是活动系统盘（`hasWindowsInstallation=true`、disk 0 partition 4），
不存在「C: 是数据盘」的真实形态。以单测
`system_drive_letter_parses_environment_variable` 锁定 `%SystemDrive%` 解析机制
（独立解析期望值后比对，且绝不出现「取不到就退回 C」）。**此处如实说明：缺实机证据。**

### 3.5 场景 D：H: 是程序卷（GUI 自身所在卷）→ 必拦（本轮补齐，铁证）

GUI 从 `H:\brwork` 运行，测试钩子选 H: 点「创建任务」，日志：

```
GUI action started: create task; operation=install-pe-entry
GUI action blocked: target H: is system=false esp=false program=true
```

截图 `v2.6.5-p4d-h-program-volume.png`：弹窗「目标分区不能是系统盘、ESP 或运行本程序的卷。」
`br-events.ps1`：APPERROR=0、WER=0（三件套之②③）。

### 3.6 P4 场景总账

| 场景 | 期望 | 证据 |
|---|---|---|
| A C: 系统盘 | 拦 | v2.6.4 铁证 |
| B ESP（挂在 R:） | 列表过滤 + 不误拦数据盘 | 本轮：mountvol + list-volumes + 单测 |
| C1 S: 数据盘 | 放行（死于空间检查） | 本轮：日志 + 截图 |
| C2 C: 数据盘 | 放行 | **本机无法构造**；单测锁定 |
| D H: 程序卷 | 拦（program=true） | 本轮：日志 + 截图 + 三件套 |

### 5.2 两个新坑（本轮实测）

1. **bash 双引号会吞掉 UNC 根的 `\\`**：`prlctl exec ... cmd /d /c "copy /y \\Mac\…"` 里
   bash 先把 `\\` 折成 `\`，UNC 根变成 `\Mac`，cmd 把它当当前盘相对路径
   （报错头显示 `C:\Mac\backupRestore\…`，极具迷惑性）。
   **修法：整条 /c 参数用 bash 单引号包裹**，`\\Mac` 原样透传；
   br-s1.sh 内部则是把 UNC 放 bash 单引号变量里，等效。
2. **cmd 不能 `cd /d` 到 UNC**（「CMD 不支持将 UNC 路径作为当前目录」）→ VM 内 cargo 用
   `--manifest-path \\Mac\backupRestore\Cargo.toml --target-dir C:\br-test-target` 绕开
   （`--target-dir` 必须指本地盘，UNC 上报 failed to remove temporary directory）。

另：`prlctl exec` 的 `-Command` 会剥双引号，PowerShell 计算属性 `@{n="SizeGB";e={…}}`
必被搅烂（本轮实测报「SizeGB 不是 cmdlet」）——只用在双引号内的简单 `Select`，
复杂形状仍走 `-File` + 脚本文件。
