## 五、原生命令语义：确认一项、否定一项、收紧一项表述

以下均在正常 Windows 的新建临时目录进行；没有进入 PE，也没有执行格式化。原始命令、退出码、标准输出、错误输出和结果文件内容全部保存。

### 5.1 确认：未整体分组的条件命令确实漏写真分支结果

原形：

```bat
if exist "present.txt" (echo SYS) else (echo NOSYS) > "result.txt"
```

| 场景 | 退出码 | 标准输出 | 结果文件 |
|---|---:|---|---|
| 文件存在，原命令形态 | 0 | `SYS` | **未生成** |
| 文件不存在，原命令形态 | 0 | 空 | 内容 `NOSYS` |
| 文件存在，整条条件外加括号 | 0 | 空 | 内容 `SYS` |

这将旧报告的“重定向只作用于 else 分支”从待验证假设推进为**本 Windows 版本上的原生命令复现**。程序源码相应调用的结果文件读不到时，确实存在错误分类的机制；但仍未通过 PE 界面真正执行该格式化分支，不能宣称已在 PE 格式化路径重现数据损坏。

### 5.2 否定：不能再说 cmd 一概不支持原生卷路径重定向

通过只读 `mountvol C: /L` 获取真实卷路径，再在其下指向本轮验收目录，执行：

```bat
echo VOLUME_PATH_OK > "\\?\Volume{实际卷标识}\Users\Public\本轮验收目录\probe-native\volume-redirection.txt"
```

**退出 0，结果文件存在且内容为 `VOLUME_PATH_OK`。** 因此此前“cmd 无法使用此路径重定向”的笼统说法错误。不能将本例外推成所有工具/所有 PE 版本都支持；也不需要靠该错误假设证明路径改造有必要。

### 5.3 收紧：读写路径错配既可能读不到，也可能读旧结果

- 写入卷根对应目录，但读取 `logs\format-check.txt`，干净场景的读取路径不存在。
- 在读取路径预置 `SYS` 后，令本轮写入路径产生 `NOSYS`，读取路径仍保留旧的 `SYS`。
- Windows 字符串检查：`NOSYS.Contains("SYS") = true`；精确匹配 `NOSYS == SYS = false`。

这验证了“不能说永远为空/永远 false”的修订。联合修复需要路径同源、每次输出归属、错误分类和精确判据；单改子串匹配不会反向把 NOSYS 判为系统。

验收脚手架也出现了两处问题，已保留记录而未改产品代码：

1. 首轮内核测试已通过，但脚本假定设置 `TEMP` 就能限定 Rust 临时目录。SYSTEM 账户实际使用 `C:\Windows\SystemTemp`，脚本在目录归属断言处停止。核实本次测试唯一目录和摘要后，从原产物继续，没有重新捕获或覆盖旧数据。

这些差异记录在脚手架日志中。原始首轮失败与后续成功日志并存，不写成“一遍运行全部通过”。
