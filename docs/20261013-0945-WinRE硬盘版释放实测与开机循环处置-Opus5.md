# WinRE 硬盘版释放（create-secondary 把 Winre.wim 释放到硬盘）实测与开机循环处置

> **一句话结论**：删掉"完整 Windows"擦除前预检硬约束后，"新增第二系统"（create-secondary）
> 把官方 `Winre.wim`（709,810,082 B，index 1）**释放到了 64GiB 目标卷**——格式化、应用、
> 建引导项全部成功（`status.stage=boot-repaired`、进度 90%），**只在最后一步"离线 WinRE 注册"
> 被 `目标缺少离线注册组件` 拦下**（该 WinRE 镜像里没有 `reagentc.exe`）。
> 但程序已把新 RE 条目设为 `{bootmgr} default`，于是**每次开机都被拖进这个 RE**，用户观感即
> "开机死循环"。本次已在 WinPE 里把 BCD 改回**基线**（字面等于 `bcd-before-bootmgr.txt`）并重启
> 回 C: 桌面。**释放路径本身是通的；真正的拦路石是下游离线注册检查。**

- 基线 commit：`d4bc2c6`（还原：移除 create-secondary 对 PE/RE 的完整性预检硬约束）
- 部署版本：**2.4.2**，`H:\brwork\BackupRestore.exe` SHA-256 `a133de4232ebafb63ad09dc2e1f634b4466af269404aa8e2212485ed74c6127b`
- 实测时刻：prepare `2026-10-13T00:25Z` / 失败 `00:52Z` / 恢复后桌面 09:36（本地）
- 证据边界：结论均来自任务目录内的 `status.json` / `prepare.log` / `task.json` / `boot-menu-plan.json` /
  `bcd-before-bootmgr.txt` / `diskpart-format.txt`，以及恢复后对 P:、BCD、事件日志的实机回读。

## 1. 诉求

用户要求：把 `Winre.wim` **释放（Apply）到硬盘**当第二系统（"RE 硬盘版"），而**不是**挂载注入；
忽略此前某次会话加在 create-secondary 上的"必须是完整 Windows"的完整性预检硬约束；让程序自动跑完
（格式化 → 应用 → 写启动项 → 武装 bootsequence → 重启进 RE），只看真实结果，不被环节拦下。

这类一次性/默认项的效果，且对象正被系统占用）。

## 3. 处置（本次实际动作 + 可复用命令）

在 WinPE（`artifacts/BaseWinPE.iso`，UEFI 菜单进入 cmd）里给 ESP 挂盘符后改**离线** BCD：

```
diskpart  →  select volume 4   （300MB FAT32 Hidden，即 ESP）  →  assign letter=S  →  exit

bcdedit /store S:\EFI\Microsoft\Boot\BCD /default {12e3701c-c361-11f1-90a2-c222b5348ef7}
bcdedit /store S:\EFI\Microsoft\Boot\BCD /displayorder {5bdd13d0-c6a0-11f1-b710-cca71dd293b2} /remove
bcdedit /store S:\EFI\Microsoft\Boot\BCD /deletevalue {bootmgr} bootsequence
bcdedit /store S:\EFI\Microsoft\Boot\BCD /set {bootmgr} timeout 10
```

再在宿主机还原引导设置并重启：

```
prlctl set   "Windows 11" --device-bootorder "hdd0"
prlctl set   "Windows 11" --select-boot-device off
prlctl set   "Windows 11" --external-boot-device hdd0
prlctl set   "Windows 11" --device-disconnect cdrom0
prlctl stop  "Windows 11" --force  &&  prlctl start "Windows 11"
```

恢复后 `bcdedit /enum {bootmgr}` 与任务内**基线** `bcd-before-bootmgr.txt` **逐项一致**：
`default {12e3701c-c361-11f1-90a2-c222b5348ef7}`、`displayorder {152dcf4e…},{12e3701c…}`、
`timeout 10`、无 `bootsequence`；桌面截图确认开机正常、GUI v2.4.2 在跑（9:36）。

> 注：C: 条目上的 `displaymessageoverride Recovery` 和 `recoverysequence {f530b9e0…}`
> **在基线里就已经存在**，不是本次改动，无需回退。

### ⚠️ 一个坑（我犯过一次，务必别再犯）

在 WinPE 里执行 `bcdedit /enum {5bdd13d0-…} /v` **会报 "The specified entry type is invalid"**——
因为该条目 `device=partition=P:`，而 PE 里 **P: 没有盘符**，bcdedit 解析不到就报"条目类型无效"。
**别据此判定该条目是"悬空引用/残留"**；回到桌面（P: 有盘符）它枚举完全正常。
这与项目已有的「凭局部证据下结论」教训同源。

## 4. 结论与发现（**仅记录，未改代码**）

1. **释放路径本身是通的**：删掉预检硬约束后，`Winre.wim` 走完 格式化 → 应用 → 建引导，目标卷上确实
   出现完整 WinRE。"RE 硬盘版释放"作为功能是可行的——前提是后续注册环节放行。
2. **真正的拦路石是下游离线注册检查**：`winre_registration.rs` 要求目标含
   `Windows\System32\reagentc.exe`，而官方 `Winre.wim` 不含它 ⇒ **任何 WinRE/WinPE 源都必然倒在这里**。
   0815 文档里被移除的 `wim_full_windows_probe`（擦除前预检）正是为提前防这个而设；移除后，本次
   就复现了它要防的场景——**目标卷已格式化、镜像已应用之后才失败**。
3. **失败未回滚 `default`**：在 `bootSequenceRequested/bootOnce` 语义下，新增的第二系统条目被设为
   `{bootmgr} default`。一旦中途失败，用户每次开机都被拖进该 RE。**建议**：失败时把 `default` 回滚到
   `previousBcdSha256` 对应基线，或新增第二系统时**不设 default**、只加菜单项。
4. **菜单名未落到 BCD**：`bootPlan.menuName="RE硬盘版释放测试"` 没有写进条目，`{5bdd13d0…}` 的
   `description` 仍是 `Windows PreInstallation Environment`。疑似命名步骤排在失败点之后未执行（待确认是否设计如此）。
5. **`verifyHash=false` ⇒ 镜像未校验**（`task.json` 的 `image.sha256` 全 0）。释放前不做哈希校验，
   与项目既有的「载荷哈希信任链」要求不一致。
6. **盘符 / 卷序列号都不能当卷身份**：计划里的 E:/H: 与现存 P:/E: 不一致；`format fs=ntfs quick`
   会把卷序列号从 `0C96DC1A` 改成 `B066C1C9`。**认卷只用 `partitionGuid` / `volumeGuid`**
   （本次正是靠 `{5dcb689a-…}` 才确认 P: = 目标）。
