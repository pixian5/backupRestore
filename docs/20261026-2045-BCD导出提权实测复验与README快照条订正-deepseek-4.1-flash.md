## 2. 实测（虚拟机 `Windows 11`，2026-10-26 20:57）

四条通道，判据只用结构化返回码与字节数，不解析中文文案：

| 通道 | 命令 | 结果 |
|---|---|---|
| SYSTEM（`prlctl exec` 默认） | `bcdedit /export H:\brwork\bcd-export-test.bcd` | **RC=OK**，文件 **503,808 字节** |
| SYSTEM | `bcdedit /store <文件> /enum {bootmgr} /v` | 离线可读：`default {af5ee73f-…}` / `resumeobject {af5ee73e-…}` / `displayorder {e41ab5e9-…}` / `timeout 10` |
| 非提权（`--current-user`） | `bcdedit /export …` | **RC=FAIL**，且文件**从未创建** |
| 非提权（`--current-user`） | `bcdedit /enum {bootmgr} /v`（只读） | **RC=FAIL** |

**结论：`AGENTS.md` 的说法今天复验成立。** 10-15 那条「未提权连只读枚举都被拒」也一并对上。

### 2.1 判据说明：字节数不能当判据

10-15 记的是 **651,264** 字节，这次是 **503,808** 字节——**少了 147,456 字节**。
原因不是导出失败，而是 **BCD 存储大小随条目数变化**（今天删过探测入口、清理过测试项）。

★ 所以「字节数与上次一致」是**错误的判据**。正确判据是两条同时成立：

1. 文件存在且**非空**；
2. `bcdedit /store <文件> /enum {bootmgr}` 能枚举出**关键项**（`default` / `displayorder` / `resumeobject`）。

只比字节数会得出「导出坏了」的假红，而它其实好得很——这正是「判据要选与结论有因果关系的那个量」。

### 2.2 一处**没有**测的

`bcdedit /import`（回导）**没有实测**。它会**覆盖当前启动配置存储**，属改引导的破坏性动作；
虽然手上有刚导出的文件，但没有第二次独立备份，不值得为一个文档订正去冒重启风险。

所以本条仍标注为「**可回导**」而非「回导已验证」——沿用 10-15 的原始出处，不冒充今天的结论。

## 3. 改了什么

### 3.1 根 `README.md` §五 第 1 条

```diff
- 1. **动启动项前必须建快照**。修改启动配置数据、默认项、一次性启动序列、恢复环境注册或预安装环境部署之前，
-    先创建并核验 Parallels 快照，记录快照 ID、目的和变更范围。快照失败不得继续。详见 `AGENTS.md`。
+ 1. **改引导不拍整机快照，改用文件级备份**。……先 `bcdedit /export <普通路径>` 导出 BCD 存储，
+    并用 `bcdedit /store <文件> /enum {bootmgr}` 核验可离线读取；导出失败则手抄 `{bootmgr}` 的
+    `default`/`displayorder`/`resumeobject` 三项兜底（只能手抄、无完整性校验）。**备份失败不得继续。**
+    详见 `AGENTS.md` 第二节。
```

### 3.2 顺带写明第 3 条的边界（否则刚修好的矛盾会以另一副面孔回来）

原第 3 条：「**测试只能在可回滚的虚拟机快照里做**，尤其是 `restore-existing` / `create-secondary`。」

这句与新的第 1 条看似冲突：改引导也是「测试」，到底拍不拍？改为：

> 3. **会重写卷的测试必须在可回滚的整机快照里做**（`restore-existing` / `create-secondary` 这类，
> 失败代价是整卷丢失）；**只是改引导项的验证走第 1 条的文件级备份，不占快照**。

判据是「**失败代价是不是整卷丢失**」——是就拍，不是就走文件级备份。
