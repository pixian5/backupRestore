# 两个选择弹窗：用系统字体覆盖了雅黑、且高 DPI 下没居中（v2.6.87）

> 模型：DS41F。时间：2026-10-30 14:50。
> 版本：**2.6.87**（改行为 +0.0.1）。
> 关联：`docs/20261030-1430-…v2.6.86-DS41F.md`（同一轮「检修全部类似问题」的第四站）。

---

## 1. 怎么发现的

上一轮修完「备份文件管理 / 查看日志」之后，继续量剩下的可打开窗口。
「镜像路径无效」和「系统分区处理方式」这两个提示框（`choice_dialogs.rs`）此前
在 2.6.82 只修过**窗口尺寸**，内部从没量过。

用「创建任务 + 空镜像路径」把它弹出来（只拒绝、不执行任何操作），一截图就看出问题：
**说明文字和按钮不是同一种字体**——按钮是雅黑粗体，说明文字是细的、发虚的另一种。

## 2. 三个缺陷

### 2.1 主因：自己用系统字体把雅黑覆盖回去了

```rust
let font = GetStockObject(DEFAULT_GUI_FONT) as Handle;   // 系统自带字体
...
SendMessageW(body, WM_SETFONT, font as WParam, 1);       // 覆盖！
SendMessageW(btn_pe, WM_SETFONT, font as WParam, 1);
```

`create_control()` 在创建每个控件时**已经**用 `gui_font()`（微软雅黑 + 用户选定的字号）
设过字体了，这两句又把它覆盖成系统字体。后果有两条：

1. 这两个弹窗的**字号根本不跟随**「设置 → 界面字号」：调到 18 号，主界面变大，
   弹窗里的说明文字还是老样子；
2. 字体族与其它窗口不一致，中文看起来像宋体、笔画发虚（系统字体在 200% 下是点阵放大）。

**这一条是 2.6.80 换雅黑时漏掉的**：那次只改了 `gui_font()` 的实现，
没有回收这两个弹窗里「显式设系统字体」的旧代码。

### 2.2 高 DPI 下弹窗不居中（偏右 230 物理像素）

```rust
(screen_w - 460) / 2,      // screen_w 是物理像素，460 是基准像素
(screen_h - 320) / 2,
```

`GetSystemMetrics(SM_CXSCREEN)` 在 200% 下返回 2350（物理），而 460 是 96dpi 基准值。
窗口实际宽 920 物理，算出来 `(2350-460)/2 = 945`，而正确值是 `(2350-920)/2 = 715`
——**偏右 230 像素**。1.78 倍缩放下同理。

### 2.3 正文高度写死，换字体后会切行

正文 STATIC 高度写死 78（系统分区弹窗）/ 64（路径无效弹窗），是按系统小字体估的。
一旦按 2.1 换成雅黑 18 号，同样宽度下正文会折成更多行：英文最长的
"Offline channel selected: ..." 要 5 行 = 105 基准像素 > 78，最后两行会被切掉。

所以 2.1 和 2.3 必须一起改，只改字体就是把「字体不一致」换成「文字被切」。

## 3. 改法

两个弹窗统一成同一套结构：

```rust
// 1) 删掉 GetStockObject + 全部 WM_SETFONT 覆盖
// 2) 正文高度按实测：再加 8 像素内边距
let body_height = measure_text_height(body_text, CONTENT_W) + 8;
// 3) 按钮从正文下方顺序排布（不再写死 y=112/162/212）
let mut y = 24 + body_height + 16;
// 4) 整窗尺寸按内容反推 + 用物理尺寸居中
let mut frame = Rect { left:0, top:0, right: dpi::s(client_w), bottom: dpi::s(client_h) };
AdjustWindowRectEx(&mut frame, WS_POPUP | WS_CAPTION | WS_SYSMENU, 0, 0);
MoveWindow(hwnd, (screen_w - frame_w)/2, (screen_h - frame_h)/2, frame_w, frame_h, 1);
```

**为什么加 8 像素**：不加时判据实测中文 18 号 `slack=0`、中文 14 号 `slack=1`——
`DrawText` 的 `DT_CALCRECT` 高度与真实排版差 1~2 像素，正好贴住时最后一行的降部
（「返」「y」这种向下伸出去的笔画）会被切。加 8 之后余量 16~17 像素。

顺带把创建时的初始位置也改成 `(screen_w - dpi::s(460))/2`：虽然 `WM_CREATE` 末尾
会 `MoveWindow` 定稿，但初始位置不换算的话，200% 下会先闪一下偏右的窗口。

`DEFAULT_GUI_FONT` 常量与 `GetStockObject` 声明一并从 `native_gui.rs` 删除，
注释写明「不要再引入系统字体」。

## 4. 验证（200% 缩放，物理像素）

判据 `dlg-fit.ps1` 这轮又扩了两项能力：
- **多行 STATIC 改判高度**（以前直接跳过——那正是 2.6.83 那类缺陷的藏身处）；
- **按钮不再被「多行」过滤误跳过**（按钮本来就比一行高）。

| 组合 | 正文 高/需/余 | 按钮 | 居中（x 与期望值） | 底边 |
|---|---|---|---|---|
| 中文 14 | 128 / 111 / **17** | 余量 632 / 744 | 702 = 702（差 0） | 余 61 |
| 中文 18 | 204 / 188 / **16** | 余量 584 / 728 | 702 = 702（差 0） | 余 61 |
| 英文 18 | 252 / 235 / **17** | 余量 384 / 681 | 702 = 702（差 0） | — |

- 三种组合 `SINGLE_LINE_CLIPPED=0`、多行块全部 `FITS`；
- **居中误差从 230 像素降到 0**；
- 视觉确认 `v2687-invalidpath-zh14.png`：说明文字与按钮同为加粗雅黑，笔画一致、无切字
  （对比修复前的 `v2686-invalidpath-zh18.png`：说明文字明显是另一种细字体）；
- 宿主机类型检查通过，0 新警告（顺手清掉了 `GetStockObject` 未使用的警告）；
- VM 构建部署 `SHA256=3a909c2ade74e48afe8b0e80e78b9254d465c5000c9f8952604269e76ae1b99a`。

## 5. 没验证到的那一半（必须写清楚）

**「系统分区处理方式选择」弹窗（`BackupRestoreSystemDriveChoice`）没有实机验证。**
原因：它只在「把镜像还原到当前正在运行的系统盘」时才弹，要走到那一步必须先建一个
合法的还原任务；而弹窗上的第一个按钮是默认按钮「进入 PE（推荐）」，
**万一注入点偏了就会真的排一个 PE 任务**——风险不对等，所以没做。

它的代码与「路径无效」弹窗是同一套（同样的 `measure_text_height + 8`、
同样的 `AdjustRect + MoveWindow` 居中、同样删掉了系统字体覆盖），
但**没有跑过就是没有跑过**。等下一次真做还原时顺手确认，届时判据：
窗口居中、正文不切、按钮文字（`进入 PE（推荐）` / `进入 Windows RE` / `取消`）完整。

## 6. 遗留

1. `boot_menu_window.rs`（开机菜单）与 `recovery_progress.rs`（PE 内恢复进度窗）
   仍在用 `GetStockObject(17)` 取系统字体。前者在开机阶段、后者在 PE 里，都无法在本轮
   环境验证，**没有动**——但它们是同一类不一致，记在这里。
2. 正文宽度仍写死 400 基准像素（窗口宽度 460）。英文最长的文案换行后仍装得下，
   但如果将来再加更长的文案，应当像设置窗口那样按内容定宽。
3. 100% 缩放仍未实测（历史遗留）。
