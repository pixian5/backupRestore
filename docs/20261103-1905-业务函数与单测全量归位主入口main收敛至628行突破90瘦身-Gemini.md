## 一、背景与设计动机

在经历了前序多轮持续重构后，CLI 主入口 `main.rs` 已经从 6,287 行巨石缩减至 761 行。然而，细致审计发现 `main.rs` 底部仍残存有少量跨模块深层业务辅助函数与遗留单测：
1. `stage_resumable_after_interruption`：属于挂起任务中断续跑决策逻辑，应归属于 `pending_task.rs`；
2. `split_workspace_root_rel`：属于恢复引擎工作区相对路径校验与防目录穿越逻辑，应归属于 `recovery_engine.rs`；
3. `index_metadata_path` / `legacy_metadata_path` / `read_index_metadata`：镜像副档元数据转调，应归属于 `image_admin.rs`；
4. `validate_task` / `show_status`：任务记录解析验证与状态呈现，应归属于 `task_admin.rs`；
5. `mod tests`：残存的 2 个单测（`workspace_path_allows_directory_named_tasks` 与 `interruption_resume_accepts_only_staged_nonterminal_tasks`）使得 `main.rs` 仍需导入核心模型类型。

本期重构目标：**将以上所有业务逻辑与单测全量按职责归位子模块，彻底清空 `main.rs` 内所有深层私有函数与测试块，使 `main.rs` 成为 100% 纯粹的顶层路由与进程生命周期分发器，达成行数突破 90% 瘦身里程碑**。

## 二、重构核心改动

### 1. 业务逻辑与单测完全归位
- **`pending_task.rs`**：
  - 移入 `pub(crate) fn stage_resumable_after_interruption(stage: Stage) -> bool`；
  - 移入 `interruption_resume_accepts_only_staged_nonterminal_tasks` 单测；
- **`recovery_engine.rs`**：
  - 移入 `pub(crate) fn split_workspace_root_rel(value: &str, task_id: &str) -> Result<String, TaskError>`；
  - 移入 `workspace_path_allows_directory_named_tasks` 单测；
- **`image_admin.rs`**：
  - 统一 re-export 跨平台元数据函数 `index_metadata_path`、`legacy_metadata_path`、`read_index_metadata`；
- **`task_admin.rs`**：
  - 承载 `pub(crate) fn cli_validate_task(path: String) -> Result<(), TaskError>`；
  - 承载 `pub(crate) fn cli_show_status(root: String, id: String) -> Result<(), TaskError>`；
- **`main.rs`**：
  - 路由分发改为单行委派调用；
  - 物理删除上述 5 组函数及底部 `mod tests`，消除未使用的类型导入（`StatusRecord`, `Task`, `TaskStore`, `read_json`, `Stage`, `PathBuf`）。
