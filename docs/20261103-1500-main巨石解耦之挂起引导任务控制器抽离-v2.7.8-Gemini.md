## 一、改造背景与目标

在 v2.7.7 中，`crates/backuprestore-cli/src/main.rs` 成功切分出四大专业自治模块（`process_runner.rs`、`recovery_bcd.rs`、`recovery_volume.rs`、`recovery_engine.rs`），行数降至 2,084 行。

在剩余逻辑中，关于**宿主开机/程序启动时的半成品恢复任务探测与续跑决策机制**（约 470 行）依然驻留在 `main.rs` 中：
1. **单阶段单次重试防打转标记**（`claim_boot_resume_attempt` / `release_boot_resume_attempt`）；
2. **跨阶段自动续跑总次数闸门**（`allow_total_attempt` / `bump_total_attempt`，防推进式循环重启）；
3. **僵尸孤儿任务安全自动收口**（`collect_orphan_tasks`，目标卷未擦除且无 BCD 启动项时安全标记 `Failed` 并清理）；
4. **中断任务发现与调度执行**（`find_pending_boot_task`、`resume_pending_now`、`defer_pending_task`、`abandon_pending_task`）。

这些逻辑与 CLI 命令行解析并无强绑定关系，属于完全独立的**任务生命周期接管子系统**。

## 二、子模块自治封装：`pending_task.rs`（427 行）

新建 [`crates/backuprestore-cli/src/pending_task.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/pending_task.rs)：
- **`PendingResume` 最小上下文模型**：只携带展示与执行必需的字段（`task_id`, `workspace`, `task_dir`, `operation`, `stage`），不持久持有易过期的完整 `Task`；
- **防无限打转双层防线**：
  - 第一层（per-stage）：`boot-resume-{stage}.attempted` 文件原子创建排他锁；
  - 第二层（cross-stage）：`boot-resume-total.count` 跨阶段总重启上限（`MAX_TOTAL_RESUME_ATTEMPTS = 3`），且仅在 `shutdown.exe` 真实成功发出后递增，避免父进程失败导致虚假烧死计数；
- **自包含单元测试**：内聚 `total_resume_attempt_tests`（验证 3 次上限阈值与 0 上限硬拒行为）。
