## 二 怎么做的（关键：用测试钩子代替鼠标点按钮）

产品这个「安装 PE」只在图形界面里有（命令行没有对应子命令），所以用项目里已备好的测试钩子：

1. 写 `C:\br-test.json`：

   ```json
   {"tab":"pe","mode":"disk","image":"C:\\BackupRestorePE\\BackupRestorePE.wim",
    "pe_name":"BR PE secboot","target_volume":"T","auto_install":true}
   ```

2. 用 `tools/win-clicker/br-s1.sh br-pe-install-secboot.ps1` 在**交互桌面（会话 1）提权**环境启动
   `H:\brwork\BackupRestore.exe --test-hook`；
3. 钩子做的事：选中「安装 PE」页签 → 目标卷选 `T:` → 填镜像与启动项名称 → 勾「硬盘启动方式」→
   自动接受破坏性确认 → 直接调**与按钮完全相同的那几个函数**（`install_pe_harddisk`）；
4. 90 秒后读 `H:\brwork\pe-install-secboot.txt`（应含 `GUI_UP pid=…`）。

> 说明：**没有真的用鼠标点**，但走的是同一段代码（钩子只负责「把控件设成用户点完的状态」+「自动按是」）。
> 这个差别在报告里必须写清楚。

## 三 两个新发现（都是坑，值得记）

### 1. 目标分区里只要有 Windows 目录，安装会被直接拦掉

第一遍我没清 `T:`（上一轮我手工铺的 PE 还在里面，`T:\Windows\…` 完整）。产品的安全校验
（`has_windows_installation`）会把它判成「这是一块装了系统的盘」，于是：

```
GUI action blocked: target partition contains a Windows installation
```

→ 提示「目标分区含 Windows 安装」，什么都不做。**这不是缺陷**（产品本来就不该把 PE 装到别人的系统盘上），
但**测试时必须先 `format T: /q`**，否则会误以为「安全启动把安装挡住了」。

### 2. 硬盘启动方式下 `PE 目录` 这个输入框其实不参与落盘

`install_pe_harddisk` 是**格式化整块分区 + 把镜像展开到分区根**（`/ApplyDir:T:\`），
不认「PE 目录」那个框（那个框是内存盘方式用的）。所以装完是 `T:\Windows\…`，
BCD 里 `systemroot \Windows`，不是 `\BackupRestorePE\Windows`。

### 3. 顺带订正上一份文档里的一处错误

上一份（`20261029-0246`）我写「产品安装还多做几件事：格式化目标、**用 `bcdboot` 写引导文件**、创建 BCD 项」——
**`bcdboot` 那句是错的**。读过代码 + 本轮实测确认：PE 安装只做「格式化 → `dism` 展开 → `bcdedit` 建项」，
**完全不碰 ESP，也不跑 `bcdboot`**。`bcdboot` 属于「还原系统」那条链（`main.rs` 里那段），不是装 PE。
这也解释了为什么装 PE 在安全启动下几乎不可能出问题：它写的全是数据分区上的文件和 BCD 数据。

## 五 至此「安全启动」这条线还有什么没验

1. **真机**：真机固件认不认「一次性启动序列」（`bcdedit` 那个一次性槽位）—— Parallels 固件本来不消费它；
   以及 OEM 机器白名单里有没有额外要求（本机 `db` 里有 `Microsoft Windows Production PCA 2011` 与
   `Windows UEFI CA 2023`，没有 `Microsoft UEFI CA 2011`）。
2. **备份 / 还原整链**在安全启动下跑一遍（进 PE 做一次真实备份再回来）—— 目前只验到「进得去、装得上、回得来」。
