## 2. 验收口径（铁证标准，弱信号不算）

1. **哨兵法**：还原前目标卷根放 `BR-时分秒.txt`，还原后必须消失；
2. **序列号变化**：目标卷 Volume Serial Number 必须变（DISM Apply 保留 WIM 内时间戳，目录时间不能证明重写）；
3. **截图**：功能可用必须有截图；
4. **无崩溃**：EventID=1000 无新增循环、WerFault ≤ 1；
5. **菜单对账**：BCD displayorder 条目只增不减（被取代的条目需门禁判定「非丢失」）。

## 4. 本轮新发现问题（3 项，均待修/待裁定）

### 4.1 待续跑对话框「文案-行为」不一致（缺陷）

`ask_pending_resume` 文案承诺「取消 = 放弃这个任务并清理」，代码是 `match answer { IDYES => Reboot, _ => Defer }`——**否 / 取消 / 关窗全是 Defer（只记日志不改状态）**。用户按文案预期操作会得不到承诺的行为。

### 4.2 ef71fccc 三按钮死锁 +「卡住的任务被烘进备份镜像」（缺陷）

- 阶段 1 04:56 建的备份任务，WinRE 捕获至 20% 中断；resume 产出 WIM 但状态停在 `Capturing`；
- 「存在未完成任务」三按钮无路可走：是 = 重启续跑（不推进状态机）、否 = 清理（`can_abandon_before_target_write` 拒收 `Capturing`）、取消 = 中止建新任务；
- **新发现（本轮截图实证）**：该任务目录被 DISM 捕获进 `BR-sys-20261018.wim`，**还原系统开机自启 GUI 时 `find_pending_boot_task` 扫到它并弹续跑框**——「卡 Capturing 的任务会跟着镜像走」，且镜像里自启的是 v2.6.15 版 GUI（镜像捕获于 v2.6.16 部署前，自洽）；
- 现场处置：按 Esc（等价 IDNO = defer）干净关闭，零写入。

### 4.3 环境观察（非缺陷）

- 还原系统（镜像）内**没有 `wmic`**，用 `Get-CimInstance` 替代；
- 在线还原（`online_operation::execute`）是进程内执行，**不落 `tasks\` 记录**（task_id 即日志目录名 `BackupRestore-online-<pid>-<ts>`）——与离线/WinRE 任务的 GUID 目录是两套，非缺陷。

## 5. 测试方法教训（本轮新增/修正）

1. **Session 0 模态框陷阱**：`prlctl exec`（SYSTEM）启动的 GUI 在 Session 0，`run()` 建窗前的待续跑框 / 未完成任务框会阻塞钩子——解法是从 `H:\brwork` 起（任务全终态无对话框）或同会话点击。
2. **宿主磁盘必须前置检查**：DISM 展开需 ~79GB；本轮曾因宿主写满（926Gi 仅剩 322Mi）导致 VM 停机，靠 `snapshot-switch --skip-resume` 回滚恢复。
3. **★ 删旧快照是最大的空间来源（修正此前的错误结论）**：此前认为「线性链删中间快照几乎不腾空间」——**错了**。本轮删三层旧快照（保留当前层）可用空间 **23Gi → 106Gi**（旧层里大量是被还原操作覆盖死的块），删最后一层又释放到 104Gi。纪律因此改为：破坏性操作前先删旧快照、只留 1 层、验证通过即删——这既是纪律也是腾空间手段。
4. PowerShell 5.1 无 BOM UTF-8 按 GBK 解码：脚本必须 ASCII-only、`Select-String -Pattern` 禁中文（会被搅成管道）。
5. `prlctl` 的重启动作是 `restart` 不是 `reboot`。
6. agent 的 `windows` rect 坐标系与截图不一致时，**用 Esc 等价 IDNO 关 MessageBox**，不赌坐标。
7. `-File` 不吃 UNC：VM 内跑脚本先 `copy` 到本地盘再 `-File`。
8. **快照回滚会连日志一起打回**：阶段 3 早期日志在回滚后消失——证据要趁早落文件，别只靠日志复盘。
