# docs 目录文件名统一日期前缀（2026-09-30 22:32）

- 版本：v2.0.2（纯文档/注释改动，产品行为未变）
- 模型：DeepSeek-V4.1-Flash
- 范围：`docs/` 全量重命名 + 全仓引用同步 + 版本号

## 一、背景

`docs/` 长期累积出五类不统一的前缀写法，导致目录排序错乱、AGENTS.md 里
「年月日-时分-标题-具体模型.md」的约定形同虚设：

| 类型 | 例子 | 数量 |
|---|---|---|
| 6 位时分秒 | `20260928-065800-parallels-...md` | 26 |
| 缺横杠 | `20260928070606-文档过时内容审计.md` | 2 |
| 缺横杠（无分隔） | `202609291948Parallels快照清理与磁盘告急处置.md` | 1 |
| 日期在末尾 | `compression-options-2026-09-26.md`、`开发方案/阶段0-设计与决策冻结-20260926-234228.md` | 17 |
| 完全无日期 | `project-status.md`、`verification-matrix.md` 等 | 36 |

## 二、统一规则

1. 前缀一律 `YYYYMMDD-HHMM-`（只到分，秒位截断）。
2. 开头即时间戳的：补齐 `-`、截秒。
3. 日期在名称末尾的：把日期搬到开头（带时分秒的用其时分；只有日期的用 git 提交时分）。
4. 名称里完全没有日期的：用该文件 **git 首次提交时间**（`git log --diff-filter=A`）兜底。
5. 例外：`docs/README.md` 保持原名（它是 `docs/` 自身的索引）。

结果：`docs/` 下 111 个 md 加 `开发方案/` 12 个，除 `README.md` 外 **全部** 符合新前缀。

## 三、执行方式

一次性脚本 `python3 .test-artifacts/rename_docs.py`（已 gitignore，不入库）：

- `git mv` 改名，保留 git 重命名血缘；
- 全仓文本文件（`.md/.rs/.sh/.toml/.json/...`）按「旧 basename → 新 basename」批量替换，
  跳过 `.git/`、`target/`、`.test-artifacts/`、`.workbuddy/`、`.codeartsdoer/`；
- 替换带幂等保护（新名包含旧名，若不判重会二次加前缀）。

工程量：82 个文件改名，约 40 个文件共 300+ 处引用更新。

## 四、踩坑与教训

1. **脚本一次运行里 `fix_refs` 被调用了两遍**，而「新名包含旧名」（如
   `project-status.md` ⊂ `20260821-1528-project-status.md`），第二次替换直接在已改好的
   名字上再加一层日期前缀，产生 `20260821-1528-20260821-1528-verification-matrix.md`
   这类双前缀。已 `git reset --hard` 回滚后修正并加幂等判重。
2. **教训**：批量文本替换脚本必须先做「跑两遍结果一致」的自检，再接入实际写盘。
3. 源码注释里存在被截断的引用（如 `docs/202609292014` 少了文件名），
   正则匹配整 basename 时替换不到，需人工补齐：`lib.rs`、`windows_prepare.rs` 共 3 处。

## 五、验证

- 目录自检：`ls docs` 除 `README.md` 外无不符合 `^\d{8}-\d{4}-` 的条目。
- 链接自检：全仓 345 个本地 md 链接，仅 1 个报失（`Windows%20一键...` 是 URL 编码，
  实际文件存在，属检查脚本误报）。
- 幂等自检：脚本二次运行输出「0 个文件待改名 / 0 处引用改动」。
- 残留扫描：全仓已无 `docs/<8位数字>` 后不接 `-HHMM` 的旧式引用。
