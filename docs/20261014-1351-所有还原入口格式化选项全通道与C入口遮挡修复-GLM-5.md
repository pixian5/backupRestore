# 所有还原入口格式化选项（全通道）与 C 入口遮挡修复（v2.5.3）

> 模型：GLM-5｜版本 **2.5.2 → 2.5.3**｜用户 2026-10-14 两条：①所有还原都要加格式化选项；②C 入口有控件被遮挡（截图指认）。

## 1. 遮挡修复（先说根因）

用户截图的 C 入口（还原系统到非 C 盘）：**「严格对比哈希」复选框被按钮行（刷新环境/读取镜像/创建任务/刷新任务状态）压住**。坐标真值：verify_hash y 469-493，按钮行 y 477-505，重叠 16px。

根因：C 沿用 create-secondary 的布局分支（`verify_hash_y = secondary_y + 32`，底缘 +56），而按钮行 `buttons_y = secondary_y + 40`——**这个重叠在 create-secondary tab 上历来就存在**（2.5.0 把 C 挂进同一分支后暴露到了还原入口上）。

修法：C/新增第二系统分支的 `buttons_y = secondary_y + 64`（复选框底缘 +56 再留 8px）。修复后实测：verify_hash y 495-519，按钮行 y 527-555，零重叠。

## 2. 格式化选项扩展到所有还原入口（全通道）

2.5.2 只给 B 在线做了格式化选项；本轮按用户要求做到 **A/B/C 三入口 × 在线离线全通道**：

| 入口 | 复选框 | 在线 | 离线（RE） |
| --- | --- | --- | --- |
| A 还原系统到 C 盘 | 显示（无通道行，位于目标详情框下方） | —（必离线） | ✓ 选项随任务落盘 |
| B 还原数据到非 C 盘 | 显示（通道行下方） | ✓（2.5.2 已有） | ✓ 新增 |
| C 还原系统到非 C 盘 | 显示（通道行下方） | ✓ 新增（restore_to_windows_volume 条件跳过格式化） | ✓ 新增 |

### 实现链路（离线）

1. **core**：`TargetSpec` 加 `format_target: bool`，`#[serde(default = "default_format_target")]`（旧任务缺字段按 `true` 兜底=历史恒格式化行为，不静默改变旧任务语义）。
2. **prepare**：CLI 新参数 `--skip-format`（默认格式化）；`PrepareOptions.format_target` 落盘进 TargetSpec。
3. **RE 恢复链**（`main.rs` 格式化段）：`target.format_target == false` 时跳过 `format_target_partition`（diskpart）与 `verify_partition_identity_after_format`（不格式化就没有「序列号已变」的校验对象），日志记「按任务选项跳过格式化（覆盖式应用）」。断电续跑从 TargetErased 重入同样按选项跳过，行为一致。**状态机不变**（TargetErased 语义保持，幂等重入安全）。
4. **GUI**：取消勾选 + 离线 → prepare 参数加 `--skip-format`。

### C 在线

`restore_to_windows_volume` 格式化段条件化：跳过格式化与格式化后校验，**BCD 快照/盘符重绑/bcdboot/菜单命名照常**（它们要求的是「应用后的 Windows」，与是否先清空无关）。基准身份直接 `refresh_identity`。

## 4. 设计说明与风险提示

- 不格式化（覆盖式）还原的语义：目标卷上**镜像里没有的文件保留**——对数据卷是「合并还原」；对系统卷（A/C）是「就地覆盖」，旧系统残留文件可能与新系统混存，一般用于不想清盘的特殊场景。默认勾选格式化=还原的完整语义。
- RE 链默认路径（format_target=true）**逐字节等价于改动前**，只有显式取消勾选才走新分支——对已验证的恢复链零回归面。
- 遮挡修复同时惠及「新增第二系统」tab（同一布局分支）。

## 5. 测试计划影响

三入口实测计划的判定项更新：所有离线还原也可验证「不格式化」分支；1a（手工格式化+程序不格式化在线还原）不变；可加 1c（B 离线 + 取消格式化 → RE 覆盖应用）作为可选扩展。
