# 真实日志回放判据夹具化：把「日志不在就静默通过」变成 CI 常跑

- 日期：2026-10-27 22:10
- 版本：**2.6.69（未升版本）**
- 提交：`7cacf59`（判据改造）、`849e2dd`（修我自己引入的两个问题）
- 前序：`docs/20261027-2145-CI恢复与工具链固定-*.md`

## 1. 一句话

`replay_real_wimlib_log` 有三条真断言，但它的输入（82 MB 本机日志）不入库，且**日志不在时直接 `return`**
—— 于是这条判据在 CI 上「恒绿但零信息」，在本机也会因为清一次 `.test-artifacts` 而永久消失。
本轮把真实日志逐字节抽样成 9 KB 夹具入库，并拆成「常态判据（CI 跑）+ 全量取证（本机跑）」两份输入、一套判据。

## 2. 问题：判据的输入也是判据的一部分

原实现：

```rust
let Ok(raw) = std::fs::read("../../.test-artifacts/e2e-brimglog-227.log") else {
    eprintln!("skip: no log");
    return;            // ← 测试通过
};
```

这是继「空集通过」（T2 没有可测对象，2026-10-27 09:55）之后，**同一类毛病的第三种形态**：

| 形态 | 表现 | 已修 |
|---|---|---|
| 空集通过 | 断言依赖某种数据状态，而机器上恰好没有那种数据 | T2 自带夹具（09:55） |
| 用例不存在 | 用例丢了 `#[test]`，门禁在「环境缺失」那步 SKIP 掩盖 | 门禁核对 `--ignored --list`（21:08） |
| **输入缺失静默通过** | 判据读外部文件，文件不在就 `return` | **本轮** |

三者的共同点：**报告「通过」，而实际什么都没验**。判据的输入（夹具、数据状态、用例本身）
和被断言的行为一样需要自己的闸门。

## 3. 原始日志的真实形态（先量再动手）

| 项 | 实测 |
|---|---|
| 大小 / 行数 | 82 MB / 2,241,023 行 |
| `Applying image` 段数 | 24 |
| **带 wimlib 进度的段** | **只有 2 段**（各 2,639 条：三段 1269 / 101 / 1269） |
| 进度分隔符 | `\r`（原地刷新），所以「224 万行」里挤着上百万片段 |
| 解析结果 | 5,278 条全部解析出百分比、段内 0 回退、每段都到 100% |

「24 段里只有 2 段带进度」这条如果不知道，很容易写成「每个 apply 段都要有进度」的错断言。
两段内容相同（同一次还原里 wimlib 被调用两次），正好覆盖**多次 apply 各自从 0 开始**这个关键场景。

## 4. 做法

### 4.1 抽取脚本（可复用）

`tools/test/extract-wimlib-fixture.py`：

- 按 `\r` 与 `\n` 切（与 Rust 侧 `split(['\n','\r'])` 同规则）；
- 按 `Applying image` 分段，段内按三个阶段分桶；
- 每阶段**首尾必留 + 均匀抽样 30 条**；
- **只留解析得出百分比的片段**（Rust 侧断言「每条命中片段都必须解析出百分比」，
  混入解析不出的样本会让夹具与真实日志不等价）；
- 全程按 `bytes` 处理，不 decode-rencode —— 保住 `\r` 与原始字节。

输出：`crates/backuprestore-cli/tests/fixtures/wimlib-progress-227.log`，
**9,122 字节 / 2 段 / 180 条片段**。

### 4.2 两份输入、一套判据

`assert_replay(label, text)` 是三条断言的**唯一实现**，两份输入共用（避免「同一逻辑写两遍」）：

- `replay_wimlib_progress_fixture_is_monotone_and_completes`（**常态，无 `#[ignore]`**）
  读入库夹具；★ 夹具缺失 **panic**（不是跳过）；另加规模闸 `parsed >= 100`
  （抽稀到几乎没内容时，三条断言太容易满足）。
- `replay_real_wimlib_log`（保留 `#[ignore]`）本机 82 MB 全量取证。

新增 `unparsed` 计数：原实现遇到解析不出的片段只是「不 push」，只能靠 `parsed == fragments`
**间接**发现，两边同时漏就不报错。现在单独计数并 `assert_eq!(unparsed, 0)`。

### 4.3 `.gitignore` 的坑

`*.log` 规则会把夹具吃掉。**本机能跑只是因为文件恰好在磁盘上**，CI 上会直接 panic。
加例外：`!crates/backuprestore-cli/tests/fixtures/*.log`。
判据用 `git add --dry-run`（`git check-ignore -v` 对否定规则也会输出，容易读反）。

## 5. 两个由我自己引入、被门禁抓出来的问题

改完本机全绿、CI 也绿，但**跑 `ignored-acceptance.sh` 立刻红**。两处都是我上一提交带进来的。

### 5.1 把「cwd 相对路径」换成编译期绝对路径 → 门禁必红

我一度把全量版改成 `env!("CARGO_MANIFEST_DIR")/../../.test-artifacts/...`。
那是**编译期**路径：门禁在 Windows 上从 `<root>\crates\backuprestore-cli` 起跑、
日志在 `<root>\.test-artifacts\`，而交叉编译发生在 `X:` —— 拼出来的绝对路径必然不存在 → `FAIL`。

改回三级定位：`BR_WIMLIB_LOG` 环境变量 → `../../.test-artifacts`（cwd 相对，与旧行为一致）→
`CARGO_MANIFEST_DIR` 兜底；找不到时把候选路径与「可用 `BR_WIMLIB_LOG` 指定」一起打进 panic 信息。

> 教训：**改判据的路径解析方式，等于改判据的语义**。旧实现用 cwd 相对不是随手写的，
> 门禁的 `REPLAY_CWD` 就是配合它的。

### 5.2 短任务用 `prlctl exec` 后台跑 → 偶发「取不到 `--ignored --list`」

门禁 STEP 3/4 原本 `(...) & echo LISTED` 后台起 `--list`，然后轮询读文件。
`prlctl exec` 返回时会把子进程一起带走 → 文件常是空的或只有前几行 →
报「仪器故障」退出 2。而**单独跑同一条命令却成功**，是典型竞争。
`--list` 是秒级任务，没有异步必要 → 改同步执行。

## 6. 变异（三条各自单红，恢复后转绿）

| 变异 | 结果 |
|---|---|
| 夹具改名（缺失） | `FAIL`「夹具必须入库（缺失 = 判据消失，不是跳过）」 |
| 删掉末段最后一条 100% | `FAIL`「每次 apply 都必须走到 100%」（`apply#1: 0% → 99%`） |
| `wimlib_overall_percent` 的 Metadata 起点 90 → 50 | `FAIL`「不允许倒退」（`regress=60`） |

第三条是**改产品代码**的变异：证明这条判据真的对着「折算语义」，不是只对着夹具。

## 7. 验收

| 项 | 结果 |
|---|---|
| 本机单测 | cli **307**（+1 常态判据）+ core **57** |
| 全量取证 | 2 段 × 2,639 = **5,278 条 / 0 未解析 / 0 回退 / 各到 100%**（4.4 s） |

| `ignored-acceptance.sh` | **pass=5 fail=0 skip=5 ran=5**（含 `wimlib_log_replay=PASS`） |
| CI `40516744674`（判据改造） | gate **307 passed / 1 ignored**、windows **342 passed / 10 ignored**，两边都含 `replay_wimlib_progress_fixture… ok` |
| CI `40518002710`（修复两个坑后） | 同上，两个 job 全绿 |

CI 那条证据是本轮的核心：改造前这条判据在云端**零信息**，现在两个 runner 都真跑了。

## 8. 遗留

- 全量版仍需本机 82 MB 日志（`#[ignore]` + 门禁 SKIP 语义正确），夹具只覆盖 180 条抽样。
  真要扩到「全量入库」不现实（82 MB），抽样 + 规模闸是这一档的合理上限。
- `#[ignore]` 仍是 **10 处**（本轮删一条加一条），门禁 `pass=5 skip=5` 不变。
  剩余 SKIP 都属「真实写入 / 必须 PE」，夹具解决不了。
