## 3. 最高优先待修：三个实锤缺陷（阶段 3 事故根因，日志证据确凿）

任务 `95ab0a7f` 终态：`stage=boot-repaired`、`error="Boot Manager default or secondary display order could not be preserved"`。事故链条：

1. RE 任务正常执行到 bcdboot（格式化 F: → DISM 应用 → repair → **bcdboot 带 /s 自定义 ESP——`/d /addlast` 被 BFSVC 忽略**，1052 文档的警告真实上演）→ **default 被挪到 F: 新 loader**；
2. **缺陷 A**：`assert_boot_default_preserved`（main.rs，STEP 3/4 后）**检测到了 default 被挪但只报错停机，不自愈**——此时 BCD 快照就在任务目录里（`bcd-before-export`），完全有能力回写；
3. **缺陷 B**：任务失败后的收尾**不恢复 default**——机器留在「默认启动指向半成品 F: 系统」的危险态（F: 的 repair_secondary/WinRE 注册没跑完，起不来）→ 开机劫持，与 10-13 事故同款，防线未闭环；
4. 重启后 F: 起不来 → 自动修复 → 触发挂起的系统还原（还原点跨卷、F: 已被格式化，卷影缺失）→「正在准备系统还原 66%」永久卡死 → C: 也进不去（今天下午的全部灾难由此而来）。

**修法建议**：
- A：assert 失败路径改为「先从任务快照回写 default/displayorder → 再报任务失败」；
- B：恢复链任何失败终态的收尾必须恢复 bootmgr default（有快照就回写）；
- C：bcdboot 之后**主动回读** bootmgr default，与快照不一致立即回写（/d 被忽略是已知的，别再依赖它）。
- 修完后必须先拍快照再重跑阶段 3。

## 6. 操作手册（接手必读）

### GUI 自动化（当前实测坐标，1153×954 最大化）
- **运行 H:\brwork 实例**（GUI 从哪个目录跑，任务就落哪个目录；**包目录=C: 的实例跑还原任务会被「程序目录与 WinRE 同分区」拒绝**——阶段 3 第一次就栽在这，用计划任务以用户 x/Interactive/Highest 启动 `H:\brwork\BackupRestore.exe`，脚本在 `.test-artifacts` 有样本 `/tmp/brclick/run-hgui.ps1` 模式）。
- TCP agent：`tools/win-clicker/br-agent-tcp.sh`（start/ping/click/key/chord/text/shot/exec/windows）；**模态弹窗开着时主窗口点击全部无效**；「执行完成」等 MessageBox 的确定按钮**鼠标常点不中，用回车（key 0x0D）**。
- tab 中心点：备份(118,99)/A(209,99)/B(332,99)/C(455,99)/新增第二系统(568,99)/安装 PE(657,99)。
- C 入口控件：目标 combo(700,133 展开，列表项每档 ~17px)、image 框(400,441)、菜单名(955,475)、通道在线(310,290)/离线(660,290)、格式化复选框(410,316)、读取镜像(210,541)、创建任务(340,541)。
- 破坏性确认「是」：1254 分辨率时 (660,579)；1153 分辨率下鼠标估位不可靠——**一律回车**。
- PE/RE 选择窗（自绘 460×320 居中）按钮屏幕坐标要加 ~39px 标题栏偏移：进入 PE≈(627,489)、**进入 Windows RE≈(627,539)**、取消≈(627,589)（1254 时实测；1153 按比例 x≈576，未重测，用前先截图确认）。**误点「进入 PE」=写 bootsequence 立即重启无确认**，误触后清 `bcdedit /deletevalue {bootmgr} bootsequence` + 删 `S:\BackupRestore\pe-requests\*.json`。
- 镜像路径输入：点输入框 → End(0x23) → Shift+Home 全选 → text 键入；跨进程 GetWindowText 对 image 框回读为空（显示层怪癖），以「读取镜像」成功为准。

### 低层救援工具箱（今天实战沉淀）
- **`prlctl send-key-event "Windows 11" -s <十进制scancode> -e press/release`**：bootmgr「按任意键」阶段需多键×多次连发（28/57/13 各三次或 60 次回车轰炸）；RE/PE 全阶段可用（含命令行逐键输入，Shift 组合=press→sleep→key→sleep→release，右 Shift=54，{=Shift+26、}=Shift+27、:=Shift+39、|=Shift+43）。
- **PE 脚本光盘**（效率远高于逐键）：宿主 `hdiutil makehybrid -iso -joliet` 造含 cmd 脚本的 ISO → `--device-add cdrom` 挂第二光驱 → PE 里 `for %p in (D E F G) do @if exist %p:\find.cmd %p:\find.cmd`。
- **`prlctl set "Windows 11" --device-bootorder "cdrom0"`**（单设备形式有效；带逗号多设备无效；config.pvs 的 BootingOrder 对 UEFI 无效）。
- **离线 bcdedit**：PE 里 `bcdedit /store S:\EFI\Microsoft\Boot\BCD …`（先遍历盘符找 `\EFI\Microsoft\Boot\bootmgfw.efi` 定位 ESP）。
- 中文系统 bcdedit 输出字段名是「标识符」（不是 identifier）；`cmd >` 重定向文件是 GBK。

### 日志/清理
- RE 主日志 `H:\BRImages\Recovery.log`（追加式）；在线任务日志 `%TEMP%\BackupRestore-online-<pid>-<ts>\Online.log`；任务目录 `H:\brwork\tasks\<id>\`。
- prepare 被非终态任务阻塞时：`BackupRestore.exe abandon-task H:\brwork <task-id>`（对 prepared 有效；二次执行报「已进入 Failed」属正常终态记法）。
- BCD 里历史「BackupRestore task RE」loader 残留可用 `bcdedit /delete {guid} /cleanup` 清（今天已清过一轮 8 个；任务失败可能再产生新的）。
