# B 键（BCD 回退）在恢复环境内整链实机验收 + 回退后续跑链文案修复（v2.6.30）

- 时间：2026-10-23 09:48–10:25
- 模型：DeepSeek-V4.1-Flash
- 背景：交接文档 §8.2 里「B 键在恢复环境 / 预安装环境内整链」长期挂账——逻辑双路径已在
  预安装环境里验过（v2.6.18 run3 字节级 / run4 锁定时干净失败），**恢复环境内触发从未单独跑**。
  本轮补上，并按实机发现修掉一处「失败原因说不清」的文案缺陷。
- 结论：**B 键在恢复环境内触发成功**（ESP 免盘符解析 → 字节级还原 → 界面回执 → 日志留痕）；
  按 B 之后续跑链校验必然失败（预期后果），v2.6.30 起会把因果写进日志与对话框。

## 一、B 键是什么

恢复环境进度窗第五个按钮「BCD 回退(B)」：把 ESP 上的 `EFI\Microsoft\Boot\BCD`
**整份还原成任务准备期保存的快照**（`bcd-before-raw` / `bcd-before-export`）。
用途是「引导链被改坏时一键退回」；成败都会弹 `BCD 回退 / BCD rollback` 回执
（2026-10-18 M5 修的就是「失败只写日志、界面零反馈」）。

## 三、实机发现的两个问题（本轮修掉）

### 3.1 回退之后续跑链校验失败，但文案不说因果

按 B 把 BCD 换回准备期快照后，任务自建的 loader / device options 随之消失，
恢复流程在 `BootRepaired` 阶段的「续跑启动链字段校验」**必然失败**——这是回退的
**预期后果**，不是新缺陷。但此前现场只剩：

```
恢复暂未完成: invalid task: 续跑启动链字段不符：device
```

用户看不出「是因为自己按了 B」，接手者也可能误判成回归。

**修复（v2.6.30）**：

- `recovery_progress.rs` 新增进程级标记 `BCD_ROLLED_BACK`：回退**成功**时置位
  （放在静态量里而不是 `ProgressShared` 字段，因为回退动作跑在工作线程、手上没有
  `Arc<ProgressShared>`；恢复环境内一个进程只处理一个任务，进程生命周期即「本次运行」）；
- `main.rs` 失败收尾：本次运行回退过 **且** 错误含「续跑启动链」时，
  ① 往日志补一条中文因果说明；② 在对话框错误文案后追加
  「（本次运行中用户按 B 回退过 BCD：BCD 已还原为任务准备期快照，续跑链校验失败属预期）」。
  **只改说明、不改行为**：失败仍按原路径收口（保留现场、可重试），避免掩盖真缺陷；
- 抽成纯函数 `annotate_chain_failure(error, rolled_back)`，单测锁三条：
  回退+续跑链错 → 补说明且原文不丢；没回退 → 不改写；回退但错误无关 → 保持原文。

### 3.2 对话框出现 `invalid task: invalid task:` 双前缀

`TaskError` 的 `Display` 自带 `invalid task: ` 前缀，而收尾处又用 `crate::err` 包了一层。
本轮第一次实机截图就撞见双前缀，顺手在 `annotate_chain_failure` 里剥掉前缀
（`strip_prefix("invalid task: ")`），并加了一条单测断言。

## 六、本轮新增的环境坑（重要）

**从 macOS 写进虚拟机的 `.cmd` 必须是 CRLF 行尾。** 本轮一个检查脚本用 LF 写出，
`cmd` 把多行拼成一行解析，出现 `'ey' 不是内部或外部命令`、`'EM' 不是…` 这类
「半截单词被当命令」的怪现象，**且脚本第一行都没执行**（输出文件根本没生成）。
此前几个脚本「碰巧能用」是因为行短。判定特征：报错里出现脚本内容的碎片。
修法：`open(p,'wb').write(s.replace('\n','\r\n').encode('ascii'))`。

另一个老坑再次确认：`.cmd` 里**不能出现中文**（含 PowerShell 的 `-Pattern '中文'`），
会被按 GBK 解析成乱码导致零匹配——查中文日志行改用 ASCII 关键词（如 `BCD`、`wimlib`）。
