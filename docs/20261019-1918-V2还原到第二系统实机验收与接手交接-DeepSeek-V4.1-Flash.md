### 3.3 ★ 本轮失误（必须记住的教训）

**时间线（北京时间）：**
| 时刻 | 事件 |
|---|---|
| 18:02:07 | prepare 完成，E: 已格式化，载荷已 stage |
| 18:05:34 | 进 WinRE（第二次会话的早期日志显示挂载在 18:08:38，此处为首次会话），STEP 1 通过 |

| 18:13:41 | 截图看到进度 **85%**，已用 04:57，剩余 00:52 |
| 18:13:55 | **成功**，status=success |

**为什么第一次会 abort：我（AI）在 DISM 跑的时候执行了 `prlctl restart`。**
我当时以为「VM 还没进 WinRE」，实际上它已经在 WinRE 里灌了 2 分 43 秒。一个 restart 把它打断，DISM 立刻返回 1235。

**为什么第二次能成功**：`bootsequence` 尚未清除，重启后 Windows 又进了 WinRE；程序重新走了一遍「挂载 → 重新格式化目标卷 → Apply」，这次没人打扰，干净跑完。所以**最终镜像仍是完整的**（见 §3.4 的体积铁证），但这是一次**不该发生的返工**。

**结论性纪律（写进守则）**：
> **`prlctl restart` 前必须先 `prlctl capture` 截图确认当前在哪。**
> 只要是 WinRE/PE 里出现进度条（尤其写着「还原镜像（时间长）」），**绝不能重启、不能 prlctl stop**。
> `prlctl exec` 在 WinRE 内本就不可用（会报 "Unable to open new session"），**这恰恰是"已经在 RE 里"的信号**，不是"还没启动完"。

## 4. ★ 盘符重排：C: 和 E: 身份互换（最容易搞错的地方）

| | 还原前 | 还原后（现在） |
|---|---|---|
| C: | 349GB，序列号 `6E64-5D70`，正在运行的老系统 | **249GB，序列号 `48D5-196E`，新还原的系统，正在运行** |
| E: | 249GB，序列号 `6402-82D5`，目标卷 | **盘符消失**（它就是现在的 C:） |
| F: | 不存在 | **349GB，序列号 `6E64-5D70`，老系统退到这里** |

**根因**：新系统成了 `{bootmgr}.default`，Windows 启动时把**启动卷**分配到 C:，原来占着 C: 的卷被挤到下一个可用字母（F:）。**BCD 里的 `device` 也会跟着同步成运行字母**（`{c46f6056}` 从 `partition=E:` 变 `partition=C:`，`{44ef1b40}` 从 `partition=C:` 变 `partition=F:`）——这是 Windows 的正常行为，**不是程序写错**，别去「修」它。

**判断当前是哪个系统的方法**（不要靠盘符猜）：
1. `bcdedit /enum {bootmgr} /v` 看 `default` 的 GUID；
2. `bcdedit /enum {current} /v` 看 description；
3. `vol C:` / `vol F:` 比序列号。

**当前 default 是新系统**，也就是说：**现在开机会默认进新还原的系统**，老系统在菜单里第二项。

## 7. 操作纪律与坑（本轮新增/重申）

### 7.1 ★ 按键注入：必须用 `tools/win-clicker/vmkey.sh`，不要手写 scancode
本轮我在 WinRE 里想点弹框「否(N)」，先试了 `--scancode 31`（那是 **M**）、再试 `--scancode 48`（那是 **B**），全错，折腾了好几轮。

**正确做法**：
```bash
./tools/win-clicker/vmkey.sh n      # ← 就这样。N 键 = Parallels keycode 57
./tools/win-clicker/vmkey.sh esc    # Escape = keycode 9
./tools/win-clicker/vmkey.sh enter
```
`vmkey.sh` 内置完整映射表（`a..z` / `0..9` / `esc tab enter space backspace up down left right home end f1..f12 ctrl alt shift win`），走的是 **Parallels 虚拟键码（`-k`）**，不是 PS/2 scancode。F 键它内部会自动切到 `-s` scancode 通道（Parallels 的 `-k` 对 F 键映射是错的）。

**WinRE/PE 内**：鼠标通道全废（没 Parallels Tools、没网络），**只能用 vmkey.sh + `prlctl capture` 截图回读**。

### 7.2 `prlctl exec` 的路径陷阱
- `cmd /d /c` 整条参数用 **bash 单引号**包（`'...'`），否则 `\B`、`\\Mac` 会被 bash 折掉一层。
- exe 在 `H:\brwork\BackupRestore.exe`，**不在 `C:\brwork`**。
- `cmd` 不能 `cd /d` 到 UNC 路径。

### 7.3 `prlctl exec` 报 "Unable to open new session" = 已经在 RE 里了
不是「还没启动完」。此时**立刻 `prlctl capture` 截图**看真实状态，**别 restart**。

### 7.4 其它既定守则（来自项目记忆，仍然有效）
- 破坏性操作前拍快照，**全程最多 1 个**；删旧快照是最大的空间来源。
- **弱信号不算验收**：必须 ①截图 ②EventID=1000 无崩溃循环 ③WerFault≤1。本轮的验收是「程序内 status + 文件系统实测」，属于**功能验收**，`EventID 1000 / WerFault` 这两项**尚未采集**（见 §8 待补）。

- 改完代码即 `git commit` + `git push origin main`，**不要问**。
