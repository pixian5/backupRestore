## 0. 一句话结论

`BackupRestore.settings.ini` 的合并写会**静默删掉不属于自己的注释行和文件头** —— 这是真缺陷，已修；
而「`failure_threshold` 没落盘」这个把人引向错误方向的判据，是**验收脚本自己读错了编码**造成的假象。
两件事必须分开记：一个是产品问题，一个是度量仪器问题；后者更危险，因为它会让前者永远看不见。

## 1. 起点：上一轮验收留下的一个红判据

拆分「程序设置」对话框后跑实机点击验收，除一项外全绿：

```

```

同批写入的 `failure_action`、`failure_pause_max_wait_secs`、`dism_timeout_secs` 都在。第一反应是
「`dism_timeout::save_to_dir` 的第二次合并写把它冲掉了」——看代码后排除：它只过滤 `dism_timeout_secs`

## 2. 现场读数与代码对不上

直接 `type H:\brwork\BackupRestore.settings.ini`：

```
# BackupRestore 程序设置（本文件由程序自动生成，可手工编辑）
# failure_threshold: ...
# failure_action: ...
# failure_pause_max_wait_secs: ...
failure_threshold=3
failure_action=auto-escape
failure_pause_max_wait_secs=0
dism_timeout_secs=0
```

**四个键都在。** 而脚本读到 3 个。矛盾只可能出在读取侧。

## 3. 根因：GBK 解码吞掉了换行

`_diag-ini.ps1` 把同一文件按两种方式切分，结果直接暴露问题：

```
bytes_lf=7  bytes_cr=0            ← 7 个 LF，且无 CR（\n 行尾）
getcontent_line_count=5           ← Get-Content 只切出 5 行
raw1=[# failure_threshold: .........................?..=20.?# failure_action: ...]
utf8_split_on_lf_count=8          ← 按 UTF-8 切是 8 行，正确
utf8_4=[failure_threshold=3]
```

`raw1` 里那个 `?` 是全角 `）`，UTF-8 编码 `E3 80 89`。PS 5.1 的 `Get-Content` 对无 BOM 文件默认按
系统 ANSI（这里 936/GBK）解码：`E3 80` 配成一个 GBK 字符，剩下的 `0x89` 是合法 GBK 首字节，
于是它把**紧跟其后的 `0x0A`** 当成尾字节一起吃掉 —— 换行消失，下一行被并上来。

三条注释各以 `）` 结尾，于是 3 次吞行：8 行变 5 行，`failure_threshold=3` 被并进第 2 行，
`IniPairs` 自然只报 3 个键。

**这个坑的可复用判据**：`Get-Content` 的默认编码不是「不重要的小事」。凡是被读的文件里同时有
（a）中文/全角标点、（b）LF-only 行尾，就必须显式 `-Encoding UTF8`；否则判据会在**不报错**的前提下
错位,比你想象的更难发现。同一份 `_diag` 里 `bytes_lf=7 / utf8_split_on_lf_count=8` 与
`getcontent_line_count=5` 三者并列，就是最快的一次性自检。

## 4. 最危险的地方：那个「通过」的判据是假通过

脚本原本的核心不变量是：

```powershell
Say ("ini_pairs_identical=" + [int](($before -join "`n") -eq ($after -join "`n")))
```

`$before` 与 `$after` 都用**同一个坏读取器**，于是两边同时丢同样的行，
比较结果恒为真 —— 无论落盘对错。上一次运行就打印了 `ini_pairs_identical=1`，
而我据此认为「保存链路没问题，只是零散键没写」，方向完全跑偏。

**教训**：一个「A 等不等等于 B」的判据，如果 A、B 都由被测代码或同一套有缺陷的仪器产生，
它证明的是「仪器自洽」，不是「被测对象正确」。修法不是把这条删掉（它仍然有用），
而是**再加一层不由该仪器产生的绝对判据**：

```powershell
# 四个键必须齐全
$expected = @('failure_threshold','failure_action','failure_pause_max_wait_secs','dism_timeout_secs')
# 文件头恰好一行、且在首行
Say ("ini_header_count=" + ...)
Say ("ini_first_line_is_header=" + [int]($iniLines[0].StartsWith('# BackupRestore ')))
```

同理新增 `LineCountUtf8()`：它与 `Get-Content` 走**不同路径**（`[IO.File]::ReadAllText` + 按 `\n` 切），
两者的行数一旦不等就说明解码又坏了。

## 5. 顺带查出的真缺陷：文件头每次保存都消失

修好读取器后，`ini_before_count=4 / after=4`、`missing_keys=0`，但对着 `type` 的输出能看出：
**`# BackupRestore 程序设置（…）` 这一行不见了。**

代码复盘（`failure_policy::save_to_dir`）：

```rust
if trimmed.starts_with('#') || trimmed.starts_with(';') {
    return false;                 // ← 2026-10-18 为了防膨胀，一刀切丢掉所有注释
}
...
if kept.is_empty() {
    kept.push("# BackupRestore 程序设置（本文件由程序自动生成，可手工编辑）");  // ← 只在文件为空时补
}
```

只要文件里还有 `dism_timeout_secs`（写入顺序上几乎必然），`kept` 就不为空 → 头部不补，
而旧头部又已被过滤掉 → **用户每打开一次设置窗口并保存，文件第一行就永久消失一次**。

同源风险：`dism_timeout` 若将来给自己那行加说明注释，会被 `failure_policy` 的合并写静默删掉。
这正是「共享文件被非属主整段重写」那类 bug 的变体 —— 2026-10-16 加 `dism_timeout_secs` 时立的
「合并写」规矩只管住了**键**，没管住**注释**。

## 6. 改法

1. 注释行按**归属**过滤：

```rust
if trimmed.starts_with('#') || trimmed.starts_with(';') {
    return !(trimmed == SETTINGS_HEADER || is_own_settings_comment(trimmed));
}
```

```rust
const OWN_SETTINGS_COMMENTS: [&str; 3] = [
    "# failure_threshold:", "# failure_action:", "# failure_pause_max_wait_secs:",
];
fn is_own_settings_comment(trimmed: &str) -> bool {
    OWN_SETTINGS_COMMENTS.iter().any(|p| trimmed.starts_with(p))
}
```

2. 文件头**无条件**写第一行（旧同文本行已被上一步滤掉，所以不会重复）：

```rust
let mut lines: Vec<&str> = Vec::with_capacity(kept.len() + 7);
lines.push(SETTINGS_HEADER);
lines.extend(kept);
lines.extend([threshold_comment.as_str(), ..., pause_wait_line.as_str()]);
```

3. 文件头文本提成共享常量 `pub(crate) const SETTINGS_HEADER`，`dism_timeout::save_to_dir` 改用它 ——
   两个写入方各写一份字面量，迟早会漂成两种说明。

## 8. 可复用的钉子

1. **`Get-Content` 默认编码会吞换行**：UTF-8 中文/全角标点 + LF 行尾 + 无 BOM ⇒ 末字节落在 GBK 首字节区间
   时吃掉后面的 `0x0A`。读任何可能含中文的文件一律 `-Encoding UTF8`。
2. **一个「相等」判据若两侧共用同一台仪器，它证明的是仪器自洽**。必须补至少一条来自**不同路径**的
   绝对判据（键齐全、行数、首行特征），否则仪器一坏，判据就是恒真装饰。
3. **共享 ini 的合并写要按「归属」过滤，不能按「行类型」过滤**：按类型（是注释/不是注释）过滤会把
   别的模块的内容一起删；按归属（是不是我写的那几条前缀）过滤才安全。文件头这类公共行要么单独
   识别、要么无条件重写。
4. **「只在文件为空时补公共行」等于「文件一旦非空就永远没有公共行」**。公共行应当每轮无条件重写，
   靠「先滤掉旧同文本行」保证不重复。
5. **验收脚本改判据比改产品代码更容易留下假结论**，改完必须用「已知为真/已知为假」的两份输入各跑一次。
   本次的确认方式是：先在磁盘上确认 4 个键都在（`type`），再看脚本能否读到 4 个 —— 两者不一致
   立刻指向仪器，而不是产品。
