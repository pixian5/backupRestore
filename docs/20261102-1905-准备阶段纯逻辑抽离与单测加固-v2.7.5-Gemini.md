---

## 一、背景与问题

原先 `crates/backuprestore-cli/src/windows_prepare.rs` 承担了系统准备阶段（`prepare`、`list-volumes`、`inspect-environment`、`wim-info` 等）的几乎所有工作。
由于它被直接标注为 `#[cfg(windows)] mod windows_prepare;`，且模块顶部直接引入了 `std::os::windows::process::CommandExt` 和 Windows 专用 API，导致：
1. **测试被平台绑定**：准备阶段的所有核心纯计算逻辑（参数解析校验、盘符合法性提取、DISM 镜像输出解析、挂载参数拼装、Windows 镜像名称启发式探测等）无法在 macOS / Linux 宿主直接运行单测，导致单元测试盲区。
2. **逻辑与系统调用纠缠**：纯数据流解析（如 DISM 字符串处理）与底层进程派生、注册表/BCD 调用混杂在同一个 3700+ 行的大模块内。

---

## 二、架构重构方案

抽离出纯逻辑模块 `crates/backuprestore-cli/src/prepare_plan.rs`：
1. **条件编译开放**：
   在 `crates/backuprestore-cli/src/main.rs` 中采用 `#[cfg(any(windows, test))] pub(crate) mod prepare_plan;`。
   在非 Windows 宿主下跑 `cargo test` 时，测试代码能无缝加载并全面覆盖 `prepare_plan`。
2. **抽取纯计算与解析组件**：
   - `PrepareOptions` 结构体：纯参数数据模型。
   - `parse_prepare_options(args)`：命令行参数解析，支持 `--target-drive`、`--operation`、`--image-path`、`--compress`、`--fail-threshold`、`--fail-action`、`--b-tree` 等。
   - `parse_drive(s)`：解析形如 `C:`、`C`、`\\?\Volume{...}` 的驱动器指示符。
   - `parse_dism_images(output)`：精准解析 DISM 镜像列表与属性（处理 Windows 逗号数字、二进制 GB/MB 换算）。
   - `parse_dism_size(s)`：尺寸与单位换算逻辑。
   - `wim_mount_args(...)`：严格锁死 `/Mount-Wim` 与 `/WimFile` 参数拼装。
   - `name_looks_like_full_windows(name)`：完整 Windows 镜像启发式判定门禁。
   - `ProbeOutcome`：探测结果三态枚举。
   - `windows_version_summary(output)`：Windows 版本字符串提取。
   - `sidecar_image_name(target_role, task_id)`：恢复期 sidecar 镜像名拼装规范。
   - `validate_prepare_options_safety(...)`：准备选项防自损互斥校验（如禁止还原目标盘等于工作盘）。
3. **保持既有接口契约**：
   `windows_prepare.rs` 中通过 `pub(crate) use crate::prepare_plan::*;` 导入，不对外部行为产生破坏性变更。
