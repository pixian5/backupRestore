# 界面字体去掉加粗，改回常规字重（v2.6.88）

> 模型：DS41F。时间：2026-10-30 15:10。
> 版本：**2.6.88**（改行为 +0.0.1）。
> 关联：`docs/20261030-0209-界面基准字号12px提到14px-中文可读性提升-v2.6.80-Hy4.md`
> （那一轮把宋体 400 换成微软雅黑 **700**；本轮只把 700 改回 400，字体族不动）。

---

## 1. 需求

> 「你把字体都改成微软雅黑不加粗」

字体族保持微软雅黑，**字重从 700（粗体）改回 400（常规）**。

这一条与 2.6.80 的改动正好相反半边：2.6.80 是因为「字体看着不是特别清楚、加粗一下」
把宋体 400 换成了雅黑 700。现在字体族（雅黑）是对的，只是不需要加粗了。

## 2. 改了哪两处

界面字体只有两个造字体的入口，两处都改：

| 位置 | 作用范围 | 改动 |
|---|---|---|
| `native_gui.rs` 的 `gui_font()` | 主窗口 + 全部对话框（设置 / 备份文件管理 / 查看日志 / 两个选择弹窗） | `700` → `400` |
| `recovery_progress.rs` 的 `create_font()` | PE 内的恢复进度窗 + 详细日志窗 | `FW_BOLD(700)` → `FW_NORMAL(400)` |

`create_font(height, bold)` 的 `bold` 参数**保留但不再生效**（改名为 `_bold`）——
它有十几处调用点，逐个改签名只会制造噪音，注释里写明了原因。

**没有动**的两处（同一个「字体」话题，但属于另一个子系统）：
- `native_gui.rs` 的 PE 恢复桌面（`BackupRestorePeDesktop`）：用的是 **Segoe UI**，
  而且 44/30/18 三档分别配 700/600/500 三级字重，是分层视觉，不是「界面字体」；
- `boot_menu_window.rs` 的开机菜单：用的是系统自带字体（`GetStockObject(17)`）。

这两处都只在 PE / 开机阶段可见，本轮环境验不了，**没动**，理由与 2.6.87 遗留一致。

## 3. 一个必须同步改的地方：判据脚本

`.test-artifacts/dpi-2679/` 下的文字宽度判据（`dlg-fit.ps1` / `tabs-fit.ps1` / `probe-fonts.ps1`）
是**自己重建一份同款字体**去量文字的。如果只改程序不改判据，判据就会拿**粗体**去量
**常规体**的文字——粗体比常规体宽，于是每一行都"量出来装不下"，全线误报红。

三个脚本的字重同步改成 400。**这一条以后每次都适用**：字体族/字重/字号任何一个变了，
判据里的字体配方都要跟着变，否则判据本身就成了错误来源（2.6.84 那个「字体名按 ANSI 传」
的假红就是这么来的，只是那次是传参错误，这次会是配方过期）。

## 4. 副作用：所有「按实测文字宽度算出来」的尺寸会跟着收窄

2.6.84 之后，设置窗口的宽度、各处的标签/按钮宽度都是**实测文字宽度**推出来的。
常规体比粗体窄，所以这些尺寸会自动缩小——这是预期的，不需要补偿，也不需要改常量。

实测：英文 + 18 号字下，设置窗口整宽从 **1898 → 1804** 物理像素（收窄 94）。
窗口变小、文字不变形，正是"按内容算尺寸"该有的行为。
