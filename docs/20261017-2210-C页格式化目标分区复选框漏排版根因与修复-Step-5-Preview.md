# C 页「格式化目标分区」复选框漏排版：根因、修复与实机验收（v2.6.12）

> 撰写：Step-5-Preview · 2026-10-17 22:10 · 版本 **2.6.12** · 部署 SHA `ae400879…` · 已实机验收

## 1. 用户报告

GUI「新增非 C 盘第二系统」页（C 页）界面错位/被遮挡，附两张截图：

- **截图 1（首发态）**：直接进 C 页，按钮行下方出现一条「灰带 + 残字」。
- **截图 2（tab 往返态）**：切到别的标签再切回 C 页，「被遮挡的内容又消失了」。

两现象实为**同一个控件**的两种发作：`ID 1214`「格式化目标分区」复选框。

## 2. 根因（一行错配 + 一段历史）

`native_gui.rs` 里可见性与排版**各写一份入口集合**， drifted：

- `set_operation_visibility`（1456-1464 行）：A/B/C 三个还原入口都**显示** `ID_FORMAT_TARGET`；
- `layout_operation`（1521 行，修复前）：`let show_format_target = is_image_restore_entry(layout_op) && layout_op != "create-secondary";` —— **C 页被排除在重排之外**。

后果：C 页复选框「显示了但永不被排版」，永远停在上一次排版的位置（或创建坐标），且因 **Z 序在最底层**（创建于 `WM_CREATE` 早期，7539-7549 行，占位坐标 180,650；目标详情框 2013 与按钮行 1001-1004 在之后 `Controls` 结构体才创建，后创建者在上）——撞上谁就被谁整块盖住。

**Git 历史链（`git log -S` 实证）**：

| 提交 | 版本 | 事件 |
|---|---|---|
| `ca9f0cd` | v2.5.3「格式化选项覆盖所有还原入口×全通道 + 修复 C 入口控件遮挡」 | 引入排除条件 `!= "create-secondary"`。当时排除的是**旧「第二系统」独立 tab**（语义 = 新建系统、不清空，故意不给格式化选项）——**当时是正确的** |
| `e2c57b0` | v2.6.4「合并两个入口」 | 旧 tab 删除；可见性列表把 `"restore-system-other"` **改名**成 `"create-secondary"`（C 语义并入该 tab），**但 layout 的排除条件原样没动** → 同一个字符串语义已变，错配在此诞生 |

即：典型的**改名型遗漏**——集合判定被复制成两份，改了一处漏了另一处。

// native_gui.rs:1277-1288
fn is_format_target_entry(gui: &str) -> bool {

## 6. 新脚本级教训（本轮踩到）

1. **PowerShell `Add-Type` 的 C# 类不能含名为 `Main` 的静态方法**——Add-Type 据此切换可执行输出，报「无法添加类型。出现编译错误。」（VM 内对照实验：含 `Main` FAIL / 含 `Click` OK）。写 dump/点击辅助类**照抄 `_dump-tabs.ps1` 的 CD4 已验证结构派生**，别自造。本轮自造的 CD5 正是因此编译失败，重写为 CD4 克隆（CD6）即过。
2. 静态查此类 bug 的 cheap 方法：grep 出「可见性列表」与「layout 定位条件」两份入口集合逐字比对——凡同义不同串处即是嫌疑；再用 `_dump-tabs.ps1` 对 5 tab 全量 dump 做 visible×visible 重叠扫描兜底。
3. 截图坐标 ≠ 控件坐标（agent 截图含任务栏、垂直有偏移），定位证据一律以控件 API dump 为准，截图只作「渲染可见」证明。
