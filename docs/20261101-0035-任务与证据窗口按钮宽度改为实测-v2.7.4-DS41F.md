## 1. 改了什么

那一排按钮原来是「宽度写死 + x 写死」：

```rust
let buttons = [
    (ID_TASK_REFRESH,   "刷新列表",   238, 100),
    (ID_TASK_CLEANUP,   "清理工作树", 346, 150),
    (ID_TASK_OPEN_DIR,  "打开任务目录", 504, 130),
    (ID_TASK_CLOSE,     "关闭",       642,  66),
];
```

改成「先按实测文本算宽、再从右边界往左排」：

```rust
let mut cursor = BUTTON_RIGHT;                 // 708，与详情框右边缘对齐
for index in (0..buttons.len()).rev() {
    let width = fit_width(buttons[index].1, buttons[index].2);   // 实测文本+12，且不小于原宽度
    widths[index] = width;
    cursor -= width;
    xs[index] = cursor;
    cursor -= BUTTON_GAP;                      // 8
}
// 按原顺序创建：WS_TABSTOP 的键盘遍历顺序 = 创建顺序，倒着建会把 Tab 顺序反掉
```

三个刻意保持的东西：

1. **floor 沿用原宽度**（100/150/130/66）→ 任何字号下都不会变窄；
2. **右边界仍是 708** → 窗口尺寸、其它控件位置全不动；
3. **创建顺序不变** → Tab 键顺序不变（这类改动最容易忽略的副作用）。

## 3. ★ 先把话说清楚：这次不是修缺陷

我一度以为「18 号中文下『打开任务目录』实测 156 > 写死的 130，早该被切了」——
**那是估算，不是测量**。真去量（`btninfo.ps1` + `dlg-fit.ps1`，18 号中文、200% 缩放）：

| 按钮 | 文本 | 控件宽 | 实测文本宽 | 余量 |
| --- | --- | --- | --- | --- |
| 刷新列表 | 4 字 | 100 | 72 | **28** |
| 清理工作树 | 5 字 | 150 | 90 | **60** |
| 打开任务目录 | 6 字 | 130 | 108 | **22** |
| 关闭 | 2 字 | 66 | 36 | **30** |

> 单位说明（踩过一次）：`dlg-fit.ps1` 打出来的 `w=` / `text=` 是**设备像素**，
> 200% 缩放下要除以 2 才是 96dpi 基准。表里已换成基准值；原始读数分别是
> 200/300/260/132 与 144/180/216/72。`SINGLE_LINE_CLIPPED=0 WORST_SLACK=32`（设备像素，= 16 基准）。
> **先确认单位再下结论**——上一版差点把「设备像素」当成「基准像素」写进文档。

**结论：当前一档都不裁切，改前改后的可见结果完全一样。** 所以这次的价值不是「修好了什么」，
而是「以后文案变长/翻译变长时不会再靠运气」——和 2.6.68 那次「改文案治标」是同一类隐患的收尾。

★ 这条自我纠正值得记下来：**估算出来的数字不能当缺陷证据**。上一轮我刚写过「判据的取样面决定你能看见什么」，
这一轮差点栽在它的反面——**没量就断言**。

## 5.1 ★ 部署后 preflight 假红一次：`Copy-Item` 会保留源文件时间

第一次「提交 → 重建 → 部署」之后，`preflight.sh` 报 `PREFLIGHT=fail`（部署件比提交旧）。
但内容明明是对的。查下去是两件事叠在一起：

1. cargo 是**增量**的：源码没变时「Finished in 0.08s」，**根本没有重新产出二进制**，
   那个 exe 的 `LastWriteTime` 还是上一轮构建那一刻（00:12）；
2. `Copy-Item -Force` **保留源文件的 LastWriteTime**，所以复制过去之后部署件的 mtime 仍是 00:12，
   而提交是 00:40 → 判「过期」。

这不是判据错，是**字段语义错位**：mtime 该表示「这份内容什么时候被放进运行目录」，
而不是「上一轮什么时候编译的」。改 `windows/build-windows.ps1`：复制并核对 SHA-256 之后，
把部署件的时间设为**本次部署时刻**。内容是否最新由 SHA 与刚构建的二进制比对保证，与时间无关。

> 这条也解释了为什么「重新构建部署」有时不解决问题：如果不改源码，cargo 不会重编，
> 复制也不改时间——看上去什么都做了，判据却还是红的。
