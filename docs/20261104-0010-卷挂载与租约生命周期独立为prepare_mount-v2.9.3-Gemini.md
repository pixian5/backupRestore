## 一、背景与动机

在 Windows 系统的准备与恢复流程中，涉及多种隐藏/系统分区的识别与临时暴露（ESP 引导分区、WinRE 恢复分区等）。
此前两轮实机故障（2026-10-27/28）证实：
- `mountvol <letter>: <卷>` 与 diskpart `assign letter=` 在底层均会持久写入 `HKLM\SYSTEM\MountedDevices`；
- 若无严格的租约管理机制，临时分配的盘符用完不撤就会变成系统幽灵盘符（导致系统反复提示「无法访问。设备未就绪。」）；
- 为此引入了 `MountLease`（RAII 作用域租约）、`hold_for_process`（进程级逃生口）以及磁盘登记与崩溃清扫机制（`release_dead_owner_leases` 按 PID 精准清理）。

此前这套涵盖分区身份识别（`efi_identity`, `recovery_identity`）、底层挂载逻辑（`mount_volume_guid`, `identity_from_diskpart`）以及租约管理的 700 行底层系统代码全部深埋在 `windows_prepare.rs` 中。

本轮重构将整个卷挂载与租约生命周期子系统完整独立为 `prepare_mount.rs`，并保持静态守卫门禁的平滑 1:1 轮替。

## 二、核心改动与重构设计

### 1. 新建 `crates/backuprestore-cli/src/prepare_mount.rs`（513 行）

- **分区身份识别**：
  - `recovery_identity` 与 `recovery_identity_from_bcd`：双通道定位系统 WinRE 恢复分区；
  - `efi_identity`：免盘符优先 + mountvol 临时探查兜底定位系统活动 ESP 分区；
  - `identity_from_diskpart`：DiskPart 驱动的安全挂载与身份探测。
- **盘符分配与卷挂载**：
  - `identity_drive_candidates`：安全排除 X: 等保留盘符的候选生成器；
  - `mountvol_letter_shows_volume` / `is_drive_letter_available`：挂载状态与可用性判断；
  - `mounted_letter_for_identity`：复用既有挂载盘符；
  - `mount_volume_guid`：标准化卷 GUID 挂载；
  - `release_mounted_letter`：`mountvol /D` 释放盘符并记入时间线。
- **租约与生命周期安全管理（MountLease）**：
  - `MountLease`：RAII 租约抽象，离开作用域自动撤销；
  - `hold_for_process`：显式声明延长至进程退出；
  - `PROCESS_LEASES` / `register_lease` / `unregister_lease` / `release_process_leases`：进程级登记收敛；
  - `release_dead_owner_leases`：启动期基于 PID 活跃探测（`process_still_alive`）的崩溃清扫；
  - `ensure_volume_mounted_leased` / `ensure_volume_mounted_tracked`：全库唯一受控挂载入口。

### 2. 静态守卫门禁（source-guard.sh）1:1 轮替

- 在 `tools/test/source-guard.sh` 中将白名单由 `windows_prepare.rs recovery_volume.rs pe_operation.rs` 更新为 `prepare_mount.rs recovery_volume.rs pe_operation.rs`；
- 白名单文件总数严格维持为 3，坚守棘轮守卫约束（只许减不许增）；
- 在 `windows_prepare.rs` 中保留 `ensure_volume_mounted_leased` 转调函数，确保守卫的 B 判据（唯一入口存在、裸入口关闭）完美满足。

### 3. 精简 `windows_prepare.rs`

- 在 `main.rs` 中登记并门控 `#[cfg(windows)] pub(crate) mod prepare_mount;`；
- 在 `windows_prepare.rs` 中引入并重导出 `pub(crate) use crate::prepare_mount::*;`；
- 移除 696 行内嵌底层实现与未使用的 std imports / 函数；
- `windows_prepare.rs` 行数由 1,280 行暴跌至 **584 行**，向纯编排器转型完毕。
