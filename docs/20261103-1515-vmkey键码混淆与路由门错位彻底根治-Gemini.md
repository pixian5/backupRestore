# vmkey.sh 键码混淆与路由门错位彻底根治

> 时点：2026-11-03 15:15
> 适用版本：v2.7.8（测试工具与经验库修复，产品代码无变动，不升版）
> 涉及模块：`tools/win-clicker/vmkey.sh`、`经验/07-墓碑与争议清单.md`、`经验/02-VM操作与传输纪律.md`

---

## 一、历史背景与现象

在 `经验/07-墓碑与争议清单.md` 表格第 55 项以及 `经验/02-VM操作与传输纪律.md` 中，长期记录着一条静态核验疑点：
> `tools/win-clicker/vmkey.sh space` 疑有键码 bug：路由门按数值区间 59-88 走 scancode，`space` (-k 65) 落入该区间被发成 scancode 65=F7；09-30 的“修复”只改了 f7 数值没动路由门，F7/F8/F9/F10 映射疑均错位。用 f7-f10 前先现场打条短命令截图核对 —— 代理静态核验 [🔸 未实证]

此问题属于自动化注入基础设施中的重大隐患：在恢复环境（WinRE / WinPE）等没有 TCP agent 的场景下，键盘注入是**唯一的宿主控制通道**。

---

## 二、根因深度剖析

审查原 `tools/win-clicker/vmkey.sh` 逻辑：

```bash
# 原 vmkey.sh 代码片段：
keycode() {
  case "$1" in
    ...
    space) echo 65;; f1) echo 59;; f2) echo 60;; f3) echo 61;; f4) echo 62;; f5) echo 63;;
    f6) echo 64;; f7) echo 66;; f8) echo 67;; f9) echo 68;; f10) echo 76;;
    ...
    alt) echo 64;;
  esac
}
...
if [ "$MAINC" -ge 59 ] && [ "$MAINC" -le 88 ]; then
  # F 键：scancode 通道（见 press_sc 注释）
  press_sc "$MAINC"; sleep 0.15
  release_sc "$MAINC"; sleep 0.12
else
  press "$MAINC"; sleep 0.15
  release "$MAINC"; sleep 0.12
fi
```

### 1. 致命缺陷一：数值范围判断类型混淆
- Parallels 官方 `-k` 键码中，`space` 的十进制键码正是 **65**；
- 脚本却以 `[ "$MAINC" -ge 59 ] && [ "$MAINC" -le 88 ]` 作为判断“是否为 F 键”的依据；
- 导致发送 `vmkey.sh space` 时，`MAINC=65` **被强制误判为 F 键**，走入了 `prlctl send-key-event -s 65`（PS/2 扫描码通道）；
- 而在标准 PS/2 Set 1 扫描码中，`0x41`（十进制 65）正是 **F7 键**！
- 结果：**向虚拟机发送空格时，系统实际收到了 F7 按键**！

### 2. 致命缺陷二：Alt 单键主键触发 F6
- `alt` 键的 `-k` 键码是 64，同样落入 `59..88`，若单按 Alt 会误发 PS/2 扫描码 64（即 F6）。

### 3. 致命缺陷三：F7 ~ F10 错位与无效
- 早期维护者发现了 `space` 65 与 F7 冲突，试图避让，竟将 `f7` 改为 66、`f8` 改为 67、`f9` 改为 68、`f10` 改为 76；
- 这导致：
  - 发送 `f7`（66）实际上按下了 **F8**；
  - 发送 `f8`（67）实际上按下了 **F9**；
  - 发送 `f9`（68）实际上按下了 **F10**；
  - 发送 `f10`（76）按下了无效键！

---

## 三、彻底修复方案

将“按数值范围猜类型”彻底推翻，重构为“按按键名称进行确定性语法路由”：

1. **显式判断 F 键**：
   ```bash
   is_f_key() {
     case "$1" in
       f1|f2|f3|f4|f5|f6|f7|f8|f9|f10|f11|f12) return 0;;
       *) return 1;;
     esac
   }
   ```
2. **准确映射 PS/2 Set 1 标准扫描码（仅供 F 键走 `-s` 通道）**：
   ```bash
   f_scancode() {
     case "$1" in
       f1) echo 59;; f2) echo 60;; f3) echo 61;; f4) echo 62;;
       f5) echo 63;; f6) echo 64;; f7) echo 65;; f8) echo 66;;
       f9) echo 67;; f10) echo 68;; f11) echo 87;; f12) echo 88;;
       *) echo "";;
     esac
   }
   ```
3. **路由执行解耦**：
   - 若 `is_f_key "$MAIN"` 为真，取 `f_scancode` 并调用 `press_sc`（`-s` 扫描码通道）；
   - 普通按键（包含 `space` 65、`alt` 64、`ctrl` 37、数字字母等）一律走 `press`（Parallels 官方 `-k` 键码通道）。

## 四、验证结果

1. **Space 键**：`vmkey.sh space` 准确调用 `-k 65`，彻底摆脱 `-s 65`（F7）的混淆；
2. **F5 键**：`vmkey.sh f5` 准确调用 `-s 63`，保证恢复环境/GUI 下刷新生效；
3. **F7 ~ F10 键**：扫描码严格对齐 PS/2 Set 1 标准规范（F7=65, F8=66, F9=67, F10=68）；
4. **经验库与待修项闭环**：`经验/07-墓碑与争议清单.md` 与 `经验/02-VM操作与传输纪律.md` 同步闭环，`tools/doc/stale-claims.sh -v` 达成 0 命中。
