## 实测暴露的问题及修复

### 跨重启磁盘编号变化

早期续跑出现 `WORKSPACE disk number differs after mounting: expected 2, got Some(1)`。磁盘/分区 GUID、卷身份与几何均一致，变化的是现场编号。新增 `rebind_after_boot`：核对稳定身份、几何、文件系统和必要序列号后，只重新绑定本次操作的编号；格式化、应用和引导修复前仍严格核验此次绑定。持久任务中的原编号不被改写。DiskPart（磁盘分区工具）挂载后备路径也先按卷身份取得现场编号。

### 克隆恢复配置引用主系统

第二系统镜像中的 `ReAgent.xml` 指向主系统恢复对象。新增第二系统专用注册分支：只在已核验目标内备份并移走克隆配置，回读必须为 Disabled（未启用），再建立独立注册。不能调用 `/disable` 沿克隆引用禁用主系统恢复环境。正常系统还原仍使用原注册路径。

### 启动菜单误吸收工具项

真实收尾错误为 `Boot Manager default or secondary display order could not be preserved`。解析器把 `toolsdisplayorder` 中的内存诊断对象混入 `displayorder`。现在只接受启动菜单字段和其纯 GUID 续行，遇到下一个字段即停止；收尾按完整顺序精确回读。

### 第二系统黑屏与系统盘符绑定

任务状态成功仍不能证明新系统能用。首次启动实际进入 `D:\Windows`，离线事件日志记录 LogonUI（登录界面）与 dwm（桌面窗口管理器）反复崩溃。`MountedDevices` 的 C: 仍绑定主系统分区，第二系统自身被分配为 D:。

新增 `secondary_registry.rs`，在镜像应用完成、首次启动前读取离线 SOFTWARE 中的原 `SystemRoot`，备份 SYSTEM/SOFTWARE 及事务日志族，再按 GPT（GUID 分区表）`DMIO:ID:` 二进制身份绑定原系统盘符至新分区，只清除该目标的重复盘符映射，回读并成功卸载配置后才继续。

首次失败启动会把 `SystemRoot` 改写为 D:，不能拿失败现场当原镜像配置。诊断时先从已验证 WIM（Windows 映像文件）只读挂载恢复两份原始配置，再用产品同一函数修复并实际启动；之后又执行最终程序的完整新任务，排除“手工修好但正常流程未接入”的假通过。

### C: 擦除后的自动续跑入口

一次性启动请求会被消费；仅保证载荷在外部分区还不够。完整系统还原现在在擦除前、BCDBoot 前后核验并重新设置同一任务的启动请求，成功收尾再清除。

- 使用当前环境 `SystemRoot` 下的 BCDEdit（启动配置编辑器），WinRE（Windows 恢复环境）中不依赖已被擦除的 C: 工具。
- 依据记录的卷身份解析现场盘符；核验完整设备链、WIM 摘要、启动文件与外部分区边界。
- 保留多行启动请求，拒绝覆盖其他任务的一次性请求。
- 先验证任务与不可变载荷；仅当持久阶段已经到擦除阶段、且 SOURCE/RECOVERY 角色确实与目标同分区时，允许格式化产生的卷序列号变化。

实测日志显示同一 C: 任务在 05:27:23、05:37:01 两次进入恢复程序，均在格式化前重武装；05:41:52 与 05:41:54 在引导修复前后再次核验，05:41:58 清理并标记成功。
