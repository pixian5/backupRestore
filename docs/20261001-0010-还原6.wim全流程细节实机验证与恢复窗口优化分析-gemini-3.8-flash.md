# 还原 6.wim 全流程细节实机验证与恢复窗口优化分析

## 1. 验证背景与目标
用户要求对 `F:\6.wim` 执行单系统还原测试，观察全流程交互与执行细节是否存在问题，涵盖：
- GUI 界面上「单系统还原」Tab 与新增的「严格对比哈希（默认仅对比大小）」复选框表现；
- WIM sidecar 元数据（`6.wim.index-1.metadata.json`）的毫秒级读取与呈现；
- 创建任务流程中破坏性提示、环境选择及最终确认对话框；
- WinRE 恢复环境中的 4 个阶段大标题、原生 Win32 恢复进度窗口、时钟及呼吸小箭头动画；
- 还原完成后 BCD 引导项清理与自动重启回 Windows 桌面的完整性。

## 2. 核心细节与发现的问题排查

### 细节 1：WinRE 状态问题排查（回答用户此前关切）
- **现象**：首次点击创建任务时，后台准备脚本报错 `invalid task: Windows RE is disabled or unavailable`。
- **根因分析**：虚拟机客体原有的 `Winre.wim` 曾被移存到 P 盘（`P:\Recovery\WindowsRE\Winre.wim`），导致系统原有的 `reagentc /info` 处于 `Disabled` 状态。
- **处置验证**：在遵守 AGENTS.md 约束创建快照 `{67dd8d62-6c8f-4e4a-bc31-dc28a14edf0e}` 后，将该镜像部署到专用的恢复分区 `Y:\Recovery\WindowsRE`，并执行 `reagentc /setreimage` 和 `reagentc /enable`，成功将恢复环境恢复为 `Enabled`（版本 10.0.26100.8031）。

### 细节 2：最高安全防线生效（关键安全隔离机制）
- **现象**：当在 `C:\BackupRestore\BackupRestore.exe` 尝试单系统还原时，弹窗提示：
  > “无法开始还原: 程序目录位于目标分区所在卷。请手动将整个 BackupRestore 文件夹移动到其他分区后重新运行。未创建任务，未修改 WinRE，未修改启动配置，未请求重启。”
- **结论**：单系统还原会彻底格式化 C 盘；若程序自身及其工作目录位于 C 盘，还原任务会被自毁。系统安全防护成功拦截了破坏性操作。切换到 `H:\brwork\BackupRestore.exe` 后正常通过。

### 细节 3：校验选项框与秒级读取
- **选项框表现**：WIM 索引右侧的 `[ ] 严格对比哈希（默认仅对比大小）` 排版正常，默认未勾选，文字清晰。
- **读取镜像性能**：输入 `F:\6.wim` 后点击「读取镜像」，秒级从 sidecar `6.wim.index-1.metadata.json` 直接加载索引 1，极速呈现。

### 细节 4：WinRE 进度窗口细节缺陷（发现的关键优化点）
- **现象**：在进入 WinRE 后的最初两分钟（流式哈希核对期）以及 DISM 输出间隔期，窗口右上角的时钟和呼吸箭头出现停滞，直到有新的日志输出才刷新一次。
- **代码根因**：在 `crates/backuprestore-cli/src/recovery_progress.rs` 中，`refresh_from_log` 函数由于前置判断 `if size == *offset { return; }`，当日志没有新增字节时直接退出，跳过了后方的时钟计算、已用时间更新和呼吸箭头交替代码！
- **优化方案**：将时钟计算和呼吸箭头刷新独立到日志检测之外，即使无新日志，定时器每秒也会驱动时钟和箭头呼吸。

### 细节 5：阶段小箭头的呼吸效果与进度条
- **小箭头呼吸**：在第二阶段执行中，小箭头 `▶` 成功实现了亮 1 秒、消失 1 秒（使用全角空格占位，文本无横向抖动）。
- **进度推进**：DISM 从 1% -> 24% -> 44% -> 100% 平滑推进，剩余时间动态收敛，全流程仅耗时 220 秒。
- **引导项与临时目录清理**：还原完成后，自动执行 BCDBoot，验证 BCD 指向 C 盘，清除临时一次性启动项，清理暂存目录，安全重启回 Windows 桌面。
