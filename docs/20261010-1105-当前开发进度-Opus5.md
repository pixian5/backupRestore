# 当前开发进度

版本 **2.2.1**，开发测试版；模型：Opus 5（1M 上下文）。

本轮处理完 [`可能的问题GPT6.md`](可能的问题GPT6.md) 的**最后两项**，14 项清单全部有结论。

- **问题 10（P2）ESP 控制文件路径**：复核发现主体已修（`esp_identity_without_drive_letter`
  校验 EFI 类型 GUID 并探测 BCD、多候选拒绝猜测），残留只是 `esp_log_path` 写死 `S:\BackupRestore\logs`
  这一条固定盘符假设。已改为 `esp_log_path_on(卷根, 文件名)`，路径只从调用方传入的已核验卷根派生；
  删掉为此服务的 `ESP_CONTROL_FILES` 与 `rewrite_s_root`（后者靠字符串替换 `S:`，且它锁定的
  "控制通道必须留在 `S:\` 根"已随旧控制通道被取代而证伪）。
- **问题 11（P1）准备期统一回滚**：新增 `compensate_prepare_failure`，覆盖建 BCD 条目、
  DISM 挂载/注入、载荷覆盖、刷新哈希、武装、状态落盘与重启请求全部失败点，固定顺序为
  清启动请求 → 删对象 → 删本任务载荷 → 恢复字节级 BCD 快照，每步回读验证，失败汇总上报。
  配套新增跨平台模块 `boot_record.rs`（半成品条目簿记）——`boot_entry` 是 `#[cfg(windows)]`，
  其单测在 macOS 上一次都不编译，所以把纯数据与文件 I/O 挪出来配本机测试。
  另抽出 `remove_entry_objects` 让正式簿记与半成品簿记的安全边界逐字一致，
  并新增 `acceptance:entry-fields:error` 注入点让 KEEP 分支在实机夹具可达。
