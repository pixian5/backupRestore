# 文档链接入库判据脚本化：本机点得开 ≠ clone 后打得开

> 时点：2026-10-26 21:40 · 模型：deepseek-4.1-flash · 版本：**2.6.62（未升版本——只加判据工具，未改任何会进二进制的东西）**

## 1. 起因

用户看到我上一份复盘里的一句注释——`# 找出「被链接、但没进 git」的文件`——问「什么意思」。

解释完顺手**重跑**了那条 bash 检查，结果是：

```
未进库: AGENTS.md
```

`AGENTS.md` 确实在 `.gitignore:135` 里（含本机凭据，绝不可入库），而 `文档索引.md` 当时已经改成纯文本了。
唯一的命中在 `docs/20261026-2029-…md:113`——那是一段**引用旧写法的行内代码**：

```
| `文档索引.md` §六 | `\| [AGENTS.md](AGENTS.md) \|` —— 在 clone 出来的仓库里必然 404 |
```

即：**判据命中的是示例文本，不是真链接**。于是有了两件事要做：
把结论固化成可复跑的判据，并且让它不会犯这个假阳性。

## 2. 这条判据到底在问什么

「被链接但未进库」拆成两问，修法完全不同，必须分开报：

| 判据 | 含义 | 修法 |
|---|---|---|
| `MISSING` | 目标文件**本机就不存在** | 链接写错 / 文件被删 / 文件改名 |
| `UNTRACKED` | 目标**本机存在、但 `git ls-files` 查不到** | 要么 `git add` 它，要么把链接降级成纯文本 |

`UNTRACKED` 才是这次的主角：**本机是绿的，clone 后必 404**。
在这之前所有「相对链接失效 0」的校验都只问「本机能否打开」，所以它一次都没被抓到。

## 3. 脚本：`tools/doc/check-doc-links.py`（新增，207 行）

不是清理工具，是判据。输出全是 ASCII 结构化字段：

```
MD_TRACKED=455
LINKS_CHECKED=839
MISSING=6
MISSING_NAV=0
ARCHIVE_MISSING=6
UNTRACKED=0
DONE
```

### 3.1 为什么不用 bash 一行流

原方案 `git grep -oh '](\{0,1\}[^)]*\.md)'` 是**纯文本匹配**，分不清「真链接」和
「写在反引号/代码块里的示例」。假阳性会训练人忽略判据（本项目已有先例：
`MISSING_CONTROLS` 那条如果只能靠人工判断，早被当成噪音关掉了）。
所以 Python 逐行扫描，先剥掉 fenced code block 与行内代码，再匹配
行内式 `[文字](目标)` 与引用式 `[id]: 目标`。

### 3.2 判据分级——这是本节最重要的一条

首跑（未分级）报 `MISSING=98`，全是假的；修掉编码误报后剩 **6 条**，全部落在
`docs/` 的历史归档里：

| 目标 | 来源 | 性质 |
|---|---|---|
| `docs/README.md` ×3 | `20260821-0918` / `20260930-1925` / `开发方案/…T3` | 该文件今天按用户要求**彻底删除**，历史文档的链接随之失效 |
| `docs/20260928-074516-registered-winre-policy-and-resume-design.md` | `20261012-1520` | 目标文档已改名/移除 |
| `docs/90-archive/crates/…/native_gui.rs` ×2 | `90-archive/round-snapshots/20261005-1050` | 指向搬迁前的代码树相对路径 |

**如果要求这 6 条全绿，唯一做法是去改历史记录**——而历史记录是「当天的快照」，
改它等于篡改证据。所以判据分两级：

- **阻塞**：导航文件（`README.md` / `文档索引.md` / `BACKLOG.md` / `经验/*`）的死链 → `MISSING_NAV`
- **阻塞**：**任何位置**的 `UNTRACKED`（与位置无关，clone 后都是 404）
- **只报**：`docs/` 历史归档的死链 → `ARCHIVE_MISSING`（打印 `ISSUE` 行，不阻塞）

分级不是为了放水，是为了让「红」永远指向**该动手的地方**。

### 3.3 仪器自检：读不到 ≠ 判据满足

- `LINKS_CHECKED=0` → `exit 2`，并明说「解析器没工作，不是没问题」
- 不在 git 仓库里 → `exit 2`
- 某个 md 读不到 → `exit 2`

这三种都**不允许**输出一个好看的 `MISSING=0`。

## 4. 首跑的两次假阳性（仪器先自证）

| 现象 | 真因 | 修法 |
|---|---|---|
| `MISSING=98`，一大片 `docs/%E9%A1%B9%E7%9B%AE…` | 只替换了 `%20`，**没做完整百分号解码**；中文文件名在链接里是 UTF-8 百分号编码 | `urllib.parse.unquote()` |
| `docs/file:/Users/x/…` 被当成相对路径 | `file:` 协议没列入跳过前缀 | `SKIP_PREFIX` 加 `file:` |

这正好复现了 10-26 一天栽三次的那条：**判据红时先证明读数那一侧对**。
这次是先用「98 条里有 90 条长得一模一样」这个形状差异发现的，没有直接去改链接。

## 5. 变异验证（5 条，每条单独弄红/弄绿）

| 变异 | 做法 | 期望 | 实测 |
|---|---|---|---|
| VAR1 未入库目标 | `README.md` 追加 `[AGENTS.md](AGENTS.md)` | `UNTRACKED=1`、`rc=1` | ✅ `UNTRACKED=1` `rc=1` |
| VAR2 导航死链 | 追加 `[缺失](docs/NOT-EXIST-XYZ.md)` | `MISSING_NAV=1`、`rc=1` | ✅ `MISSING_NAV=1` `rc=1` |
| VAR3 代码内假链（反向） | 追加行内代码 + 代码块内的假链接 | **不变红**、`LINKS_CHECKED` 不增 | ✅ `rc=0`、仍 839 |
| VAR4 解析器空转 | 临时仓库只有 1 个无链接 md | `rc=2` | ✅ `rc=2` + `ERROR: LINKS_CHECKED=0` |
| VAR5 不在仓库 | 在 `/tmp` 下跑 | `rc=2` | ✅ `rc=2` |

VAR3 是反向变异：它证明的是「跳过我没写漏，也没写过头」——
如果豁免写过头（把真链接也跳了），正常态的 `LINKS_CHECKED=839` 会掉。
变异后 `README.md` 已逐字节还原（`diff` 与备份一致、`git status` 干净）。

## 6. 接进 pre-push 门禁（第 6 步）

`tools/git-hooks/pre-push` 从 5 步扩到 **6 步**，编号 8 处一并改（改完断言 `HIT_5=8 / LEFT_5=0`）。
第 6 步要点：

- `rc=2` 单独处理并明确写「这不是通过，先修判据本身」——**把仪器故障记成红判据**与
  **把仪器故障记成绿**一样有害
- `rc=1` 时只打印前 20 条 `ISSUE` 行，不刷屏

## 7. 现状与遗留

- 当前：`MISSING_NAV=0` / `UNTRACKED=0` / `ARCHIVE_MISSING=6`，`--strict` 退出 0
- 遗留（有意不做）：那 6 条归档死链**不修**。要修就得改历史文档正文，
  价值低于风险；它们已被本文件与 `文档索引` 记录在案
- 未覆盖：README 之外的纯文本引用（无 `[]()` 形式的裸路径）不在判据范围内——
  这类「提到了但没链接」不影响 clone 后可用性，故不做

## 8. 一句话结论

**「本机自洽」证明不了「仓库可用」**；要证明后者，判据里必须有一步去问
`git ls-files`，而且这一步的输出必须能把「读不到」和「不满足」分开。
