## 1. 为什么需要终态收口（问题回顾）

`20261016-2016` 复核发现两件事，合起来构成"用户没有自救出口"：

1. **续跑只挡一次**：`main.rs::claim_boot_resume_attempt` 用 `create_new` 建
   `boot-resume-{stage}.attempted`，每个 stage 只自动续跑一次；
2. **续跑依赖启动副本**：`resume_pending_boot_task()` 的工作区 = **exe 自身所在目录**。
   本机自启的是 `C:\Users\Public\backupRestore-package\BackupRestore.exe`，
   它**看不见** `H:\brwork\tasks`；只有从 `H:\brwork` 启动才会看到并续跑。

于是任务在擦除后失败时：
- 停在 `TargetErased`（非终态）→ 从 `H:\brwork` 启动仍会被自动续跑一次 → 又进 RE；
- `abandon-task` 在擦除后**主动拒绝** → 既不能续、也不能清 → **永久悬置**。

**本轮把"失败"这件事显式终结掉**：失败就是失败，标成终态，现场留着，引导清干净。

### 2.1 终态标记为什么必须"顺手把引导也清了"

`auto_escape_to_windows` 里 disarm 在前、标终态在后，两步缺一不可：

- 只标终态不 disarm → `bootsequence` 仍指向恢复环境，**下次启动直接进 RE**；
- 只 disarm 不标终态 → 任务停在 `TargetErased`，**从 `H:\brwork` 启动又会被续跑一次**。

`disarm` 本身只按**精确 GUID** 删本任务的两个 BCD 对象、且只清**属于本任务**的
`bootsequence`（别人的一律不碰）——这条安全边界是 `boot_entry.rs` 既有的，本轮未改。

### 2.2 为什么"连败 3 次"直接逃出而不是再问一次

v2.6.6 的实现只在文案里预告"累计 3 次后关闭窗口将自动清理"，**实际仍要用户点「取消」**——
文案与行为不符。本轮改为名副其实：达阈值即视为确定性失败（同一任务、同一错误连撞 3 次），
自动逃出。前 2 次仍给用户「重试」的机会。

```

### 3.4 终态收口成功（用真实悬置任务验证）

把悬置任务 `2f8f8efb`（`stage=target-erased`，exit 5）按 `auto_escape` 的**同一形态**
标成终态（纯字符串替换 `"status"/"stage": "target-erased"` → `"failed"`，
不重排 JSON、不动其它字节），然后跑收口：

| 步骤 | 结果 |
|---|---|
| `validate-task task.json` | `valid task 2f8f8efb-… operation=RestoreExisting **status=Failed**`，exit 0 |
| `abandon-task H:\brwork 2f8f8efb-…` | **exit 0**（此前必拒） |
| 任务目录**保留** | `task.json` / `status.json` / `manifest.json` / `prepare.log` / `recovery.log` / `Recovery-early.log` / `boot-entry.json` / `bcd-before-*` / `boot-resume-TargetErased.attempted` —— 证据齐全 |
| 大目录**已删** | `payload` / `stage` / `original` / `mount` 全部消失 |
| 载荷目录 | `H:\BackupRestoreRE` → 找不到（已清） |
| BCD 对象 | `bcdedit /enum osloader | findstr 7c347ac` → **空**（`{7c347ac7}`/`{7c347ac6}` 已删） |

### 3.5 ★ 复核报告新增验收点：从 `H:\brwork` 启动**不再触发续跑**

用 `tools/win-clicker/restart-gui-h.ps1` 从 `H:\brwork` 启动 GUI（此前正是这份副本会触发续跑）：

```
GUI_UP pid=8356        （标题栏：BackupRestore - Rust GUI v2.6.8）
```

`H:\brwork\tasks\2f8f8efb-…\prepare.log` **尾部仍是 11:23 那条历史续跑记录，无任何新增**：

```
[2026-10-16T11:23:05.966] Detected durable interrupted task after normal Windows startup; resuming task 2f8f8efb-…

→ 任务已是 `Failed`，`stage_resumable_after_interruption` 不选它 → **不再武装、不再重启**。
这正是 `20261016-2016` §5.2 新增的那条验收标准。
