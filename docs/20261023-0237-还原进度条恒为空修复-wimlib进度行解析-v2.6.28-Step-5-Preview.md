# 还原进度条恒为空：wimlib 进度行解析修复（v2.6.28，2026-10-23 02:37）

> 现象来源：用户 2026-10-23 02:30 提问「为什么还原期间没看到进度条变化啊，一直是空」，
> 附恢复环境进度窗截图（02:09:27，`2/4 还原镜像（时间长）`，已用 06:25，剩余 `--:--`，
> 进度条全空，日志尾部显示 `Extracting file data: 15 GiB of 68 GiB (22%) done`）。
> 结论：**进度窗口没有解析 wimlib 的进度行**——`parse_percent` 是给 DISM 的
> `[= 45.6% =]` 写的，wimlib 的 `(22%)` 行首带计数，拼出来的数字必然越界 → 恒为 `None` → 进度条恒 0。

## 一、现象与影响面

- 第 2 步「还原镜像」是整条还原里最长的一步（2026-10-23 实测 11 分 43 秒 / 68 GiB），
  进度条全程 0、剩余时间恒 `--:--`，用户无法判断是在推进还是卡死。
- 只影响**覆盖式还原（wimlib 通道，v2.6.25 起）**；格式化还原走 DISM，进度条一直正常。
- 步骤清单（1/4、2/4…）与日志尾部是正常的——它们不依赖百分比。

## 二、根因（三条硬证据）

### 1. wimlib 的进度是 `\r` 原地刷新的英文计数行

恢复日志里一次 apply 的原始字节（`.test-artifacts/e2e-brimglog-227.log`，2026-10-23 那轮）：

```
Applying image 1 ("Windows Backup") from "E:\BRImages\br-2619-cur.wim" to directory "F:\"\r\n
\rCreating files: 0 of 633699 (0%) done\rCreating files: 500 of 633699 (0%) done\r…\r
\rExtracting file data: 0 GiB of 68 GiB (0%) done\r…\r
\rApplying metadata to files: 0 of 633699 (0%) done\r…\r\n
```

- 三个阶段各自从 0% 报到 100%，**不是** DISM 那种「整条命令一个 0–100」；
- `\r` 分隔（重定向到文件后同一行会很长：`Creating files` 段 55,487 字节 / 1,270 次刷新）；
- 进度窗已按 `\r`/`\n` 拆行（`recovery_progress.rs` 的 `read_log_delta`），**拆行没问题**——
  问题在拆出来的每一段没人认。

### 2. `parse_percent` 认不出这个格式

`text_parsing::parse_percent` 的算法是：找到 `%` → 往回找到最近的 `[`（没有就从行首）→
把这段里的数字和 `.` 全拼起来 → 解析成 f32 并要求落在 0–100。

| 输入行 | 拼接出来的数字 | 结果 |
| --- | --- | --- |
| `Extracting file data: 15 GiB of 68 GiB (22%) done` | `156822` | `None`（>100） |
| `Creating files: 500 of 633699 (1%) done` | `5006336991` | `None`（>100） |
| `Applying metadata to files: 633699 of 633699 (100%) done` | `633699633699100` | `None`（>100） |
| DISM `[stdout] [=  45.6% =]` | `45.6` | `Some(45)` ✅ |

### 3. 于是进度窗拿到的是 `None`

`classify_log_line` 返回 `percent = None` → `read_log_delta` 不更新 `cached_percent` →
`refresh_from_log` 里 `pos = progress.current_percent.unwrap_or(0) = 0` →
`PBM_SETPOS 0`，且 `剩余时间` 的判据是 `pos > 0`，所以恒 `--:--`。
**这与截图完全吻合**（进度条空 + 剩余 `--:--` + 日志尾部仍在滚动）。

## 三、修复（v2.6.28）

改动全在 `crates/backuprestore-cli/src/text_parsing.rs`：

1. **新增 `WimlibPhase` 与 `parse_wimlib_progress`**：按行内关键字认三个阶段
   （`Creating files:` / `Extracting file data:` / `Applying metadata to files:`），
   取行尾最后一对括号里的百分比。
2. **新增 `wimlib_overall_percent`**：把阶段内百分比折成整条 apply 的 0–100。
   权重按本轮实测（68 GiB / 633,699 条目 / 总 11 分 43 秒：创建文件约 1 分钟、
   展开数据约 9 分半、应用元数据约 1 分 15 秒）取 **10% / 80% / 10%**。
   三阶段顺序固定，映射天然单调——用户看到的是「一条不倒退的 0→100」，
   而不是「0→100 走三遍」。
3. **新增 `wimlib_detail_line`**：把英文片段改写成一句中文进度
   （`正在展开系统文件：15 GiB of 68 GiB (22%)`），保留数字、换掉标签。
   否则日志尾部每秒被一条英文计数刷掉，真实消息看不见。
4. **`classify_log_line` 接线**：先试 wimlib 解析，认不出再回落 DISM 的 `parse_percent`
   （DISM 行为零改动）。

版本三处同步到 **2.6.28**（`VERSION` + 两个 `Cargo.toml` + `Cargo.lock`）。
