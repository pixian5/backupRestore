## 二、实测结果

**通过的：**

- 真实界面「备份系统」→ 产出有效 WIM（索引 1，24 字节 = 源文件大小）。
- 真实界面「还原系统」正例 → 格式化真的发生（还原前放的 `old-only.txt` 被清除），内容还原正确。
- 还原确认框文案合格：点名镜像全路径与目标卷，明确警告将格式化。

**发现的缺陷（五项，均有实机证据）：**

| 级别 | 缺陷 | 关键证据 |
|---|---|---|
| **P0** | **镜像不存在时先格式化、再失败、最后报"还原完成"** | DiskPart `成功格式化该卷` + DISM `错误: 2 系统找不到指定的文件` + 对话框标题 `还原完成` + 测试盘两个文件全部消失 |
| **P0** | 探测文件写入 ESP 根、读回 `BackupRestore\logs` 子目录 | `S:\format-check.txt` 存在 7 字节；`S:\BackupRestore\logs\format-check.txt` 不存在；`pe-drive.txt` 0 字节 |
| **P0** | `mountvol` 的 `NO MOUNT POINTS` 被当英文固定串，中文系统打的是 `无装入点` | 代码注释明确声称"不随本地化变"；实测 Windows 与 PE 都打中文 → 零盘符 ESP 定位必定失败 |
| **P1** | 命令输出用 `read_to_string` 读，GBK 解码失败被当"无输出" | `backup-out.txt` 实有 142 字节 DISM 成功文本，产品记录 `no output` |
| **P1** | `mountvol` 退出码被当判据，实际已挂载却判失败 | 日志 `mountvol S: /S FAILED exit 1`，但随后 `S:\…` 写入全部成功 |

**顺带确认：** PE 内盘符确实漂移（Windows `T:`→PE `D:`，`P:`→`E:`，`H:`→`F:`，`F:`→`G:`）。

## 三、对既有文档结论的修正

- 第 4 项「PE 失败后仍推进」从"静态分析"升级为**实机复现的数据丢失路径**，应是全部待办里的第一优先。
- ESP 定位失败的根因此前被归为"方案 A 在 PE 不适用"，**实际根因是本地化字符串假设**，而且在 Windows 侧同样失败，不止 PE。
- 新增一项此前所有文档都未提到的缺陷：命令输出的 GBK 解码失败（第 5 项）。
