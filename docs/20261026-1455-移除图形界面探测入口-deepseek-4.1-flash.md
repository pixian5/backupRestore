# 移除图形界面「探测」入口（2.6.61）

> 2026-10-26 14:42。「把探测tab删除」——六个入口变五个。

## 1. 范围界定：只删入口，不删能力

先划清边界，避免顺手删掉别的东西：

| 层 | 处理 | 理由 |
|---|---|---|
| 图形界面入口（tab 按钮 1107） | **删除** | 用户要求 |
| 图形界面的选中文案 / 索引映射 / 快捷键 / 测试钩子 | **删除** | 入口没了就是死接线 |
| `prepare --operation probe`（命令行） | **保留** | 用户说的是「tab」，不是「功能」 |
| core 的探测契约（`incomplete_tasks` 按 `Probe` 跳过、探测不弹破坏性确认） | **保留** | 命令行仍会创建探测任务 |
| `operation_display("probe")` = 「探测（仅检查）」 | **保留** | CLI 建的探测任务会在 GUI 里被渲染成待续跑提示（`native_gui.rs:6272`/`6408`），删了就显示空白 |

一句话：**GUI 不再提供入口，能力仍在命令行**。这条也写进了手册 §3.3，免得用户以为功能消失了。

★ **报错面最大的是第 10 项和数组长度**：`select_operation` 用 `index.min(N)` 兜住越界，
如果把数组缩到 5 而 `min` 还是 5，`set_operation_tabs` 里 `index == state.operation_index`
会让 5 号按钮永远不被勾选——不崩、不报错，只是「最后一个 tab 点了没反应」。这类静默错位
比 panic 难查，所以两处必须同改。

## 3. 顺带订正一处早就错的文案

`main.rs` 里 `--tab` 的注释写着「1=备份 … 5=安装 PE」，而实际索引是 **0 基**（`0=备份 … 4=安装 PE`），
帮助文本也一直写 `<0..=4>`。错误文案会让人传错参数、把「安装 PE」当成 3。

已改为 0 基，错误提示同步成 `--tab requires an index 0..=4`——**探测移除后上限确实只剩 4**，
这句现在是对的。

## 5. 可复用的钉子

1. **删入口 = 删除 8 类接线**：常量 / 结构体数组长度 / 审计表 / 控件名表 / 创建代码 / 文案键 /
   索引映射 / 快捷键 + 测试钩子。逐个 grep 名字，别凭记忆数。
2. **「缩数组」与「缩索引上限」必须成对改**，否则得到的是「点了没反应」这种静默错位。
3. **删 UI 前先问「能力还在吗」**：命令行还在用的，core 契约与显示文案都不能跟着删——
   否则 GUI 渲染 CLI 建的任务时会出现空白。
4. **验收脚本里的页数断言是资产**：`PAGES_CHECKED=5` 同时守住「页数对」与「脚本没中途死」；
   改入口数量时必须同步，否则它会一直绿（因为少查一页也算「都过了」）。
5. **结构性数字比截图更硬**：五页控件数各减 1 这件事，比「看起来对」可靠得多。
