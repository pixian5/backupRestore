# 加一行日志：记录 GDI 实际选中的字体（v2.6.90）

> 模型：DS41F。时间：2026-10-30 15:55。
> 版本：**2.6.90**（改行为 +0.0.1）。
> 关联：`docs/20261030-1520-PE镜像字体核查-…-v2.6.89-DS41F.md`（本轮的起因）。

---

## 1. 为什么加这一行

`CreateFontW` 请求一个不存在的字体时**不会失败**——Windows 会静默挑一个最接近的替代品，
返回的句柄照样有效。于是：

- 代码里写着「微软雅黑」；
- 屏幕上可能是宋体；
- **没有任何痕迹**说明发生了替换。

今天就被这件事绕了很久：PE 里字体到底生效没有，只能靠「拆镜像列字体 + 抽注册表查登记 +
看截图」三件事拼出来。能拼出来是因为 PE 镜像就在本机；换成别人的机器、或者镜像被别人换掉，
就完全失去排查手段。

所以加一行日志，把「实际用的是哪个字体」变成可查的事实。

## 2. 改了什么

`crates/backuprestore-cli/src/native_gui.rs`：

```rust
const GUI_FONT_WEIGHT: i32 = 400;   // 提取常量，日志与实际传参不可能走岔

unsafe fn log_resolved_font(state: &mut State) {
    // 每个进程只记一次；GetDC(NULL) → SelectObject(gui_font()) → GetTextFaceW
    append_gui_log(state, &format!(
        "font: requested=\"Microsoft YaHei\" weight={GUI_FONT_WEIGHT} size={} -> GDI selected \"{face}\"",
        crate::dpi::font_size()));
}
```

在主窗口 `WM_CREATE` 末尾调用一次。新增一个 Win32 声明 `GetTextFaceW`。

**为什么用 `GetDC(NULL)` 而不是控件自己的 DC**：这一步只关心「按同样的参数造出来的字体，
GDI 解析成了哪个族」，与具体控件无关；用屏幕 DC 最快且不依赖窗口句柄。

## 3. 验证

### 3.1 正向：日志里报了真名

部署 2.6.90 后启动一次，`gui.log` 里出现：

```
font: requested="Microsoft YaHei" weight=400 size=14 -> GDI selected "微软雅黑"
```

### 3.2 负向：证明它真能报出替换（否则「报了雅黑」不算证据）

按项目规矩，判据必须能变红。用一个独立探针按同样的参数造三种字体，看 `GetTextFaceW` 报什么：

| 请求的字体名 | GDI 实际选中 | 说明 |
|---|---|---|
| `Microsoft YaHei` | 微软雅黑 | 正常命中 |
| `NoSuchFontXYZ123` | **宋体** | ✅ 不存在的名字被替换成兜底字体，探针照样报出来 |
| `Segoe UI` | Segoe UI | 正常命中 |

中间那一行是关键：**如果字体不存在，这行日志会写出别的名字，一眼就能看出「代码写的和实际用的不是一个东西」。**

## 4. 局限（写清楚，别让这行日志被高估）

1. **只报族名，不报文件**。它证明「GDI 认为这是微软雅黑」，但不会告诉你这份雅黑是
   `msyh.ttc` 还是别的什么伪装成同名的字体文件。
2. **只报一次**。中途改字号会重新造字体，但那一次不重复记（避免刷日志）。若将来出现
   「改字号后字体不对」的问题，需要把这行放到 `apply_font_size` 里再记一次。
3. **PE 侧没验证到这行日志**：PE 里跑的是 `Recovery.exe`，它的日志落在哪取决于
   `log_root` 在 PE 下的解析结果；而要让 PE 里带上 2.6.90 必须再重建一次 `boot.wim`。
   本轮没做。**这行日志在 Windows 侧已验证有效，PE 侧属于「同一份代码、同一套 API」，
   但没亲眼看到它的输出。**

## 5. 仍然挂着的那一项：PE 内的恢复进度窗

想让它在 PE 里出现，必须真跑一个离线任务。本机现状：

- `prepare` 的空间判据是 `已用字节 + 保留量`（不看压缩）：C: 已用 68.6 GiB；
- 能放镜像的卷：F: 剩 61.3 GiB、H: 剩 55.7 GiB —— **分别差约 7 GiB / 13 GiB**；
- C: 本身不能当目标（它承载 WinRE，被显式拒绝）；
- H: 里唯一能腾出足够空间的是 `H:\BRImages\r0-c-2677.wim`（28.2 GB，**唯一的还原测试镜像**）。

所以这一项要么**删掉那个还原镜像**腾空间，要么承认它「没有亲眼看到」。
按规矩不擅自删测试夹具，等用户决定。
