## 2. A 入口阻塞与解法（本轮唯一新踩的坑）

**现象**：从 `C:\Users\Public\backupRestore-package\` 启动的 GUI 点「创建任务」即弹「还原已停止」，GUI 日志：
`GUI action blocked: program workspace volume matches restore target`。

**根因**：A 入口目标 = C:，而 GUI 自启副本的程序目录就在 C: 上——「程序所在卷 == 还原目标卷」触发自毁保护（防把正在运行的程序卷本身格式化）。

**解法**：从 **H: 卷**启动纯净 GUI（`H:\brwork\BackupRestore.exe`，SHA256 `491BFF5E…` 与部署版一致），程序卷 ≠ 目标卷，保护不再触发。新脚本 `tools/win-clicker/restart-gui-h.ps1`（计划任务 Interactive+Highest 从 H: 启动，ASCII 正文）。

> 经验：验收 A/C 入口（目标可能是程序所在卷）时，一律先用 `restart-gui-h.ps1` 从 H: 起 GUI；`restart-gui-plain.ps1`（package 目录）只适合目标不在 C: 的场景。

## 6. 与交接文档（0021）的差异：未拍快照的决策

> 🪦 **本节的「空间论据」不可引用（2026-10-29 审计标注）。** `经验/07` §2 已登记：
> 「决策本身（C:→C: 自替换 + 启动配置数据基线 + 同镜像可再还原）**有验算价值**，
> **空间论据不可引**」。原因是下面那段用的「快照会整份复制一层 87GB」是错的模型——
> 快照走写时复制（CoW，只记增量），代价是「写入量 × 保留层数」。
> 结论（可以不拍）仍然成立，但**成立的理由不是空间账，而是「C:→C: 自替换 + 有 BCD 三行基线 + 同一镜像可再还原」这三条回滚保障**。

0021 待办 1 建议「执行前必须拍快照」。**实际未拍**，依据用户自有快照纪律（高于交接文档建议）：

- 纪律原文：备份/改引导不拍整机快照，**只有确需整机回滚时才拍、全程最多 1 个**；宿主 926GiB 中空闲 116GiB，而本 VM 第二系统盘 87GB 的快照会整份复制一层 → 拍完仅剩 ~29GB，还原写 C: 还要长 VM 磁盘（~75GB），正是 10-12 吃满磁盘事故的同款乘法。
- 本次风险结构不同：**C:→C: 自替换**（镜像就是 2.5 小时前的 C: 本身），数据丢失风险低；回滚路径 = BCD 三行基线（00:19 已记录）+ 同一 WIM 可再次还原。
- 结果验证该决策无害：全链一次通过，未动用任何回滚。

## 7. 新增工具与 PowerShell 5.1 陷阱（脚本已入仓库）

`tools/win-clicker/` 新增 4 个脚本（均 ASCII 正文，可经 `br-agent-tcp.sh exec <本地.ps1>` 在提权 agent 内跑）：

| 脚本 | 用途 |
| --- | --- |
| `br-focus-gui.ps1` | 点击前聚焦 BackupRestore 主窗 + `GetForegroundWindow` 回读（`FOCUS_OK hwnd=…`） |
| `br-enum3.ps1` | 枚举主窗全部子控件（id/class/rect/text）→ `C:\Users\Public\pkg\enum3.txt` |
| `br-wins2.ps1` | 列出全部可见顶层窗口（找自绘弹窗类名）→ `wins2.txt` |
| `br-enum-dlg.ps1` | 枚举 `#32770` / BackupRestore 系弹窗的子控件 → `enumdlg.txt` |

踩过的 PowerShell 5.1 陷阱（旧 `br-enum.ps1` 因此 ROOT=0 失灵）：

1. **EnumWindows 回调里不能 `| Out-Null` 管道化 + 提前 `return $false`**：旧脚本两者都占，回调对主窗的匹配静默失效（ROOT=0），但同脚本的 Dump 又能列出顶层窗口，现象自相矛盾、极难排查。可靠模式：回调只往 `ArrayList` `Add` 并恒返回 `$true`，循环内在托管代码侧判定。
2. **`$pid` 是只读自动变量**，`GetWindowThreadProcessId(..., [ref]$pid)` 直接报错，须改名（如 `$wpid`）。
3. **PS 5.1 不支持三元 `? :`**，报「表达式或语句中包含意外的标记"?"」。
4. `powershell -File` 不吃 UNC 路径；脚本要先 `copy` 进 VM 再跑。且 `prlctl exec` 传 UNC 必须**双反斜杠转义**（`\\\\Mac\\…`），单反斜杠会静默失败（返回 0 但没执行）——与 `build-win.sh` 的部署命令同样式。
