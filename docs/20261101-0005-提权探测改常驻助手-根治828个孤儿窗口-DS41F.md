# 提权探测改成常驻助手：根治「每探测一次漏一对终端窗口」

- 时间：2026-11-01 00:05
- 版本：**无改动**（`VERSION` 仍 2.7.3；只动 `tools/gui-check/` 与 `tools/vm/postflight.sh`，零个 `.rs`）
- 性质：工具链根治（上一轮 `docs/20261031-2357` 只做了「漏了能查出来、能清掉」）
- 待办：关闭 `BACKLOG.md` 的 **B-2692**

---

## 1. 病根

`ps/runas.ps1` 原来每量一个窗口就 `Start-Process cmd.exe -Verb RunAs` 提权一次。
Windows 11 的默认终端是 Windows Terminal，每个控制台进程都要**交接**给它托管；
进程退得太快时交接失败，`conhost.exe` + `OpenConsole.exe` 成了一对**没有父进程的孤儿**，
窗口却留在桌面上。一次 GUI 矩阵几百次探测 → 几百个黑窗（实测 828 对）。

## 2. 新结构：一个助手，一套控制台

```
run.sh ──prlctl exec──► runas.ps1（中等权限，只做「递条子」）
                          │ 写 C:\Users\Public\pkg\run\<id>.req
                          ▼
                        helper.ps1（提权，常驻，控制台已隐藏）
                          │ Start-Process powershell -NoNewWindow -Wait
                          │   ↑ 关键：-NoNewWindow 让子进程**继承**助手的控制台，
                          │     不新建控制台 → 没有可漏的东西
                          ▼
                        <id>.out（目标脚本的 stdout，含它自己的 __END__）
```

| 部件 | 职责 | 关键约束 |
| --- | --- | --- |
| `helper.ps1`（新） | 提权启动一次；隐藏自己的控制台；循环读请求、执行、写结果 | 单个请求超时 120 秒就 `Kill`，避免一个卡死的探测把助手拖死 |
| `runas.ps1`（改写） | 确认助手活着（不在就提权拉起它），写请求、150 ms 轮询结果 | 输出契约不变：目标脚本 stdout + `HELPER=resident pid=N` + `__END__` |
| 兜底 | 助手起不来就退回旧的逐次提权 | 打印 `HELPER=fallback`——**功能优先，但让泄漏显式可见** |

为什么不直接 `-WindowStyle Hidden` 糊住旧路径：那只是把窗口藏起来，`conhost` 照样漏，
反而更难发现。宁可漏得看得见，也不要把问题变隐身。

## 4. 修的过程中揪出一个更贵的假绿：同步步骤根本没在同步

改完第一次调用，输出里**没有** `HELPER=resident`，控制台也没多。查虚拟机里的文件：

```
2026/10/31  01:10   1,863  runas.ps1      ← 12 小时前的旧版
（helper.ps1 根本不存在）
```

而 `run.sh` 的同步步骤刚刚打印了 `SYNC_OK`。两个缺陷叠在一起：

1. **路径被 bash 吃掉反斜杠**：`"... ${SHARE}\\tools\\..."` 在双引号里 `\\` 折成 `\`，
   UNC 路径 `\\Mac\backupRestore\...` 变成 `\Mac\backupRestore\...`（驱动器相对路径）——
   源目录根本不存在，robocopy 一句话不说就失败；
2. **判据是 `& echo SYNC_OK`**：`&` 无视前一条命令的成败，**只能证明「命令执行过」**。

后果比窗口泄漏更严重：**整轮矩阵可能跑在旧脚本上**，而同步步骤一路绿。
这和 `preflight` 那条「部署件是不是最新」是同一类病，只不过发生在工具自身。

修法：

```bash
# ① 用单反斜杠拼，拼出来才是真正的 UNC
local src='\\Mac\backupRestore\tools\gui-check\ps'
# ② 判据换成 robocopy 的 errorlevel（0~7 成功、≥8 失败）
robocopy ${src} ${DST} /E ... >nul & if errorlevel 8 (echo SYNC_FAIL) else (echo SYNC_OK)
# ③ 再叠一条**内容比对**：新脚本里必须有只有新版本才有的串
findstr /C:"HELPER=resident" ${DST}\runas.ps1 ... CONTENT_NEW / CONTENT_STALE
```

内容不对就让整轮 `ABORT`（`GUI_CHECK sync=FAIL`）。

## 5. 顺手修掉一个空诊断

`clickenv.ps1` 里 `param([int]$Id = 1007)` 与 `$id = [WindowsIdentity]::GetCurrent()`
**大小写撞车**：PowerShell 参数名不区分大小写，于是 `$id` 被套上 `[int]` 约束，
赋值直接抛 `ArgumentTransformationMetadataException`，`IDENT=` / `ADMIN=` **永远是空**。
改成 `$ButtonId`，现在能正常打出 `IDENT=P8B6\x ADMIN=True`。
