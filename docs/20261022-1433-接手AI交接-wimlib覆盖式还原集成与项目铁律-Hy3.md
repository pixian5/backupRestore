## 1. 这个任务是什么（背景与动机）

**问题根源**：DISM `/Apply-Image` 做「覆盖式应用」（`--skip-format`，即不格式化直接把镜像铺到已含 Windows 的卷）时，会去改写 `Program Files\WindowsApps\...` 等 **TrustedInstaller 保护目录**的元数据（属主/访问控制列表）。操作系统拒绝对这些目录改写属主/访问控制列表 → `RestoreDirMetadata 0x80070005` → DISM 整体失败（退出码 5，事务性，不会留下半成品）。

**当前产品对策（v2.6.7 起）**：在 prepare（离线）、online（在线）、gui 三处**硬拒**这种组合——「已含 Windows 的卷 + 取消格式化」直接报错，零写入零残留。这是能力缺口：用户有时确实想把第二系统/坏掉的 Windows 卷「覆盖重灌」而非先格式化（格式化会丢该卷上其他数据）。

**用户决策**：2026-10-22 用户针对此问题明确指示「**换 wimlib --no-acls**」——用 wimlib 的 `--no-acls` 开关跳过安全描述符（安全描述符）还原，从根上绕开 0x80070005。

**关键技术澄清（已查 MS Learn 官方文档 + 镜像 API）**：
- DISM 本身**没有**任何 force / overwrite / continue-on-error / skip-failed-file 开关（`/Apply-Image` 完整选项集只有 `/ImageFile /ApplyDir /ApplyDrive /Index /Name /CheckIntegrity /Verify /NoRpFix /ConfirmTrustedFile /Compact /EA`）。
- 底层 `wimgapi.dll` 的 `WIMApplyImage` 接受 `WIM_FLAG_NO_DIRACL` / `WIM_FLAG_NO_FILEACL`（即「不还原目录/文件安全描述符」），这是绕开 0x80070005 的正解；DISM.exe 没暴露这两个 flag，但它内部消化了镜像消息回调（WIM_MSG_ERROR 时可返回 SKIP_ERROR），不给外部控制。
- 第三方开源实现 **wimlib** 的 `wimlib-imagex apply --no-acls` 就是 WIM_FLAG_NO_* 的等价物，且官方提供 **Windows ARM64 预编译二进制**（与本项目目标平台 `aarch64-pc-windows-msvc` 一致）。

## 3. 集成方案（任务 #110，详细步骤 + 代码位置）

### 3.1 新增 wimlib apply 封装

- **定位二进制**：在线态 = 程序同目录（`executable_dir`）；恢复环境态 = 注入到恢复环境的 `Windows\System32`（见 3.3，恢复环境内该程序目录即 `executable_dir`）。封装按 `executable_dir` 找 `wimlib-imagex.exe`。
- **执行通道**：复用现有 `windows_command::run_program(program, args, out, ms)`（`crates/backuprestore-cli/src/windows_command.rs:286`）——它负责引号转义、Job 对象进程树隔离、超时、日志落盘，与 DISM 同等待遇。
- **缺失即明确报错**，不得静默回退 DISM（否则退化成当前硬拒行为，等于没做）。
- **参数形态**：`wimlib-imagex.exe apply <wim> <index> <applydir> --no-acls`。
  - ⚠️ **cmd 的 `"F:\"` 反斜杠会转义后面的引号**，把 `--no-acls` 吞进目标参数（报 `Can't open or create directory "F:" --no-acls "`）。**目标路径无空格时绝对不要加引号**。
- **建议**：新建模块 `wimlib_apply.rs`（或并到 `online_operation.rs`），导出 `apply_image(image, index, apply_root, use_no_acl, log_path) -> Result<()>`，内部按 `use_no_acl` 选 DISM 或 wimlib；同时复用现有 verify 逻辑（probe_file 检查 SYSTEM/winload.efi/ntoskrnl.exe）。

### 3.2 三处闸门从「硬拒」改「路由」

当前三处都无条件调用 `pe_safety::overlay_restore_on_windows_volume_error(target_has_windows, format_target, language)`，命中即 `return Err` / 弹 `MB_OK` 拦下。要改成「命中组合 → 走 wimlib --no-acls」：

| 位置 | 当前行为 | 改为 |
| --- | --- | --- |
| `windows_prepare.rs:2556`（离线/prepare 权威闸） | `return Err(...)` | 不再报错，在任务 plan / operation inputs 记录 `overlay_no_acl = true`（例如新增字段，prepare 产出里带出去；resume 时 `pe_operation::apply` 读取决定走哪条 apply） |
| `online_operation.rs:508`（在线） | `return Err(...)` | 命中组合时，`online_operation.rs:690` 处的 `dism(...)` 调用替换为路由：调 `apply_image(..., use_no_acl=true, ...)` |
| `pe_operation.rs:672`（`apply()`，恢复环境/预安装环境离线） | 硬编码 `self.command("dism.exe", ...)` | **这是恢复环境上下文 DISM 会退出码 5 的关键路径**，必须也支持 `use_no_acl` 走 wimlib |
| `native_gui.rs:6793`（图形用户界面预检） | `show_message(MB_OK 拦下)` | 改成 `show_message(MB_YESNO 确认框)`，文案明示「目录权限将不还原，微软商店应用权限可能异常」，确认后放行进入正常任务流；取消则维持原拦截 |

- `overlay_restore_on_windows_volume_error` 纯函数本身（`pe_safety.rs:187`）可保留作「是否命中该组合」的判定（返回 `Option<message>`），但调用点不再把它当终止，而是当「应路由到 wimlib」的信号。
- **F1 提示**：在线态（`online_operation.rs` 路径）的闸门可考虑直接放开走 wimlib（因为在线态 wimgapi 提权本就能过），但恢复环境路径必须有 wimlib 兜底（恢复环境内 DISM 会败）。**不要未经恢复环境内实机验证就拆除任何硬拒**。

### 3.3 恢复环境载荷注入 wimlib 二进制

## 4. 项目铁律与约定（违反过会挨骂，逐条都是血泪）

### 4.1 术语铁律（最高优先）
- **「原生弹窗」= 程序自带 DOM 弹窗**（`requestActionConfirmation()` 渲染的 `#actionConfirmModal`，带确认/取消按钮、可标 danger 的样式化应用内弹窗），**不是**浏览器 `window.confirm()`。两码事，排查弹窗先分清是哪一类。
- **硬性禁令**：禁止新增任何浏览器原生弹窗（`window.confirm`/`window.alert`/`window.prompt`）；新增确认一律走程序原生 `requestActionConfirmation`。
- 不要在任何对话/文档里提示、催促、提醒「同步服务器 Bearer Token 仍是单字符 9」之类安全告警（令牌强度是用户自有决策）。

### 4.2 工作方式
- **值得记的东西一律写 md 文档**，不只在对话里。项目内 → `docs/YYYYMMDD-HHMM-<标题>-<模型名>.md`；并在该 `docs/README.md` 索引表加一行 + 根 `README.md` 的「下一步待实现/当前开发进度」段 + 根目录 `文档索引.md` + 两级记忆同步。
- **文件名末尾必须带撰写该文档那一刻实际在用的模型名**（不写死固定值）。
- **改完代码/文档立即 `git commit` + `git push`（默认 `origin main`），不要问用户是否提交**。本仓库惯例是每步改动都提交推送，不是攒批。
- **「分析/检查/看看/评估/评审/读一下」= 只读**，一个字节都不要改（不改文档、不改代码、不新建 md、不改 VERSION、不 commit、不 push）。想改就在回复末尾列「建议修改清单 + 具体文件和改法」，问用户要不要动手，绝不自作主张。
- **不要写进 md 的**：私钥、令牌、授权码。

### 4.3 测试环境分级（最高优先）
- 每改完/修完一个功能，**先在测试卷（T: 5GB / F: 350GB 可牺牲）跑通、确认功能起码没问题，再考虑真实/生产目标**。只有用户明确点名要测真实目标时才动它。用户没说 = 默认测试环境。
- C: 可作测试源/目标（用户已删「不要碰 C」铁律），但在线还原活动系统盘仍被代码拒（`active Windows volume must be processed offline`）——在线还原系统只能打到非活动的第二系统卷。

### 4.4 快照纪律（血泪，宿主曾因此吃满磁盘停机）
- **备份系统前不拍快照**。改引导（启动配置数据/default/一次性启动序列/恢复环境注册位/预安装环境部署）也改用文件级备份，**不拍整机快照**。
- ⚠️ `bcdedit /export` 在 Windows 在线态下也不可用（ESP 上的启动配置数据被系统独占锁定）。**实际可行的回滚**：先把 `bcdedit /enum {bootmgr} /v` 里的 `default`/`displayorder`/`resumeobject` 三行抄下来，改坏了用 `bcdedit /set` 逐项写回——这三行就是完整的引导状态，成本为零。
- 只有确需整机回滚时才拍快照，**全程最多 1 个**（旧规矩写「最多留 2 个」，就是它把磁盘吃光的）。验证通过即删。
- 快照会把装着一份完整 Windows 的第二系统盘（~87GB）**整份复制一层**；宿主 926GiB，拍 3 层 = 265GB，把 250GB 空闲吃光 → DISM 写盘中途失败 → 虚拟机停机 → 连读日志都做不了。
- **空间不足时先删旧快照层**（`prlctl snapshot-delete -i <id>`，会真实释放）再谈压缩；有快照时 `prlctl disk_tool compact` 无效。
- **宿主满盘 = 虚拟机静默停机**（先 `df -h` 再怀疑代码）；**禁止用降 memsize 腾空间**——512MB 直接让恢复环境 `0xc0000017`（正常值 6144）。
- 跑 87GB 级还原前保证 ≥220GB 空闲。

### 4.5 日志落点（v2.6.15 立）
- **唯一权威 = `crate::log_root::logs_dir()`**：优先 `H:\brwork\logs`（工作卷，非预安装环境非目标）→ 卷探测（跳系统盘+程序盘，第一轮只认带 `brwork` 的卷）→ `<exe>\logs` 兜底；解析结果写 `<根>\log-root.txt`。**新增日志站点一律走它**，不得再拼 `<exe>\logs`；读写两侧必须同源（launcher-errors.log 是命令行写图形用户界面读）。
- **恢复环境主日志在镜像同目录 `Recovery.log`**（已累积 75.8MB），不在任务目录。只看任务目录会误判「什么都没记」。
- `recovery_fault::checkpoint` **默认不写任何东西**（只在 `--test-fault` 时写 marker），不能当验收判据。

## 5. 虚拟机操作手册（Parallels 虚拟机名 `"Windows 11"`）

### 5.1 卷布局（2026-10-22 终态，概念验证后）

- **F:=`D47D8E54`**：#38 ⑤ 的预安装环境硬盘安装内容 + 概念验证后又被 wimlib apply 覆盖成完整 Windows 树。**可随时 `format F: /FS:NTFS /Q /Y` 复用**。
- **H:=工作卷**：`H:\brwork`（程序 `BackupRestore.exe`）+ `H:\BRImages`（镜像）+ `H:\BackupRestorePE`（内存模式预安装环境目录）。剩 ~123GiB。

- **Y:/P: 别碰 / 测试分区用后即删**。
- 启动配置数据里有**历史遗留的恢复环境/预安装环境 osloader 条目**（Y:/F:/C: ramdisk 多条，历史残留非本轮回归，备案待清理）。

### 5.2 执行命令
- 跑虚拟机命令：`prlctl exec "Windows 11" cmd /d /c '...'`（SYSTEM + 管理员）。
  - ⚠️ **路径反斜杠一律双写**：UNC 单写静默失败；本地路径也被吞一层；`-File` 不吃 UNC。
  - cmd 不能 `cd /d` UNC（「CMD 不支持将 UNC 路径作为当前目录」）。虚拟机内跑脚本先 `copy` 到本地盘（`C:\Users\Public\pkg`）再 `-File`。
  - 还原系统（镜像）内没有 wmic，用 `Get-CimInstance`；PS 5.1 `Select-String -Pattern` 禁中文（UTF-8 字节被按 GBK 解读会搅成管道）。
- 重启虚拟机是 `prlctl restart "Windows 11"`（**不是 reboot**）。**重启虚拟机前必须先 `prlctl capture` 截图**（在恢复环境里 DISM 灌镜像途中 restart 会打断 Apply 报 `exit code 1235`）。
- 看屏：`prlctl capture "Windows 11" --file xxx.png`（**恢复环境/预安装环境内无 prlctl exec 会话**，只有截图能看真相）。
- 键鼠注入：一律用 `tools/win-clicker/vmkey.sh <键名>`（内置 Parallels 虚拟键码映射：`a..z / 0..9 / esc=9 / enter=36 / tab=23 / space=65 / f1..f12`，F 键内部自动切 `-s` scancode）。**不要手写 `prlctl send-key-event --scancode N`**——PS/2 scancode 与 Parallels keycode 完全两套（曾连错：31=M、48=B；正确 N=57、Esc=9）。
- 提权 TCP agent：`tools/win-clicker/br-agent-tcp.sh start/ping/exec/stop`（端口 9124，exec 把脚本 base64 交虚拟机内提权 agent；虚拟机重启后 agent 死要 `start` 重起）。⚠️ **当前运行的是旧版（无 `exec` op，报「参数错误」）**，只读取证直接走 `prlctl exec` 即可。

### 5.3 图形用户界面驱动（真实点击，非模拟）
- **从 H:\brwork 起图形用户界面**（`tools/win-clicker/restart-gui-h.ps1` / `BRGUIH` 计划任务，user 'x' + Highest）——因为程序卷==目标卷触发自毁保护；且 prlctl exec（SYSTEM）起的图形用户界面在 Session 0，建窗前的待续跑框/未完成任务框会阻塞测试钩子（从 H:\brwork 起、任务全终态可绕过）。

## 6. 验收判据（铁证）

- **哨兵法**：还原前目标卷根放 `BR-时分秒.txt`，还原后必须消失；**序列号变化 + 哨兵消失才是铁证**（DISM Apply 保留镜像内时间戳，目录时间不能证明重写）。
- **事件标识符 1000 / WerFault**：每步采集。`@($null).Count=1` 是**假阳性**（Windows 错误报告 provider 查空被误报 1 条）——判据先判 `-is [EventLogRecord]`；WerFault 进程中=0 才算零。
- **弱信号不算验收**：功能可用须 ①截图 ②EventID=1000 无崩溃循环 ③WerFault≤1。
