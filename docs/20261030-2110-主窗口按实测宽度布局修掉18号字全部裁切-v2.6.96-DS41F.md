# 主窗口改成「按实测宽度布局」：18 号字下 8 处裁切全部消失（v2.6.92~2.6.96）

> 模型：DS41F。时间：2026-10-30 21:10。
> 版本：**2.6.96**（BACKLOG B-2691 关闭）。
> 关联：`docs/20261030-2045-100%缩放实测跑通并揪出18号字8处被切-v2.6.91-DS41F.md`

---

## 1. 背景

2.6.91 那轮在 100% 缩放下铺开「字号 × 语言」矩阵，一次露出主窗口 8 处固定宽度被切。
根因不是缩放，而是这些控件的宽度是**按 14 号字估的死值**——2.6.84 的「按实测算宽」
只铺到了设置窗口和两个辅助窗口，主窗口顶栏按钮、右侧小标签、按钮行都还是老写法。

## 2. 做法：宽度跟着文字走

新增一个公共辅助：

```rust
/// 按文字实测给控件定宽：不少于 floor，并在测量值上加 12 px 余量。
unsafe fn fit_width(text: &str, floor: i32) -> i32 {
    (measure_text_width(text) + 12).max(floor)
}
```

然后逐处替换（都带中文注释说明为什么）：

| 位置 | 原写法 | 现写法 |
|---|---|---|
| 顶栏 5 个控件（语言标签 / 设置… / 取消待重启任务 / 备份文件管理… / 查看日志） | 固定 55/90/150/140/120 | `fit_width(ui_text(...), 原值)` |
| 按钮行 4 个（刷新环境 / 读取镜像 / 创建任务 / 刷新任务状态） | 固定 x（20/150/280/410）+ 固定宽 | **顺序排布**：`x += w + 10`，宽度实测 |
| 「保留最近 N 个」标签 + 右侧计数框 | 标签 100 固定 | 标签实测，计数框跟着右移 |
| 「第二系统名称」标签 + 右侧输入框 | 标签 100 固定 | 标签实测，输入框跟着右移 |
| PE 页「PE 目录路径」标签 / 目录输入框 / 浏览按钮 | 110 / 380 固定 / 80 固定 | 标签实测，后两者依次跟随 |
| PE 页浏览按钮的**创建值** | 60 | 96（未激活该页时的初始值） |

★ **顶栏是右对齐链条**，加宽只会把整条链往左推，天然不会压到邻接控件；
**按钮行改成顺序排布**之后，以后再加一个按钮不用重算全排 x 常量。

## 3. 一个绕了两圈的坑：布局期测量拿到的是旧字号

`目标卷（镜像位置）` 这个标签在 18 号字下会折成两行（150 宽装不下 162），
而高度写死 40 → 切掉半行。我先改成「按实测高度」，结果**仍然切**——
因为 `layout_operation` 跑的时机在「字号设置已改、控件字体还没应用」的窗口期，
`measure_text_height` 量到的是**上一号字体**的行数（1 行 → 高度算成 40）。

改法：**不测量，直接按「最坏 2 行 × 当前行距 + 8」算**：

```rust
let label_h = crate::dpi::text_block_height(2, 8).max(40);
```

行距本身跟随字号（`line_height()`），所以与测量时机无关。这是本轮最值得记的一条：
**在布局函数里「按当前文字测量」并不可靠，除非能保证字体已经应用。**

## 4. 验收（100% 缩放，实测）

判据：`dlg-fit.ps1`（单行裁切 / 多行高度）+ `overlap-all.ps1`（两两重叠）。

| 组合 | 修前 | 修后 |
|---|---|---|
| 中文 14 号 | 0 | **0** |
| 英文 14 号 | 0 | **0** |
| 中文 18 号 | 3 | **0** ✅ |
| 英文 18 号 | 8 | **0** ✅ |

四组全部 `OVERLAPS=0`（`MIN_GAP=2`，最紧的一对是 1208/1209，与 100% 下一直以来的值一致），
底边 `FITS`（余 1227）。截图：`v2696-zh18-crop.png`、`v2696-en18-crop.png`，
肉眼可见 `Image path`、`Keep latest N`、`Refresh environment`、`Refresh task status`
都完整、不重叠。

## 5. 剩余与提醒

- **200% 缩放没有重跑**（用户把 VM 切到 100% 了）。不过宽度现在由**文字实测**决定，
  而实测返回的是 96dpi 基准值、`reposition` 统一乘系数，所以两档缩放的**基准宽度相同**；
  200% 下不应回退。要彻底确认，需要把 VM 切回 200% 再跑一遍这四个组合。
- 中间档（125/150/175%）仍未验。
- 判据脚本 `dlg-fit.ps1` 会量到**隐藏控件**（PE 页那个浏览按钮就是这样被抓出来的），
  这属于「宁可多报」的行为，保留。

## 6. 追加（v2.6.97）：铺到其余四个页签，又抓出 2 处

2.6.96 的验收只覆盖了**「备份」一个页签**。补测其余页签（还原 C / 还原数据 /
第二系统 / 安装 PE）后，在「新增第二系统」页又抓出两个问题：

| 问题 | 数值 | 原因 |
|---|---|---|
| `Boot entry name` 标签被切 | 控件 260 / 文字 288（基准 130 / 144） | 固定 130，18 号英文装不下 |
| 「刷新任务状态」压住「重启进入 PE」 | 重叠 **208×56** | 按钮行改成顺序排布后变宽（伸到 486 基准像素），而 PE 那两个按钮仍写死 560 / 710 |

修法：
- 启动项名称标签按实测加宽，右侧输入框跟着右移；
- PE 页两个按钮改成 `buttons_x.max(560)` 接着按钮行末尾排，并用实测宽度。

## 7. 200% 缩放的复验（当初缺的那一半，已补）

用户把虚拟机缩放切回 **200%（DPI 192，DPI 感知探针实测）**后重跑，结果：

| 页签 | 组合 | 裁切 | 重叠 |
|---|---|---|---|
| 备份 | 中文 14 / 英文 14 / 中文 18 / 英文 18 | **0 / 0 / 0 / 0** | 全 0 |
| 还原系统到 C 盘（1102） | 英文 18 | **0** | **0** |
| 还原数据到非 C 盘（1103） | 英文 18 | **0** | **0** |
| 新增第二系统（1104） | 英文 18 / 中文 18 | **0 / 0** | **0 / 0** |
| 安装 PE（1105） | 英文 18 / 中文 18 | **0 / 0** | **0 / 0** |

底边：中文 14 号 `FITS`（余 514，与改动前的基线一致，无回归）。

**结论：宽度改成「文字实测」之后，100% 与 200% 两档缩放都干净。**
中间档（125/150/175%）仍未验——这台 VM 只能在 100 / 200 之间切。

★ 一条可复用的判断：`measure_text_width` 返回的是 96dpi 基准值、`reposition` 统一乘系数，
所以**只要基准宽度对，两档缩放都对**；反过来说，改这类问题时**只需要在任意一档缩放下验基准宽度**，
不必两档都跑（两档都跑是为了确认缩放换算本身没坏，属于另一类风险）。
