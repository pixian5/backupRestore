## 2. 问题的真身：同一份版本流水账有**三个副本**

| 文件 | 位置 | 行数 |
|---|---|---|
| 根 `README.md` | 第 9–100 行 | **92** |
| `文档索引.md` | 第 7–17 行（banner） | **11** |
| `docs/README.md` | 「当前入口」段 | **211** |

三份内容基本同源：都是「当前仓库版本 2.6.62（某时点：①②③…）」+「此前 2.6.6x…」逐版回退。
根源不是哪一次写多了，而是**我自己定的规矩**：

> 旧规则（记在 `MEMORY.md`）：「值得记的写 `docs/…md` **+ 三处索引**（`docs/README.md`、`文档索引.md`、根 `README.md`）」

**「三处索引」= 每写一篇文档，就把同一段摘要往三份文件里各抄一遍。** 今天 9 个版本 → 抄了 27 遍。
所以三份文件一起膨胀，`docs/README.md` 光「当前入口」就 211 行。

## 3. 改法

### 3.1 根 `README.md`（336 → 233 行）

- **第 9–100 行（92 行流水账）→ 1 行**：
  `当前版本 **2.6.62**。每一版的改动与验收判据，见 [`文档索引.md`](./文档索引.md) 顶部「当前与权威」。`
  版本号进位规则（1.7.9 → 1.8.0，满十进位）原样保留——那是规则，不是流水账。
- **§六 文档索引（23 行）→ 7 行**：删掉「首选入口 / 主题导航 / 高频主题入口 7 行表 / 轮次快照说明」，
  只留一句「全部文档的逐份说明与主题导航**只有一处**：`文档索引.md`」+ 三条怎么用它。

### 3.2 `文档索引.md`（479 → 471 行）

- banner 里 11 行逐版流水账 → 1 行：`当前版本：2.6.62（2026-10-26 17:07）。本版改动逐条见下表首行；更早版本见 §一 与 git log。`
- 命名规范保留（它本来就在这儿，`docs/README.md` 那份是复制品）。
- §六 根目录文档两行订正：根 README 的描述从「含【当前开发进度】【下一步待实现】（指向 `docs/20261020-1025`）」——**这句早已过期**——改为「文档入口只有一句指向本文件」；`docs/README.md` 的描述从「主题导航与阅读顺序（比本索引更精简）」改为「只是 `docs/` 的落地页」。

### 3.3 `docs/README.md`（265 → 32 行）

删掉 211 行「当前入口」后，剩下的内容**几乎全是 `文档索引.md` 的复制品**：
主题导航（§一 16 行）、三条判读规则、归档说明、命名规范——`文档索引.md` 全都有，而且更全
（§二 按主题分组有 346 条逐份说明，`docs/README.md` 只有 12 行粗导航）。

所以它现在的唯一独立价值是：**GitHub 浏览 `docs/` 目录时自动渲染的落地页**。
改写成 32 行，四件事：

1. 这是落地页、不是索引，索引只有 `../文档索引.md` 一处；
2. 先查 `经验/`，两者冲突以经验库为准（墓碑清单 `经验/07-墓碑与争议清单.md`）；
3. `docs/` 是**过程文档**、不是权威结论来源，共 341 份顶层 md；
4. 子目录表：`90-archive/round-snapshots/` 80 份 / `90-archive/` 1 / `开发方案/` 12（冻结于 1.7.4）/ `features/` 1（只有模板）/ `decisions`·`discussions` 空。

## 5. 规则修正（这条比改文件重要）

`MEMORY.md` 里那条「**三处索引**」已改为：

> 值得记的写 `docs/YYYYMMDD-HHMM-<标题>-<当前模型名>.md`，**索引只更新 `文档索引.md` 一处**
> （2026-10-26 用户拍板：根 `README.md` 的文档段只有一句指向 `文档索引.md`；`docs/README.md`
> 只是目录落地页，不是索引）。★ 旧约定「三处索引」是病根：它让同一条版本流水账在三份文件里
> 各存一份，一天九版就把三份都撑爆。

以后每轮的「索引」动作从 3 处降到 1 处。附带效果：`文档索引.md` 的头部 banner 不再逐版堆积，
只留当前版本一句——逐版改动本来就在 §一 的表格首行里，那里才是唯一该有摘要的地方。
