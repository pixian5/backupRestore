## 一、PE 作第二系统：preflight 门禁过窄（已修）

### 缺陷

`winre_registration::preflight` 用 `HKLM\SYSTEM\CurrentControlSet\Control\MiniNT` 键
判断"是否在恢复环境"。但**那是纯 WinRE 专属标记，WinPE 没有**。

`pe_operation.rs:768` 在 `bcdboot` **之后**调用 `winre_registration::repair()`，
于是「PE 作第二系统」会走到：

```
格式化目标卷 ✓ → 应用镜像 ✓ → bcdboot ✓ → preflight 拒绝 ✗
```

**目标卷已经毁掉，任务才失败。**

### 修复

改为接受两种合法的恢复环境形态：

| 形态 | 判据 |
|---|---|
| WinRE | `Control\MiniNT` 键存在（纯恢复环境专属） |
| WinPE | `wpeutil.exe` 存在（PE 自带工具） |

附带修正：`wpeutil.exe UpdateBootInfo` 原为无条件调用，但**纯 WinRE 环境没有这个程序**，
`capture_logged` 会因「找不到程序」直接失败。现改为仅在 PE 形态下执行。

### 未验证的边界

**「PE 下 WinRE 注册能否真正成功」未经实机验证。** 本次只放开了门禁，
后续步骤（`reagentc /setreimage` 在 PE 内是否可用、PEFirmwareType 是否为 0x2）
需要真实 PE 环境才能确认。

已知约束（来自 09-27 实测）：**PE 里没有 `reagentc.exe`**（rc=9009），
WinRE 注册修复在环境层面就做不到。因此即使门禁放开，
`winre_registration::repair` 的后续步骤仍可能失败——
**这是下一步需要实机验证并可能继续收敛的点。**

## 二、多 ESP 报错文案与实现不符（已修）

### 缺陷

`esp_identity_without_drive_letter()` 在检出多个含 BCD 的 ESP 时报错：

```
multiple EFI system partitions found (disk 0 partition 1, disk 1 partition 2);
pass --efi-drive to choose one
```

但 **`--efi-drive` 参数从未实现**：
- CLI 帮助里只有 `--test-efi-drive`（开发测试用）
- GUI 侧没有多 ESP 选择界面
- 任务结构里没有 `efi_drive` 字段

用户照着提示操作只会得到「unrecognized option」。

### 修复

改为如实说明现状，不再承诺不存在的参数：

```
检测到多个含 BCD 的 EFI 系统分区（disk 0 partition 1, disk 1 partition 2）；
当前版本尚不支持选择目标 ESP，请避免多 ESP 布局后重试
```

**保持"不猜"的行为不变**——多个 ESP 时选错会把引导写进另一块磁盘的 BCD，
这个保护是正确的，不该为了给出选项而放松。

### 待办（未实现）

真正的多 ESP 支持需要：CLI 参数 + 任务结构字段 + GUI 选择界面。
当前只做了"报错准确化"，**功能缺口仍在**。
