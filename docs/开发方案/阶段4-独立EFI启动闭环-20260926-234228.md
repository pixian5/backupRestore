> **文档性质声明（强制）**：本文件是**待实施的诊断/闭环方案**。当前状态：独立 EFI 首启动**多次诊断均失败于 `0xc0430001`，根因未定**（`development-roadmap-2026-09-26.md:29`）。本文件**不把任何假设写成结论**。

> 基线：`VERSION=1.7.4`。上游：[project-status.md](../project-status.md):86-96、[continuation-handoff.md](../continuation-handoff.md):43、[verification-matrix.md](../verification-matrix.md) 独立 EFI 行。

## 1. 背景与目标

程序已能：在隔离目标上 Apply Windows（`U:`）、用管理员令牌 `bcdboot U:\Windows /s E: /f UEFI /v` 重建独立 EFI `E:` 的 BCD，且 `bcdedit /store E:\EFI\Microsoft\Boot\BCD /enum all /v` 返回 0、默认 loader 的 `device/osdevice` 均为 `partition=U:`。但把独立 EFI 磁盘 `hdd2` 调为首启动后，固件确实尝试启动，却稳定进入 Windows Recovery 并显示 `0xc0430001`，**未进入 `U:`**。

**目标**：在隔离快照中定位根因（跨磁盘 UEFI / Secure Boot / 分区关联 / loader 引用），使独立 EFI 能**实际首启动进入恢复系统**，完成后回归正常 Windows，并恢复 `hdd0` 首启动顺序。`C:` 全程不作为备份源或还原目标。

**边界**：该功能只保留为开发测试；**不作为 V1 发布门槛**（`development-roadmap-2026-09-26.md:87`）。若根因证明是 Parallels 固件限制，应如实记录并保留为已知限制，不用“构建通过”替代。

## 3. 详细改动点

### 3.1 诊断信息采集（不修改产品行为）

**拟新增** `scripts/efi-boot-diagnose.py`（或等价 PowerShell/Rust 子命令），在隔离快照中**只读**采集：

| 类别 | 采集项 | 目的 |
|---|---|---|
| 固件 | Parallels VM 配置中的启动顺序、EFI 模式、Secure Boot 状态 | 确认 `hdd2` 首启动与固件策略 |
| 磁盘/分区 | `diskpart list disk/partition`、`Get-Partition`、GPT 类型 GUID、分区属性（`attribute`）、偏移/大小 | 确认 `E:` 与 `U:` 的 GPT 属性与关联 |
| EFI 分区内容 | `E:\EFI\Microsoft\Boot\bootmgfw.efi`、`E:\EFI\Boot\bootaa64.efi`、`E:\EFI\Microsoft\Boot\BCD` 哈希与版本 | 确认 loader 版本与入口 |
| BCD 引用 | `bcdedit /store E:\EFI\Microsoft\Boot\BCD /enum all /v` 的 `device/osdevice/path/systemroot/winpe/ramdisk` | 确认引用目标与元素完整性 |
| 目标系统 | `U:\Windows\System32\winload.efi` 存在性与哈希、`U:\Windows\System32\config\SYSTEM` | 确认被引导系统完整 |
| Recovery 显示 | `0xc0430001` 出现时的屏幕/日志、固件日志（若可得） | 定位错误来源层（固件 vs bootmgr vs WinRE） |
| 参照组 | 同一 VM 中 `hdd0` 正常 Windows 的 EFI/BCD 结构 | A/B 对照 |

**纪律**：每项采集标注“观察值”，不得把推测写成根因；不得在补证时反复升降级 Parallels（`winre-repair-implementation-plan-2026-09-25.md:42`）。

### 3.2 隔离诊断假设清单（必须逐条可验证/可否定）

以下为**待验证假设**，不是结论。每条需给出“验证方法 + 预期观察 + 否定条件”：

| # | 假设 | 验证方法 | 否定条件 |
|---|---|---|---|
| H1 | 跨磁盘引导：固件从磁盘 2 的 EFI 启动 bootmgfw，但 BCD 指向磁盘 3 的 OS，存在跨磁盘限制 | 把 `U:` 与 `E:` 放到同一磁盘的 A/B 对照实验 | 同磁盘仍失败 |
| H2 | Secure Boot 策略拒绝非签名/不匹配的 loader 或 WinRE 组件 | 采集 Secure Boot 状态 + 临时关闭（仅隔离快照）对照 | 关闭后仍失败 |
| H3 | 独立 EFI 缺少 `U:` 引导所需的附加文件（语言资源、bootstr、字体、BCD-Template） | 与 `hdd0` EFI 内容逐项 diff | diff 后补齐仍失败 |
| H4 | BCD 元素不完整（缺 `winpe`/`systemroot`/`nx`/`detecthal` 或 SDI 引用） | 与 PE 恢复桌面成功案例（`verification-matrix.md` PE 行）对照元素 | 补齐元素仍失败 |
| H5 | 分区关联/属性问题（如 `U:` 缺 `required`/`noautomount` 之外的 GPT 属性，或 EFI 分区未标记） | 对比 `E:` 与正常 ESP 的 GPT 属性 | 属性一致仍失败 |
| H6 | `0xc0430001` 由 WinRE 自身恢复路径触发（而非固件/bootmgr） | 采集错误出现时机与 Recovery 日志 | 错误早于 WinRE 加载 |
| H7 | Parallels 固件对“独立 EFI + 跨磁盘 OS”组合的已知限制 | 查阅 Parallels 文档/版本行为；不同版本对照（不反复升降级） | 找到支持该组合的版本证据 |

**注意**：H2 的“临时关闭 Secure Boot”与 H1 的“同磁盘对照”都会触碰启动项/固件设置，**每条实验前必须新建快照**。

### 3.3 可能的代码调整（仅在诊断指向具体缺口后实施）

**拟新增/调整**（必须由诊断证据触发，不得预先实施）：

| 位置 | 可能的调整 | 触发条件 |
|---|---|---|
| `windows_prepare.rs:1684` `efi_identity()` | 增强 `--test-efi-drive` 的校验与诊断输出 | 需要更精确的 EFI 身份 |
| `main.rs:2418` `find_efi_root()` | 支持显式独立 EFI 根与诊断模式 | 隔离测试需要 |
| BCDBoot 调用（`main.rs` BCDBoot 路径，见 `verify_bcd_target` `:2789`） | 调整 `/s` 目标、`/f UEFI`、必要时 `/d`/`/p` 组合 | 诊断指出引导文件落点问题 |
| 独立 BCD 对象的 SDI/WIM 引用（阶段 2 `task_boot.rs`） | 按诊断结果修正引用 | 阶段 2 机制可用后 |
| 诊断子命令（拟新增） | 只读输出 BCD/EFI/磁盘对照，不写启动项 | 始终 |

**红线**：不得用“把 default 永久改到独立 EFI”或“改共享 `{ramdiskoptions}`”绕过诊断（与阶段 2 约束一致）。

### 3.4 启动顺序与恢复

- 每次实验前记录当前启动顺序；实验后**必须恢复** `hdd0 cdrom0 usb hdd1 hdd2 hdd3`（历史值，实施前重新读取实际值）。
- 若实验导致无法回到正常 Windows，按快照回退，并记录停留位置。

## 6. 安全边界与回滚策略

1. **仅开发测试**：`--test-efi-drive` 只在开发 CLI；普通 GUI 不暴露（`continuation-handoff.md:128` 的令牌边界：`bcdboot` 必须由同一管理员账户经 `Start-Process -Verb RunAs` 启动）。
2. **一实验一快照**：包括关闭 Secure Boot、改启动顺序、改独立 EFI BCD。
3. **恢复启动顺序**：每次实验后恢复 `hdd0` 首启动；失败则按快照回退。
4. **不碰共享对象**：只操作独立 EFI 存储与显式隔离 EFI；不改系统 ESP 的 default/recoverysequence。
5. **`C:` 边界**：全程不把 `C:` 作为备份源或还原目标；只读取其启动配置作对照。
6. **不反复升降级**：补证不通过反复升降级 Parallels 实现；若需版本对照，记录两组完整镜像/BCD/NVRAM/软件版本条件（`winre-repair-implementation-plan-2026-09-25.md:42`）。
7. **不夸大**：隔离 Apply/BCDBoot 成功**不等于**独立 EFI 实际引导成功。

## 8. 风险与依赖

| 风险 | 说明 | 缓解 |
|---|---|---|
| 根因未定 | 多次诊断未收敛 | 逐条假设验证；不预设结论；必要时判定固件限制 |
| 实验影响测试机可启动性 | 改启动顺序/EFI BCD 有风险 | 一实验一快照；立即恢复 `hdd0` |

| 与阶段 2 交叉 | 独立 BCD 对象机制尚在阶段 2 | 阶段 4 排在阶段 2 机制可用后 |
| 投入产出比 | 该功能非 V1 门槛 | 设时间盒；超期即记录已知限制并停止 |
| 历史证据被误用 | 旧快照 ID/任务 ID | 实施前重新读取当前事实，不写死 |

**依赖**：阶段 2 的独立 BCD 对象机制；Parallels VM 快照能力；管理员令牌通道（`continuation-handoff.md:128`）。
