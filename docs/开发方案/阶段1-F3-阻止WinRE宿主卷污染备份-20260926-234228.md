## 1. 背景与目标

现有准备流程会把当前任务的启动入口注入**系统注册的 WinRE**：`prepare_payload` 读取 `R:\Recovery\WindowsRE\Winre.wim`（`windows_prepare.rs:676-683`）→ DISM 挂载 staged 副本 → `inject_winre_payload` 注入 `Recovery.exe`/`task.json`/`RecoveryTask.env`/`winpeshl.ini`（`windows_prepare.rs:698-733`，注入实现见 `winre_payload.rs`）→ 覆盖注册 WIM（`windows_prepare.rs:759-774`）→ `reagentc /boottore`（`:775`）。

若备份的**源卷恰好是注册 WinRE 宿主卷**，那么 `recover_windows` 的 Capture（`main.rs:1939` `/Capture-Image`、`main.rs:1909` `/Append-Image`）会把**已被注入当前任务入口的注册 WIM** 打进镜像；还原后系统会携带旧任务入口/env/可自动续跑记录，形成“被污染”的备份。现有排除规则 `build_capture_exclusions`（`core/lib.rs:1141`）只排除回收站/临时目录/更新缓存/浏览器缓存，**不包含**本项目生成的任务目录、`last-task.json` 或 `Recovery\WindowsRE` 下的注入状态。

**目标（第一段）**：在旧覆盖模式（`legacy-registered-wim`）下，**拒绝**“备份源 = 注册 WinRE 宿主卷”的备份任务，错误码拟新增 `BackupSourceHostsRegisteredWinre`，从而停止继续产生 F3 污染镜像。
**目标（第二段）**：在任务专用 WIM 启动落地后，允许该组合，但必须：Capture 前核对注册 WIM 哈希仍等于准备基线；生成精确的项目路径排除规则；备份验收时从 WIM 内部抽检确认干净。

## 3. 详细改动点

> 标 **（拟新增）** 的为设计意图。第一段与第二段改动分开列出。

### 3.1 第一段：拒绝危险组合（必须与 F1 同批）

**(a) core：`validate_volume_roles`（拟新增，见 F1 方案 3.1c）**

在 F1 的纯校验函数中加入：

```rust
if operation == Operation::Backup
    && source.same_partition(&registered_winre.volume)
    && strategy == RecoveryBootStrategy::LegacyRegisteredWim
{
    return Err(TaskError::BackupSourceHostsRegisteredWinre(
        policy_codes::BACKUP_SOURCE_HOSTS_REGISTERED_WINRE.into()));
}
```

第一段语义（计划 `:130-142` 表格）：

| 条件 | 第一段 | 第二段 |
|---|---|---|
| 备份源 = 注册 WinRE 宿主卷（旧覆盖模式） | **拒绝** | 允许（需干净备份证明） |
| 备份源 = 注册 WinRE 宿主卷（任务专用 WIM） | 不适用 | 允许 |
| 备份源 = 镜像卷 | 拒绝（已有，`windows_prepare.rs:933-935`） | 仍拒绝 |
| probe（不 Capture） | **允许**（不产生镜像；但需保留诊断） | 允许 |

**(b) CLI 准备层：`windows_prepare.rs`**

- `validate_operation_inputs()`（`:927-1013`）的 `Operation::Backup` 分支（`:931-956`）内，拟新增：
  ```rust
  if source.same_partition(&registered_winre.volume) {
      return Err(TaskError::BackupSourceHostsRegisteredWinre(
          policy_codes::BACKUP_SOURCE_HOSTS_REGISTERED_WINRE.into()));
  }
  ```
  需要为函数**拟新增**参数 `registered_winre: &WinreLocation`（与 F1 共用同一参数）。
- 插入点必须在 `prepare_task` 第 587 行 `bcdedit /export` 与 payload 注入之前（当前校验在 439-493，安全）。
- **诊断增强**：拒绝日志必须写出源卷身份、注册 WinRE 卷身份与策略，便于用户理解“为什么不能备份这个卷”。

**(c) CLI 执行层：`main.rs`**

- `recover_windows` 的 `Operation::Backup` 分支（`main.rs:1820` 起）在进入 Capture 前，拟新增执行层二次校验：读取 env 中的 `REGISTERED_WINRE_*` 与策略，若 `source == registeredWinre` 且策略为 `legacy-registered-wim`，则拒绝（防止旧任务绕过准备层）。
- 拒绝时任务进入 `failed`，**不创建 `.partial`、不写 metadata**。

**(d) GUI：`native_gui.rs`**

- 在“备份”模式选择源卷后，若源卷 = 注册 WinRE 宿主卷，显示阻止/警告弹窗，说明“当前启动机制下该卷备份会包含本次任务入口，第一段暂不支持”。
- 参考现有 GUI 阻止逻辑（`continuation-handoff.md:110`）与 `drive_role_description`（`native_gui.rs:1725`）。

### 3.2 第二段：干净备份（阶段 2 落地，本方案给出设计）

**(a) 注册 WIM 基线核对**（计划 `:271`）

- 准备阶段已在 `prepare_payload` 记录 `original_hash`（`windows_prepare.rs:684`）并写入 env `ORIGINAL_WINRE_SHA256`（`:693-696`）。
- **拟新增**：Capture 前（`main.rs` Backup 分支）重新计算注册 WIM 哈希，与基线比较；不一致则停止并重新准备，**不得覆盖外部更新来“恢复一致”**。
- 需要 env 或 task 中持久化 `REGISTERED_WINRE_RELATIVE_DIR`（F1 已拟新增）。

**(b) 项目路径排除规则**（计划 `:273-279`）

**拟新增** core 函数：

```rust
/// 拟新增：在现有缓存排除基础上，追加本项目在源卷内的活动路径排除项。
/// program_root / source_root 均为卷根（如 X:\），路径先转源卷相对路径并校验范围。
pub fn build_project_capture_exclusions(
    source_root: &Path,
    program_root: &Path,
    task_relative_dirs: &[String],
) -> Result<Vec<String>, TaskError>
```

规则：
- 排除程序目录内、确认归本项目所有的 `tasks/`、挂载临时目录、`last-task.json` 等自动续跑入口；
- 路径必须先转换为源卷相对路径并校验范围；
- **只排除明确的项目路径**，不以通配符排除整个用户目录或整个 `Recovery`；
- 程序 EXE、普通用户文件、干净系统 WinRE 保留；
- 程序在卷根时只排除明确生成目录/文件，**禁止把源卷根当作排除项**；
- 排除清单持久化到任务与备份元数据（`capture_exclusions` 字段，F1/阶段 2 schema 已预留）。

调用点：`main.rs:1889` 的 `build_capture_exclusions(&source_path)` 拟改为组合调用，生成最终 `/ConfigFile` 内容。

**(c) WIM 内容抽检**（计划 `:281-289`，验收手段）

**拟新增**离线工具 `scripts/verify-wim-winre-clean.py` 或等价 Rust 子命令，从生成 WIM 的指定 index 提取/只读挂载并核对：
1. 注册位置对应的 WinRE SHA-256 等于备份前干净原件；
2. 该内部 WinRE 不带本次 `RecoveryTask.env`、任务 ID 或项目注入 shell（以原件哈希为主要依据，避免误判 OEM 文件）；
3. 镜像里不存在被排除的本项目活动任务与自动续跑入口；
4. 代表性 Windows 文件、用户 fixture 文件的内容与相对路径完整；元数据、WIM 索引与外部哈希一致；
5. 若既有系统原件本来已被旧项目任务注入，先阻止将其作为“干净基线”。

**(d) `.partial` / append-candidate 原子发布**

沿用现有机制（`main.rs` Backup 分支的 `partial` 与 candidate 逻辑），Capture 失败不得让失败候选覆盖已有有效镜像（计划 `:279`）。

## 6. 安全边界与回滚策略

1. **第一段拒绝点必须在 BCD 导出与 payload 注入之前**（`windows_prepare.rs:587` 之前），否则仍会污染注册 WIM。拒绝后注册 WinRE SHA-256 与 BCD 语义必须不变。
2. **不允许用“Capture 前再恢复原件”替代拒绝**：计划 `:74` 明确该方案不作为最终方案（会引入恢复/重新注入/断电续跑事务，且目标格式化问题仍在）。
3. **第二段放开的前提**：独立任务 WIM 启动已实测可启动 + WIM 内容抽检通过 + 原恢复资产保护（计划 `:136,271-289`）。
4. **不得通配符排除**：`build_project_capture_exclusions` 禁止排除整卷根、整个 `Users`、整个 `Recovery`；路径范围校验失败即拒绝。
5. **回滚**：沿用 `prepare_payload` 的 `restore_registered`（`:759-767`）与 `rollback_boot_request`（`:869`）；第二段若 Capture 失败，保留原 WIM 与 `.partial` 供诊断，不删除已有有效镜像。
6. **快照前置**：实机 W04/W05/W06 前必须建新快照并核验。
