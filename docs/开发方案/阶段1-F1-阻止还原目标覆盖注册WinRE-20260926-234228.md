## 1. 背景与目标

当前 `reagentc /info` 在本测试机报告 WinRE 注册在 `harddisk0\partition4\Recovery\WindowsRE`，而该分区就是 `C:`（普通 GPT Basic Data / NTFS，见 `winre-repair-implementation-plan-2026-09-25.md:25-26`）。若用户选择 `C:` 作为还原目标，现有代码会在格式化 `C:` 后使当前恢复入口（`C:\Recovery\WindowsRE\Winre.wim`）随之消失；`restore_original_winre()` 又依赖把 `original\Winre.wim` 写回注册路径，若该路径所在卷刚被格式化，写回目标目录可能不存在，任务进入失败且机器可能无法再进入 WinRE。

**目标**：在**任何 BCD/WinRE 写入之前**，拒绝“还原目标卷 = 注册 WinRE 宿主卷”的组合，返回可读、可测试的专用错误码 `RestoreTargetHostsRegisteredWinre`；准备层（CLI/GUI）与执行层（WinRE `recover-env`）都必须拒绝，形成双层防线。第一段不改变启动机制，因此该组合**暂时不支持**，需在阶段 2 完成独立启动 + 离线重新注册后才放开。

### 3.2 CLI 准备层：`crates/backuprestore-cli/src/windows_prepare.rs`

**(a) 拟新增注册查询**（替代只返回卷的 `recovery_identity()`）

```rust
/// 拟新增：解析 reagentc /info，返回 WinreLocation。
/// 复用现有 text_parsing 的 lossy 解码与超时/子进程处理；
/// 兼容中文/英文输出，路径规范化后拒绝 ..、ADS、UNC、卷根逃逸、控制字符。
pub(crate) fn query_registered_winre() -> Result<WinreLocation, TaskError>
```

实现要点（对应计划 `:114-123`）：
1. 读 `reagentc /info`（现有 `recovery_identity()` `windows_prepare.rs:1665` 已用 `capture("reagentc.exe", &["/info"])`），解析 `harddisk N\partition M\<剩余目录>`；
2. 用现有 `identity_from_diskpart(disk, partition, 'R')`（`windows_prepare.rs:1754`）取稳定身份；
3. `relative_directory` 取实际剩余目录，**不得硬编码** `\Recovery\WindowsRE`；
4. 核验 `wim_relative_path` 指向的文件存在、大小合理、可读；
5. `hosting_kind` 由 `partition_type_guid` 判定：`de94bba4-…` → `DedicatedRecovery`，否则 `OrdinaryNtfs`；
6. `registration_enabled` 以 `reagentc /info` 的 Enabled/Disabled 为准，不以路径存在代替。

**(b) `prepare_task()` 接入（`windows_prepare.rs:433-634`）**

- 第 479 行：`let recovery = recovery_identity()?;` → 拟改为

- 第 487-493 行：调用 `validate_operation_inputs(...)` 时**拟新增参数** `&registered_winre`，或在其后单独调用 `validate_volume_roles(...)`。

## 6. 安全边界与回滚策略

1. **拒绝时不得有副作用**：`RestoreTargetHostsRegisteredWinre` 必须出现在第 587 行 BCD 导出与 payload 注入之前；拒绝后注册 WinRE SHA-256 与 BCD 语义必须与拒绝前一致。
2. **双层防线**：准备层 + 执行层都校验；执行层校验失败时任务进入 `failed`，不格式化、不写 BCD。
3. **回滚**：第一段沿用现有回滚路径——`prepare_payload` 的 `restore_registered` 闭包（`windows_prepare.rs:759-767`）与 `rollback_boot_request`（`windows_prepare.rs:869`）；BCD 回滚见 `restore_bcd_snapshot`（`main.rs:1657`）。
4. **不放开 F2**：本方案**不**放宽 `windows_prepare.rs:481-483` 的程序同卷判断；该放宽必须与阶段 2 绑定（计划 `:67`）。
5. **快照前置**：实机 W04 前必须建新快照并核验，记录快照 ID、目的、变更范围（`AGENTS.md`）。
6. **`C:` 边界**：W04 只需验证“目标=宿主卷时在业务磁盘写入前被拒”，**不需要真正格式化 `C:`**；不得把拒绝测试变成对 `C:` 的破坏性测试。

## 7. 测试与验收标准

### 7.1 离线测试（代码完成后，先于实机）

| ID | 场景 | 必须断言 |
|---|---|---|
| F1-U01 | `target == registered_winre.volume`（`hostingKind=ordinary-ntfs`） | `validate_volume_roles` 返回 `RestoreTargetHostsRegisteredWinre` |
| F1-U02 | `target == registered_winre.volume`（`hostingKind=dedicated-recovery`） | 同样拒绝（保留分区限制不得因 F2 放宽） |
| F1-U03 | `target != registered_winre.volume` | 通过（不误伤正常目标） |
| F1-U04 | `target == image` 且 `target == registered_winre.volume` | 优先返回 image 冲突或 WinRE 冲突之一，但必须拒绝且错误码稳定 |
| F1-U05 | `operation == Probe` | 不受本规则影响（probe 不格式化） |
| F1-U06 | 历史任务缺 `recoveryBoot` 字段 | 识别为 `legacy-registered-wim`，仍执行 target 校验 |
| F1-U07 | `query_registered_winre` 中文 `reagentc /info` fixture | 正确解析目录，不硬编码 `\Recovery\WindowsRE` |
