> **文档性质声明（强制）**：本文件是**待实施的整理方案**。当前 `tools/`、`docs/` 仍保留大量历史脚本与按日期进度文档，尚未归档。所有“拟新增/拟移动”均为设计意图。
> 归档 = **移动 + 索引**，**不删除**用户文件、系统恢复原件、开发工具链或现有快照（`AGENTS.md`）。

## 1. 背景与目标

仓库内存在大量“一次性”产物与多份按日期的进度文档：

- `tools/` 约 49 项，其中多数是调试/复现脚本（`reproduce-*.ps1`、`enum-*.ps1`、`stress-*.ps1`、`test-write*.ps1`、`dump-*.ps1`、`scan-c-*.ps1` 等），命名相近、用途重叠；
- `docs/` 有 `current-progress-2026-09-09.md`、`current-progress-2026-09-11.md`、`current-progress-2026-09-13.md`、`current-progress-2026-09-15.md`、`current-status-2026-09-16.md`、`project-status.md` 等多份“进度/状态”文档，互相引用；
- 根目录历史上堆积一次性探测脚本（`.gitignore` 已用大量规则忽略，见其“临时验证脚本”段）；
- `docs/README.md` 已声明“当前执行基线”与“历史测试记录不能覆盖当前执行基线”的消歧规则。

**目标**：把历史脚本与旧进度文档**归档到明确目录**，保留可追溯性，同时建立**唯一当前入口**，避免新人/AI 接手时误用历史入口（`development-roadmap-2026-09-26.md:34`）。

## 3. 详细改动点

### 3.1 拟新增 `docs/archive/` 与归档规则

**拟新增** `docs/archive/README.md`，声明：
- 本目录内容为**历史记录**，不代表当前状态；
- 当前唯一入口见 `docs/README.md` 的“当前执行基线”；
- 归档文件保留原文件名（含日期），**不改写历史内容**。

**拟移动**（示例清单，实施前以实际 `ls` 为准）：

| 移动前 | 移动后 | 理由 |
|---|---|---|
| `docs/current-progress-2026-09-09.md` | `docs/archive/` | 历史测试记录 |
| `docs/current-progress-2026-09-11.md` | `docs/archive/` | 历史 |
| `docs/current-progress-2026-09-13.md` | `docs/archive/` | 历史（`README.md` 已声明不能覆盖基线） |
| `docs/current-progress-2026-09-15.md` | `docs/archive/` | 历史 |
| `docs/current-status-2026-09-16.md` | 视情况保留或归档 | 现为“当前执行基线”（`docs/README.md` 指向）；若阶段 1/2 产生新基线，则旧基线归档 |
| `docs/current-progress-2026-09-13.md` 等被引用处 | 同步更新链接 | 大量文档互相引用 |

**关键约束**：移动会**破坏相对链接**。必须：
1. 用 `rg -n "current-progress-2026-09-1[135]|current-status-2026-09-16" docs/` 找出全部引用；
2. 逐处更新为 `archive/...` 或改写为指向当前基线；
3. `git diff --check` 与 Markdown 链接检查通过。

### 3.2 `tools/` 分类与 README

**拟新增** `tools/archive/`（或移动至 `.archive/tools/`）并移入一次性脚本：

| 类别 | 示例 | 处理 |
|---|---|---|
| 复现/调试 | `reproduce-*.ps1`、`stress-*.ps1`、`redraw-test.ps1`、`sendinput-session1.ps1` | 归档 |
| 枚举探测 | `enum-*.ps1`、`dump-*.ps1`、`scan-c-*.ps1`、`dump-partitions.ps1` | 归档 |

**保留原则**：有长期价值、被文档引用、或属于 T2 加固范围的脚本保留；纯一次性调试脚本归档。

### 3.3 根目录已入库脚本评估

`.gitignore` 显式保留了 `build-winre-bcd.cmd`、`click-pe-disk.ps1`、`compare-pq.ps1`、`br-test.json`。需逐项判断：
- 是否仍被文档引用（`rg` 搜索）；
- 是否已被 Rust 实现取代（如 WinRE BCD 操作已由 `windows_prepare.rs` 接管）；
- 若是历史配方，移到 `tools/archive/` 或 `docs/archive/`，并同步 `.gitignore` 的保留段。

### 3.4 唯一当前入口（`docs/README.md` 强化）

**拟修改** `docs/README.md`：
- 顶部明确“当前执行基线”单一文件（如 `docs/project-status.md` 或新的 `docs/CURRENT.md`）；
- 列出**必须按顺序阅读**的少量当前文档；
- 明确“`docs/archive/` 内为历史，不得作为当前依据”；
- 明确“按日期命名的新文档必须被本索引收录，否则视为历史草稿”。

**可选拟新增** `docs/CURRENT.md`：只包含当前版本、当前基线、当前待办入口、本目录各开发方案的指针。**避免与 `project-status.md` 重复内容**，只做指针。

### 3.5 `.gitignore` 收敛

- 归档目录（`docs/archive/`、`tools/archive/`）**应入库**（作为历史可追溯），因此需确认不被 `.gitignore` 的宽通配误伤；
- 清理仅针对**确认属于本项目的旧测试包、测试任务和开发残留**；不删除用户文件、系统恢复镜像、开发工具链或现有快照。

## 6. 安全边界与回滚策略

1. **只移动、不删除**：归档保留全部历史内容与 git 历史；不删除用户文件、系统恢复原件、工具链、现有快照。
2. **不触碰运行时代码**：本工作项不改 `crates/`、`windows/`、构建脚本（除 `.gitignore` 与文档）。
3. **链接完整性**：每批移动后立即修复引用，避免死链提交。
4. **回滚**：`git revert` 或 `git mv` 反向；归档不丢内容。
5. **清理边界**：仅清理确认属于本项目的旧测试包/任务；`.test-artifacts/` 保持忽略。
6. **不升版本**：纯文档/目录整理不影响产品包；不触发版本一致性检查变化。

## 8. 风险与依赖

| 风险 | 说明 | 缓解 |
|---|---|---|
| 移动破坏链接 | 大量文档互相引用 | 每批移动后立即修复 + 死链检查 |
| 误删有价值脚本 | 一次性与长期脚本难辨 | 先归档不删除；README 明确保留/废弃 |
| 归档目录被 `.gitignore` 忽略 | 宽通配可能误伤 | T3-U06 验证；必要时加反否定 |
| 与 T1/T2 冲突 | T2 会改 `tools/vm-snapshot.sh` | T3 与 T2 协调顺序；或 T3 后做 T2 |
| 索引再次漂移 | 新文档未收录 | `docs/README.md` 声明“未收录即历史草稿” |
| 过度整理 | 投入产出比 | 设范围：只归档明确历史项，不做全文重写 |

**依赖**：无技术依赖；依赖对“哪些脚本仍有效”的判断（可结合 `docs/` 引用与 T2 结论）。
