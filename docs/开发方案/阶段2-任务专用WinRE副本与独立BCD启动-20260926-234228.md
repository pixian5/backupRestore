> **文档性质声明（强制）**：本文件是**待实施的代码改动方案**，是本路线图中改动最大、实机依赖最深的一段。当前代码**未修改**：仍使用“覆盖注册 WIM + `reagentc /boottore`”。所有“拟新增”均为设计意图，**不代表已实现**。

> 基线：`VERSION=1.7.4`。上游：[winre-repair-implementation-plan-2026-09-25.md](../winre-repair-implementation-plan-2026-09-25.md) §3/§5/§6/§10、[development-roadmap-2026-09-26.md](../development-roadmap-2026-09-26.md):62-74。

## 1. 背景与目标

阶段 1 只做“拒绝”，无法在“WinRE 位于普通 OS 卷（当前 `C:` 的形态）”时完成系统还原。阶段 2 改用**任务专用的 WinRE WIM + SDI 副本**与**任务独占的一次性 BCD 对象**启动，使：

- 系统注册 WIM 不再被临时覆盖（消除 F3 污染根因）；
- 运行资产（任务 WIM/SDI/原件）可置于**非还原目标卷**；
- 目标 = 原 WinRE 宿主卷的场景，在“独立启动 + 原恢复资产保护 + 离线重新注册”全部通过后才放开；
- F2（程序与 WinRE 同在普通 NTFS 卷时允许合法 probe/backup）随本阶段一并放开。

**硬门槛（计划 `:231-232`）**：独立设备选项对象与 osloader 的具体 `bcdedit` 参数，必须先在**复制的离线 BCD 存储**中完成创建/枚举/删除 PoC；若 CLI 不支持所需对象操作，阶段**停在拒绝状态**，**不得退回共享 `{ramdiskoptions}` 或永久改 default 的捷径**。

## 3. 详细改动点

> 所有标 **（拟新增）** 的均为设计意图。

### 3.1 core 层：数据模型与纯校验（`crates/backuprestore-core/src/lib.rs`）

**(a) 复用 F1 已拟新增的 `WinreLocation` / `RecoveryHostKind` / `RecoveryBootStrategy`**，并补齐阶段 2 字段（计划 `:104-113`）：

| 字段 | 内容 / 约束 |
|---|---|
| `volume` | 现有 `VolumeIdentity`（磁盘/分区 GUID、几何、文件系统、卷身份） |
| `relative_directory` | 从实际注册位置解析，**禁止硬编码** `\Recovery\WindowsRE` |

### 3.2 CLI 新模块：`crates/backuprestore-cli/src/winre_location.rs`（拟新增）

职责（计划 `:114-123,377-378`）：

1. **拟新增** `query_registered_winre()`：读 `reagentc /info`，从设备路径解析磁盘/分区/剩余目录；兼容中英文输出；按磁盘与分区 GUID 获取稳定身份；**盘符只是访问路径**。
2. **拟新增** `resolve_winre_from_bcd()`：交叉核对当前 Windows 的 `recoverysequence`、目标 osloader 的 WIM 与 SDI 引用；**不能拿“第一个大括号 GUID”直接当启动项**（现状 `native_gui.rs::extract_bcd_guid` `:3828` 是粗解析，不可直接复用为权威校验）。
3. 路径规范化后拒绝 `..`、ADS、UNC、卷根逃逸、控制字符及指向预期目录外的重解析点。
4. 核验文件存在、大小、WIM 架构及可读性；未知/禁用/不一致状态在启动修改前明确拒绝。
5. 查询和挂载工具有超时；临时盘符按所有权释放；失败**不继续使用上次缓存**。

> 未覆盖的挂载目录/路径/文件系统必须明确报错并记录实际值，**不能悄悄套默认路径**。

### 3.3 CLI 新模块：`crates/backuprestore-cli/src/task_boot.rs`（拟新增）

**拟新增**函数（计划 `:204`）：

| 函数 | 职责 |
|---|---|
| `prepare_task_boot_plan()` | 分配任务 GUID 与两个预定 BCD 对象 ID，写不可变 `boot-plan.json` |
| `install_task_boot_entries()` | 创建任务独占设备选项与 osloader；每步先记“准备执行”，执行后回读确认 |
| `verify_task_boot_entries()` | 枚举确认对象类型、`device/osdevice`、SDI 路径、`winload.efi`、`systemroot`、`winpe` 等属性及实际文件身份 |
| `arm_task_boot_once()` | 设置只包含本任务 osloader 的一次性请求；回读 GUID 后持久化 `boot-requested` |
| `cleanup_task_boot_entries()` | 对象级差异撤回；不执行全局 `deletevalue bootsequence` |

**重要约束**（计划 `:207-217`）：

- 指向当前系统**实际 ESP** 的 BCD，核验磁盘/分区身份；`--test-efi-drive` 只用于显式隔离测试。
- 为每个任务创建**独占** osloader 与设备选项对象；**不改共享 `{ramdiskoptions}`、既有 WinRE recoverysequence 或正常 Windows 默认项**。
- **不把设备选项对象作为 bootsequence 目标**；目标必须是核验过的 osloader。
- osloader 的 WIM 与其 SDI 引用都指向 `boot/` 下的受保护文件。
- 正常任务不加入永久 `displayorder`，不改变菜单超时；**发现已有其他一次性启动请求时，在覆盖前拒绝并提示冲突**。
- 使用 Rust `Command` **参数数组**调用工具，不用字符串拼接 shell 命令处理路径、菜单名或 GUID。
- `native_gui.rs::install_pe_ramdisk` 会修改共享 `{ramdiskoptions}`，**不能整段挪作**本模块实现；可复用已验证的字节解码与 GUID 解析基础，但独立设备对象创建、对象类型查询、路径回读必须**重新实现并验证**。

### 3.6 任务布局（计划 `:169-186`）

```text
<程序目录>/tasks/<task-id>/
  task.json / status.json / manifest.json
  boot-plan.json                 # 不可变：计划对象 ID、卷身份和卷内路径
  boot-transaction.json          # 可变：每一步已执行/已回滚记录
  payload/                       # Recovery.exe、env、task、内嵌 shell
  boot/Winre.wim                 # 最终用于引导的任务 WIM
  boot/boot.sdi                  # 已验证的独立 SDI 副本
  original/Winre.wim             # 原系统干净 WIM，必须在非还原目标卷
  original/boot.sdi
  original/registration.json     # 语义注册信息、原路径、基线摘要
  original/ReAgent.xml           # 若存在：仅作诊断/同系统回滚，禁止盲目写回新系统
  bcd-before-raw / bcd-before-export
  prepare.log / recovery.log / Recovery-early.log
  cleanup.json / returned-windows.json
```

约束（计划 `:188-190`）：所有任务数据仍在程序目录内；不引入用户填写的 TaskDrive，不自动迁移应用；空间预检按**实际拷贝次数、最大挂载/提交临时空间和安全余量**计算，不能沿用仅“两份 WIM”的固定估算；检测文件系统可启动性、压缩/EFS/BitLocker 访问条件，缺少 SDI 或引导可读性证据就拒绝，**不自动联网下载工具**。

### 3.7 一次性 BCD 启动事务（计划 `:219-232`）

**创建顺序**：
1. 完成所有读校验、空间判断、任务目录创建和 Windows/WinRE 基线记录。
2. 保存当前真实 ESP 的逻辑及原始 BCD 备份；记录已有 `default`/`displayorder`/`bootsequence` 语义状态。
3. 生成任务 GUID 与两个预定 BCD 对象 ID，写不可变 `boot-plan.json`。
4. 从干净系统 WinRE 构造任务副本，注入直接 Rust 启动入口；提交后**重新读取并验证 WIM 内部载荷**。
5. 哈希、env、manifest、任务状态全部持久化。`--no-reboot` **在这里结束**（不创建 BCD 对象、不设 bootsequence、不替换注册 WIM）。
6. 创建任务独占设备选项和 osloader；每步先记录“准备执行”，执行后回读确认并记录完成，**允许崩溃后对账**。
7. 枚举确认对象类型、`device/osdevice`、SDI 路径、`winload.efi`、`systemroot`、`winpe` 等属性及实际文件身份。
8. 确认任务对象创建**没有改坏**正常系统 `default`/`displayorder`/`timeout`/既有 `recoverysequence`。
9. 设置只包含本任务 osloader 的一次性请求；回读 GUID 后持久化 `boot-requested`，最后发出重启。

**启动对象 GUID 先分配并写入不可变计划**，再写任务 env/任务快照/WIM；BCD 创建在哈希固定之后进行，避免事后回写已注入 WIM 的 `task.json`（计划 `:166`）。

### 3.8 回滚、并发与残留（计划 `:234-248`）

| 失败位置 | 处理 |
|---|---|
| 创建任务副本前/中 | 保留错误日志；释放本次挂载；系统注册 WIM、BCD 未被任务修改 |
| 仅创建了设备选项对象 | 根据预定 ID 与属性确认所有权后删除该对象；**不碰同名但不同 ID 的对象** |
| osloader 已创建，未重启 | 删除本任务对象，恢复本任务改变的 bootsequence 部分并回读确认 |
| 设置一次性请求或记录状态失败 | 先撤回本任务请求，核验正常启动引用；**撤回未成功就禁止重启** |
| 清理时出现别人的新启动请求 | **不执行全局 `deletevalue bootsequence`**；保留对方请求并报告冲突 |
| BCDBoot 已修改正常系统项 | 按备份/单系统/第二系统各自预期状态核验；不直接导入旧整库覆盖成功还原后的配置 |
| BCD 损坏且所有权无法判定 | 保留任务与原始备份，停止自动操作，给出明确修复证据和快照回退入口 |

- 用**跨进程锁**限制本程序同时只修改一个系统 BCD；每次关键写入前重新核对外部变更；**锁不能阻止 Windows 更新或其他工具改 BCD**，仅依赖进程锁不足以保证安全。
- 正常清理采取**对象级差异撤回**；原始整库回滚仅适用于已验证允许回滚的失败事务，不作为默认清理手段。

### 3.9 断电恢复入口（计划 `:250-264`）

在独立恢复环境中、**任何目标擦除前**：
1. 再次确认任务启动 WIM、SDI、任务与原件**都不在目标卷**；
2. 在系统 ESP 为**下一次意外启动**预置本任务的一次性请求，并回读验证；**失败则不格式化**；
3. 使用持久化阶段和重试计数避免重复擦除错误目标；每次重新进入后重新核验入口保护；
4. 仅在 Apply、正常 Windows 引导修复、系统 WinRE 注册及收尾均成功后撤销本任务请求，转向正常 Windows；
5. 相同阶段连续无法推进时留在恢复界面展示错误，**不自行无限重启**；目标已擦除时不把“自动回 Windows”当安全退路。

> BCDBoot 和离线 WinRE 注册也可能改变 BCD；调用前后都要核对任务对象和保护请求。工具内部写入期间断电是否保留可用 BCD **必须单独实测**，不能承诺任意指令时刻断电均可恢复。

### 3.10 还原后的系统 WinRE 与收尾

- **目标不包含原 WinRE**（计划 `:293-296`）：Probe/backup/还原其他卷时，系统注册 WIM/SDI/注册关系保持原样；新策略清理函数只核验原始资产、清除任务启动引用、登记待清理文件，**不再无条件调用 `restore_original_winre()`**。
- **目标包含原 WinRE**（计划 `:298-312`）：只有完成以下能力后才放开 F1：
  1. 格式化前把干净 WinRE、实际引用的 SDI、注册语义和必要原件备份到程序任务目录，并再次证明该目录不在目标卷；
  2. 从独立 WIM 执行格式化和 Apply，运行环境不依赖目标卷文件；
  3. 按不可变分区身份重新定位已格式化目标（允许预期卷序列号变化，不允许磁盘/分区被替换）；
  4. 确认目标 Windows 文件存在并取得真实 OS loader GUID，完成 BCDBoot 与目标绑定校验；
  5. 建立受验证的系统 WinRE 目标目录，以临时文件、刷新、原子替换和哈希核对写入干净 WIM/SDI（**不能继续用“父目录不存在就失败”的旧收尾实现**）；
  6. 对还原后的 Windows 重建匹配的 WinRE 注册，而不是盲目覆盖旧 `ReAgent.xml` 或直接复制旧 BCD GUID；
  7. 回读离线注册与 BCD 引用，确认指向目标系统、正确 WIM/SDI 和正确分区；返回 Windows 后再读一次在线 `reagentc /info`。
- **离线注册拟采用** `reagentc` 的离线目标设置与目标 OS GUID 启用能力；具体参数、WinRE 中工具可用性、Windows 10/11 与 ARM64/x64 差异，**必须先在隔离镜像/快照中验证**。此能力未通过时，目标同卷还原**保持拒绝**。
- 恢复镜像 OS 与原系统版本/架构变化时，预检须判断保存的 WinRE 是否适配；**不明确适配的组合拒绝**。

## 6. 安全边界与回滚策略

1. **不改变共享启动状态**：不改共享 `{ramdiskoptions}`、既有 `recoverysequence`、正常 Windows `default`；正常任务不加永久 `displayorder`、不改超时。
2. **不覆盖注册 WIM**：注入只发生在任务 `boot/Winre.wim`；Capture 因此能读取干净系统文件。
3. **对象级清理**：只删除本任务预定 ID 的对象与请求；发现他人请求即冲突并保留。
4. **崩溃可对账**：`boot-transaction.json` 记录每一步“准备执行/已完成/已回滚”；重入时按记录对账。
5. **断电保护**：擦除前预置下一次意外启动请求并回读；失败则不格式化。
6. **成功判定**：数据操作完成但清理失败**不写 `success`**；`success` 表示任务执行与预定清理通过，**不虚构已观察到后续 Windows 启动**；`returned-windows.json` 由下次正常 GUI 启动或测试验收入口写入。
7. **回滚到阶段 1**：阶段 2 若 PoC 或实机失败，保留阶段 1 的拒绝状态；任务与原始备份不删除，给出快照回退入口。
8. **快照**：每次触发完整应用启动变更事务前单独建快照；进入 PE 后新手动动作另建快照；**不复用旧快照**。

### 7.1 离线测试

| ID | 场景 | 必须断言 |
|---|---|---|
| U01 | 真 Recovery/EFI/MSR 与普通 NTFS 承载 WinRE | 分类正确；保留分区限制不随 F2 放宽 |

### 7.3 故障注入

| ID | 注入点 | 必须保持的性质 |
|---|---|---|
| X01 | 任务 WIM/SDI 缺失、哈希不符、架构错误 | 启动前失败，无新的有效启动请求 |
| X02 | BCD 创建设备对象后、osloader 后、bootsequence 后 | 恢复时可对账，不残留未知启动引用，不影响别人 |
| X03 | WinRE 挂载超时/盘符被占/身份被替换 | 不覆盖盘符、不格式化，日志含阶段和身份差异 |
| X04 | Capture 中断、追加候选满盘、原 WinRE 被外部改变 | 原已有镜像不损坏；拒绝把变化当作原始基线 |
| X05 | 目标已擦除、镜像应用中、BCDBoot 前后断电 | 下一次可进入受保护任务环境；阶段续跑不依赖已擦除目标里的程序 |
| X06 | 系统 WinRE 写回/离线注册失败 | 不标 success、不清理恢复入口；可明确重试收尾 |
| X07 | 清理期间出现外部 bootsequence / BCD 更新 | 不删除对方请求、不整库覆盖新配置 |
| X08 | 状态写入、撤回启动请求、重启调用失败 | 持久化结果如实反映；不依赖 Drop 吞错后报成功 |
| X09 | 同一任务同一阶段反复重入 | 有熔断和人工恢复界面，不无限重启；已擦除目标不自动回退坏系统 |

**通过标准**：故障实验的成功标准是**预期安全状态和恢复能力**；不能要求所有故障都出现 `success`，也不能把“写了 failed”当作启动资产已修复。

### 7.4 快照与最小证据

每次手动修改 BCD/默认项/一次性启动/WinRE 注册/PE 或任务引导部署前，创建并核验新快照；每次触发完整启动变更事务前单独建快照。每个场景保留：版本、commit、二进制哈希、VM/客体架构、快照 ID、目的、变更范围；前后 WinRE WIM/SDI 哈希、注册语义、BCD 关键引用、任务 manifest 与最终状态；最小 `prepare.log`/`recovery.log`/早期挂载日志、WIM 内容抽检结果；必要截图与返回 Windows 的启动时间/系统身份记录。证据存 `.test-artifacts/`。

## 8. 风险与依赖

| 风险 | 说明 | 缓解 |
|---|---|---|
| `bcdedit` 不支持独立设备对象 | PoC 可能失败 | 硬门槛：失败即停在拒绝状态，不用共享对象捷径 |
| 实机依赖最深 | 失败可能影响测试机可启动性 | 每次新快照；保留阶段 1 拒绝状态；对象级清理 |
| 断电窗口不可控 | 工具写入期间断电可能损坏 BCD | 单独实测；不能承诺任意时刻可恢复；保留快照/外部介质路径 |
| 离线 WinRE 注册未验证 | `reagentc` 离线能力与 ARM64/x64 差异未知 | 先在隔离镜像/快照验证；未通过保持拒绝 |
| 与 GUI PE 安装冲突 | `install_pe_ramdisk` 改共享对象 | 明确禁止复用；新模块独立实现 |
| 空间预检不足 | 多副本 + 挂载临时空间估算错误 | 按实际拷贝次数计算；不足即拒绝 |
| 历史任务误升级 | 旧任务被新策略自动重启 | `legacy-registered-wim` 隔离 + U05 |
| 与 F1/F3 语义交叉 | 阶段 2 放开 F2/F1 需精确边界 | 由 `validate_volume_roles` 单一来源控制 |

**依赖**：阶段 1 完成；离线 BCD PoC；Windows ARM64/x64 工具链；足够磁盘空间与可回滚快照。
