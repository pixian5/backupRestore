## 1. 背景与目标

测试与部署依赖 Parallels 通道（`prlctl exec`），该通道会间歇性返回 `PrlJob_GetResult / PrlJob_GetRetCode: Invalid argument` 并以 255 退出，与客体命令是否成功无关（本机 GuestTools 报 `state=outdated`，见 `build-win.sh:37-41`）。当前已在 `build-win.sh` 内联重试（`:42-66`），但：

- 重试逻辑**只在 `build-win.sh` 内联**，其他脚本（故障矩阵、诊断、快照流程）无法复用；
- 部署是**直接 `copy /y` 覆盖**目标 EXE（`build-win.sh:76`），SHA 校验发生在复制**之后**（`:81-88`）——若复制中断，客体处于半成品状态，直到校验才发现；
- `tools/vm-snapshot.sh:7` 把 VM ID **硬编码**为 `{caee9cb3-bac7-41e2-85f2-32b3a7369114}`，与其他文档出现的 VM ID 不一致，存在误操作风险；
- 部署清单只校验 EXE，未校验 `winpe-winpeshl.ini`、`VERSION` 等其他包内文件。

**目标**：把测试通道抽象为**可复用、可诊断、可核验**的脚本，部署改为**原子替换 + 清单级校验**，快照工具参数化并支持恢复，降低“半成品状态”和“误操作 VM”的概率。

## 3. 详细改动点

### 3.1 拟新增 `scripts/prl-exec.sh`（通道重试抽象）

```bash
#!/bin/bash
# 拟新增：Parallels exec 通道统一重试封装。
# 用法：scripts/prl-exec.sh <vm-name-or-id> [--current-user] <program> [args...]
# 语义：仅对 "Invalid argument" 抖动重试；其他非零退出原样返回。
# 输出：stdout 为客体命令的 stdout；诊断写 stderr（不污染调用方的数据解析）。
```

要点：
- 复用 `build-win.sh:42-66` 的判定与 `mktemp` stderr 分离；
- 支持 `--attempts N`、`--delay S`、`--quiet`；
- **成功判据**由调用方定义（如 `DEPLOYED` 标记、SHA），重试不得放过真实失败（沿用 `build-win.sh:40-41` 的原则）；
- 退出码：客体退出码透传；连续抖动耗尽返回非零并在 stderr 标注。

### 3.2 拟新增 `scripts/deploy-package.sh`（原子部署 + 清单校验）

```bash
#!/bin/bash
# 拟新增：把构建包原子部署到测试机并做清单级 SHA 校验。
# 用法：scripts/deploy-package.sh <vm> <package-dir>
```

流程（每一步失败即停止，不留半成品）：
1. 在客体创建/清理目标目录（复用 `build-win.sh:75` 的 `taskkill` + `mkdir`）；
2. **先复制到临时名**：`BackupRestore.exe.new`、`Recovery.exe.new`、`winpe-winpeshl.ini.new`、`VERSION.new`；
3. 逐项计算客体 SHA-256，与主机清单比对；
4. **全部通过后**才 `move /y` 原子替换（`.new` → 正式名）；
5. 回读正式名 SHA-256 再校验一次；
6. 输出 `DEPLOYED SHA256=<exe-hash> FILES=<n>` 供调用方断言。

清单来源：`build-manifest.json`（`windows/build-windows.ps1:166-179`）的 `binarySha256` + 各文件哈希。

**注意**：Windows 上可执行文件被占用时替换会失败；部署前必须 `taskkill /f /im BackupRestore.exe /im Recovery.exe`（现有 `build-win.sh:75`），并在替换失败时给出明确提示。

### 3.3 修改 `build-win.sh`

| 位置 | 改动 |
|---|---|
| `:42-66` `prl_exec_retry` | 改为调用 `scripts/prl-exec.sh`（保留函数名作为薄包装，或直接替换调用点） |
| `:68-92` 部署段 | 改为调用 `scripts/deploy-package.sh`；`--deploy` 语义不变 |
| `:81-88` SHA 比对 | 由 `deploy-package.sh` 接管，`build-win.sh` 只断言最终 `DEPLOYED` 标记与哈希 |
| 新增 | 构建后调用 `scripts/verify-pe-runtime.py`（F4 方案）与本脚本无强绑定，可组合 |

**兼容**：保持 `./build-win.sh [--deploy]` 的现有用法与输出标记。

### 3.4 修改 `tools/vm-snapshot.sh`

| 位置 | 改动 |
|---|---|
| `:7` 硬编码 `vm_id` | 拟改为 `BACKUPRESTORE_VM_ID` 环境变量，缺省时报错并提示；**不写死具体 VM** |
| 子命令 | 拟新增 `list`（列出快照与 ID）、`verify <id>`（核验存在）、`restore <id>`（**破坏性**，需 `--yes` 二次确认） |
| 记录 | 继续写 `.test-artifacts/snapshots/<stamp>-<label>.txt`，并记录 VM ID、目的、变更范围 |
| `restore` 安全 | 恢复前打印目标快照与当前状态；要求显式 `--yes`；恢复后核验 VM 状态 |

**红线**：`restore` 会丢弃快照点之后的所有变更（包括用户数据），必须二次确认；不得自动恢复。

### 3.5 拟新增 `scripts/test-channel-check.sh`（通道自检）

- 只读检查：VM 存在、GuestTools 状态、`prlctl exec` 是否可用（`echo` 往返）、共享目录 `X:` 可见性；
- 输出结构化诊断，便于在“抖动”与“真故障”之间区分；
- 不执行任何写入。

### 3.6 部署并发保护

- 拟新增锁文件（如 `.test-artifacts/.deploy.lock`，`flock`）；
- 同一时间只允许一个部署进程，避免两个构建同时替换客体文件；
- 锁超时/残留有明确提示与清理方法。

## 6. 安全边界与回滚策略

1. **部署边界**：只写 `C:\Users\Public\backupRestore-package`；不碰用户文件、系统恢复镜像、开发工具链。
2. **原子性**：临时名 + 校验 + 原子替换；任何一步失败都不覆盖现有可用包。
3. **快照恢复是破坏性操作**：`restore` 必须 `--yes` 且打印目标快照；不得自动执行。
4. **不删现有快照**：清理仅限确认属于本项目的旧测试包/任务；不删除用户快照。
5. **回滚**：脚本改动可 `git revert`；部署失败保留旧包；快照恢复提供回到基线能力。
6. **凭据**：脚本不硬编码 VM ID/路径为唯一真相，改用参数/环境变量，避免误操作其他 VM。

## 8. 风险与依赖

| 风险 | 说明 | 缓解 |
|---|---|---|
| 原子替换在 Windows 上被占用失败 | 进程未退出 | 部署前强制 `taskkill`；失败明确提示 |
| VM ID 参数化后误传 | 可能操作错误 VM | 自检打印 VM 名称/ID 并要求确认 |
| 快照恢复误用 | 破坏性 | `--yes` + 打印目标 + 文档强调 |
| GuestTools outdated | 抖动根因未消除 | 重试 + 自检；不把抖动当成功 |
| 与 build-win.sh 现有行为不一致 | 破坏既有用法 | 保留 `--deploy` 语义与输出标记 |

**依赖**：Parallels CLI 可用；`.test-artifacts/` 已忽略；无产品代码依赖。
