## 1. 背景与目标

阶段 1（F1/F3）和阶段 2（任务专用 WinRE）的改动直接触及 WinRE 注册、BCD 一次性启动与目标格式化。这些改动一旦选错方向，返工成本极高，且失败会影响测试机的可启动性。因此在写第一行代码前，必须先把以下四件事冻结：

1. **两段式边界**：明确第一段（拒绝危险组合 + 统一构建）与第二段（任务专用 WinRE 副本 + 独立一次性 BCD）各自交付什么、哪些能力在第一段仍保持“拒绝”。
2. **任务 schema 版本隔离策略**：新字段（`recoveryBoot` / `registeredWinre` / `captureExclusions`）如何与历史任务共存，历史任务如何被识别并禁止静默续跑。
3. **启动方式技术选型**：确认“任务专用 WIM + SDI + 独立一次性 BCD 对象”是唯一推荐路径，并接受其前置 PoC 门槛。
4. **验收口径**：明确“离线通过 / 交叉编译通过 / 实机通过”三者的边界，禁止外推。

**目标产出**：用户对 `winre-repair-implementation-plan-2026-09-25.md` 第 3~6 节评审通过；明确第一段/第二段可独立交付；确认 `development-roadmap-2026-09-26.md:124-129` 的四个待决策项。

## 3. 详细改动点（本阶段无代码改动，仅冻结以下设计决策）

> 以下为**拟冻结的设计决策**，全部为“拟新增”接口/数据模型，尚未实现。

### 3.1 冻结项 A：两段式交付边界

| 能力 | 第一段（阶段 1） | 第二段（阶段 2 通过验收后） |
|---|---|---|
| 还原目标 = 注册 WinRE 宿主卷 | **拒绝**，错误码拟新增 `RestoreTargetHostsRegisteredWinre` | 仅“独立任务启动 + 原恢复资产保护 + 离线重新注册”均通过才放开 |
| 备份源 = 注册 WinRE 宿主卷 | **旧覆盖模式暂时拒绝**（防 F3） | 独立 WIM 启动 + WIM 内容抽检通过后允许 |
| 程序卷 = 承载 WinRE 的普通 NTFS 卷（F2） | **不单独放宽**（必须与阶段 2 绑定） | 允许 probe/backup；还原另按目标规则校验 |
| 真实保留分区（EFI/MSR/Recovery） | 始终拒绝 | 始终拒绝 |
| 还原目标 = 程序/任务目录卷、镜像卷 | 拒绝 | 仍拒绝，不自动复制程序 |
| 启动机制 | **不变**（仍用注册 WIM 覆盖 + `reagentc /boottore`） | 任务专用 WIM/SDI + 独立一次性 BCD 对象 |

**依据**：`winre-repair-implementation-plan-2026-09-25.md:62-67,130-142`；`development-roadmap-2026-09-26.md:36,60`。

**决策编号映射**：路线图 `:124-129` 的四个待决策项对应总览第 3 节的 **D1~D4**；总览额外列出的 **D5**（阶段 1 中“备份源 = 注册 WinRE 宿主卷”的处理）与 **D6**（F4 是否随阶段 1 一并交付）也由本节冻结项 A 覆盖（分别为“旧覆盖模式暂时拒绝”与“F4 须早于阶段 1 的 Release 产物验收”）。

### 3.2 冻结项 B：任务 schema 版本隔离策略

- 保留现有 `BootMode` 表达“返回已有系统 / 新增第二系统”（`core/lib.rs:226-231`）。
- **拟新增** `RecoveryBootStrategy` 枚举，独立表达恢复入口策略：
  - 新策略值：`task-wim-one-time`；
  - 历史任务缺字段时识别为 `legacy-registered-wim`，**只能按明确旧任务收尾规则处理，禁止默认升级成新策略并自动重启**。
- **拟新增** `Task` 字段：`recovery_boot`、`registered_winre`、`capture_exclusions`（按需），并提升任务 schema 版本（`TASK_VERSION` 从 `1` → 拟新增版本号，具体数值在阶段 2 落地时确定）。
- **拟新增** `PayloadManifest` 摘要字段：任务 WIM、SDI、注册基线、启动计划、排除规则；字段必须注明哈希覆盖对象，避免 manifest 自引用。
- 启动对象 GUID **先分配并写入不可变计划**（`boot-plan.json`），再写任务 env/任务快照/WIM；BCD 创建在哈希固定之后进行，避免事后回写已注入 WIM 的 `task.json`。

**依据**：`winre-repair-implementation-plan-2026-09-25.md:157-167,192-198`。

### 3.3 冻结项 C：启动方式技术选型

| 候选方案 | 结论 | 理由 |
|---|---|---|
| 只加 `target != recovery` | 采纳为第一段保护 | 改动小、立即阻止危险还原；不能完成 C: 布局下的系统还原 |
| 继续覆盖注册 WIM，Capture 前再恢复原件 | **不采纳为最终方案** | 需增加恢复/重新注入/断电续跑事务；目标格式化问题仍存在 |
| 任务专用 WIM + SDI + 独立一次性 BCD | **采纳为第二段方案** | 原始 WinRE 保持干净；运行资产可置于非目标卷 |
| 自动移动程序 / 改分区 / 永久迁移 WinRE | **不采纳** | 违反“程序目录即工作目录”的既定边界，扩大操作范围 |

**依据**：`winre-repair-implementation-plan-2026-09-25.md:69-79`。

**冻结的硬门槛**：独立设备选项对象与 osloader 的具体 `bcdedit` 参数，**必须先在复制的离线 BCD 存储中完成创建/枚举/删除 PoC**，再在新快照中验证启动；若 CLI 不支持所需对象操作，阶段停在拒绝状态，**不得退回共享 `{ramdiskoptions}` 或永久改 default 的捷径**（`winre-repair-implementation-plan-2026-09-25.md:231-232`）。

### 3.4 冻结项 D：验收口径与证据分级

| 级别 | 允许声明 | 禁止外推 |
|---|---|---|
| 离线通过 | `cargo fmt/test/clippy`、`scripts/audit-runtime-boundaries.sh`、PE 导入审计通过 | 不能声明 Windows/WinRE 可运行 |
| 交叉类型检查 | `cargo clippy --target aarch64-pc-windows-msvc` 通过 | 只证明类型检查，不链接、不运行 |
| Windows 构建 | ARM64/x64 实际链接成功、导入表静态 | 不证明 WinRE 启动 |
| 实机通过 | 有 VM 日志、`status.json`、持久化证据、快照 ID | ARM64 不能勾选 x64；probe 不能勾选 Capture/Apply |

**依据**：`winre-repair-implementation-plan-2026-09-25.md:410-462`；`verification-matrix.md` 状态定义段。

## 5. 涉及的外部命令/系统接口

本阶段**不执行**任何系统变更命令。仅在评审时可**只读**采集以下事实（不得修改）：

| 命令 | 用途 | 是否只读 |
|---|---|---|
| `reagentc /info` | 读取 WinRE 注册状态与位置 | 是 |
| `bcdedit /enum all /v` | 读取当前 BCD 语义（default/displayorder/bootsequence） | 是 |
| `bcdedit /store <ESP>\EFI\Microsoft\Boot\BCD /enum all /v` | 读取 EFI 存储 | 是 |
| `Get-Partition` / `diskpart list partition` | 读取分区类型（区分保留分区与普通卷） | 是 |
| `mountvol` / `Get-Volume` | 读取卷 GUID 与挂载点 | 是 |
| `manage-bde -status` | 读取 BitLocker 状态 | 是 |

**红线**：本阶段禁止 `reagentc /boottore`、`bcdedit /set`、`bcdboot`、`diskpart format`、`dism /Apply-Image`、`shutdown /r` 等任何写入/重启命令。
