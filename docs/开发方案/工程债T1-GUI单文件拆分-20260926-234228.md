# 工程债 T1 开发方案：`native_gui.rs` 单文件拆分与 unsafe 收敛

> **文档性质声明（强制）**：本文件是**待实施的重构方案**。当前 `native_gui.rs` **未拆分**（7907 行、97 处 `unsafe`）。本文件为设计意图，不代表已重构。
> 本重构为**零行为变更**；但不改行为仍可能因 Windows-only API 细节引入回归，所以必须实机 GUI 回归；实机操作前按 `AGENTS.md` 建快照。

- 工作项：T1（P2，工程债）

## 1. 背景与目标

`crates/backuprestore-cli/src/native_gui.rs` 是唯一的 Rust Win32 桌面前端，承担窗口过程、控件布局、任务参数组装、PE 桌面、在线执行、系统信息采集、盘符枚举、多语言文案、大量手写 `unsafe` P/Invoke。实测规模：

- 文件 **7907 行**（`wc -l`）；
- `unsafe` 出现 **97 次**；
- 通过 `main.rs:42` `mod native_gui;` 引用；入口为 `native_gui::run()`（`main.rs:283`）与 `native_gui::run_pe_desktop()`（`main.rs:131`）、`native_gui::pe_reboot_standalone()`（`main.rs:151`）。

**目标**：按职责拆分为模块目录，把 `unsafe` 集中到少数 FFI 边界层并补齐 `SAFETY` 注释，降低维护与回归成本；**行为与产物完全不变**（同一二进制、同一 GUI 外观、同一 CLI 行为）。

**风险边界**：Windows-only 错误只在 ARM64 客体暴露，静态检查无法替代实机 GUI 回归。

## 3. 详细改动点

### 3.1 目标模块结构（拟新增目录）

把 `crates/backuprestore-cli/src/native_gui.rs` 改为 `crates/backuprestore-cli/src/native_gui/`，`main.rs:42` 的 `mod native_gui;` **不需要改**（Rust 自动解析 `native_gui/mod.rs`）。

```text

  win32.rs        # 拟新增：FFI 声明、结构体、wide()、句柄封装、SAFETY 注释集中处
  wndproc.rs      # 拟新增：窗口过程、消息循环、布局调度
  controls.rs     # 拟新增：控件创建/排版/显隐（现有 Controls :548 及其使用点）
  state.rs        # 拟新增：State(:570)、PeDesktopState(:585)、状态刷新
  text.rs         # 拟新增：ui_text(:813)/tooltip_text(:671)/operation_display(:1108)/
                  #          operation_hint_key(:1124)/drive_display(:1619)/

  drives.rs       # 拟新增：DriveInfo(:794)/parse_drive_infos(:1873)/discover_drives(:2569)/
                  #          suggested_drive_defaults(:2574)/same_partition_by_gui_identity(:2583)/resolve_drive(:7117)
  tasks.rs        # 拟新增：rust_cli_output(:2110)/create_task 参数组装/run_cmd_to_file(:2875)/
                  #          run_cmd_to_file_timeout(:2881)

  pe.rs           # 拟新增：PE 桌面 UI 与动作、write_pe_exit_log(:5635)/pe_list_volumes(:5901)/
```

> 现有函数/行号来自 v1.7.4；拆分时按实际归属调整，**函数实现逐字搬运**，不在同一提交里改逻辑。

### 3.2 unsafe 收敛策略

- 所有 `extern "system"` 声明、FFI 结构体、裸句柄与 `unsafe { ... }` 调用集中到 `win32.rs`，并以**安全包装函数**暴露（如 `fn show_window(hwnd: Hwnd)` 内部 `unsafe`），把 `unsafe` 从业务模块移除。
- 每个保留的 `unsafe` 块**必须**有 `// SAFETY:` 注释，说明前置条件（句柄有效、指针非空、生命周期）。
- 目标：业务模块（`text/drives/tasks/online/pe/sysinfo`）中 `unsafe` 数量降为 **0**；`win32.rs` 成为唯一 `unsafe` 集中地。

### 3.3 保持不变的契约

| 契约 | 约束 |
|---|---|
| 二进制/入口 | 同一 `backuprestore-cli.exe`；`BackupRestore.exe`/`Recovery.exe` 同源同哈希 |
| 三个公开入口 | `native_gui::run()`（`main.rs:283`）、`run_pe_desktop()`（`:131`）、`pe_reboot_standalone()`（`:151`）签名不变 |
| GUI 外观与行为 | 四标签、字段显隐、详情框尺寸、二次确认、UAC、键盘导航、多语言、单实例收敛均不变 |
| WinRE/WinPE 契约 | `windows/winre-winpeshl.ini`、`windows/winpe-winpeshl.ini` 不被改动；`Assert-ShellContracts`（`windows/build-windows.ps1:14-31`）继续通过 |
| 文案 | 不做任何文案修改（文案改动会污染“零行为变更”判定，另开提交） |

### 3.4 建议的提交切分

按“可编译、可测试”的最小步切分，每步一次中文提交：

1. `native_gui.rs` → `native_gui/mod.rs`（仅移动，`git mv` + 路径调整）；`cargo clippy --target aarch64-pc-windows-msvc` 通过。
2. 抽 `text.rs`（纯函数、无状态）→ 编译通过。
3. 抽 `drives.rs` → 编译通过。
4. 抽 `win32.rs` 并把 `wide()` 等基础 FFI 迁入 → 编译通过。
5. 抽 `controls.rs`/`state.rs`/`wndproc.rs` → 编译通过。
6. 抽 `tasks.rs`/`online.rs` → 编译通过。
7. 抽 `pe.rs`/`sysinfo.rs`/`bcd.rs` → 编译通过。
8. unsafe 收敛最后一轮：`SAFETY` 注释补齐，业务模块 unsafe 归零。
9. 版本 `+0.0.1`，文档同步。

**禁止**：把重构与功能改动混在同一提交；不得借重构“顺手修 bug”（发现的问题另开任务，记入文档）。

## 6. 安全边界与回滚策略

1. **零行为变更**：同一二进制、同源同哈希；不引入新功能、不改文案、不改 BCD/WinRE 契约。
2. **回滚**：纯文件移动与函数搬运，可用单个 `git revert` 回退到重构前；建议按 3.4 的提交切分，便于逐步回退。
3. **实机前快照**：GUI 实机回归前按 `AGENTS.md` 建快照。
4. **不删旧数据**：用户规则允许“先备份旧数据、合理重构”，但本重构不涉及数据迁移。
5. **不借重构修 bug**：发现的问题单独记录并另开任务。
