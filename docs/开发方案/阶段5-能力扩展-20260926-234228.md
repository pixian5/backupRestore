## 1. 背景与目标

`peer-comparison.md:27-33` 列出当前最重要的未覆盖项。本文件把“能力扩展”拆成 8 个可独立立项的子项，每项给出：目标、与现有架构的接入点、拟新增接口/数据结构、外部接口、风险、工作量与前置条件。**用户只需挑选优先级最高的 1~2 项先做**，不必一次全上。

**V1 与扩展的边界（现状）**：

| 能力 | 当前 | 同类成熟工具 | 差距 |
|---|---|---|---|
| 指定分区备份还原 | 已支持任意卷身份；非 C 真实 Capture/Index 2 Apply 已成功 | 整盘/分区/布局/多盘映射 | 无整盘分区表一体化镜像 |
| 增量/差异 | 不在 V1 | 普遍支持 | 每次完整 Capture，空间/时间成本高 |
| 在线一致性 | 依赖离线 WinRE Capture | VSS 快照 | 无在线热备 |
| 镜像格式 | WIM + SHA-256 + metadata | 块镜像、压缩分卷、去重 | 无块级稀疏/去重/分卷/加密 |
| 加密 | BitLocker 开启时拒绝 | 加密镜像 + 密钥托管 | 无镜像加密 |
| 目标容量/身份 | GUID/几何/容量校验 | 缩放/迁移 | 不支持自动调整分区 |
| 驱动/硬件迁移 | 目标必须同语义 NTFS | 异机还原/驱动注入 | 无驱动注入 |
| 网络/云 | 本地绝对路径 | SMB/NFS/S3/云 | 无网络目标 |
| 调度/保留 | 不支持 | 计划任务/保留点/通知 | 只能手动 |
| 恢复粒度 | 整分区 Apply | 文件级浏览/恢复 | 无文件级 |
| 校验/演练 | SHA-256/DISM 校验 | 定期恢复演练 | 缺自动演练 |

（表格来源：`peer-comparison.md:7-21`。）

## 2. 逐项扩展方案

### 2.1 增量/差异备份

**目标**：在完整备份基础上，仅捕获自上次备份以来的变化，降低时间与空间成本。

**接入点/改动**：
- core：`BackupMetadata`（`core/lib.rs:260-287`）拟新增 `chain_root_index`、`parent_index`、`backup_kind: full|incremental|differential`；`ImageSpec`（`:183-197`）拟新增 `chain` 描述。
- CLI：`recover_windows` Backup 分支（`main.rs:1820` 起）需支持新的捕获策略；Apply 分支（`main.rs:2116` 起）需按链应用。
- **关键约束**：WIM 的 `/Append-Image`（`main.rs:1909`）是“同 WIM 多索引”，**不等于增量**；真正的增量需要块级变更跟踪（CBT）或 VSS，或第三方块格式。**不得把 append 索引冒充增量**。
- 还原时必须能定位并校验整条链的哈希与顺序；链不完整即拒绝。

**外部接口**：`dism /Capture-Image`（含 `/Append-Image`）、可能的 `fsutil usn`/CBT、或新增块级读写。

**风险**：链式依赖使断电/回滚复杂度显著上升；与 `.partial` 原子发布、状态机（`core/lib.rs:60-108`）耦合深。

**工作量**：**XL（10~20 人日）**，取决于是否引入块级格式。

**前置条件**：阶段 1~3 稳定；用户确认放弃纯 WIM 格式或接受 WIM append 的“伪增量”限制。

---

### 2.2 VSS 在线一致性

**目标**：在正常 Windows 在线状态（无需进入 WinRE）对运行中的系统卷做一致性快照后 Captue，或为在线数据卷提供应用一致备份。

**接入点/改动**：
- CLI：拟新增模块 `vss_snapshot.rs`，封装 `vssadmin`/`diskshadow` 或 VSS COM API（`IVssBackupComponents`）。
- core：`Task` 拟新增 `capture_source: offline-pe | vss-snapshot`；`BackupMetadata` 增加 `consistency: crash|vss`。
- GUI：在线备份路径（现有 `native_gui.rs::run_online_operation` `:4776` `execute_online`）扩展为可选 VSS。
- 需处理：快照卷盘符分配与释放、快照存储空间、写入者（writer）状态、快照超时。

**外部接口**：`vssadmin list writers/shadowstorage`、`diskshadow` 脚本、VSS API；`dism /Capture-Image` 指向快照卷。

**风险**：VSS writer 失败会阻塞；快照盘符与 WinRE 盘符策略冲突；ARM64 上 VSS 组件可用性需实测；与现有“离线 Capture 更干净”的安全性权衡。

**工作量**：**XL（8~15 人日）**。

**前置条件**：阶段 1~3 稳定；明确“在线热备”与“离线严格一致”的产品取舍。

---

### 2.3 镜像加密 / 分卷 / 去重

**目标**：镜像可加密（口令/密钥托管）、可分包（便于介质/网络传输）、可去重（节省空间）。

**接入点/改动**：
- core：`ImageSpec`/`DestinationSpec`（`:183-206`）拟新增 `encryption`、`volume_split_size`、`dedup` 元数据；`BackupMetadata` 增加对应字段与密钥标识（**不存明文密钥**）。
- CLI：拟新增 `image_codec.rs`，在 DISM 产出 WIM 后做加密/分卷容器包装，或改用支持这些特性的格式。
- **关键约束**：WIM 原生不支持加密；若保持 WIM，需要外层容器（如 AES-GCM 包装 + 分卷），并在 Apply 前解包；这会改变 `.partial`/哈希/SHA-256 链的语义。
- 分卷可先用 DISM `/Split-Image` 评估。
- 去重需要块级索引，成本最高。

**外部接口**：`dism /Split-Image`、可能的 `wimlib-imagex`、加密库（需评估 ARM64 静态链接）。

**风险**：加密密钥丢失即不可恢复；分卷使完整性校验与原子发布复杂化；去重与增量重叠，易重复投入。

**工作量**：加密 **L（5~8 人日）**；分卷 **M（3~5 人日）**；去重 **XL（15+ 人日）**。

**前置条件**：阶段 1~3 稳定；用户确认恢复密钥流程（这是产品级决策）。

---

### 2.4 整盘分区布局备份

**目标**：备份整盘（GPT 表 + EFI/MSR/Recovery + 各数据分区），支持裸机恢复。

**接入点/改动**：
- core：拟新增 `DiskSpec`（磁盘 GUID、扇区大小、分区表、各分区 `VolumeIdentity`）；`Task` 拟新增 `scope: volume | disk`；`TargetSpec` 支持整盘目标与布局重建。
- CLI：拟新增 `disk_layout.rs`；备份 `GPT` 头/表与各分区；还原时重建分区表并逐分区 Apply。
- **关键约束**：现有 `is_reserved_partition`（`:170-178`）禁止 EFI/MSR/Recovery 作为目标；整盘恢复必须重新设计这些规则，且要处理“目标磁盘必须是全新/已擦除”。
- 需要处理 4K 扇区、跨磁盘、隐藏分区、恢复分区大小差异。

**外部接口**：`diskpart`、`Get-Disk`/`Get-Partition`、`dism /Apply-Image`、`bcdboot`、可能的 `sgdisk`/WMI。

**风险**：整盘重建是最高风险操作；一旦目标选错会毁掉其他系统；现有安全模型需要针对性扩展。

**工作量**：**XL（15~25 人日）**。

**前置条件**：阶段 1~3 稳定；独立 EFI/启动闭环（阶段 4）最好先有结论；用户明确接受整盘破坏性授权流程。

---

### 2.5 文件级恢复

**目标**：从 WIM 中浏览/提取单个文件，无需整分区 Apply。

**接入点/改动**：
- CLI：拟新增 `wim_browse.rs`，用 `dism /Mount-Image`（只读）或 `wimlib` 列出/提取；
- GUI：拟新增“浏览镜像”面板与文件树；
- core：`Operation`（`:50-56`）拟新增 `RestoreFiles`；目标为普通目录，**不涉及格式化/BCD/WinRE**。

**外部接口**：`dism /Mount-Image /ReadOnly`、`/Get-ImageInfo`、`/Export-Image`；或 `wimlib-imagex extract`。

**风险**：只读挂载需清理；路径穿越防护（复用 `validate_relative_path` `:666`）；权限与长路径。

**工作量**：**M~L（4~7 人日）**。相对独立、风险低，**是阶段 5 中最适合先做的一项**。

**前置条件**：阶段 1~3 稳定；无 WinRE 依赖（可选在线 GUI 内完成）。

---

### 2.6 调度 / 保留策略

**目标**：定时自动备份、按数量/时间保留、失败通知。

**接入点/改动**：
- GUI/CLI：拟新增 `schedule` 子命令，写 Windows 任务计划程序（`schtasks`）或注册计划任务；
- core：拟新增 `ScheduleSpec`（频率、保留 N 份、通知方式）；`TaskStore::cleanup_terminal_tasks`（`core/lib.rs:1008`）扩展为按策略保留；
- 通知可复用 Bark/邮件（用户级凭据不入库）。

**外部接口**：`schtasks.exe`、`Task Scheduler` COM；通知 HTTP。

**风险**：计划任务与 UAC/管理员令牌交互；自动备份需在无人值守下处理 BitLocker/空间不足；**不得自动进入 WinRE 破坏性流程**（建议只做在线数据卷或提示）。

**工作量**：**M（3~5 人日）**。

**前置条件**：阶段 5 其他项按需；用户确认通知凭据管理方式。

---

### 2.7 异机驱动注入

**目标**：把备份还原到不同硬件时，向离线目标注入启动关键驱动。

**接入点/改动**：
- CLI：拟新增 `driver_inject.rs`，在 Apply 后、BCDBoot 前用 `dism /Image:<target> /Add-Driver /Recurse`；
- core：`Task` 拟新增 `driver_source`（目录/清单）；
- 需要处理 HAL、存储控制器、网络驱动；Win10/11 与 ARM64/x64 差异。

**外部接口**：`dism /Add-Driver`、`pnputil`、驱动签名校验。

**风险**：注入错误驱动会导致目标无法启动；驱动签名/版本不匹配；无法完全自动化验证。

**工作量**：**L（6~10 人日）**。

**前置条件**：整盘/分区恢复稳定；有真实异机测试环境。

---

### 2.8 网络 / 云目标

**目标**：备份到 SMB/NFS/S3 等网络位置，支持断点续传与带宽控制。

**接入点/改动**：
- CLI：拟新增 `remote_target.rs`，抽象本地/远程目的地；`DestinationSpec`（`:199-206`）扩展为 `target_kind`；
- 凭据管理：Windows Credential Manager 或用户配置，**不入库**；
- 传输：分块 + 校验 + 断点续传；与 2.3 分卷天然协同。

**外部接口**：SMB（`net use`/Win32）、S3 SDK、TLS。

**风险**：凭据安全；网络中断与 `.partial` 原子发布；上传大文件前的网络授权规则（`continuation-handoff.md:14`）。

**工作量**：**XL（10~18 人日）**。

**前置条件**：分卷/加密（2.3）优先；用户明确目标协议与凭据策略。

## 3. 实施步骤与顺序（建议）

| 序 | 子项 | 理由 |
|---|---|---|
| 1 | 2.5 文件级恢复 | 风险低、独立、无 WinRE 依赖，最快见效 |
| 2 | 2.6 调度/保留 | 复用现有 cleanup 与在线路径，用户价值直观 |
| 3 | 2.3 加密 + 分卷 | 为网络目标与介质传输铺路 |
| 4 | 2.2 VSS 在线一致性 或 2.1 增量/差异 | 二者在“一致性 vs 空间”上互补，需先做取舍 |
| 5 | 2.8 网络/云目标 | 依赖分卷/加密 |
| 6 | 2.7 异机驱动注入 | 依赖整盘/分区恢复稳定 |
| 7 | 2.4 整盘分区布局备份 | 风险最高，放最后或独立立项 |

**顺序硬约束**：2.8 依赖 2.3；2.1 与 2.2 不建议同时做（架构冲突面大）。

## 5. 安全边界与回滚策略（跨子项）

1. **不改变 V1 默认行为**：所有扩展必须**显式选择**，默认路径保持离线 WinRE + 本地 WIM。
2. **保守的破坏性授权**：整盘/异机/在线热备等高风险评估必须先建快照。
3. **状态机与原子发布复用**：新能力必须接入现有 `Stage`（`core/lib.rs:60-108`）、`.partial`、SHA-256 与清理守卫，不得绕开。
4. **密钥/凭据不入库**：加密密钥、SMB/S3 凭据不得写入仓库或任务 JSON 明文。
5. **网络下载规则**：涉及大文件下载时遵守用户级网络规则（热点逐次授权，`continuation-handoff.md:14`）。
6. **回滚**：每项独立可回滚；失败的扩展不进入默认发布。

## 6. 测试与验收标准

### 6.1 通用门槛

- 每项扩展必须有：离线单测 + Windows 交叉 clippy + 至少一条实机证据（隔离快照）；
- 不得把“格式可生成”当成“可恢复”：必须完成一次真实 Apply → 启动 → 数据核对闭环；
- 不把 ARM64 成功勾选 x64。

### 6.2 逐项关键验收

| 子项 | 关键验收 |
|---|---|
| 2.1 增量 | 完整备份 + N 次增量可还原到指定时间点；链不完整即拒绝 |
| 2.2 VSS | 在线快照期间应用可继续运行；捕获内容与快照点一致；writer 失败有明确错误 |
| 2.3 加密/分卷 | 正确口令可还原；错误口令明确拒绝；分卷缺一即拒绝；密钥丢失流程有文档 |
| 2.4 整盘 | 裸机目标可重建 GPT + 各分区 + 引导；目标磁盘选择有二次确认 |
| 2.5 文件级 | 从 WIM 提取单文件内容与哈希一致；路径穿越被拒 |
| 2.6 调度 | 计划任务按频率触发；保留策略生效；失败通知可达 |
| 2.7 驱动 | 异机目标可启动；错误驱动有拒绝/回滚 |
| 2.8 网络 | 断点续传可恢复；凭据安全；网络失败不破坏已有镜像 |

## 7. 风险与依赖

| 风险 | 说明 | 缓解 |
|---|---|---|
| 范围蔓延 | 8 项全上会拖垮维护 | 只立项 1~2 项；用户决策 |
| 与 V1 稳定性冲突 | 扩展改动核心状态机 | 扩展与默认路径隔离；V1 回归门禁 |
| 格式切换成本 | 加密/去重/增量可能要求放弃纯 WIM | 事先明确格式决策 |
| 恢复密钥/凭据 | 丢失即不可恢复/泄露风险 | 产品级决策 + 不入库 |
| 实机验证成本 | 每项都需真实闭环 | 复用阶段 3 矩阵与快照流程 |

**依赖**：阶段 1~3 稳定；用户明确立项与优先级；必要的新工具链（需遵守网络授权规则）。
