# 20260930-1635-下一步待实现-Gemini

## 一、下一步核心任务规划

在 WinRE 离线无压缩系统盘备份实机端到端全链路完全跑通（v1.9.1）之后，接下来的工作重点将转向恢复还原闭环实机验证及交互细节深度优化：

### 1. 离线 WinRE 还原（Restore）端到端实机验证
- **目标**：验证在 WinRE 下将备份好的 WIM 镜像完整还原回目标卷，并成功修复引导启动。
- **阶段策略**：
  1. **小卷/非系统卷测试先行**：先在独立的测试分区（如 scratch 卷）上执行还原，验证格式化、DISM 应用镜像（`/Apply-Image`）、进度显示、BCD 注册全流程；
  2. **系统卷真实还原**：在宿主机磁盘空间安全（大于 120GB）及用户明确授权的前提下，执行真实系统卷还原验收。

### 2. GUI 与 CLI 性能优化建议（供用户裁定）
- **问题观察**：
  在本次验证中，`wim-info` 命令为了展示镜像的完整信息，会主动对整个数十 GB 的 WIM 文件计算 SHA-256。对于 62GB 的未压缩镜像，这需要耗费 30~40 秒，导致 GUI 读取镜像信息时出现较长等待。
- **优化方案**：
  1. `wim-info` 默认优先读取同目录下的 sidecar 元数据（如 `*.metadata.json`），若存在则毫秒级直接返回；
  2. 为 `wim-info` 增加 `--skip-hash` 快速查看选项，仅在用户需要严格校验或准备恢复时流式计算整包哈希。

### 3. 启动项自检与孤儿清理机制产品化
- 在应用启动时自动检测并清扫因异常掉电或意外终止遗留的孤儿 BCD 条目与载荷暂存目录，进一步增强自愈能力。

### 4. 快照管理纪律保持
- 严格维持 Parallels 虚拟机最近不超过 2 个快照的约束，每次启动项变更前新建并核验快照，及时清理旧快照。
