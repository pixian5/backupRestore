# CLI 代码整洁化与 Clippy 警告归零

> 时点：2026-11-03 15:30
> 适用版本：v2.7.9（改源代码版本号 +0.0.1）
> 涉及模块：`crates/backuprestore-cli/src/{i18n.rs, main.rs, text_parsing.rs, log_root.rs, prepare_plan.rs}`

---

## 一、背景与动机

在完成了两大巨石深度解耦（`native_gui.rs` 与 `main.rs`）以及 0 unwrap 零 panic 改造后，工程代码结构清晰度大幅提升。为进一步追求卓越的 Rust 现代惯用法与零技术债务，本轮对全仓生产代码进行了全方位的静态代码审查（`cargo clippy --all-targets`）。

---

## 二、整洁化改动要点

### 1. `i18n.rs` 与 `main.rs` 重复 dead_code 标注消除
- 消除 `i18n.rs` 内部与 `main.rs` 外部声明的重复 `#![allow(dead_code)]`；
- 在 `main.rs` 中采用 `#[cfg_attr(not(windows), allow(dead_code))]` 精准门控，在非 Windows 宿主（macOS）测试目标下彻底消除警告。

### 2. `text_parsing.rs` 现代化语法收拢
- 利用 Rust 2024 edition 原生支持的 `let-chains`，收拢嵌套的 `if reading { if let Some(...) { ... } }`；
- 消除 `line.contains(&crate::i18n::msg_in(...))` 中的冗余借用。

### 3. `log_root.rs` 排序惯用化
- 将 `found.sort_by(|left, right| right.modified.cmp(&left.modified))` 优化为现代惯用语法 `found.sort_by_key(|entry| std::cmp::Reverse(entry.modified))`。

### 4. `prepare_plan.rs` 条件分支折叠
- 将错误注入预检和工作区重叠校验中的嵌套 `if let` 通过 `let-chains` 优雅扁平化，提升逻辑可读性与分支紧凑度。

---
