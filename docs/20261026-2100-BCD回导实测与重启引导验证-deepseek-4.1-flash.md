**基线 commit**：`6872cbc`

## 1. 用户的原话，以及我上一轮错在哪

> **你肯定要回导啊，要不然你备份了之后，还原之后没法用那不完蛋了吗？你傻逼呀你。**

上一轮我只验证了「**能写出一个 BCD 文件**」，就宣布 `AGENTS.md` 的说法成立。
但备份的目的不是「文件存在」，是「**出事时能把机器救回来**」。没做过回导的备份，
只证明磁盘上多了 503,808 字节，证明不了任何事——**我上一轮把「写出来」当成了「用得上」**。

更糟的是我当时的理由是「`/import` 会覆盖启动存储，不值得为文档订正冒重启风险」。
**这个理由本身就把结论架空了**：如果回导有风险到不敢试，那这份备份就不该被写成「首选手段」。

## 2. 实验设计：不测「有没有报错」，测「值有没有回来」

只跑一次 `/import` 看返回码是不够的——它可能什么都不做却返回 0。所以设计成**可证伪**的：

```
① 导出基线 A（并另导一份独立的 B 作第二保险，再拷一份到宿主作第三保险）
② 记录 /enum all /v 基线（对象数、逐对象内容）
③ 故意改一个已知值：bcdedit /timeout 3        （基线是 10）
④ 确认改动生效：timeout = 3                     ← 证明「当前状态 ≠ 基线」
⑤ bcdedit /import A                             ← 被测动作
⑥ 看值有没有回来：timeout = 10 ?                ← 真判据
⑦ /enum all /v 与基线逐对象比对
⑧ prlctl restart                                ← 终极判据：还能不能开机
```

第 ③④ 步是关键：**先让当前状态偏离基线**，否则「回导后等于基线」可能只是「什么都没变」。

**结论：`bcdedit /export` + `bcdedit /import` 这条链成立，且在重启后依然可用。**

## 4. 三个必须记下来的坑（每个都会让人得出错结论）

### 4.1 ★ 退出码不可靠：同一条 `/import` 报过非 0，但值已正确还原

第一次回导时用 `bcdedit /import A >nul 2>&1 & if errorlevel 1 (echo RC=FAIL)` → 打印 **`RC=FAIL`**，
可 `timeout` 明明已经回到 10。之后重复两次，同样的写法得到 `JUDGE=OK` / `RCEXIT=0`。

我没有停在「大概是偶发」上，而是**用值级判据反证**：值回来了，说明动作生效了。
所以判据必须是 **「值有没有真的回来」**，退出码只作参考。

> 这与项目既有纪律同源：**判据红时先证明读数那一侧对，再怀疑被测对象。**
> 这里的「读数那一侧」就是退出码。

### 4.2 ★ 跨重启不能拿整份 `/enum all` 相等当判据

重启后再枚举，与基线有 **20 行差异**。看着像回导失败，实际全在固件自己身上：

| 有差异的对象 | 数量 | 差异字段 |
|---|---|---|
| `{fwbootmgr}` = `{a5a30fa2-…}` | 1 | `displayorder` 顺序 |
| 固件设备条目（`183260a9` / `183260aa` / `183260ab` / `183260ad` / `68321b05` / `7b9becb0`） | 6 | 仅 `description`（`UEFI Virtual DVD-ROM` / `UEFI Shell` / `No OS found` 的先后被 UEFI 重排） |
| **非固件对象** | **0** | **无** |

**UEFI 每次开机都会重排自己的启动项**，与回导无关。所以正确判据是：
**排除 `{fwbootmgr}`（`{a5a30fa2-…}`）段后逐对象比对**——本次结果是「零差异」。

### 4.3 ★ `bcdedit` 的标签中英混排，`findstr "identifier"` 数不出对象

对象标识那行的标签是「**标识符**」（中文，被 ASCII 过滤后只剩 GUID），
而 `displayorder` / `timeout` / `default` / `resumeobject` 保持英文。

我一开始用 `findstr /c:"identifier"` 数对象，得到 **0**，差点以为「枚举是空的」。
改用 `^-{10,}$` 分隔线计数才拿到 548。**混排标签的坑和「不要 grep 中文文案」是同一类**。

## 6. 安全措施（这次敢测的前提）

1. **两份独立导出**：`bcd-test-A.bcd` / `bcd-test-B.bcd`，各 503,808 字节；
2. **第三份在宿主**：拷到 `.test-artifacts/bcd-test-A.bcd`（已 gitignore），虚拟机侧出任何问题它都还在；
3. **改的是 `timeout`**：10 → 3，纯显示设置、与引导哪一项无关，即使回导失败也能手改回来；
4. **改动前先备份、改动后先确认偏离**，避免「什么都没变也算通过」。

事后清理：虚拟机侧 `bcd-test-*.bcd` 与各 `bcd-enum-*.txt` 已删；宿主 `.test-artifacts/` 留证。
