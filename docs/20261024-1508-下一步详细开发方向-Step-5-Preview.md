## 3. 候选开发方向（详细设计）

> **D1/D2 的展开设计（函数签名、判据表、日志契约、三层实机剧本）已落库：
> [`20261024-1636-DISM失败自动降级wimlib与错误分类详细设计`](./20261024-1636-DISM失败自动降级wimlib与错误分类详细设计-Step-5-Preview.md)，
> 可照该文直接开工；本节保留方向级论述。**

### D1（P1·首推）：DISM apply 失败 → 自动降级 wimlib 重试

- **动机**：DISM 是格式化还原主力通道（A/B/C 入口都走它），历史实机全过但**无兜底**；
  RE 内 DISM 有 `RestoreDirMetadata 0x80070005` 退出码 5 的真实失败史（正是 #110 的起因）。
  wimlib 通道已产品化（v2.6.25 集成 / v2.6.27 保留 ACL / 两轮端到端），POC E5 证明其自带
  SeRestore/SeBackup 提权。让 DISM 失败时自动降级 wimlib，可把「任务失败」救回「任务成功」。
- **方案**：
  1. `pe_operation::apply` 的 DISM 分支捕获失败 → 若 `locate_wimlib` 两件就位 →
     记 WARN「DISM apply 失败（原因分类），自动降级 wimlib 重试」→ 调 `wimlib_apply::apply_overlay`
     （保留 ACL，不带 `--no-acls`）。`online_operation.rs:699-716` 同步加同款降级（行为一致）。
  2. **边界（写进代码注释）**：仅当 format 已执行（目标卷已空，半成品风险低）或本就是 overlay
     场景才降级；prepare 期/校验期失败不进 apply。缺件镜像的「放行 + 恢复期降级」是 v2.6.23
     既有语义，与本方向判据优先序要分开写清，不得互相覆盖。
  3. 降级判据纯函数化，放 `failure_policy.rs`（跨平台，macOS 单测可锁）。
- **工作量**：中（2 处调用点 + 1 个判据函数 + 单测 + 一轮 VM 实机）。
- **风险**：wimlib 与 DISM 对「已格式化卷」的写入语义差异（DISM 会顺带处理元数据，wimlib 是
  文件树覆盖）→ 验收必须含**人造 DISM 失败现场**（如挂起占用/损坏镜像触发），不能只测happy path。
- **验收**：T: 5 G 卷人造 DISM 失败 → 自动降级 → wimlib 完成 → 任务 success/100 + 哨兵法 +
  序列号判据 + EventID=1000/WerFault 零新增 + 截图。

### D2（P1，与 D1 合并一轮）：apply 失败错误模式分类 + 中文因果

- **动机**：现在失败回执只有退出码/英文 stderr；磁盘满、文件被占用、镜像损坏是三类最常见
  失败，各给一句中文因果 + 处置建议，用户价值直接。也是 D1 降级日志的判据来源。
- **方案**：`failure_policy.rs` 新增纯函数 `classify_apply_failure(stderr, exit_code)
  -> Option<FailureHint>`（磁盘满 / 占用 / 镜像损坏 / 兜底未知），GUI 与 CLI 失败回执统一展示；
  单测锁死各模式。wimlib 与 DISM 两套 stderr 形态都要覆盖（wimlib 行首带计数，参考
  `parse_wimlib_progress` 的教训）。
- **工作量**：小。**风险**：低。**验收**：macOS 单测 + D1 实机时顺带验证真实 stderr 分类正确。

### D3（P0·前置）：宿主空间与镜像治理——✅ **已执行（2026-10-24 16:26，结果超预期）**

- **动机**：宿主 ~13 Gi，而 A/C 入口大回归需 ≥220 Gi；快照 0 层，「删旧快照腾空间」的路子没有。
  **空间不治理，D1 之后的任何大回归都做不了。**
- **方案（只读核查 → 列清单 → 用户确认后执行，遵守「分析=只读」铁律）**：
  1. `prl_disk_tool compact` 虚拟机磁盘（无快照时有效，先看工具帮助再动手）；
  2. `.test-artifacts/` 各轮证据目录大小盘点，>100 MB 的列清单（证据保留边界：任务目录全留，
     但 `.test-artifacts` 里的过程产物可按清单清理）；
  3. H:\BRImages 三份 30–40 GB 镜像保留策略（哪份可删/归档宿主，列表问用户）。
- **工作量**：核查半小时；执行待授权。**风险**：compact 属官方工具操作，执行前抄 BCD 三行 +
  确认 VM 可正常启动。**验收**：`df -h` 前后对比 + VM 重启正常 + 目标镜像仍在。

### D4（P2·产品化）：B6 备份/还原任务目录命名分叉

- **现状**：`online_log.rs` 共用 `BackupRestore-online-*`（10-16 审查记过，改动面大未动）。
- **方案**：按 `operation` 分叉为 `BackupRestore-backup-*` / `BackupRestore-restore-*`；
  **旧目录名必须照常可读**（兼容解析 + 单测锁死），只影响新建。同步文档口径。
- **工作量**：小。**风险**：低（关键是兼容读取）。**验收**：新建两类目录名正确 + 旧目录
  （如 `771b3ee2` 那批）仍能 resume/读取 + 单测。

### D5（P2·流程）：deploy 后最小冒烟套件脚本化

- **动机**：#38-lite 第②步（T: 数据备份 → B 入口在线还原，约 15 分钟）已是成熟步骤，
  固化成 `tools/smoke/` 一键脚本，作为**每次 deploy 的发布门禁**——尤其 D1 改的是 apply 主链，
  之后每次发版都该跑。
- **方案**：把 br-s1.sh 链路（`--tab 0` 备份 → `--tab 2` B 入口还原 → 判据回读：哨兵重现 +
  序列号变化 + success/100 + EventID/WerFault 采集）写成单脚本 + 判据汇总输出。
- **工作量**：中（脚本 + 判据自动化）。**验收**：一键跑完输出三项判据全过的结论行。
