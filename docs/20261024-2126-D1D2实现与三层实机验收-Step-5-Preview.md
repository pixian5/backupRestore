## 1. 实现摘要

### 1.1 D1 降级编排（`wimlib_apply::fallback_after_dism_failure`）

四个 apply 落点全部接线，共用一个编排函数（杜绝「PE 降级了、在线没降级」的分叉）：

| 落点 | 文件 | 接线形态 |
|---|---|---|
| RE 恢复主链 | `main.rs`（recover_windows） | `run_logged` 失败 → fallback |
| PE 链 | `pe_operation.rs` | `command()` 失败 → fallback |
| 在线数据卷分支 | `online_operation.rs:458` | `apply_image_with_fallback` |
| 在线第二系统分支 | `online_operation.rs:756` | `apply_image_with_fallback` |

编排逻辑：分类（纯函数）→ 判据（ImageCorrupt 不降 / wimlib 缺件不降 / 其余含 Unknown 降一次）→ 日志 → **wimlib 以不限制超时重试** → 结果合成（成功=任务继续；双失败=两条中文因果都进回执）。

### 1.2 D2 错误分类（`failure_policy::classify_apply_failure`）

六类因果 + 中文处置建议：AccessDenied / DiskFull / Busy / ImageCorrupt / TimedOut / Unknown。
判据优先序：**TimedOut > AccessDenied > ImageCorrupt > DiskFull > Busy > Unknown**。
分类结果进 `TaskError message` → 在线链 detail → GUI 弹窗直达用户（展示层零改）。

## 2. 三层实机验收（VM「Windows 11」，只动 T:/F: 测试卷，不拍快照）

### 2.1 第一层：损坏镜像 → 判 ImageCorrupt、不降级 ✓

现场：`br-tdata-2629.wim` 副本中段清零 64KB → `corrupt-test.wim`；在线还原到 T:（5G 空卷）。

```
Error: 1392
The file or directory is corrupted and unreadable.
DISM 结果：退出码 1392
[ERROR] DISM apply 失败分类：ImageCorrupt——镜像文件损坏或不完整（校验未通过）。请重新制作备份镜像；同一镜像换任何应用引擎都会失败。
[WARN] 未自动降级：镜像损坏类失败换应用引擎同样会失败，重试无益
```

判据：分类正确 + 明确不降级 + 中文因果完整。

### 2.2 第二层：DISM 超时 → 降级 wimlib 成功 ✓（本特性的核心场景）

现场：`BACKUPRESTORE_DISM_TIMEOUT_SECS=90` + `br-2629-20261023.wim`（37.8 GiB）→ F:（350G 空卷）。

```
DISM 开始（等待上限 90 秒）：[… /Apply-Image … /CheckIntegrity /Verify]
DISM 结果：等待 90000 毫秒超时；进程树确认结束=true
[ERROR] DISM apply 失败分类：TimedOut——应用镜像超过等待上限被终止……
[WARN] DISM apply 失败（……），自动降级 wimlib 重试一次（等待上限：不限制）
wimlib 开始（覆盖式应用，还原安全描述符）：H:\brwork\wimlib-imagex.exe apply H:\BRImages\br-2629-20261023.wim 1 \\?\Volume{f0753766-…}\
Creating files: 658023 of 658023 (100%) done
Extracting file data: 79 GiB …
Done applying WIM image.
wimlib 结果：退出码 0
降级成功：wimlib 完成 apply，任务继续
STEP 3/4 回读目标卷身份；DISM 已执行完整性和应用校验
STEP 4/4 完成在线还原；未执行格式化或系统引导修复
操作完成：命令、回读和副档簿记均已通过
```

耗时：DISM 90s 超时 + wimlib 17 分钟（658023 文件 / 79 GiB）。内容验证：
- `F:\Windows\System32\ntoskrnl.exe`（11.6 MB）、`F:\Windows\System32\config\SYSTEM`（14 MB）均在；
- **`F:\BR-overlay-proof.txt`（还原前放置的镜像外文件）仍在**——overlay 语义铁证：wimlib 覆盖式写入不删镜像外既有文件。

### 2.3 第三层：锁句柄占用（Busy）→ 降级 + 双失败双因果 ✓

现场：PowerShell 以 `FileShare.None` 独占打开 `T:\BR38Data\file1.txt`（镜像内文件），在线还原 br-tdata 到 T:。

最终版（2.6.37）日志：

```
DISM 结果：退出码 32
[ERROR] DISM apply 失败分类：Busy——目标卷正被其它程序占用（文件句柄未释放）。请关闭占用目标卷的程序后重试。
[WARN] DISM apply 失败（……），自动降级 wimlib 重试一次（等待上限：不限制）
[ERROR] Can't open "\\?\Volume{…}\BR38Data\file1.txt" for deletion (perms=10000, flags=1040) (status=c0000043):
ERROR: Exiting with error code 47:
wimlib 结果：退出码 47
自动降级 wimlib 重试仍失败：目标卷正被其它程序占用（文件句柄未释放）。请关闭占用目标卷的程序后重试。
```

**结论（修正设计文档的预期）**：镜像**内**文件被独占锁定时，wimlib 同样写不进去（两个引擎都要重写该文件），救回不成立——实机结果是「双失败 + 两条都正确归因 Busy 的中文因果」。overlay 语义保证的是**镜像外**文件不被碰（第二层已证）；「锁句柄救回」的真实适用范围 = 占用源在镜像外（DISM 因卷级检查失败而 wimlib 不碰该文件的场景）。这一条已写入分类函数文档。

### 2.4 对照组：好镜像 → DISM 直通不降级 ✓

br-tdata 还原到 T:，无任何降级记录，EXIT=0「操作完成」。

## 3. 实机挖出并修复的三个真 bug（2.6.35–2.6.37）

### 3.1 分类被自家日志行污染（2.6.35 修复）——**严重，降级功能几乎全失效**

现象：第三层首跑，DISM 输出 `Error: 32 / The process cannot access the file because it is being used by another process.`（明确 Busy），却被分类为 **ImageCorrupt → 不降级**。

根因：四个接线点的错误文本把**任务日志尾部**一起带进 Err，其中 `[…ISO 时间戳…] DISM 开始：[… /CheckIntegrity …]` 回显行的子串 `integrity` 先于真正的 `being used by another process` 命中 ImageCorrupt 模式。同一污染还会让双失败时 wimlib 的分类被 DISM 阶段的中文因果日志行带偏。

修复：`strip_self_log_lines` 分类前净化——剥掉行首 `[YYYY-MM-DDTHH:MM:SS` 的 append_log 行 + 命令行回显兜底（`/Apply-Image`、`/ImageFile:`、`/CheckIntegrity`、`wimlib-imagex apply`）。4 条回归单测锁死（Busy 不被抢 / 损坏仍识别 / DiskFull+AccessDenied 不污染 / 双失败不被第一次因果污染）。

### 3.2 wimlib 的 NTSTATUS 码无模式覆盖（2.6.36 补）

第三层二跑暴露：wimlib 失败输出 `(status=c0000043)`（STATUS_LOCK_NOT_GRANTED）与 `(status=c0000022)`（STATUS_ACCESS_DENIED），不在任何模式里 → 双失败第二条归 Unknown。修复：Busy 加 `c0000043`/`lock_not_granted`，AccessDenied 加 `c0000022`/`status_access_denied`；单测 `classify_wimlib_ntstatus_lock_not_granted` 用实机原文锁死。

### 3.3 `apply_overlay` 的 Err 不带输出尾部（2.6.37 修复）

第三层三跑仍归 Unknown 的原因：wimlib 真实报错只落在日志文件里，`apply_overlay` 的 Err 只含 `wimlib apply failed: 退出码 47`——classify 拿到空文本。修复：失败时附 `tail_text(log, 8192)`（与在线链 `dism()` 同一契约）。修后第三层四跑：双失败两条因果均正确归因 Busy。
