## 2. 先纠正一个会打错包的坑：mac 产物不是发布版

第一版脚本我从 `target/aarch64-pc-windows-msvc/release/` 取 exe，跑出来一个 3,063,837 字节的包，哈希自洽、能解压、看着完全正常——**但它是错的**。

README §三 写得很清楚（用户 2026-10-15 拍板）：

> 用户 2026-10-15 拍板「编译完全走虚拟机内 Windows」。macOS 侧 `./build-win.sh`
> **不再用于构建/部署发布产物**；仅保留供本地快速确认跨平台代码"没把公共库改崩"
> （`cargo check` 级用途），产物不得部署、不得作为发布版。
> **macOS 的绿灯对 `#[cfg(windows)]` 模块零证明力。**

两个产物对比：

| 来源 | 大小 | 说明 |
|---|---|---|
| macOS 交叉编译 | 3,185,664 字节 | 仅供类型检查，**不是发布版** |
| 虚拟机内原生编译 | 3,194,368 字节 | 唯一发布路径 |

差 8,704 字节，运行时行为可能一致，但**「用哪条路径编出来的」本身就是交付件的一部分**——今天一致不代表以后一致，而一旦不一致（静态 CRT 漏 flag、SDK 版本漂移），症状会是恢复环境里「退出码 0xC0000135、零输出零副作用」这种最难查的形态。

所以脚本改为：**默认只认 `artifacts/windows/BackupRestore-windows-arm64-v<版本>/`**（= 虚拟机内 `X:\artifacts\windows\` 的构建产物目录，宿主可见），找不到就直接报错并打印该跑哪条命令。保留 `--local` 开关，但会打印警告、包名加 `-local` 后缀，明确「不是发布版」。

## 3. 为什么要往原生构建包里再补东西

`windows/build-windows.ps1` 打的是**开发包**，内容是：

```
BackupRestore.exe  Recovery.exe  VCRUNTIME140.dll  VCRUNTIME140_1.dll
winpe-winpeshl.ini  VERSION  build-manifest.json
```

**故意不含 wimlib 两个文件**（`wimlib-imagex.exe` / `libwim-15.dll`）——它们在 `windows/wimlib-aarch64/`，由部署脚本单独拷到 `H:\brwork`。所以直接把这个目录当交付包发出去，**覆盖式还原（`--apply` 走 wimlib 那一路）会失败**，而且失败形态是「运行到一半才报找不到 wimlib」，不是启动就报。

`tools/release/pack-dist.sh` 因此在原生构建包基础上补齐：

| 补什么 | 为什么 |
|---|---|
| `wimlib-imagex.exe` + `libwim-15.dll` | 覆盖式还原通道的必需件，原生包里没有 |
| `USER-GUIDE.md` / `USER-GUIDE.en.md` | 拿到包的人不该再去 clone 仓库找手册 |
| `README.txt`（脚本生成） | 写清这是什么、怎么跑、文件分工、运行前提、**对应哪个 commit 与打包时间** |
| `SHA256SUMS.txt`（脚本生成） | 包内逐个文件哈希，可自行 `certutil -hashfile` 核对 |

`VCRUNTIME140*.dll` 保留（原生构建自己带的）：`+crt-static` 下理论上非必需，但原样带上比替构建脚本做减法安全——少带一个文件的代价是 0xC0000135，多带两个的代价是 300 KB。

配套判据：包内 10 个文件 `shasum -c SHA256SUMS.txt` 全 OK（`VCRUNTIME`/`manifest` 也在清单里，所以是 10 条不是 7 条）。

## 5. 制造它的完整流程（三条命令）

```bash
# 1) 虚拟机内原生构建 + 部署（唯一发布路径，约 10 秒增量）
prlctl exec "Windows 11" --current-user cmd /d /c \
  'powershell -ExecutionPolicy Bypass -File X:\windows\build-windows.ps1 \
    -Architecture arm64 -Deploy -CargoTargetDir H:\br-target'

# 2) 打包（只读上游产物，不编译）
./tools/release/pack-dist.sh

# 3) 复核：包内 exe 的 SHA 与 H:\brwork 的相等
prlctl exec "Windows 11" powershell -NoProfile -Command \
  "(Get-FileHash -Algorithm SHA256 'H:\brwork\BackupRestore.exe').Hash.ToLowerInvariant()"
```

## 6. 顺带清掉一条只在 Windows 构建里出现的告警

虚拟机原生构建报了本机永远看不到的一条：

```
warning: method `samples` is never used
   --> crates\backuprestore-cli\src\capture_heartbeat.rs:118:19
```

`Heartbeat::samples()` 只在**测试**里被断言用；生产路径的 Drop 直接读 `self.samples.load(...)` 本体。macOS 上 `cargo test` 因 `test` cfg 成立而看不见这条告警——又一次印证「本机绿灯对 `cfg(windows)` 与发布 profile 零证明力」。修法：给该方法加 `#[cfg(test)]`。
