## 5. 本轮新发现的环境/代码事实（已写入项目记忆）

1. **`prepare` 的真实参数解析在 `windows_prepare.rs`**（`--skip-format` 在 668 行，
   默认 `format_target=true`，显式跳过才 false）；`main.rs:104` 的 usage 串虽准确，
   但 main.rs 里另有一条**旧在线 CLI 路径** `online_cli`（`--format-target`/`--index`，
   `online_operation::execute`）——**两套解析器并存，别互相抄参数**。`restore-existing`
   = A 入口（目标必须=源=活动卷），`create-secondary` = C 入口（目标必须≠源且非活动）。
2. **交互会话（`--current-user`）未提权**：prepare 读卷身份
   `CreateFileW failed on \\.\H: (error 5)` → prepare 必须走 **SYSTEM 通道**（UNC 输出），
   与 bcdedit 同通道（此前只有 bcdedit 需要，现在 prepare 也需要）。
3. `prlctl exec` 返回 137/SIGTERM 仍是常态；**输出文件常比命令返回晚 5-10 秒落盘**，
   读文件前先 sleep。
4. **任务列表勘误**：#3/#27–#32 共 7 条 pending 是 10-17 v2.6.9 时代的陈旧项，
   实际工作均已在 `d3cc6a6`/`dd49996`/`31c0954` 完成，已全部改 completed；
   剩余真实缺口另建 #38–#41。
