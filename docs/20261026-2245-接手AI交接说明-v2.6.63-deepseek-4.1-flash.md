## 3. 构建 · 部署（唯一路径）

**发布路径唯一 = VM 内 Windows 构建。** mac 的 `./build-win.sh` 产物**不得部署、不得发包**。

```bash
# ① 先杀掉占着 exe 的 GUI（否则部署报 Copy-Item IOException）
prlctl exec "Windows 11" cmd /d /c 'taskkill /im BackupRestore.exe /f'

# ② VM 内原生构建 + 部署（必须带 -CargoTargetDir H:\br-target）
prlctl exec "Windows 11" --current-user cmd /d /c \
  'powershell -ExecutionPolicy Bypass -File X:\windows\build-windows.ps1 -Architecture arm64 -Deploy -CargoTargetDir H:\br-target'

# ③ 期望输出最后一行形如：
#    DEPLOYED SHA256=4f8d9ff2a227e67362b2fca13e399839b0f099a6a68eb8878e0494ce3155a62d

# ④ 起 GUI（session 1 提权桌面）
cd tools/win-clicker && ./br-s1.sh start-gui.ps1
```

**门禁里的硬规矩**：
- `cargo target` 必须在 `H:\br-target`。`X:\target` 是 9p 卷，cargo 删临时目录会报 `os error 87`。
- 编译产物**绝不能放在还原目标卷**上——它会被格式化抹掉。
- 部署后**必须核对二进制哈希**再跑实机，否则你验的是旧 exe。

## 5. 硬约束（违反则结论作废）

1. **判据只认结构化特征**。进 `prlctl` 的串一律 ASCII；判据用 `STEP n/m`、`stage=success`、
   `progress=100`、字节数、SHA256、卷序列号、`--json` 字段。**绝不 grep 中文文案**（i18n 会把它翻译掉）。
2. **「A 等不等于 B」若两侧都由同一台仪器产生，只证明了仪器自洽**。必须叠加一条不同代码路径的绝对判据。
3. **判据红时先证明读数那一侧对**，再怀疑被测对象。「读不到」与「判据不满足」必须在报告里分开；
   通道抽风记 `SKIP`/`ERROR` 并点名，不能记成红判据。
4. **命令退出码不是判据，副作用才是**（`bcdedit /import` 曾报非 0 而值已还原）。
5. **结果文件可疑先 `del` 再跑**：脚本挂死时读回的是上一次的旧文件，看着像「稳定复现的 0」。
6. **补测试的验收标准是变异，不是变绿**：拆掉守卫重跑，看新用例红、老用例仍绿。
7. **「分析 / 检查 / 看看 / 评估 / 评审 / 读一下」= 只读**：一个字节都不改；想改先列清单问用户。
8. **版本号**：改行为 / 新增代码路径 → `+0.0.1`（满十进一）；纯文档 / 纯判据工具 / 结构搬迁 → **不升**，
   但要在提交与文档里写明依据。三处同步：`VERSION` + 两个 `Cargo.toml`，跑 `cargo check` 刷 `Cargo.lock`。
   版本看 **GUI 标题**（`--version` 不被识别）。
9. **索引只更新 `文档索引.md` 一处**。根 `README.md` 的文档段只有一句指针；**`docs/` 下没有 README**。
   相对链接只能指向**已入库**文件（`.gitignore` 里的东西只能写纯文本名）。
10. **改完必须检查成功再停**；每轮 commit + push（中文提交信息），不必问。

## 7. 十个高频坑（每个都真实栽过）

| 症状 | 真因 | 正确做法 |
|---|---|---|
| 「配置没落盘」 | PS 5.1 `Get-Content` 对无 BOM 文件按 **ANSI/GBK** 解码：UTF-8 全角 `）` 末字节 `0x89` 是合法 GBK 首字节 → 吃掉紧跟的 `0x0A`，换行消失且不报错 | 读文本一律 `-Encoding UTF8` 或 `[IO.File]::ReadAllText` |
| 脚本报 0，屏幕明明压着 | 同步 `SendMessage` 发 `BM_CLICK` 遇模态挂起 → 脚本**一字节未写**，`type` 读回上一次的旧文件 | 一律 `PostMessage`；GUI 脚本开头写 `STARTED`、逐段 `Append`；可疑先 `del` |
| `SendMessage` 全被静默拒（`CB_GETCOUNT` 返 0、`GetLastError=5`） | **UIPI**：目标是管理员进程，`--current-user` 只有标准令牌 | 走 SYSTEM 通道借 GUI 自身令牌 `CreateProcessAsUser` 到 session 1（`tools/win-clicker/br-s1.sh`） |
| 拿到空串/0，判据 FAIL | `SendMessageTimeout` 返回值只表示**调用成功与否**，真答案在 `out` 参数 | 读 `out`；`Add-Type` 编译失败是 PS **非终止**错误 → 必须 try/catch 落 `ADDTYPE_ERROR=` |
| 文本框最后一行被切一半 | 断行高按 `tmHeight`(12) 算，实际行距是 **14**（`tmHeight + tmExternalLeading`） | 高度 = 行数 × 14，按**最坏那页**算；更长的靠 `WS_VSCROLL` |
| 「字被切」但改高度后仍被切 | **裁图切了字**：截图裁剪边界落在最后一行中间 | 判「字被切」时裁剪框必须落在控件边框外 |
| `fsutil` 输出肉眼可见、脚本读不到 | GBK 输出让 `grep` 判成二进制，一个字符都不给 | 通道一律 `LC_ALL=C tr -cd '\11\12\40-\176'`；**不能留 `\r`**，否则 `grep -qxF` 永不匹配 |
| 中文文件名链接一片红 | 只替换了 `%20`，没做完整百分号解码 | `urllib.parse.unquote()`（`tools/doc/check-doc-links.py`） |
| 部署报 `Copy-Item IOException` | GUI 还占着 exe | 先 `taskkill /im BackupRestore.exe /f` |
| 五件套全被写进镜像 | RE 内调用 `build_capture_exclusions` 传了 `current_exe`（跨卷暂存）→ 动态项永不生成 | RE 内必须传 `store.root` |

更多同类坑：`经验/05-验收判据与实机测试.md`、`经验/06-开发构建部署.md`、`tools/win-clicker/` 各脚本头注释。
