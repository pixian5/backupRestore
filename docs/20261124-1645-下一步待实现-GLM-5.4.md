## 1. 等用户裁定：缺陷 1（离线数据卷还原走不通）的修法

**问题**：「还原数据到非 C 盘」选离线、进恢复环境，三道确认后报
`restore-existing target must be the active Windows volume`。复核成立，详见
[`20261124-1645-离线数据卷还原缺陷复核`](20261124-1645-离线数据卷还原缺陷复核与备份暂停问题-GLM-5.4.md)。

| 方向 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **一（推荐）** | 准备期接受「数据镜像 → 数据卷」这一种组合 | 能力保留；A 入口（系统还原）的保护原样保留 | 中等：改判据、补单元测试与变异验证、一轮实机验证（要重启进恢复环境） |
| 二 | 界面对数据卷不再提供「进入 Windows RE」，只保留「进入 PE」 | 改动小 | 数据卷的离线还原能力在恢复环境这条路上作废；**PE 通道能否承担数据卷还原没有核实**（界面能为数据卷排队 PE 任务，但 PE 内执行成功与否没有实机记录） |

**推荐方案一，但有一个关键点**：区分「要拦的事故」和「要放行的场景」**必须看镜像**——

- 要拦的事故：用户在 A 入口想还原系统盘，目标却落在数据盘上（**系统镜像** → 数据卷）。
- 要放行的场景：B 入口的数据卷还原（**数据镜像** → 数据卷）。
- 两种情况下目标都是数据卷，所以现成的「目标卷是不是 Windows 卷」判据分不开它们。
- 现成的「镜像是不是完整 Windows」探测（`image_admin.rs` 的 `wim_full_windows_probe`）只对完整 Windows 返回通过、
  对数据镜像直接报错，不能直接拿来当开关——要先把「确认不是完整 Windows」和「探测本身失败」分成两种结果。

**同一轮顺手做**：缺陷 2（目标卷默认选中光驱）、缺陷 3（选择框文案不随「格式化」变化）、给这类「非法任务」拒绝补上错误码
（现在 `error_code` 恒为 `null`）。

## 2. 修「备份时按暂停无效」（已坐实的缺陷，修法二选一）

**现象**：备份进行中按「暂停(P)」或 P 键，按钮翻成「继续(P)」、日志写「将在下一个步骤边界挂起」，
但备份一路跑完并自动重启。实机证据与代码位置见
[`20261124-1645-离线数据卷还原缺陷复核`](20261124-1645-离线数据卷还原缺陷复核与备份暂停问题-GLM-5.4.md) §七。

| 修法 | 含义 | 评价 |
| --- | --- | --- |
| **备份时隐藏或禁用「暂停(P)」按钮，并注明「备份不支持暂停」** | 界面不再给出一个做不到的承诺 | **倾向这个**：改动小，也更诚实。捕获交给 DISM 子进程，本来就没法中途停 |
| 在备份链「捕获结束 → 校验」这个边界加一次暂停检查 | 点了暂停，备份会在捕获结束后停住，按「继续」再走 | 与用户对「暂停」的直觉不一致；恢复环境里的「继续」也要跟着验证 |

## 3. 补实机验证的缺口（只剩一项）

| 缺口 | 怎么补 | 前提 |
| --- | --- | --- |
| **新版上重跑一轮系统盘还原** | 用基线镜像还原 C:，核对哨兵消失、序列号变化、`RESTORE_SELFCHECK` 自检行、启动配置回基线 | 约 12 分钟往返；**会抹掉系统盘上当天的改动**——由用户指定时间；动盘前按规矩做启动配置的文件级备份 |

（原先列在这里的另一项「实机坐实备份时按暂停无效」已经不需要：原样拷出的原始日志显示它早就坐实了，见 §2。）

## 4. 哈希相关的三个小改进（都不是缺陷）

1. 在线备份的校验步也写一行 `backend=` 日志（目前只有恢复环境的备份链写）。
2. 日志里的秒数改成带小数（现在是整数、向下取整）。
3. 给「回落到软件实现」补一条单元测试（「接口中途报错才回落」这一小段分支目前连单元测试都没有覆盖）。

## 5. 没做完的验证（凌晨基线就留下的）

- 把系统还原到非 C 盘（经恢复环境 / 在线）：各需在宿主上临时占用约 83 GB，要先腾空间。
- 装预安装环境（要先用当前二进制重出镜像）、断电矩阵、第二系统启动：属专项。
- 物理机：拿到机器后。

## 6. 测试设施与流程

1. **把「改动-复验对应表」做成脚本**：输入基线标签，输出必须重跑的实机项。这次就派上了用场——
   靠人工对照才发现「改了备份链要重跑还原」这半边欠着。
2. **安全用例门禁第 0 步按用例区分前提**（现在两个夹具缺失会挡住不需要夹具的用例）。
3. **用户主动取消的任务记录原因**（现在错误是空串、错误码是 1）。
4. **不提权运行命令行时明确报「需要管理员」并返回非零**（现在是退出码 0 加误导性的结论）。
5. **副档里补系统版本信息**（现在 `windowsEdition` 等都是 `unknown`，界面显示「版本未知」）。

## 7. 建议的顺序

1. 你裁定缺陷 1 的修法 → 修（连带缺陷 2、3 与错误码）→ 实机验证。
2. 做「备份时按暂停无效」的修复（§2）——它和缺陷 1 的界面改动可以合成一版，实机验证也用同一类备份任务。
3. 你指定一个「可以抹系统盘」的时间，补上系统盘还原（§3）；在做第 1 项的实机验证时顺带做最省事。
4. 三个小改进合成一版。
5. 其余按 §5、§6 排。
