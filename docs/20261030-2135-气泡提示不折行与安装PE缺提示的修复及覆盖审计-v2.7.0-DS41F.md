# 气泡提示：不折行、安装 PE 没提示，以及一次全量覆盖审计（v2.6.98 ~ v2.7.0）

> 模型：DS41F。时间：2026-10-30 21:35。
> 版本：**2.7.0**（本轮三处改动，2.6.98 → 2.6.99 → 2.7.0，见 §5 为什么分三次）。
> 用户反馈：「现在气球只能显示一行，不能自动换行，而且安装 PE 还没有气球，你检查还有其他的没有提示的吗？」

---

## 1. 为什么气球只有一行

`install_tooltips()` 建出提示窗后**从来没给过最大宽度**：

```rust
CreateWindowExW(..., WS_POPUP | TTS_ALWAYSTIP | TTS_NOPREFIX | TTS_BALLOON, ...)
// 然后直接 TTM_ADDTOOLW 挂 37 个控件，中间没有 TTM_SETMAXTIPWIDTH
```

Win32 气泡在**没设最大宽度**时按「整段文字一行」排版——本项目的提示文案动辄 80~120 字，
于是就摊成一条横贯屏幕的细条，右边被屏幕边缘截掉。

修法：

```rust
// TTM_SETMAXTIPWIDTH = WM_USER + 24 = 0x0418，单位像素，按 DPI 缩放
SendMessageW(tooltip, TTM_SETMAXTIPWIDTH, 0, crate::dpi::s(420) as isize);
```

420 基准像素 ≈ 20 个中文字，200% 下 840 物理像素。

## 2. 为什么「安装 PE」没有气球

`install_tooltips` 里确实给 5 个页签都挂了提示，**但 `tooltip_text()` 没有 `"pe"` 这个 key**：

- `gui_text.rs` 第 296 行那条 `(Language::Chinese, "pe") => "安装 PE"` 是 **`ui_text`（按钮标签）**，不是提示文案；
- `tooltip_text(language, "pe")` 因此返回空串 → 挂上去也是空提示，看不见。

★ 这类「有 key 但挂错表」的错，单元测试兜不住：那条测试是**遍历已存在的 key** 检查非空，
压根遍历不到缺失的 key。

补上 `pe` 的完整说明（中英各一条）。

## 3. 顺带查出来的另外两个

1. **「备份文件管理…」按钮**：`image_admin` 的提示文案**早就写好了**，但从没出现在 `controls` 数组里
   ——文案躺在表里没人用。
2. **「安装 PE」页的启动项名称输入框**：既没文案也没挂。

两者已补（新 key `pe_name_edit`）。

## 4. 覆盖审计：把「还有哪些没提示」变成可查的数字

新增启动时审计：枚举主窗口所有子控件，按类名分类统计，把**没挂提示的 id 打出来**：

```
tooltip audit: children=49 candidates(button=23 edit=9 combo=5) total_candidates=37 tipped=37 untipped=0 []
tooltips installed: added=37 missing=0 tool_count=37 balloon=true wrap=840 hwnd=6095564
```

★★ **为什么一定要打「候选数」**：只报 `untipped=0` 是没有说服力的——万一枚举根本没找到按钮
（类名比较写错、控件还没创建），也会「成功报 0」。**候选 37 > 0 且 untipped=0，才算真全覆盖。**
这一条是 2.6.99 专门补的：2.6.98 第一版只打了 `interactive=49 tipped=37 untipped=0`，
我自己都不敢信，回头加了分类计数才敢下结论。

结论：**37 个可交互控件（按钮 23 / 输入框 9 / 下拉框 5）全部有提示，缺口 0。**

## 6. 验证

### 6.1 程序化（确定性）

提权探针查提示窗本身：

```
hwnd=6095564 pid=10632 maxTipWidth=840 toolCount=37
```

`maxTipWidth=840` = 420 基准 × 2（200% 缩放），说明折行设置真的落到 comctl32 上了；
`toolCount=37` 与审计一致。

★ **坑：UIPI 会拦跨权限的 `WM_USER` 消息。** 主程序是提权运行的，未提权的探针
`SendMessage(TTM_GETMAXTIPWIDTH)` 会被系统**静默丢弃并返回 0** —— 我第一版探针读到
`maxTipWidth=0 toolCount=0`，差点误判「设置没生效」。提权后立刻读到 840 / 37。

### 6.2 视觉（把气泡本身抓成图）

`prlctl capture` 整屏在「悬停之后」总是黑帧（虚拟机显示器休眠不刷新），
改成**用 `PrintWindow` 直接把提示窗画到内存位图**再存 PNG：

| 悬停对象 | 气泡尺寸 | 结果 |
|---|---|---|
| 新增非 C 盘第二系统 | 866 × 164 | **折成 4 行**，文字完整 |
| 安装 PE | 866 × 102 | **折成 2 行**，文字完整（新补的提示） |

宽度 866 ≈ 840 上限 + 边距；高度随文案长短自适应——折行确实生效。
图片：`.test-artifacts/dpi-2679/tip-balloon.png`、`tip-balloon-pe.png`。

## 7. 遗留

1. **行首标点**：comctl32 按词折行不遵守中文「标点不能出现在行首」的排版规则，
   抓到的气泡里出现过「。」单独落在第三行开头。要完美得自己做折行（按字符宽度算），
   本轮没做——属于观感优化，不是功能缺陷。
2. 审计目前只覆盖主窗口的子控件；两个辅助窗口（备份文件管理 / 查看日志）与设置对话框
   没有提示、也没进审计。它们都是「一屏看完」的简单窗口，暂按不需要处理。
3. `tipgrab.ps1` 里有个硬编码的旧 pid 判断（只为「只抓可见的那个」），不影响结论，
   下次顺手清理。
