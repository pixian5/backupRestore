## 二、每处缺陷：现象 → 根因 → 修法 → 判据

### 缺陷 1：离线数据卷还原走不通

**现象**（11-24 基线实测与下午复核）：界面选「离线 → 进入 Windows RE」三道确认后弹「任务准备失败」，命令行
`prepare --operation restore-existing` 同样被拒，错误文字是
`restore-existing target must be the active Windows volume`，没有错误码；失败干净（无任务、无写入、无重启）。

**根因**：同一个入口在线走 `online` 子命令（不经过准备期校验），离线走 `prepare`。10-18 为防「把完整 Windows
镜像覆盖式写进一个数据卷」加的安全闸（`08ec341`）装在 `prepare_validation.rs`，条件写成了「目标必须是当前
系统卷」——把合法的「数据镜像 → 数据卷」也拦了。

**修法**（`prepare_plan.rs` / `prepare_validation.rs` / `error_code.rs` / `i18n.rs`）：

1. 删掉「目标必须是当前系统卷」这条闸。
2. 「还原到原卷」且目标不是系统卷时，**判断镜像是不是完整 Windows**，三路判据：
   - 镜像**自己的**副档（`<镜像名>.index-<索引>.metadata.json`）记录的备份源卷就是当前系统卷 → 是完整 Windows，
     **不挂载**，直接拒绝（`BR-IMG-009`）；
   - 否则只读挂载看有没有 `reagentc.exe` 与 `SYSTEM`（不采信镜像的索引名）→ 有则拒绝（`BR-IMG-009`）；
   - 都没有 → 数据镜像，放行并写一行放行日志；
   - 挂载探测本身失败 → `BR-IMG-010`（性质未知），不放行。
3. 错误码：`BR-IMG-009`「这是一份完整 Windows 镜像，不能按『还原到原卷』离线写入非系统卷 …本次未创建任务、
   未写入任何卷」；`BR-IMG-010` 镜像性质未知。

**判据**：

- 拒绝那一侧（最终二进制 `c9336473…`，22:56）：带副档的 40 GB 系统镜像 `c-bl-20261124.wim` 用于 F 盘 →
  `success:false error_code:BR-IMG-009 task_id:null`，没有创建任务。
  证据 `evidence/backup-pause-guard.json`。
- 拒绝那一侧、无副档（二进制 `7e2d29bc…`）：把副档拿掉的同一份系统镜像 → 走挂载探测 → 仍拒绝 `BR-IMG-009`。
  证据 `evidence/guard-B2.txt`；耗时由**系统自己的 DISM 日志**独立佐证：22:16:36 `/Mount-Wim` → 22:19:45
  `/Unmount-Wim`，**189 秒**（`evidence/diag-dism.raw.log`）。数据镜像（100 MB）同一秒内挂完卸完。
- 放行那一侧：见 §三 的 5 次还原。
- 单元测试：`prepare_plan.rs` 新增 4 项（副档指认系统卷、挂载确认是完整 Windows、探测失败判未知、数据镜像放行）。

### 缺陷 4：备份时按「暂停」无效

**现象**（11-24 11:07，任务 `37eb3aa2`）：恢复环境日志写了「用户按 P 暂停：恢复将在下一个步骤边界挂起」，其后
捕获又跑了 88.5 秒直到完成——因为备份链里**没有任何**暂停检查点，登记了也没人看。

**修法**（`progress_text.rs` / `recovery_progress.rs` / `recovery_engine.rs`）：

1. 只在恢复链真的会检查暂停的两个操作上提供暂停：`restore-existing`、`create-secondary`
   （`pause_supported_for`）。**操作名取自任务里记录的小写名字**，不是日志首行的枚举格式。
2. 不支持的操作：进度窗里按钮文字改成「暂停不可用」并禁用；按 P 或点按钮都不翻转状态，只记一行
   `Pause ignored: operation=<操作> does not support pause (via key P|button)`。
3. 数据卷还原分支原来**只有应用镜像前一个检查点**（应用只要 10 秒，按了暂停很快就过去），在校验前补了第二个
   检查点（这一条是实机抓出来的，见 §四）。

**判据**（恢复环境日志，原样取回）：

| 二进制 | 任务 | 按键 | 日志 |
|---|---|---|---|
| `7e2d29bc…` | `34623cea` | 1 次 | `Pause ignored: operation=backup does not support pause (via key P)` × 1 |
| `50c6b0e7…` | `0abab889` | 2 次（捕获 58 秒） | 同上 × 2，捕获照常做完 |

（最终二进制 `c9336473…` 上这一项被新缺陷打断了，改在 v2.10.9 / v2.10.10 的二进制上验完，见另一份文档。）

### 缺陷 2：默认目标是光驱

**根因**：列卷结果里没有「驱动器类型」，默认目标只按「不是系统卷、（必要时）没有 Windows」挑，于是排在前面的
光驱 D 盘被选中。

**修法**（`volume_device.rs` / `wim_parse.rs` / `native_gui/drive_selection.rs` / `operation_tabs.rs`）：
`GetDriveTypeW` 取类型（可移动 / 固定 / 远程 / 光驱 / 内存盘），类型是光驱、或文件系统是 UDF / CDFS 的都算光驱；
默认目标候选里排除光驱。列卷命令 `list-volumes` 与 `inspect-environment` 的每个卷都多了 `driveType` 字段。

**判据**（二进制 `65a49489…`，界面实测）：`COMBO id=1204 count=4 selected=2`，第 2 项是 `F: | NTFS`；
光驱 `D: | UDF` 在第 1 项、未被选中。`A_RESULT=PASS`。证据 `evidence/gui-fix-v2.10.10-verdict-A.txt`。

### 缺陷 3：选择框文字不跟着复选框变

**根因**：选择框只看「是不是离线」，文案固定写「目标卷将被格式化并写入镜像」，没看「格式化目标分区」有没有勾。

**修法**（`choice_dialogs.rs` / `task_executor.rs`）：创建任务时把复选框状态传给选择框。未勾选时正文改为
「已选择离线通道，且未勾选『格式化目标分区』：进入 Windows RE 后，镜像会写入目标卷但不格式化——目标卷上镜像
之外的文件会保留，与镜像同名的文件和文件夹会被覆盖。**进入 PE 则仍会格式化目标卷。**」

**判据**（二进制 `65a49489…`，界面实测，读到正文后点「取消」）：

- 勾选（默认）：`BODY_KIND=FORMAT`；
- 未勾选：`BODY_KIND=NO_FORMAT`；两段正文不同（`B_BODIES_DIFFER=True`）；两轮后任务列表都是 27 个，没变。

证据 `evidence/gui-choice-v2.10.10-verdict.txt`。⚠ 这一项的直接被测对象就是对话框文字，所以判据落在文字上；
控件文字由常驻助手回传时是**系统本地编码**，脚本按本地编码严格解码后才比对（第一版按通用编码读，中文全成乱码，
把两段明明不同的正文判成了「无法识别」）。

## 四、实机抓到、单元测试没抓到的三处（已在本版内修正）

1. **副档指认被旧式文件误导**：按索引命名的副档不存在时，读副档的函数会回退读同目录的旧式 `metadata.json`——
   那可能是**别的镜像**留下的。对照实验里数据镜像被判成了「完整 Windows」。改为只采信镜像自己的副档。
2. **暂停白名单的名字写错**：第一版写的是 `restoreexisting`（枚举的 Debug 格式），实机日志
   `Pause ignored: operation=backup` 暴露任务里记录的是带连字符的小写名 `restore-existing`。改为
   `restore-existing` / `create-secondary`，单测改用序列化后的真实名字。
3. **数据卷分支没有第二个暂停点**：任务 `14e5ca33` 登记了暂停却 10 秒后就完成。补检查点后任务 `5897b083`
   停住 144 秒。

## 七、这一轮的教训

1. **实机验证会抓到单元测试抓不到的回归**：§四 的三条里两条是「名字取错来源」「分支漏检查点」——单元测试用的是
   我自己写的常量，和产品真实取值对不上时测试照样绿。取名字要从产品的真实来源取（序列化后的任务字段）。
2. **最终二进制才是结论**：前两个二进制上的通过不算数。证据文件名要带版本号，否则后一轮会覆盖前一轮
   （11-25 凌晨就覆盖过一次，靠虚拟机里的原始记录补取回来）。
3. **准备期的窗口里有别的进程会动任务目录**——这是下一份文档的主题（孤儿任务守卫）。
4. **对无副档的大镜像做挂载探测很慢**（40 GB 镜像 189 秒）。可改进的方向：不挂载，直接列镜像目录判断；
   需要用户决定要不要做。
