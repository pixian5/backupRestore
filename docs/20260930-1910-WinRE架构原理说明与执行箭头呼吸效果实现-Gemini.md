## 一、用户关切问题解答：WinRE 是原生系统自带的还是修改后的？

针对用户提出的核心疑问：
> “原生 WinRE：这是系统原本的re还是程序修改后放到其它分区的re？”

### 1. 核心架构原理
- **底包来源**：WIM 基础镜像是从**系统当前注册的恢复分区**（例如 `R:\Recovery\WindowsRE\Winre.wim`）只读复制出来的，它是 Windows 11/10 操作系统官方自带的原生 WinRE 恢复环境镜像。
- **系统原件保护（只读保护）**：程序**绝对不会修改或破坏系统原有恢复分区里的 Winre.wim**，也不执行任何可能导致原恢复条目损坏的 `reagentc /disable` 操作。
- **运行载体（外部分区独立暂存）**：程序将复制出的原生 `Winre.wim` 放置到**其它分区（镜像卷/工作区，如 `F:\BackupRestoreRE\Winre.wim`）**。
- **载荷注入与独立 BCD 武装**：
  - 使用 DISM 挂载该外部复制件，注入本次任务专用的 `Recovery.exe`、`task.json` 与 `RecoveryTask.env`；
  - 在系统的 ESP（EFI 系统分区）BCD 中为该独立位置创建一条一次性启动条目（One-time Boot Sequence）。
- **任务结束后收尾**：WinRE 任务执行完成或重启回正常系统后，程序自动删除该独立 BCD 条目并清理 `BackupRestoreRE\` 暂存目录，系统原本的恢复分区和 WinRE 注册条目自始至终未受任何变动。

## 二、正在执行阶段小箭头呼吸闪烁（亮1秒、消失1秒）实现

### 1. 刷新机制确认
- 进度窗口内部通过 Win32 API `SetTimer(hwnd, TIMER_ID, 1000, None)` 挂接了每 1000 毫秒（1 秒）触发一次的定时器消息（`WM_TIMER`）；
- 每次触发时重新读取日志增量并重绘进度与状态，文本确实是精确按秒级刷新的。

### 2. 平滑呼吸效果设计
- 根据启动后的耗时秒数 `elapsed`：
  - `elapsed % 2 == 0`：显示小箭头 `▶`（亮起 1 秒）；
  - `elapsed % 2 == 1`：显示全角空格 `\u{3000}`（消失 1 秒）。
- **杜绝文字横向抖动**：在微软雅黑中，全角空格与全角小箭头 `▶` 宽度严格一致，小箭头在消失时不会引起后续阶段文字与时间戳产生左右横向位移，视觉呈现平滑稳重。
