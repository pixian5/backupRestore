# 虚拟机备份还原测试操作手册（给 AI 直接照做）

> 写给：**要在本项目上做备份/还原实机测试的其它 AI 代理**。
> 目的：把"怎么驱动虚拟机 + 怎么让程序真的跑一次备份/还原 + 怎么验证"写成
> 可照抄的步骤，重点解决 **AI 操作虚拟机时反复踩的坑**。
> 环境：macOS 宿主 + Parallels Desktop，客体是名为 `Windows 11` 的 ARM64 测试机。
> 本手册所有命令在 macOS 终端里跑；客体内命令一律通过 `prlctl exec` 下发。

---

## 零、最重要的三个坑（不看这节必卡）

1. **`Pause idle` 会让 `prlctl exec` 随机超时**。测试 VM 默认 `Pause idle: on`，
   会在你两条命令的间隙把 VM 自动暂停，下一条 `prlctl exec` 报
   `Unable to open new session in this virtual machine...`。这**不是**通道坏了，
   是 VM 睡着了。两种处理，按需求选（**每次快照回滚后都要重做一次**，见坑 3）：
   ```bash
   # A. 测试期间直接关掉空闲暂停（最省心，测完可再开回）：
   prlctl set "Windows 11" --pause-idle off
   # B. 想让它测试中仍能休眠、只是别睡太快：把"空闲暂停时间"调到 ≥15 分钟。
   #    prlctl 没有这个时长开关，要在 Parallels Desktop GUI 设：
   #    配置 → 选项 → 更多选项（优化）→ "闲置若干分钟后暂停 Windows" 改大。
   ```
   遇到上面那条报错先 `prlctl list -i "Windows 11" | grep -E "State:|Pause idle"`，
   若 `State: paused` 就 `prlctl resume "Windows 11"`，不要重启整个 VM。

2. **客体里的 GUI 窗口你点不到、也枚举不到**。`prlctl exec` 跑在 Session 0 的
   服务窗口站（`Service-0x0-3e7$`），GUI 在 Session 1 的 `WinSta0`。
   `FindWindow`/`EnumWindows`/`Get-Process.MainWindowHandle` 跨窗口站**结构性失效**，
   在客体里枚举 GUI 窗口一定失败。要操作 GUI：
   - 读屏：`prlctl capture` 截图 + macOS Vision OCR（见第八节）；
   - 发键：`prlctl send-key-event`（能送达交互桌面的 GUI，见第八、十一节）；
   - GUI-only 的功能（如 PE 安装）：用 `--test-hook` + `C:\br-test.json`（见第七节），
     不要试图点按钮。

3. **快照回滚会连 VM 配置一起还原**。`prlctl snapshot-switch` 之后，
   `Pause idle` 会变回快照里的旧值（通常是 on）。所以**每次回滚后立刻**重做坑 1 的
   处理（`--pause-idle off` 或在 GUI 调大空闲暂停时间）。

## 一、虚拟机基本操作（prlctl 速查）

```bash
# 看状态
prlctl list -a                                  # 运行/暂停/关机
prlctl list -i "Windows 11" | grep -E "State:|Pause idle"

# 电源
prlctl resume  "Windows 11"                     # 从 paused 恢复（首选，别动不动重启）
prlctl start   "Windows 11"
prlctl stop    "Windows 11"                      # 正常关机
prlctl stop    "Windows 11" --kill               # 强制断电（断电测试用）

# 在客体里执行命令（已提权，可跑 bcdedit/diskpart/dism）
prlctl exec "Windows 11" cmd /c "echo OK"        # 回显 OK 即通道正常
prlctl exec "Windows 11" powershell -NoProfile -Command "..."

# 截屏（PNG）
prlctl capture "Windows 11" --file /tmp/shot.png
```

- **判断通道是否可用**：`prlctl exec "Windows 11" cmd /c "echo OK"` 回 `OK` 即通。
  回 `Unable to open new session...` → 看坑 1。
- **GUI 应用会卡住 `prlctl exec`**：启动 GUI 用 `cmd /c "start \"\" /b 程序.exe ..."`，
  否则 `prlctl exec` 会一直等它退出（GUI 不退）。
- WinRE 里**没有** Parallels Tools，`prlctl exec` 在 WinRE 内不可用；
  WinRE 阶段只能靠 `capture` + `send-key-event`。

## 二、快照纪律（AGENTS.md + 用户 2026-10-12 细化）

**只在破坏性 / 持久改引导的操作前拍快照；备份前不拍。**

- **要拍快照**：还原系统（`restore-existing`，会格式化目标卷）、新增第二系统
  （`create-secondary`）、PE 硬盘版/内存版安装、以及任何直接改 BCD、默认项、
  一次性启动序列、WinRE 注册、PE 部署的操作。这些不可逆，必须留回滚后路。
- **不用拍快照**：**备份**（`backup`）。它只读源卷、把镜像写到镜像卷，不格式化、
  不持久改引导（即便经一次性启动进 PE 离线捕获，那条 bootsequence 也自清、
  非破坏性），出错也毁不了数据，拍快照是多余开销。

```bash
# 建快照（命名：年月日-时分-用途）
prlctl snapshot "Windows 11" --name "20261012-0002-用途说明"

# 列快照（* 是当前）
prlctl snapshot-list "Windows 11"

# 删快照（注意：ID 要用 --id，裸 ID 不认）
prlctl snapshot-delete "Windows 11" --id "{快照GUID}"

# 回滚到某快照
prlctl snapshot-switch "Windows 11" --id "{快照GUID}"
```

规矩：
- 需要拍的操作：触发一次完整启动变更事务（prepare→进 PE）前就得有快照；进 PE 后再手动变更或返回，
  需要**另建**快照，不要复用早先的。
- 保持 ≤2 个。要新建而总数会超 2 时，先 `snapshot-delete` 最旧的。
- 清理只删确认属于本项目的测试快照，别碰用户的、系统恢复镜像、开发工具链。
- **破坏性测试（格式化目标卷）前的那个快照 = 你的回滚后路**。测完
  `snapshot-switch` 回去就能把目标卷和 BCD 一次性还原干净（回滚后记得关 pause-idle）。

## 三、把产物部署进客体

宿主仓库通过共享 `\\Mac\backupRestore` 映射到客体（即 macOS 侧
`/Users/x/code/backupRestore`）。交叉构建产物在
`target/aarch64-pc-windows-msvc/release/BackupRestore.exe`。

```bash
# 1) 宿主侧构建（macOS → Windows ARM64）
./build-win.sh                                   # 产物在 target/aarch64-pc-windows-msvc/release/
shasum -a 256 target/aarch64-pc-windows-msvc/release/BackupRestore.exe

# 2) 客体侧从共享复制并核对哈希（哈希必须一致，否则是旧档）
prlctl exec "Windows 11" powershell -NoProfile -Command "Copy-Item '\\\\Mac\\backupRestore\\target\\aarch64-pc-windows-msvc\\release\\BackupRestore.exe' 'F:\\BR\\BackupRestore.exe' -Force; (Get-FileHash 'F:\\BR\\BackupRestore.exe' -Algorithm SHA256).Hash"
```

- **程序目录不能放在承载注册 WinRE 的分区上**，也**不能放在卷根**；
  放一个子目录如 `H:\brwork\`。放卷根会报 `program directory cannot be a volume root`，
  放 WinRE 宿主分区会报 `程序目录不能位于承载 Windows 恢复环境（WinRE）的分区`。
- 还原/第二系统还需要同目录放一份 `Recovery.exe`（可以就是 BackupRestore.exe 的副本）。
- 改完代码**务必重新复制并比对哈希**，否则会拿旧二进制测出假结果。

## 四、卷布局与角色（当前测试机）

| 盘符 | 用途 | 说明 |
|---|---|---|
| C: | 系统盘（有 Windows） | 在线入口代码会拒绝把它当在线目标（`active volume must be processed offline`）；**2026-10-12 起用户撤销「不许当源/目标」铁律，CLI/PE 路径可用 C: 做源或目标**，但默认仍先测测试卷 |
| E: | 大号测试目标卷（270G） | 可格式化的一次性目标 |
| F: | 镜像卷（350G，标签 BRIMG） | **只放镜像**（`F:\BRImages` 等）；**不再放程序**——旧工作区 `F:\BR` 已于 2026-10-13 退役删除 |
| H: | 工作区/程序目录（192G，标签 DATA） | **唯一开发目录 `H:\brwork`**（部署脚本 DeployWorkDir）；另有 `H:\c-backup\c-system.wim`（36.9G 真实 C 盘备份，勿删） |
| P: | 测试卷（64G） | 备用 |
| T: | 小测试卷（5G，数据卷） | 还原数据卷最快的目标；内容是 BRRE213+testdata |
| Y: | WINRE（0.8G） | 注册 WinRE 宿主，别碰 |

现成可用的测试镜像：
- `H:\BRRE-219-20261009\a230-focus\images\test.wim`（约 1.3MB 的小数据卷 WIM，还原 T:/E: 快）
- `F:\sysbackup.wim`、`H:\brworkRE-217-20261008\system.wim`（系统镜像，大，跑系统还原用）
- 纯 WinPE：`C:\BackupRestorePE\media\media\sources\boot.wim`（测 PE 路径用）

## 五、命令行跑备份 / 还原（主路径）

程序 CLI 子命令（`BackupRestore.exe` 不带参数会打印全部）：

```text
prepare --operation <probe|backup|restore-existing|create-secondary>
        --source-drive <盘符> [--target-drive <盘符>] [--image-path <绝对WIM>]
        [--wim-index <n>] [--boot-menu-name <名>] [--allow-destructive] [--no-reboot]
resume  <task-root> <task-id>     # 续跑/重试，也是触发进 WinRE 的动作
status  <task-root> <task-id>
abandon-task <task-root> <task-id># 放弃未写目标卷的任务并清理
list-volumes
inspect-environment
```

**两段式**：`prepare` 建任务（并武装一次性启动），`resume` 真正触发进 WinRE 执行。
`<task-root>` 就是程序所在目录（如 `H:\brwork`）。

### 还原数据卷（最快，推荐先跑通这条）

目标 T:（数据卷，无 Windows），用小 WIM。注意还原要 `--allow-destructive`：

```bash
# 清掉上次遗留任务目录，避免互斥拦截（见坑：未终结任务会拒绝新任务）
prlctl exec "Windows 11" cmd /c "rmdir /s /q H:\brwork\tasks 2>nul & echo cleaned"

# 1) 准备
prlctl exec "Windows 11" cmd /c "H:\brwork\BackupRestore.exe prepare --operation restore-existing --source-drive T --target-drive T --image-path H:\BRRE-219-20261009\a230-focus\images\test.wim --allow-destructive"
#   回显 TASK_ID=<guid> / TASK_ROOT=H:\brwork\tasks\<guid>

# 2) 触发执行（数据卷还原会进 WinRE 跑一圈再回来，终态 success）
prlctl exec "Windows 11" cmd /c "H:\brwork\BackupRestore.exe resume H:\brwork <task-id>"

# 3) 查状态（stage=success progress=100 即成功）
prlctl exec "Windows 11" cmd /c "H:\brwork\BackupRestore.exe status H:\brwork <task-id>"
```

- `restore-existing` 的目标必须等于源（单系统还原语义）：`--source-drive` 与
  `--target-drive` 同盘符。
- `create-secondary`（新增第二系统）目标必须≠源，且镜像必须是**完整 Windows**
  （含 SYSTEM hive + reagentc），**纯 WinPE 会在 WinRE 注册阶段失败**
  （见 `docs/20261011-2140-PE作第二系统实验结论-Fable5.md`）。
- 系统卷还原会多跑 BCDBoot + WinRE 注册，用 `F:\sysbackup.wim` 这类系统镜像，耗时长。

### 备份（capture）

```bash
prlctl exec "Windows 11" cmd /c "H:\brwork\BackupRestore.exe prepare --operation backup --source-drive T --image-path F:\out\t-backup.wim"
# backup 只读源、写镜像到目标卷，不格式化任何卷；镜像卷必须≠源卷
```

### 常见 prepare 拒绝原因（都是设计拦截，不是 bug）

| 报错 | 原因 / 处理 |
|---|---|
| `restore requires --allow-destructive` | 还原要显式加 `--allow-destructive` |
| `--image-path is required for backup and restore` | 补 `--image-path` |
| `program directory cannot be a volume root` | 程序别放卷根，放子目录 `H:\brwork\` |
| `程序目录不能位于承载 Windows 恢复环境（WinRE）的分区` | 程序别放 WinRE 宿主分区 |
| `检测到尚未终结的任务...` | 有未完成任务占用一次性启动；先 `abandon-task` 或清 `tasks` 目录 |
| `image volume must differ from restore target` | 镜像和目标别同卷 |
| `second-system target must differ from source` | create-secondary 目标≠源 |

## 六、读状态 / 验结果（别只看 "success"）

```bash
# 任务状态 JSON
prlctl exec "Windows 11" cmd /c "type H:\brwork\tasks\<task-id>\status.json"
#   stage=success progress=100 → 任务流程走完

# 看它在 WinRE 里到底干了什么（STEP / cleanup / bcdboot / 断电点）
prlctl exec "Windows 11" cmd /c "type H:\brwork\tasks\<task-id>\Recovery.log 2>nul | findstr /i \"STEP cleanup bcdboot Recovery completed\""
#   数据卷还原会有 "data-volume restore ... skipping BCDBoot"
```

**启动成功≠备份还原成功。** 要再核内容：
- 数据卷还原：对目标卷逐文件 `Get-FileHash` 比对预存清单（如
  `<workspace>:\BRRE-213-20261005\before\files.json`）。
- 系统卷还原：核对第二系统能否真起、`reagentc /info`、`bcdedit` 回基线、
  原注册 WinRE 原件哈希未变。

## 七、GUI-only 功能（PE 安装）用测试钩子，别点按钮

PE 恢复环境安装（`install-pe-entry`，含「硬盘版」「内存版」）只有 GUI 入口。
因窗口站隔离点不到按钮，用内置测试钩子无头触发：

```bash
# 1) 写 C:\br-test.json（经共享从宿主拷，避开 shell 转义地狱）
cat > /Users/x/code/backupRestore/.test-artifacts/br-test.json <<'JSON'
{"tab":"pe","mode":"disk","target_volume":"E","image":"C:\\BackupRestorePE\\media\\media\\sources\\boot.wim","pe_name":"PE Lab","auto_install":true}
JSON
prlctl exec "Windows 11" powershell -NoProfile -Command "Copy-Item '\\\\Mac\\backupRestore\\.test-artifacts\\br-test.json' 'C:\br-test.json' -Force; Get-Content C:\br-test.json | ConvertFrom-Json | ConvertTo-Json -Compress"

# 2) 后台启动带钩子的 GUI（start /b，否则 prlctl exec 会一直等 GUI 退出）
prlctl exec "Windows 11" cmd /c "start \"\" /b H:\brwork\BackupRestore.exe --test-hook"

# 3) 轮询安装完成（硬盘版会 format+dism+bcdedit），再读 GUI 日志确认
prlctl exec "Windows 11" cmd /c "type H:\brwork\logs\gui.log" 
#   末行 "GUI action completed: PE recovery installed..." 即成功

# 4) 完事杀掉这个 GUI 进程（它不会自己退）
prlctl exec "Windows 11" cmd /c "tasklist | findstr /i BackupRestore"   # 找 Services 会话那个 PID
prlctl exec "Windows 11" cmd /c "taskkill /PID <pid> /F"
```

`br-test.json` 字段：`tab`=`pe`/`backup`/`restore`/`secondary`；`mode`=`disk`/`ram`；
`target_volume`、`source_volume`、`image`(WIM 路径)、`pe_name`、
`auto_install`:true（自动触发并自动点确认框）、`system_drive_choice`(0取消/1 PE/2 RE)。

## 八、驱动 WinRE 画面（没有通道时唯一手段）

进了 WinRE，`prlctl exec` 不可用。只能截图 + 发键：

```bash
# 截图
prlctl capture "Windows 11" --file /tmp/winre.png

# OCR（macOS Vision，识别中英文）
sips -Z 1280 -s format jpeg /tmp/winre.png --out /tmp/winre.jpg
swift -e 'import Vision; let r=VNRecognizeTextRequest(); let h=VNImageRequestHandler(url:URL(fileURLWithPath:"/tmp/winre.jpg")); try h.perform([r]); for x in (r.results ?? []){print(x.topCandidates(1)[0].string)}'

# 发键（Enter 的扫描码是 28；按下+抬起成对发）
prlctl send-key-event "Windows 11" --scancode 28 --event press
prlctl send-key-event "Windows 11" --scancode 28 --event release
```

- WinRE 开机常先停在「选择键盘布局」页：发两次 Enter 选中「微软拼音」继续。
- **判 UI 有没有真响应，用截图 SHA-256 逐像素比对**，别靠肉眼："看起来没变"
  会把"根本没响应"和"响应后恰好相同"混为一谈。
  ```bash
  shasum -a 256 /tmp/before.png /tmp/after.png
  ```

## 十一、在虚拟机内操作本程序（Win11 GUI / WinRE）

前面几节是"从宿主下发命令"。这一节讲**在客体里本程序本身怎么被操作**——
Win11 全系统里的图形界面、以及重启进 WinRE 后的恢复界面。三种驱动方式，
**优先级从高到低**：CLI 等价 ＞ test-hook 无头驱动 GUI ＞ 真人式截图+发键。

### 11.1 Win11 里的程序 GUI 长什么样

原生 Win32 窗口（标题 `BackupRestore - Rust GUI v<版本>`），布局：

- **操作模式**四个按钮：`备份` / `单系统还原` / `新增第二系统` / `PE 恢复`；
- **源卷（备份来源）** 下拉、**目标卷** 下拉、**镜像绝对路径** 输入 + `浏览…`；
- `压缩率`、`索引名`、`保留最近 N 个`；
- 底部按钮：`刷新环境` / `读取镜像` / `创建任务` / `刷新任务状态`；
- 右上角 `语言` 下拉（中/英）。

每个 GUI 操作在后台都对应一条 CLI 子命令（见第五节），**测试首选 CLI**，
因为它不受窗口站隔离影响、可脚本化、输出可解析。GUI 只在"必须验界面本身"
（如 PE 安装入口、进度窗显示）时才驱动。

### 11.2 方式一：CLI 等价（推荐）

GUI 的「创建任务」= `prepare` + `resume`；「刷新任务状态」= `status`；
「读取镜像」= `wim-info`；「刷新环境」= `list-volumes`/`inspect-environment`。
直接用第五节的命令即可，不必碰窗口。

### 11.3 方式二：test-hook 无头驱动 GUI（要验 GUI 行为时）

`C:\br-test.json` + `BackupRestore.exe --test-hook` 不止能装 PE，也能驱动
备份/还原/第二系统这几个 tab：程序启动后自动选 tab、填源/目标/镜像、
（`auto_install:true` 时）自动点「创建任务」并自动接受确认框。

```json
{"tab":"restore","target_volume":"T","source_volume":"T",
 "image":"H:\\BRRE-219-20261009\\a230-focus\\images\\test.wim",
 "system_drive_choice":2,"auto_install":true}
```

- `tab`：`backup` / `restore` / `secondary` / `pe`（默认 pe）；
- `mode`：`disk` / `ram`（仅 PE tab）；
- `system_drive_choice`：对系统盘的智能分流弹窗**预置**选择（0 取消 / 1 PE / 2 RE），
  设了就跳过弹窗，便于无法精确点弹窗按钮的自动化环境；
- 启动方式同第七节：`start "" /b ... --test-hook`，跑完读 `H:\brwork\logs\gui.log`
  末行确认，再 `taskkill /PID <Services会话的PID> /F`。
- 注意：`--test-hook` **只在显式带该参数时**读 `C:\br-test.json`，正常启动不读。

### 11.4 方式三：真人式截图 + 发键（验真实交互 / 弹窗）

`prlctl send-key-event` 的按键送达的是**交互桌面（Session 1）里有焦点的那个窗口**，
也就是用户看到的那个 GUI——所以它能驱动 Win11 里的程序 GUI（这点和
`prlctl exec` 不同，exec 到不了 Session 1）。鼠标点不了，但程序支持**键盘导航**：

| 键 | 作用 |
|---|---|
| `Ctrl+B` | 切到「备份」 |
| `Ctrl+R` | 切到「单系统还原」 |
| `Ctrl+P` | 切到「PE 恢复」 |
| `Ctrl+O` | 读取镜像 |
| `F5` | 刷新环境 |
| `Ctrl+Enter` | 创建任务 |
| `Tab` / 方向键 / 回车 | 在控件间移动、下拉选择、按默认按钮（标准对话框导航） |

配合 `capture`+OCR 读当前界面、`send-key-event` 发键，可无鼠标完成一轮操作。
组合键要先按 Ctrl（press）再按字母、再依次 release；回车/方向键的扫描码见下。

```bash
# 例：发 Ctrl+R（扫描码 Ctrl=29, R=19）
prlctl send-key-event "Windows 11" --scancode 29 --event press
prlctl send-key-event "Windows 11" --scancode 19 --event press
prlctl send-key-event "Windows 11" --scancode 19 --event release
prlctl send-key-event "Windows 11" --scancode 29 --event release
```

常用扫描码：Enter=28、Esc=1、Tab=15、↑=72、↓=80、←=75、→=77、
空格=57、Ctrl(左)=29、R=19、B=48、P=25、O=24、L=38、F5=63。

### 11.5 WinRE 里操作程序（进度窗 + 失败对话框）

还原/第二系统任务 `resume` 后，机器重启进 WinRE，产品自动拉起 `Recovery.exe`
按任务续跑，**正常是全自动的**：显示「BackupRestore 恢复进度」窗口，跑完
STEP 1→4 后自动重启回 Windows。WinRE 里**没有 Parallels Tools，`prlctl exec`
用不了**，只能截图 + 发键。

进度窗能做的交互（全靠 `send-key-event`）：

- **按 `L`**（扫描码 38）打开「详细日志」弹窗，判断卡在哪一步；主界面也常驻显示
  日志最后 3 行；
- 弹窗里 `PageUp`/`PageDown`（扫描码 73/81）滚动日志；编辑框已有 `WS_TABSTOP`+
  `SetFocus`，无鼠标也能滚（2.3.0 修）；底部吸附：翻上去会停住、翻回底恢复跟随；
- 开机若停在「选择键盘布局」页，发两次 `Enter`(28) 选「微软拼音」继续。

**失败对话框**：恢复中途失败会弹「BackupRestore 恢复需要处理」对话框，
两个按钮 `重试(R)` / `取消`：

- 发 `R`(19) 或 `Enter`(28) = 重试（排除磁盘/镜像/空间问题后继续同一任务；
  已完成的任务只重试清理，不再擦目标）；
- 发 `Esc`(1) 或点`取消` = 进入系统恢复工具。
- 判断按了有没有用：`capture` 前后截图 `shasum -a 256` 比对（见第八节）。

> WinRE 阶段的验收判据同样用**截图 SHA-256 逐像素比对** + OCR 读首行，
> 不要靠肉眼。进度窗卡很久不一定是卡死——可能是故障注入
> `acceptance:*:hold` 的无限 hold（详见断电矩阵相关文档），要看详细日志末行
> 是不是 `ACCEPTANCE_CHECKPOINT ... hold`。

### 11.6 一句话决策

- 要**验备份还原逻辑**：用 CLI（11.2），最省心最可靠；
- 要**验 GUI 本身**（控件、分流、PE 入口）：用 test-hook（11.3）；
- 要**验真实键盘交互 / WinRE 弹窗**：用 send-key-event + 截图比对（11.4/11.5）；
- 任何时候**别试图用鼠标点客体 GUI**——窗口站隔离，点不到。
