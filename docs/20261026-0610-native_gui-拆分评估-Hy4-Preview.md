# `native_gui.rs` 拆分评估（只读评估，未改代码）

- 评估时间：2026-10-26 06:10；版本：v2.6.53（远端 `a2daf8d`）
- 评估对象：`crates/backuprestore-cli/src/native_gui.rs`
- 结论先行：**建议拆两项（文案表 + 对话框族，约 2,250 行 / 19%），不建议动 `create_task` 与 PE 桌面窗口。**

## 2. 拆分候选与判定

### 候选 A：双语文案表 → `gui_text.rs`（~350 行）

- **边界**：`tooltip_text` / `ui_text` 两个 `match (language, key)`，输入枚举输出 `&'static str`，**零 Win32、零 unsafe、零 State 依赖**。
- **收益**：
  1. 这是唯一一块**天然可单测**的图形界面代码——现在它在 `#[cfg(windows)]` 模块里，macOS 上 `cargo test` 根本看不到它，加一百条文案也无法断言（项目铁律：`cfg` 内改动只能靠交叉编译验证）。
  2. 改一个字的文案，不用重编译 12k 行。
- **风险**：极低。调用点全文件替换成 `crate::gui_text::ui_text(...)`；`Language` 需 `pub(crate)`。
- **判定：做。**

### 候选 B：5 个自包含对话框 → `gui_dialogs.rs`（~2,040 行）

- **边界**：每个对话框 = 一个窗口过程 + 一个 `ask_*` 模态外壳 + 自己的静态量（`IMAGE_ADMIN_*` / `LOGS_*` / `SETTINGS_*`…），对外只暴露 `ask_xxx(...)`。
- **收益**：主文件减重 17%；「改备份文件管理对话框」时不用在 PE 桌面代码旁边翻找。
- **风险**：中低，但有两个必须遵守的约束：
  1. 全部静态量与 `ask_*` 要改 `pub(crate)`——**静态量是这些对话框的传值通道，改成跨模块后仍然安全**（同一进程、同一窗口生命周期），但要逐一确认没有第二个模块同名。
  2. 拆分后代码依然在 `cfg(windows)` 下，**mac 侧 `cargo check` 完全看不见**（项目踩过的坑），所以**验收只能靠交叉编译 + 实机点击**，不能靠 `cargo test`。
- **判定：做，但必须一次只搬一个对话框、搬完立刻实机点击验收**（现有工具链已具备：`tools/run-gui-token.ps1` 借图形界面令牌跨 UIPI 点击 + `br-list-windows.ps1` 断言窗口类名）。

### 候选 C：`create_task` 巨型函数（~1,230 行）

- **现状**：一个函数里串行完成「未终结任务处置 → 镜像路径校验 → 索引校验 → 目标/源卷取值 → 三道入口闸门 → 破坏性确认 → 档案校验 → 通道分流 → 提权启动」。
- **判定：不建议整块搬出**（与 `State` 深度耦合，搬出去等于把 `State` 暴露成半公开）。
- **可选替代**：**同文件内**按上面 9 个步骤各提取一个小函数，主函数只留调度。收益是「读得懂」，风险是动了V1 已验收通过的主路径——**做之前必须保证冒烟 7/7 与一次真实备份/还原不回归**。优先级低于 A/B。

### 候选 D：PE 桌面窗口（~1,000 行）

- **判定：不动**。它是恢复环境里的另一套交互（无外壳、自绘时钟、系统信息采集），与主窗口共用大量静态量与 `Msg` 循环，拆开收益小、回归面大。

## 3. 不拆也能接受的理由（反方论据，如实列出）

1. 该文件是**稳态代码**：V1 功能已 100% 交付，日常改动集中在文案与入口（本轮两项改动分别只动了 350 行与 40 行）。
2. 拆分**不解决任何实际问题**：不是性能瓶颈（编译一次约 6 秒，见 `build-win.sh` 增量），不是缺陷来源。
3. 回归风险**不对称**：图形界面坏了只能靠实机点击发现（门禁只跑单测 + 交叉编译），一次拆分失误的代价远大于导航不便。
4. 现有兜底已经够：pre-push 门禁（单测 + 交叉编译）+ `tools/smoke/deploy-and-smoke.sh`（7 项冒烟）+ 本轮新增的图形界面点击验收脚本。

## 4. 建议的执行顺序（如用户决定拆）

1. **A（文案表）** —— 0.5 天，零风险，顺带补上「图形界面文案可单测」这个长期缺口。
2. **B 分五次搬**（系统分区选择 → 无效路径选择 → 设置 → 备份文件管理 → 日志查看）—— 每次 0.5 天，搬一个验收一个。
3. **C 只在有明确诉求时做**，且必须与一次真实备份/还原验收绑定。
4. 全程纪律：**每步提交即推送**；每步都跑 `./build-win.sh --deploy` 后实机点击对应入口，不能只靠编译通过就宣称完成。
