**A 还原系统到 C 盘**（目标锁定当前系统盘）、**B 还原数据到非 C 盘**、**C 还原系统到非 C 盘**。

## 2. 核心目标：三个还原入口（含 2.4.9 后的最新理解）

### 2.1 入口定义

| 新入口 | 目标卷 | 镜像类型 | 通道 | 一句话 |
| --- | --- | --- | --- | --- |
| **A · 还原系统到 C 盘** | **锁定** = 当前系统盘（`%SystemDrive%`） | 完整 Windows | 必走离线（PE/RE） | 把当前系统还原回它自己 |
| **B · 还原数据到非 C 盘** | 用户选的数据卷 | 数据卷镜像（无 SYSTEM hive） | 在线为主 | 只覆盖数据，不碰引导 |
| **C · 还原系统到非 C 盘** | 用户选的非系统分区 | 完整 Windows | 在线（离线亦可） | 把系统装到另一个分区（= 第二系统） |

### 2.2 底层机制在 2.4.9 已经统一了

三个入口对应**程序里已有的三个执行分支**，且恢复期收尾现在**真正按目标性质路由**（P1 的成果）：

```
准备阶段（联机，%SystemDrive% 可用）：
  TargetSpec.is_active_system = target.same_partition(活动系统卷)   ← 落盘进 task.json

恢复阶段（RE 内，读 task 里的结论——RE 里 %SystemDrive% 是 RAM 盘 X:，探测不到用户系统卷）：
  target_is_secondary = !target.is_active_system
  if 目标有 SYSTEM hive:
      if target_is_secondary → NewWindows 收尾（repair + /d /addlast + repair_secondary + 保 default）
      else                  → ExistingWindows 收尾（不加 /d，default 指向新 loader）
  else → data-volume（跳过 BCDBoot，不碰引导）
```

**关键设计原则（别退化回去）**：不要按 tab/操作类型把 role 写死。`TargetRole`（existing/new-windows）
表达的是**操作语义**（重启后回哪里），与 `boot_plan.mode` 是耦合校验对（`core/lib.rs:793/798`、
`main.rs:2513`），不能重解释为目标性质——2.4.9 曾试过此路不通，详见 1052 文档「走过的弯路」。

### 2.3 三个入口的校验矩阵（不能省）

| 校验 | A | B | C |
| --- | --- | --- | --- |
| 镜像完整性预检 | 必须（完整 Windows） | **必须放行数据卷**（已实现，P2） | 必须（完整 Windows） |
| 容量预检 | **必须加强**（用户无法换盘纠错） | 建议 | 必须 |
| BitLocker / 保留分区 | ✓ | ✓ | ✓ |
| 身份重绑定（RE 内盘符会重排） | ✓ | ✓ | ✓ |
| `target ≠ %SystemDrive%` | N/A（目标就是它） | 必须 | 必须（**已实现**，P0） |
| 破坏性确认 | **必须，最强**（两道确认） | 必须 | 必须 |

### 2.4 UI 拆分落地要点（接手方的主要新工作）

- **A**：目标锁定用 `%SystemDrive%` 的 `volume_identity`（disk/partition/GUID/serial），
  **绝不写字面 `'C'`**（P4 待修）；界面显示实际盘符「当前系统盘 (D:)」；隐藏误导性的「源卷」控件（P3）；
  必走离线 → **PE/RE 选择弹窗 + 破坏性覆盖确认，两道确认都要保留**
  （有前科：`--test-hook` 的 `TEST_AUTO_CONFIRM` 会自动接受所有确认框——验收真实确认链必须用纯净 GUI：
  `tools/win-clicker/restart-gui-plain.ps1`）。
- **B**：默认在线；把通道差异写在界面上：**在线不格式化（覆盖），离线会 diskpart 格式化**。
- **C**：可在线（不重启）——这是它与「新增第二系统」tab 仅存的差别（后者永远离线）。两者并存是用户拍板的。
- **tab 总数 6 个**：备份 / A / B / C / 新增第二系统 / 安装 PE。

## 4. 操作手册（接手方必读）

### 4.1 构建与部署

```bash
./build-win.sh --deploy        # 宿主机交叉编译 + 部署到 H:\brwork（同时刷自启包）
```

- 产物真名 `backuprestore-cli.exe`；**核对二进制内含新代码**：Rust 字符串字面量在二进制里是
  **UTF-8**，用 `[Text.Encoding]::UTF8.GetString([IO.File]::ReadAllBytes($p))` 再 `Contains`；
  部署脚本会打印 SHA256，与 `Get-FileHash` 比对。
- **版本三处同步**：`VERSION` + 两个 crate 的 `Cargo.toml`。
- macOS 侧快速检查（不产出可部署 exe）：
  `cargo check --all-targets --target aarch64-pc-windows-msvc -p backuprestore-cli`（linker/RUSTFLAGS 照 build-win.sh）。

### 4.2 VM 与 GUI 自动化

- VM 名 `Windows 11`（Parallels）。`prlctl exec "Windows 11" cmd /d /c "..."` = SYSTEM+管理员。
- **prlctl exec 会间歇性抖动**（`Invalid argument` / `Unable to open new session`）：重试即可，不是客体故障。
- **GUI 界面自动化唯一可靠路线** = VM 内 TCP agent `tools/win-clicker/br-agent-tcp.sh`
  （提权 + Session 1 + 高完整性，真实键鼠）：`click x y / key 0xVV / chord mod,key / text / exec / shot`。
  消息级注入（SendMessage/BM_CLICK）被 UIPI 拦，不可行。
  - agent 内 `exec` 脚本里写 `exit` 会**杀死 agent**，一律用 `return`。
  - 激活窗口用 `SetForegroundWindow`（**勿用 `SW_RESTORE=9`**，会把最大化窗口打回 1020×760，坐标全失效）。
  - combo 回读：`CB_GETCOUNT=0x0146`（勿用 `0x014B`=RESETCONTENT 会清空列表）；全选 = `End(0x23)` + `Shift+Home`。
- **控件 ID**：创建任务 `1003`、源卷 combo `1202`、镜像路径 `1203`。
  **屏幕坐标（1254×954 最大化）**：创建任务 (340,489)、源卷 (705,133)、路径框 (660,383)、确认框「是」(660,579)。
- **验收真实确认链必须用纯净 GUI**（`--test-hook` 的 `TEST_AUTO_CONFIRM` 会自动点是）：
  `tools/win-clicker/restart-gui-plain.ps1`；`restart-gui-testhook.ps1` 切回钩子版。
- **控制台是 GBK**：`prlctl exec` 的中文输出会乱码、`ConvertFrom-Json` 可能截断中文——
  复杂命令写成 .ps1 文件，UTF-16LE base64 后用 `-EncodedCommand` 执行；看文件真实内容用 UTF-8 解码。

| **RE 里 `%SystemDrive%` = X:** | WinRE RAM 盘；离线侧探测活动系统只会得到 RAM 盘，一切「目标是否活动系统」的判断都在准备期完成 |
| **活动卷共享违例** | `C:\Windows\System32\config\SYSTEM` 被独占锁定（两种共享模式都打不开）。`pe_safety::probe_file` 对它抛 os error 32（**不是 NotFound**）→ 绝不能对活动卷做文件探测；2.4.9 用 `target_is_active \|\|` 短路 |
| **盘符绑定** | 盘符是 hive `MountedDevices` 的 `\DosDevices\<字母>:` = blob 记录；GPT blob = `DMIO:ID:` + PARTUUID 小端。策略 = **迁就镜像自认字母**（SOFTWARE hive 的 `SystemRoot`）。⚠️ **只支持 GPT**：MBR 盘（12 字节 blob）走不了 `gpt_mapping()`，README 已标为实现限制。详见 `docs/盘符与MountedDevices-经验总结.md` |
| **BCD 不依赖盘符** | 启动用设备路径/分区 GUID；bcdedit 显示的 `partition=C:` 只是实时翻译 |
| **ramdisk 规格** | 一律写设备路径 `ramdisk=[\Device\HarddiskVolumeN]\...`；数据卷盘符形式会被 bootmgr **静默丢弃**（不报错，看着像没重启） |
| **数据卷 vs 系统卷判据** | 目标卷有无 `Windows\System32\config\SYSTEM`。没有 → 只应用不碰引导（全通道一致，2.4.9 起 prepare 预检与恢复期判据一致） |
| **本机 probe 形同虚设** | DISM `/Mount-Wim` 在有 VHD 附加时报 87 → `wim_full_windows_probe` 走镜像名启发式放行。真实拒绝路径要换 DISM 挂载可用的机器验 |
| **加必填字段** | `incomplete_tasks` 已修成「先读 status 定性，终态跳过」，以后 Task 加必填字段不再是破坏性变更；非终态任务仍 fail-closed（故意的） |
| **prepare stdout 是协议** | GUI 按行解析 `TASK_ID=`/`TASK_ROOT=`，别随便加日志行；审计线索写在任务目录日志里 |
| **WinRE 里没有 reagentc.exe** | 要操作注册位必须全路径调用离线目标 OS 自带的 `<目标>:\Windows\System32\reagentc.exe` |
| **镜像副档** | `<wim名>.index-N.metadata.json`：容量预检 + 防冒充。副档 `name` 固定 `Windows Backup (index N)`，WIM 实际索引名才是 `--image-name` 的值 |
