# PE 写盘安全修复与双环境实测

- 日期：2026-10-05；模型：GPT-6；版本：**2.1.2**。
- 开发基线：`ac5ab9f` / 2.1.1。修订前源码归档：`.test-artifacts/pe-safety-20261005-1112/source-before.tar.gz`。
- 本轮处理预装 PE（预安装环境）的备份、系统还原、第二系统界面和新自动请求；主 WinRE（Windows 恢复环境）任务链、硬盘模式 PE 安装器仍是独立待办。
- 结论：历史“镜像不存在仍先格式化、最后报还原完成”的 PE 界面故障已在同类一次性测试盘上验证修复。**不是整个产品、完整系统还原或断电续跑全部验收完成。**

## 一、实现

| 范围 | 变化与边界 |
|---|---|
| 写入前检查 | 读取本地镜像、SHA-256（安全散列算法）摘要、指定索引、展开容量及可选副档；系统意图要求镜像列出 SYSTEM 注册表文件、winload.efi 和 ntoskrnl.exe。缺失或未知在格式化前失败 |
| 身份与角色 | 请求保存磁盘/分区/卷 GUID（全局唯一标识符）、类型、位置、大小、序列号；启动后从稳定卷路径回读，写命令前复核现场编号。拒绝镜像、日志、运行程序、当前系统、恢复载荷与目标冲突及保留分区。第二系统另存用户明确选择的主系统身份，确认不能豁免禁区 |
| 路径检查 | 逐层检查目录及文件，不跟随重解析点；同时拆解 `/`、`\`，拒绝逃逸、替代数据流、尾点/尾空格。祖先不可达和文件确实缺失分开 |
| 卷路径 | `VolumeIdentity::volume_path` 同时规范化原生接口返回的完整卷路径和裸 GUID。Windows 实测发现旧两种表示不兼容，已增加回归测试 |
| 命令执行 | 直接传程序及参数；每次命令使用独立输出文件，写入、进度读取和最终回读同源；保留原始字节，支持 UTF-8、UTF-16 和 OEM（系统控制台代码页）输出；短探针限时，格式化/捕获/应用没有十分钟硬时限 |
| 失败与成功 | 共享编排依次持久记录格式化意图、应用意图、引导意图和回读结果；任何一步失败停止后续操作。界面只有完整成功才报完成、询问重启。数据覆盖明确跳过格式化和引导 |
| 自动请求 | `BackupRestore/pe-requests/<id>.json` 保存结构化请求。执行前独占创建并刷新 `.claimed`，进程互斥；失败或中断后保留领取记录，后续启动不自动重放。旧 `pe-task.txt`、`pe-click.txt` 保留原件但停止执行，不能把旧文件直接当作新任务 |
| 备份 | 复用候选镜像事务，已有 WIM（Windows 映像格式）不预先删除，不就地追加唯一正式镜像；新日志目录和目标镜像在非捕获源卷 |
| ESP | 用原生卷枚举定位 EFI 系统分区（ESP），验证分区类型、BCD（启动配置数据）路径和唯一候选，不解析本地化的 `NO MOUNT POINTS`。活动 BCD 的类型检查与 bcdedit 内容回读分开；普通文件打开遇到共享锁不能误判为无 ESP |
| 引导 | 格式化前保存引导状态及 BCD 副本；引导前复核，按精确 device/osdevice/path 字段定位唯一加载器。第二系统命名、默认项和菜单顺序需要回读。完整引导事务回滚及系统可启动性仍待独立实测 |

核心文件：`crates/backuprestore-cli/src/pe_operation.rs`、`pe_safety.rs`、`native_gui.rs`、`windows_prepare.rs`，以及 `crates/backuprestore-core/src/lib.rs`。此外修复了已删除枚举的 Windows 测试引用、未使用导入，并应用仓库格式化及静态检查要求；没有放宽检查规则。

## 三、真实 PE 界面验收

通过私有 WinRE 副本启动，独立 Rust 驱动操作真实产品窗口和控件。宿主不使用前台鼠标键盘；返回时用 Parallels（虚拟机软件）的定向客体按键通道，先截图确认测试对话框，再按已核验的新快照约束返回。

工作区为 `H:\BRPE-212-20261005`，有唯一 `workspace.marker`。仅附加工作区新建的 `test.vhdx`，卷标 BRPE212，临时盘符 V:；没有格式化或还原 C:、P:、T:、F:、H: 的既有分区。C: 在原生测试中仅保存独立小文件夹，恢复镜像来源只读。

| 实际界面操作 | 结果与证据 |
|---|---|
| 备份 V: | 出现“备份完成”；实际 WIM 存在，DISM 读取成功 |

准备阶段修正两类测试脚本问题：PowerShell 数组内未加括号的字符串拼接使 DiskPart 指令串行错误；`Start-Process -Wait` 可等待派生服务而卡住，另有退出码读取为空的情况。此次仅在已核对实际命令完成、镜像挂载状态和精确脚本身份后结束卡住的测试包装进程，随后新建快照继续。后续脚本改为直接调用原生命令并立即记录 `$LASTEXITCODE`，没有把空退出码当作成功。所有这些问题均在测试脚本中，不当作产品验证通过。

## 五、交付边界

1. 本轮已验证 PE 界面的备份和五类拒绝路径，以及 Windows 一次性盘上的实际格式化/应用/失败状态；完整系统还原后的启动、第二系统启动和大镜像不在本轮通过清单中。
2. 新请求的防重放采用失败后停止，由人工核查后另建任务；不是自动断电续跑。真实 FAT/NTFS 断电持久性、请求生命周期、启动失败后的待执行请求撤销仍需补充验收。
3. BCD 副本与严格回读不能替代完整回滚事务；格式化后引导失败仍可能需要人工恢复。ESP 临时挂载的完整生命周期、并发外部工具、卷离线/克隆歧义和镜像目录竞争窗口仍需专项测试。
4. 硬盘模式 PE 安装器、主 `recover-env` 状态机和启动/清理链未在本轮重构；不得将本轮安全结论套用到这些入口。
5. 第二系统界面的主系统选择和索引选择需继续改善；未知角色不得以确认框放行。删除旧可执行文本协议是本轮有意的开发测试版变更。
6. 已校准 2.1.1 计划中“精确匹配会把 NOSYS 当 SYS”“不改名即可安全续跑”“角色未知可凭确认放行”等错误，统一遵守 D01～D10。

交付包：`dist/BackupRestore-v2.1.2-windows-arm64.zip`，包含已实测程序、Recovery.exe 同版入口、PE 启动配置、版本与本轮说明；这是 ARM64 程序包，不是可直接启动的独立 WIM。
