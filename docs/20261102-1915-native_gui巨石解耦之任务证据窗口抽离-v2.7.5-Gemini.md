## 一、背景与解耦目标

原 `crates/backuprestore-cli/src/native_gui.rs` 包含超过 11,000 行代码，汇集了主窗口、顶栏、底栏、各个 Tab、模态弹窗与二级辅助窗口。此前已有 `settings_dialog.rs`、`image_admin_window.rs`、`logs_viewer.rs`、`choice_dialogs.rs` 成功下沉至 `native_gui/` 子模块的先例。

本次解耦对象为：**「任务与证据」管理窗口（Task Admin Window）**。
该子窗口拥有自己的一套窗口类名（`BackupRestoreTaskAdmin`）、独立控件 ID 空间（`1400..=1407`）、私有模型缓存与毒化免疫锁（`TASK_ADMIN_MODEL` / `lock_task_admin()`）、以及完整的模态事件泵循环（`PeekMessageW`）。它在巨石文件中占据了近 600 行空间，与主窗口唯一的耦合点仅为入口调用：
```rust
show_task_admin(state.root, language, &state.executable_dir);
```

---

## 二、架构演化方案

1. **创建独立子模块**：
   新建 `crates/backuprestore-cli/src/native_gui/task_admin_window.rs`。
   采用 `use super::*;` 承接父模块的 Win32 API 绑定、全局字体与高 DPI 算宽机制（`fit_width` / `s()`）。
2. **完整封装自治实体**：
   - 将 `TaskSlot`、`TaskAdminModel`、`load_task_slots()` 归入子模块私有域。
   - 保留防锁毒化安全读取范式（`lock_task_admin` 取 `into_inner()`），防止 Win32 消息循环中异常打崩全局。
   - 暴露接口唯一化：`pub(super) unsafe fn show_task_admin(parent: Hwnd, language: Language, root: &Path)`。
3. **父模块瘦身**：
   在 `native_gui.rs` 中引入：
   ```rust
   mod task_admin_window;
   use task_admin_window::show_task_admin;
   ```
   移除非必要的近 600 行代码。
