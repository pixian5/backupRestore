## 4. 三条新守则（2026-10-15 用户确立，已写入项目 MEMORY.md「还原验收与现场清理」）

1. **哨兵法**：每次还原前在目标卷根放 `BR-时分秒.txt`（如 `BR-071000.txt`，精确到秒，
   防同日多次还原重名），还原后必须消失；与卷序列号变化互为印证。
2. **还原成功后删快照**：还原 C:/第二分区并成功进入系统后，`prlctl snapshot-list` 有残留
   立即 `prlctl snapshot-delete -i <id>`，不等用户提醒（本期检查：列表已空）。
3. **测试分区用后即删**：第二系统类测试卷验证通过、且无后续测试计划时，删除启动项并
   格式化释放空间，不留着占地方。

> **快照空间模型更正（2026-10-15 07:30，用户纠正本文档早期伴随结论中的错误说法）**：
> 「快照层数越多、每次修改占用越高（层数乘法）」是**错的**。正确模型：每个快照只记录
> 相对父快照的增量；一次写操作只把旧块保留进**对应的那一层父层**（CoW 不遍历所有快照、
> 不给每层都复制旧块），因此每次修改只占用一次空间。层数多的真正代价 = 各快照增量
> 各自累积、删除前不释放——所以「验证通过立即删」依然必要，但理由不是层数乘法。
> 10-12 吃满磁盘的真因 = 多轮大量写入（每轮被改块的旧版本各留一份）累积，绝非
> 「每层复制一份」。

## 6. 顺手记录：prlctl exec 传输层新坑（本期实证）

| 现象 | 结论 |
|---|---|
| `powershell -File C:\x.ps1` 报「没有提供 .ps1 文件的路径」 | **本地路径反斜杠也被吞一层**，必须双写（`C:\\x.ps1`）——与 UNC 双反斜杠同源 |
| `powershell -Command \"Write-Output X\"` 只回显不执行 | `-Command` 参数**禁带转义双引号** |
| `-Command` 内含 `\|`、`{}` 被干扰 | 管道/花括号在 prlctl 传输中不稳 |
| `wmic ... /value`、GBK 中文输出经 `strings` 后为空 | 用 `iconv -f GBK -t UTF-8` |
| 可靠落地链 | `powershell -Command`（`[char]92`/`Join-Path` 拼路径，无反斜杠字面量）→ `Out-File` → UNC 拷回宿主 |
