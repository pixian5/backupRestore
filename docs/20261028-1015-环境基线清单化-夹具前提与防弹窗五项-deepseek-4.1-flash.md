# 环境基线清单化：从 3 条注册表扩到 5 项前提

> 接上一轮（`docs/20261028-0945-…`）：那轮把「防弹窗三条注册表」脚本化了。
> 这轮把它扩成**清单**——因为这台机器上「长得像惯例、其实是前提」的东西不止三条。

* * *

## 一、为什么夹具目录也算「基线」

`boot_entry_fault` 与 `secondary_menu_repair` 两条验收用例各有自己的夹具根
（`H:\br-accept` / `H:\br-accept2`），而且都要求 `tasks/` 下**只有一个**已完成任务。

这条要求一旦破了，症状非常误导人：用例会去 `load` 到**别人的**任务，
然后以「任务不是 create-secondary」「测试任务必须先成功」之类的断言失败收场——
**看起来像产品坏了，其实是环境脏了**。

所以它和那三条注册表是同一类东西：**不成立 → 后续判据全部失真**。放进同一张清单，
门禁一进门就先把它验掉。

## 二、清单长什么样

```
ITEM=reg_persist_browsers     status=pass
ITEM=reg_nodrivetypeautorun   status=pass
ITEM=reg_nodriveautorun       status=pass
ITEM=fixture_boot_fault       status=pass
ITEM=fixture_menu_repair      status=pass
BASELINE=pass
```

每一项都是独立一行，**点名到项**；汇总行只有一句。不成立时长这样：

```
ITEM=fixture_boot_fault status=fail want=1 got=2 remanual=1
ITEM=fixture_menu_repair status=fail want=1 got=MISSING remanual=1
BASELINE=fail（注册表类可修：tools/vm/baseline.sh ensure；目录类需人工）
```

- `got=MISSING` = 目录不存在（不是「读不到」，那是 `status=error`）
- `remanual=1` = **不可自动修复**，必须人去处理

## 三、`ensure` 的边界：能修的修，不能修的不许碰

| 项 | `ensure` 会做什么 | 为什么 |
| --- | --- | --- |
| 注册表 3 项 | 写回期望值，**写完复核** | 幂等、无破坏性；上一轮的教训是「不复核就报 repaired」 |
| 夹具根 2 项 | **只报告，绝不动手** | 「多出来的任务目录」要删掉才能符合预期，而那是**别人的数据**。把它变成自动动作，下一次就会有人指着一次莫名其妙的删除问「谁干的」 |

实测：夹具里多塞一个目录 → `ensure` 输出 `BASELINE=repair_failed`，**exit 1**，
那个目录原封不动。

## 四、判据（四处变异，各自单独变红）

| 变异 | 期望 | 实测 |
| --- | --- | --- |
| 往 `H:\br-accept\tasks` 多塞一个目录 | `got=2` | `ITEM=fixture_boot_fault status=fail want=1 got=2 remanual=1`，EXIT=1 |
| 把 `H:\br-accept2\tasks` 改名（模拟丢失） | `got=MISSING` | `ITEM=fixture_menu_repair status=fail want=1 got=MISSING remanual=1` |
| 上面两种状态下跑 `ensure` | 拒绝自动删，`repair_failed`，exit 1 | 实测 `ensure_EXIT=1`，探针目录仍在 |
| 恢复后复跑 | `BASELINE=pass` | EXIT=0 |

（注册表三项的变异上一轮已验过：改回 `1` → `got=1`；删键 → `got=ABSENT`。）

## 五、这轮踩的两个格式坑（都是「判据被无关细节搞坏」）

1. **`echo BEGIN &` 在 cmd 里输出的是 `BEGIN `（带一个尾空格）**，而哨兵按 `^BEGIN$` 匹配
   → 每一项都报 `dir_unreadable`，看着像「目录读不到」，其实是格式细节。
   修：读回来先 `sed 's/[[:space:]]*$//'` 去行尾空白。
2. **`find /c /v ""` 里的 `""` 会让 `prlctl exec` 偶发报 `PrlJob_GetRetCode: Invalid argument`**
   （调用侧参数问题，不是 guest 失败）。干脆不用它——改成 **`BEGIN`/`dir /b /ad`/`END` 哨兵**：
   空目录时哨兵仍在，所以「连 BEGIN/END 都不全」才是仪器故障，**空输出不再有歧义**。
