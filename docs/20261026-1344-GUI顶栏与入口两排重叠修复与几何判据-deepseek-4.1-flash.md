# GUI 顶栏与操作模式两排重叠：修复 + 补一条几何判据（2.6.59）

> 2026-10-26 13:44。用户一句话起的头：
>
> **「gui最顶上那两排的按钮重叠了，这么严重的问题你为什么不检查？」**
>
> 这句话有两层。第一层是「把这个重叠修掉」；第二层是「为什么 7 条用例全绿还没抓到」。
> 第二层才是真问题——**改坐标只要十分钟，补不上判据，下次照样漏**。

## 1. 起点：屏幕上就是错的，而验收全绿

上一轮收尾时报的是「冒烟 10/10 PASS」。用户随手截了个图，一眼就看见：
「操作模式」那 6 个入口按钮，被顶栏「查看日志… / 备份文件管理… / 取消待重启任务… / 设置… / 语言」压在上面，
`新增非 C 盘第二系统`、`安装 PE`、`探测（仅检查）` 三个入口几乎整块被盖住，还留着残影。

当时 7 条既有用例分别问的是：

| 用例 | 问的问题 |
|---|---|
| 查看日志窗口 | 窗口**存在**吗、能关吗 |
| 备份文件管理窗口 | 清单**填充**了吗、提示非空吗、详情可读吗 |
| 探测入口 | **选中**了吗、无关字段隐藏了吗 |
| 探测实跑 | 任务目录**建出来**了吗 |

**没有一条问「两个控件是不是占了同一块像素」。** 这就是漏的原因，不是运气差。

## 2. 根因：两排控件共用了一个 `y = 60`

顶栏 5 个控件（语言标签、语言下拉、设置、取消待重启任务、备份文件管理、查看日志）与操作模式的
6 个入口按钮**全部创建在 `y = 60`**。入口从 `x = 90` 向右排到 ~741，顶栏按钮从右边往左排，
最小宽度下最左的「查看日志…」落在 `x ≈ 227–347`，正好压在入口上面。

原注释写着「最小窗口 1020 宽下两者不重叠」——它只对「6 个入口 + 语言栏两者」成立，
**没把后来追加的四个顶栏按钮算进去**。这行注释本身就是陷阱：它给了后来者「这块算过了」的错觉。

`GetWindowRect` 实测（`CLIENT_W=1175 CLIENT_H=898`）**6 对重叠**：

```
tab_restore_nonC x btn_view_logs    =  10x24 px
tab_secondary    x btn_view_logs    = 107x24 px   ← 该按钮宽 150，被盖 71%
tab_secondary    x btn_image_admin  =  35x24 px
tab_install_pe   x btn_image_admin  =  72x24 px
tab_probe        x btn_image_admin  =  27x24 px
tab_probe        x btn_cancel_pending = 83x24 px
```

## 3. 修法：顶栏独立成一行

新增一个具名常量，创建坐标与 `layout_operation` 的重排坐标**全部改用它**：

```rust
/// 顶栏操作按钮（查看日志… / 备份文件管理… / 取消待重启任务… / 设置… / 语言）
/// 独立成一行，放在客户区顶部这条原本空着的窄带里。
const TOP_BAR_Y: i32 = 18;
```

共 11 处 `y: 60` → `TOP_BAR_Y`：创建侧 5 处（语言 combo、`ID_SETTINGS`、`ID_VIEW_LOGS`、
`ID_IMAGE_ADMIN`、`ID_CANCEL_PENDING`），`layout_operation` 内 6 处（语言标签 `TOP_BAR_Y + 7`、
语言 combo、设置、取消待重启、备份文件管理、查看日志）。原先那条误导注释一并订正。

版本 `2.6.58 → 2.6.59`（改了可见行为，三处同步：`VERSION` + 两个 `Cargo.toml`，跑 `cargo check` 刷 `Cargo.lock`）。

修后 `OVERLAP_COUNT=0`，顶栏独占一行、六个入口全部完整露出。

## 4. ★ 真正难的部分：**判据仪器自己坏了三回**

补的判据是 `tools/win-clicker/_t-layout-rects.ps1`：枚举窗口的子控件、取 `GetWindowRect`、
两两算交叠面积，`OVERLAP_COUNT=0` 才算通过。它写了三版，**前两版都是「报绿灯的坏仪器」**。

### 4.1 第一版：手挑 15 个控件，只查当前页

能测出 6 对重叠，但只证明「当前打开的那一页」。**隐藏行会把别的行顶上去，六个入口的可见字段集完全不同**
（实测可见子控件数：`backup` 30 / `restore_c` 28 / `restore_nonC` 30 / `secondary` 32 /
`install_pe` 33 / `probe` 18）——只查一页等于只验了 1/6。

而且手挑清单这个思路本身就该废掉：2.5.2 那次「底部按钮行压住严格对比哈希复选框」是同一类缺陷，
手挑清单同样会漏。

### 4.2 第二版：全量枚举 + 六页全查，但**同步 `SendMessage`**

改成 `EnumChildWindows` 枚举全部直接子窗口、`BM_CLICK` 逐个翻六页各查一遍。看着完备了，
结果**在变异版本上照样报 `OVERLAP_COUNT=0`**——而截图里按钮明明还压着。

根因：`BM_CLICK` 用了 **`SendMessageW`（同步）**。这是本项目反复踩过的坑（模态处理会挂住同步发送），
脚本直接死掉、**一个字节都没写**。于是 `type` 读回来的是**上一次（修好之后跑的那次）留下的旧文件**，
内容当然是 0。

判断这一步差点被骗过去：两次输出连 `visible_children` 计数都一模一样，看起来像「稳定复现」。

### 4.3 抓到「读的是旧文件」的办法：先删再跑

```
del /q H:\brwork\gui-layout-rects.txt   → 重跑 → 文件根本不存在
```

一次就证明了「脚本没写盘」而不是「脚本算出 0」。**以后凡是「结果文件内容可疑」，先删再跑，别猜。**

另一处自己给自己挖的坑：body 钩子文件 `H:\brwork\gui-token-body.txt` 里还是上一个诊断脚本的名字，
中间有两轮实际跑的是**别的脚本**。钩子路径是隐式输入，跑之前必须 `type` 一眼。

### 4.4 第三版：`PostMessage` + 逐页落盘 + 全量矩形

```powershell
[void][Lay]::PostMessageW($tabHwnd, $BM_CLICK, [IntPtr]::Zero, [IntPtr]::Zero)   # 异步，不阻塞
...
Emit "PAGE $tabName visible_children=$($snap.Rects.Count)"
foreach ($rc in $snap.Rects) { Emit ("  RECT {0} x={1} y={2} w={3} h={4}" -f ...) }
```

关键是**每翻一页就落盘一次**（`Add-Content`），开头先写一行 `STARTED`：

- 文件里有 `STARTED` 但没到 `PAGES_CHECKED` → 中途挂了，能看出卡在第几页；
- 文件根本不存在 → 启动器或 `Add-Type` 就失败了；
- 两者都与「判据不满足」严格区分。

同时把每一页的全部矩形（名字 + `x/y/w/h`）写进结果文件：将来任何一次变红，现场数据直接在手，
不用再写第二个诊断脚本重跑一遍。

## 5. 变异验证：36 对 vs 0 对

判据必须证明「能变红」，否则等于没有判据。

| 部署 | 源码 | `OVERLAP_COUNT` | `PAGES_CHECKED` |
|---|---|---|---|
| 变异版 | `TOP_BAR_Y = 60` | **36**（6 对 × 6 页，逐页列出） | 6 |
| 正式版 | `TOP_BAR_Y = 18` | **0** | 6 |

三版部署 SHA 依次 `91ce9062…`（正式）→ `1294aebc…`（变异）→ `47d4bb7f…`（恢复后最终）。

★ 注意变异版是**逐页都报 6 对**，不是只有一页——这反过来证明了「六页全查」是必要的：
每页的可见字段集不同，但顶栏与入口的横向排布不变，所以每页都该独立成立。

## 6. 判据与结果

`tools/smoke/gui-clicks.sh` 新增第一条用例：

```bash
run_case _t-layout-rects.ps1 'H:\brwork\gui-layout-rects.txt' '全部页签两两不重叠（几何判据，全量枚举）' \
    'OVERLAP_COUNT=0' 'PAGES_CHECKED=6' 'CLIENT_W='
```

三条断言各管一件事：

| 断言 | 证明 |
|---|---|
| `OVERLAP_COUNT=0` | 真的没有两块像素重合 |
| `PAGES_CHECKED=6` | 六页**都走完了**（挂在中途就不会有这行，防止「只查一页」复活） |
| `CLIENT_W=` | 窗口确实量到了（防止枚举到空集也算通过） |

结果：**冒烟 10/10 PASS**。冒烟用例数 4 → 5，断言数 7 → 10。

顺带补掉一条隐性断裂：`.gitignore` 里 `tools/win-clicker/_*.ps1` 是被忽略的，而入库的
`gui-clicks.sh` 要调用 `_t-layout-rects.ps1`——加 `!tools/win-clicker/_t-layout-rects.ps1` 例外，
否则换台机器 clone 下来跑冒烟会直接找不到文件（同一类问题 12:47 那轮刚修过四条例外，这次是第五条）。

## 7. 可复用的钉子

1. **「控件存在 / 点得动」不等于「看得见」**。可见性缺陷只能靠几何判据抓：同一父窗口下两个可见子控件
   不得占据同一像素。这类缺陷有过两次（2.5.2 底部按钮压复选框、本轮顶栏压入口），说明它不是偶发。
2. **两排控件共用同一个 `y`，必须按最坏宽度核算**：最小窗口宽 + 最长文案的语言 + 后加的全部按钮。
   「各自的起点不冲突」这种算法会因为「后来有人往这排再加一个按钮」而失效，而且失效时没人会想起来重算。
3. **验收脚本用同步 `SendMessage` 会静默死亡**。要 `PostMessage`；并且结果文件开头写 `STARTED`、
   逐段 `Append`，否则死掉的脚本留下的旧文件会被当成「通过」。
4. **结果文件可疑，先删再跑**。`del` 之后文件不存在 = 脚本没写盘；文件在但内容不全 = 中途挂了。
   这两种都不该被读成「判据满足」。
5. **钩子/配置文件是隐式输入**，跑之前 `type` 一眼。我这两轮各有一回跑的是别的脚本。
6. **判据必须做变异验证**：把修复改回缺陷值，新用例必须变红。这次两步都做了（6 对 → 0 对）。
7. **`retry` 不能替代「区分空返回与判据不满足」**。通道偶发返回空是真实存在的，但这次的空不是通道问题，
   是脚本没写文件——两者必须分开报，否则会把产品缺陷记成基础设施抖动。
