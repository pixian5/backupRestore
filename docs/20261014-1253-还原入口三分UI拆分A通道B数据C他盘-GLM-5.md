# 还原入口三分：UI 拆分 A（系统还原C盘）/ B（数据卷还原）/ C（他盘系统还原）

> 模型：GLM-5（bigmodel-api/GLM-5.3）｜版本 **2.4.9 → 2.5.0**（满十进一）
> 对应交接文档待办 2（UI 三入口拆分），底层机制零改动（复用 2.4.9 的收尾路由）。

## 1. 本轮做了什么

把「单系统还原」一个 tab 拆成三个入口，tab 总数 4 → **6**：

| tab | 内部键 | CLI operation | 通道 | 目标约束 |
| --- | --- | --- | --- | --- |
| 备份 | `backup` | backup | 智能分流（不变） | — |
| **A · 系统还原C盘** | `restore-existing` | restore-existing | 必离线（PE/RE 弹窗） | **锁定 `%SystemDrive%`**，下拉禁用、显示实际盘符 |
| **B · 数据卷还原** | `restore-data` | restore-existing | 默认在线，可选离线 | ≠系统盘、≠已有 Windows 的卷 |
| **C · 他盘系统还原** | `restore-system-other` | create-secondary | 默认在线，可选离线 | ≠系统盘；需菜单名（在线离线都要） |
| 新增第二系统 | `create-secondary` | create-secondary | 必离线（不变） | ≠系统盘（P0 闸） |
| 安装 PE | `install-pe-entry` | — | —（不变） | — |

**核心映射决策**：C 复用 `create-secondary`（交接文档 §2.4 自己说「C 与新增第二系统仅存差别是可在线」）——P0 安全闸、菜单名必填、NewWindows 收尾全套免费；B 复用 `restore-existing`（在线路径已天然支持数据卷不格式化）。**底层（core/prepare/RE 收尾）一行未改**。

## 2. 改动清单（文件:要点）

### crates/backuprestore-cli/src/native_gui.rs（主体）

1. **常量/控件**：新增 `ID_OPERATION_RESTORE_DATA=1105`、`ID_OPERATION_RESTORE_OTHER=1106`、`ID_CHANNEL_ONLINE=1212`、`ID_CHANNEL_OFFLINE=1213`；`operation_tabs: [Hwnd; 4] → [Hwnd; 6]`（6 个 84px 按钮从 x=180 排到 704，避开 x=755 的语言下拉）。
2. **`selected_operation()`**：6 项映射 + 三个新辅助函数：
   - `cli_operation()`：GUI 键 → CLI operation（B→restore-existing、C→create-secondary）；
   - `is_image_restore_entry()`：A/B/C/新增第二系统共用的「镜像还原类」闸门（原 10 处 `matches!("restore-existing"|"create-secondary")` 全部换成它）；
   - `active_system_letter()`：`%SystemDrive%` 归一（无冒号大写）。
3. **可见性矩阵**（`set_operation_visibility`）：源卷行只在备份/新增第二系统显示（A/B/C 隐藏——P3 的「源卷（当前系统）」误导文案随隐藏消除）；菜单名在 C/新增第二系统显示；通道单选只在 B/C 显示；**A 的目标下拉 EnableWindow(0)**。
4. **布局**（`layout_operation`）：源卷行隐藏时目标行上移到 y=100；通道单选行在目标卷详情框下方（在线 180-480 / 离线 500-860）；C 与新增第二系统共用带菜单名的索引布局。
5. **`select_operation`**：进入 A 时自动 `select_drive(target, %SystemDrive%)`；进入 B/C 时通道复位「在线」（防跨入口残留离线选择导致误格式化）+ **目标自动跳离系统盘**（B=非系统非 Windows 卷、C=非系统卷，找不到就不动、交给创建闸门报错）。
6. **`refresh_environment`**：刷新卷列表后 A 重新锁定系统盘。
7. **`create_task` 校验链**：
   - 目标先选、源卷按入口归一（A/B 源=目标，C 源=系统盘，备份/新增第二系统仍读源卷下拉）；
   - 新闸门①：B/C 目标 == 系统盘 → 拦下并指引用 A 入口；
   - 新闸门②：B 目标含 Windows 安装 → 拦下并指引改用 C/新增第二系统（数据通道不修引导）；
   - 新闸门③：C 菜单名为空 → 拦下（create-secondary prepare 必填）；
   - **A 容量预检加强**：`metadata.required_target_size()`（=max(备份时源分区大小, 已用+保留量)）vs 目标分区总大小，不足在重启前拦下（进 PE 才发现=白重启）；
   - 智能分流重构：A 必走 PE/RE 弹窗（不受 affected 比较影响）；备份行为不变；
   - **B/C 通道分流**：在线→`run_online_operation(cli_operation)`（C 的菜单名经 `image_name` 传给在线通道，`restore_to_windows_volume` 会优先用它命名新启动项）；离线 B→通用文案的 PE/RE 弹窗（新静态 `CHOICE_GENERIC_OFFLINE`，弹窗 WM_CREATE 时 swap 消费）→PE=排队 PE 任务 / RE=确认后提权 prepare；离线 C→与新增第二系统完全一致直接提权 prepare；
   - `--operation` 参数传 `cli_operation()` 归一后的值。
8. **文案**：tab 标签/tooltip/状态栏提示/目标卷用途说明全部中英双语补齐（B 的提示明确写「在线不格式化（覆盖），离线会 diskpart 格式化」）；顺手修了 P3 的 create-secondary tooltip 误导（"current Windows to keep"→"kept untouched"，代码里本无此校验）。
9. **测试钩子**：`br-test.json` 的 `tab` 支持 6 个键 + 新增 `channel:"online"/"offline"`；`--tab N`/`BACKUPRESTORE_OPEN_TAB` 范围 `(0..=5)`。

### crates/backuprestore-cli/src/online_operation.rs

新增 `"create-secondary"` 分支：C 的在线通道，**无条件**走 `restore_to_windows_volume`（格式化→应用→盘符重绑→bcdboot→菜单命名），不按目标现状分叉——这条入口的语义就是装系统。`execute_inner` 顶部的 `affected==活动系统` 拒绝天然保证目标≠系统盘。

## 4. 已知未验项 / 遗留

1. **三入口的端到端任务执行未跑**（本轮只验 UI 布局与控件态）：按交接文档 §2.5，B 在线还原 T: / C 离线还原 E:（= P1 收尾路由实机验证，最高优先）/ A 全链路（风险最高放最后）。
2. C 在线通道（online_operation 的 create-secondary 分支）零实机记录；离线 C 恰好就是待办 1 的 P1 验证路径——**做待办 1 时直接用 C 入口离线通道跑**，一次验两个。
3. GUI 自动化坐标表漂移：tab 按钮/源卷行/通道行的屏幕坐标全变了，`tools/win-clicker` 里引用旧坐标的脚本需要重新测量（本轮用 `GetDlgItem+GetWindowRect` 枚举法可复用）。
4. B 目标自动跳选落在「第一个合法卷」（本次是 F:），不保证是理想卷（如 T:）——用户仍需自查；不做成更智能的猜测。
5. menu 默认值在中文界面偶现 'Windows Backup'（应为「Windows 备份」）——apply_language 的默认值替换逻辑时序问题，不影响功能（用户可编辑、创建时校验非空），列入低优先待办。
6. PE 桌面（`--pe-desktop`）的任务对话框仍是「备份/还原/第二系统」三分，未跟随主窗口拆分——PE 内本无在线/离线之分，暂不需要。
