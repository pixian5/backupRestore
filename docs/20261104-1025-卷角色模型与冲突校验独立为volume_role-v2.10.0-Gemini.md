## 一、架构背景与重构动因

在 BackupRestore 的任务生命周期与启动链中，**卷身份与卷角色**是系统最底层的安全基石：
1. **方案 A 的基石：Verbatim 卷路径（`\\?\Volume{GUID}\`）**：
   在联机与 WinRE 恢复环境下，读写卷无需且绝不应依赖临时盘符。Rust `std::fs` 底层 `CreateFileW` / `CopyFileExW` 以及 Win32 `bcdedit` / `dism` 均直接支持 verbatim 路径。原 `lib.rs` 内的 `volume_path()` 通过精确 ASCII 字节拼接严格防范脏盘符和反斜杠格式退化。
2. **多卷角色校验与冲突阻断（`validate_volume_roles`）**：
   任务涉及程序工作区卷（`workspace`）、镜像存储卷（`image`）、备份源卷（`source`）与还原目标卷（`target`）。为避免还原目标清空破坏宿主系统或备份阶段捕获污染，`validate_volume_roles` 构筑了严密的分区级防线。
3. **消除核心巨石、实现高内聚自治**：
   此前 `crates/backuprestore-core/src/lib.rs` 行数高达 1,673 行，混合了任务定义、卷角色模型、容量计算与顶层规范。将卷角色模型及其专属单测独立抽取为 `volume_role.rs`，可使 core 库职责高度内聚、结构清晰，并为后续抽离容量规划（`capacity_plan.rs`）扫清道路。

## 二、抽取清单与 API 零漂移保证

### 1. 独立自治模块：`crates/backuprestore-core/src/volume_role.rs`（449 行）
完整收拢以下领域模型：
- **`VolumeIdentity` 结构体及其实装方法**：
  - `new(disk_guid, partition_guid)`：基础卷身份构造；
  - `is_complete()`：所有磁盘、分区、卷 GUID、文件系统及大小必填项完整性校验；
  - `same_partition(&self, other: &Self)`：大小写不敏感的跨卷物理分区同体比对（`disk_guid` + `partition_guid`）；
  - `volume_path()`：严格校验并构造 38 字符标准带花括号的 verbatim 设备路径（`\\?\Volume{...}\`）；
  - `is_reserved_partition()`：精准识别 ESP、MSR 及 Windows Recovery 特殊保护分区 GUID。
- **`VolumeRoleConflict` 枚举及其实装方法**：
  - 枚举项：`WorkspaceOnRegisteredWinre`、`ImageOnRegisteredWinre`、`BackupSourceOnRegisteredWinre`、`RestoreTargetOnRegisteredWinre`；
  - `code()`：返回不可变、可用于跨进程日志和 GUI 分支判断的稳定字串错误码；
  - `message()`：面向最终用户的详尽行动指导性说明文案。
- **`VolumeRoles` 结构体**：
  - 四角色引用捆绑（`workspace`, `image`, `source`, `target`）。
- **`validate_volume_roles` 核心校验函数**：
  - 判定操作类型与恢复环境宿主分区的互斥规则，安全放行或准确拦截。

所有外部调用方（如 `backuprestore-cli`、GUI、Recovery）均无感知，保留原有导入路径，代码 100% 零修改、零漂移。
