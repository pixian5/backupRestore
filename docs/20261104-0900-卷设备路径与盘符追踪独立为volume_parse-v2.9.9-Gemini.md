## 一、背景与动机

`crates/backuprestore-cli/src/text_parsing.rs` 是「macOS 本机也能被 `cargo test` 完整覆盖的纯解析逻辑」的家。v2.9.6（`wim_parse`）、v2.9.7（`bcd_parse`）、v2.9.8（`step_progress`）已连续三轮把 WIM/BCD/步骤进度三类自治职责抽走。本轮收走的是**最后一大块与「文本解析」名实不副的卷语义职责**：

1. **mountvol 查询三态判定（`VolumeMountQuery` / `classify_mountvol_output`）**：`Mounted` / `Unmounted` / `Unknown` 三态必须严格区分——把 `Unknown`（查询超时）当 `Unmounted`（盘符空闲）处理，曾让恢复路径绕过「拒绝覆盖已有挂载」守卫，是实机事故级教训；
2. **mountvol 无参清单解析（`parse_mountvol_listing` / `mountvol_listing_has_volume`）**：卷 GUID ↔ 盘符配对（多语系表头免疫）；`/L` 有卷判定是「ESP 挂载成功」的**唯一可靠判据**（`/S` 退出码会骗人，2026-09-29 提权实测）；
3. **卷路径 ↔ 设备路径转换（`volume_path_to_device_path` / `device_path_volume_name` / `esp_volume_prefix`）**：卷 API 吃 `\\?\Volume{GUID}\`、设备 API 吃 `\\.\Volume{GUID}`，混用报 `CreateFileW` 161/162；NT 命名空间大小写无关（2026-10-19 实机缺陷修复）；
4. **卷标识符归一化比较（`bare_volume_guid` / `same_volume`）**：裸 GUID / verbatim 路径 / 大小写三种写法必须判等（2026-09-30 实机事故：盘符挂成功了但身份比输，日志看起来像「每个盘符都挂不上」）；解析不出 GUID 必须拒绝相等；
5. **ESP 取证日志路径（`ESP_LOG_SUBDIR` / `esp_log_path_on`）**：子目录纪律（ESP 根目录曾堆 38 个日志拖慢固件枚举）、盘符零假设（路径只来自调用方已核验的卷根）；
6. **共享卷盘符复用表（`MountedVolumes`）**：diskpart `assign letter=` 是**移动**不是新增，同卷双角色必须复用同一盘符（RECOVERY/SOURCE 同卷时 `S:` 抢走 `R:` 的事故）；
7. **盘符时间线（`letters_in_mask` / `letter_delta_line`）**：2026-10-29 用户裁决「盘符这件事要观测」的纯逻辑半边（采样与写文件在 `letter_trace.rs`），输出全 ASCII（进 `prlctl` 铁律）。

以上七类全部是「卷/盘符的语义」，与「文本解析」只剩「恰好都吃字符串」这一点共性——按自治边界应当独立成 `volume_parse.rs`。

## 五、本轮新经验

### 1. glob 再导出在非 Windows 纯 check 下会被误报 unused

`pub(crate) use crate::volume_parse::*;` 在 macOS `cargo check`（不带 `--tests`）下报警告 `unused_imports`，带 `--tests` 或 Windows 构建则无警告。根因：**再导出的全部生产调用点都在 `#[cfg(windows)]` 函数体内**（如 `prepare_mount.rs` 的挂载探测），非 Windows 编译单元里这些路径根本不存在；只有测试（`--tests`）与非 Windows 可达的少量测试代码在用。前三个再导出（wim/bcd/step_progress）碰巧有非 Windows 生产使用点所以从未暴露。处理：该行加 `#[allow(unused_imports)]` 并注释原因，不做 `cfg` 条件化（Windows 侧与测试侧都是真实使用点）。

### 2. 「删除脚本 + doc 粘连」是残留事故温床

按 `#[test]` → 连续 `///` 回溯定位测试块边界的脚本，在本文件遇到了**上一轮遗留的 doc 与 doc 直接粘连**（无空行、无属性分隔），删除后留下了三段孤儿 doc，且第一次修补时又引入了孤立括号。修法与教训：

- 删块脚本必须对「块前一行」「块后一行」做 assert 校验（本轮脚本有 assert，所以崩溃可见而非静默删错——但 assert 通过≠边界正确，粘连场景下 assert 本身会骗人：上一块的 `}` 恰好能被误当分隔）；
- 删完必须 `cargo check` + 逐段重读文件尾部与接缝，**「跑过了」不等于「删干净了」**；
- 根治手段是本轮顺手做的：把孤儿 doc 归位/删除，让「doc 紧贴函数名」恢复一一对应，下次任何搬移脚本都不会再被粘连骗到。

### 3. `esp_volume_prefix` 补上了形状锁定单测

迁移清单核对时发现它是唯一零专属单测的公开函数。「反斜杠个数只有一处说了算」这条纪律此前只靠纪律本身，现在有测试钉死。
