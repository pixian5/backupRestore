# 外部命令失败带码 + 启动菜单修复的拒绝路径入门禁（v2.6.69）

> 撰写：2026-10-27 21:08。前序：`docs/20261027-1055-第二系统映射拒绝路径入门禁`。
> 本轮把一个**只读拒绝用例**接进门禁，它当场逼出三处「码没追到出口」的产品缺陷。

## 1. 为什么要加这条用例

`secondary_menu_repair_native`（改启动菜单）需要「已完成的第二系统任务 + 已挂载 ESP + 新核验快照」，
环境一删就**永远 SKIP**——而它是**真实修改启动菜单**，是最该有常态护栏的一类。

先读守卫再谈夹具（10-27 上午确立的做法）：

| 用例 | 前置守卫 | 能否常态化 |
|---|---|---|
| `secondary_registry::repair()` | 身份不符 / 目标是当前系统盘 / 缺 hive，**纯拒绝、一个字节不写** | ✅ 已做（10-27 上午） |
| `preserve_primary_boot_manager()` | 第一句 `bcdedit /store <ESP>\EFI\Microsoft\Boot\BCD /enum all /v`：**读不到存储就返回** | ✅ 本轮做 |
| `winre_offline_reg` | `/copy` 作用于**活动 BCD 存储** + reagentc，必须 PE | ❌ 夹具解决不了 |

新用例 `secondary_menu_repair_rejections`：给一个**不存在的 store 路径**（临时目录），
断言「必须报错」「失败必须带码」「不得创建 `EFI` 目录」——不需要 ESP、不需要快照、不需要第二系统。

## 2. 用例第一次跑就红了，红得有价值

失败证据：

```
invalid task: bcdedit.exe failed with exit code: 1
```

**不带错误码**。而 `--json` 的 `errorCode` 就会是 `null` —— 正是 2.6.51 那类
「`Coded` 的码到出口被无码 `err()` 顶掉」的缺陷复发。根因：

| 路径 | 非零退出时 | 结果 |
|---|---|---|
| `run_logged`（流式落盘） | `errc_with(ProgramFailedNamed)`（`BR-APL-009`） | 有码 + 输出尾部 |
| **`capture_logged`（一次性收集）** | `err(...)` | **无码** |
| **`run_command`（直通，不捕获）** | `err(...)` | **无码** |
| **`windows_prepare::run_bcdedit_quiet`** | `err(...)` | **无码** |

同一类失败（外部命令非零退出）在四条路径上**一条有码、三条没码**。

## 3. 修法与新增的码

- `capture_logged`、`run_bcdedit_quiet` → 改用 `ProgramFailedNamed`（`BR-APL-009`），
  附**内存里已有**的输出尾部（不重读文件）。为此在 `text_parsing` 加纯函数
  `tail_of_text(&str, max) -> &str`：按字节截尾并把起点挪到最近的 char 边界
  （直接 `&text[len-max..]` 会在多字节字符中间切开而 panic）。
- `run_command` 是**直通**通道（子进程输出直接给用户，不捕获），没有尾部可附。
  第一版复用了 `BR-PE-039`（模板 `{0} 失败：{1}\n{2}`）并传空串，实机 `--json` 里出现
  `"[BR-PE-039] cmd.exe exit code: 3\n"` —— **文案尾部一个裸换行**。
  改用新码 `ProgramExitNonZero`（`BR-APL-010`，模板 `{0} 失败：{1}`）。
  `docs/ERROR-CODES.md` 由 `tools/gen-error-codes.py` 重生成（215 条 CLI 码 + 3 个结构性码）。

## 4. 验收

| 项 | 结果 |
|---|---|
| 单测 | CLI **306** + core **56** 全绿（新增 `tail_of_text` 边界用例、`dispatch_failure_carries_its_code_even_without_json`） |
| Windows 目标编译 | 零新增告警；VM 原生部署 `9e56b6cd…` |
| ignore 门禁 | **pass=5 fail=0 skip=5**（原 4；新增 `secondary_menu_repair_rejections`） |
| GUI 冒烟 | **PASS=42 FAIL=0** |
| 端到端 | `run-command cmd.exe /c exit 3 --json` → `"error_code":"BR-APL-010"`，文案无尾部换行（`od -c` 逐字节确认 `3` 后直接是 `"`） |

**变异（判据不变红等于没有判据）**：

1. 把 `capture_logged` 改回无码 `err()` → `secondary_menu_repair_rejections` **FAIL**
   （`assert_eq!(error.code(), Some("BR-APL-009"))`）。
2. 把 `run_command` 改回无码 `err()` → `dispatch_failure_carries_its_code_even_without_json` **FAIL**（mac 侧）。
3. 恢复后两条各自转绿，`grep MUTATION` = 0。

## 5. 顺手踩到的两个坑

- **★ `#[cfg(windows)]` 被插入位置打断**：用「锚点替换」插入新用例时，原用例的 `#[cfg(windows)]`
  留在了锚点之前 → 我插入的新函数拿走了这个属性，原用例失去门控，于是 mac 侧 `cargo test`
  立刻报 `cannot find Operation in super`（3 个 E0425/E0433）。
  **教训**：插入新测试时，锚点要包含**它自己的全部属性**，别把属性行留在外面。
  这次的「红」反而是好事——说明 mac 侧编译也能抓到这类结构性错误。
- **★ 升版本必须刷 `Cargo.lock`**：改了两处 `Cargo.toml` 后直接进 VM 构建，`--locked` 报
  `cannot update the lock file X:\Cargo.lock because --locked was passed`。本地跑一次
  `cargo check --offline` 即可刷新（不出网）。

## 6. 判据设计上的两条结论

- **断言「有码」不够，要钉住具体码**：第一版写 `error.code().is_some()`，只能证明「有码」，
  证明不了「是对的那个码」。改为 `assert_eq!(error.code(), Some("BR-APL-009"))` 后，
  将来换了码也会红。
- **能跨平台跑的判据优先**：`run_command` 的回归测试用 `sh -c 'exit 3'` 而不是 Windows 专有程序，
  这样它在 mac 上也跑（本项目最贵的教训之一：`#[cfg(windows)]` 里的测试在 mac 上是零信息）。

## 7. 追加：门禁补一道「用例真在二进制里」的核对（同日）

上一条「插入测试抢走 `#[cfg(windows)] #[test]`」的坑，**最危险的不是编译错误，而是它的静默版本**：
本轮原用例 `secondary_menu_repair_native` 确实丢了 `#[test]`，编译只报一句
`function ... is never used`；而门禁在「环境变量缺失」那一步就 SKIP 了，
**永远不会发现这条用例根本不在这份测试二进制里** —— 即「改启动菜单」这条最危险路径
从「偶尔手跑」退化成「根本不存在」，却仍显示 SKIP（看起来像可跑）。

修法（`tools/test/ignored-acceptance.sh` 新增 STEP 3/4）：

- 跑之前先 `cli-tests.exe --ignored --list` 取**真值**，任何一条 filter 在列表里找不到
  → `CASE=<名>=FAIL reason=test_not_in_binary`（**这是缺陷，不是环境缺失，不许记 SKIP**）。
- 两个仪器细节（第一版都踩了，各造出 4 条假红）：
  1. **`--list` 是边输出边刷新**：看到第一行就 `break` 会只拿到前几条 → 必须等结尾
     `N tests, 0 benchmarks` 出现；
  2. **过滤器是子串，不是路径后缀**：列表里是 `pe_operation::tests::disposable_vhd_preflight_
     index_two_apply_and_reject_without_write: test`，而表里写的是 `reject_without_write`，
     所以用 `grep -F <filter> | grep ": test"`，不能用 `grep "::$filter: test"`。
- 变异：把表里的 filter 故意改错一个字母 → `CASE=...=FAIL reason=test_not_in_binary`，
  `SUMMARY pass=0 fail=1 ran=0`；恢复后回到 `pass=5 fail=0 skip=5`。

**判据**：SKIP 只能表示「环境不具备」，不能表示「用例不存在」。这两件事的处置完全不同。
