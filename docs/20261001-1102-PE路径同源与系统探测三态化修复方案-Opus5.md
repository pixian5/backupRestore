### 2.1 授权与受保护角色矩阵

`DestructiveConsent`（破坏性确认）绑定任务、目标稳定身份、镜像/索引、意图和处理模式。确认只是必要条件之一，**不能覆盖任意受保护卷**。

| 目标或冲突 | 系统替换 | 第二系统安装/重装 | 数据覆盖 |
|---|---|---|---|
| 当前正在运行的系统卷/内存运行卷 | 不在线执行，先安排合适离线环境 | 拒绝 | 在用系统卷不得当普通数据覆盖目标 |
| 任务指定的主系统卷，当前已离线 | 仅明确系统替换且所有检查通过时允许 | 拒绝；若确需替换主系统，须另建系统替换任务 | 不隐式转为系统替换 |
| 另一个已有 Windows 的卷 | 需明确绑定目标和替换意图 | 可以，但主系统已确认且目标覆盖获得明确确认 | 不因其“不是默认项”自动放行 |
| 镜像卷、权威工作区卷、仍需的恢复载荷卷 | 格式化目标与之重合时拒绝 | 同左 | 拒绝源镜像与覆盖内容冲突 |
| ESP、保留分区 | 不作为镜像格式化/应用目标 | 同左 | 不作为普通数据覆盖目标 |
| BCD 引导写入目标 ESP | 独立的引导写许可，仅限指定对象与存储 | 同左，保留主系统约定 | 不适用，不运行引导修改 |
| 必需角色无法确定、多个身份候选 | 拒绝，补齐证据后重新规划 | 拒绝 | 拒绝依赖该未知信息的写操作 |

**重要区分：** 已有可信计划和现场证据证明某检查不适用于当前阶段，可按契约跳过；这不等于“检查失败后用户同意就放行”。例如独立恢复载荷已验证，原 WinRE（Windows 恢复环境）卷仅为历史模板来源时，不再强制依赖其旧序列号；它若仍是工作区或镜像源则必须可达。

启动存储损坏而需修复时，应有单独、可验证目标与作用范围的恢复计划；本方案不通过给普通还原入口增加通用豁免来处理。

## 三、PE 路径与探测：已核实机制及适用边界

### 3.1 写入和读回路径不同源

`text_parsing.rs::esp_log_path` 将普通文件放在 `S:\BackupRestore\logs\`，但若干命令仍把输出重定向到 `S:\` 卷根。这一静态差异与是否真的成功执行命令是两回事。

| 文件组 | native_gui.rs 写入行 | 读回行/用途 |
|---|---|---|
| `format-check.txt` | 7695 | 7700：格式化保护 |
| `bcdboot-check.txt` | 7734 | 7739：是否修引导 |
| `find-drive.txt` | 7580 | 7585：标记盘定位 |
| `find-system.txt` | 7674 | 7678：系统盘定位 |
| `find-marker.txt` | 7510 | 7514：测试卷定位 |
| `format-out.txt` | 7713 | 7718：格式化输出 |
| `bcdboot-out.txt` | 7769 | 7775：引导工具输出 |
| `bcdboot-def-before.txt` | 7747 | 7751：先前默认项 |
| `bcdboot-after.txt` | 7781 | 7786：引导回读 |
| `bcdboot-restore.txt` | 7815 | 7825：默认项恢复日志 |
| `bcdboot-order.txt` | 7821 | 仅写；仍需纳入统一输出管理 |
| `verify-bcd-enum.txt` | 7450 | 7453：取证 |
| `verify-dir.txt` | 7458 | 7459：目录取证 |
| `dir-attached.txt` | 7522、7592 | 7525、7595 |
| `attach-vhd-out.txt` | 7501 | 7505 |
| `pe-addsec-create.txt` | 7848 | 7853：新建对象标识 |
| `diag1`～`diag4` | 7605～7617 | 7622～7625 |

这是**文件组清单**，不把只有写入的条目和四个诊断文件硬算成相同数量的写读配对。`backup-out`、`restore-out` 等原本同源的文件也统一使用新输出对象；进度窗口必须消费同一文件/流引用。

读回路径不存在时，系统标记保留默认 `false`，可能导致保护失效或跳过引导；有旧文件、人工文件或其他生产者时，可能读到陈旧内容。不能据此声称“所有环境恒为 false”“相关代码永远不可达”。

### 3.2 控制通道必须两端同步

`ESP_CONTROL_FILES` 当前只有三个 `pe-task*` 名称；`pe-click.txt` 及 `.done` 会被定位到日志子目录。沿用历史“向 ESP 卷根写 pe-click”的生产者时，消费者无法收到该请求。若生产者也写子目录，则未必失效；因此不能推翻所有历史自动验收，也不能仅凭白名单推断 2.0.4 闭环实际走了哪条入口。

`AUTO`（自动定位）的中间文件同样可能为空或陈旧；新方案必须唯一解析身份，不能把空字符串继续拼进动作，更不能用历史标记代替普通任务身份。

### 3.3 新路径契约

- `PeSessionPaths`（会话路径）持有现场发现且验证可写的临时目录。不得假定一定为 `X:`，也不在失败时静默改到可能被格式化/捕获的卷。
- `TaskControlRoot`（任务控制根）绑定稳定卷身份、任务 ID 与协议版本，位于不被本任务覆盖的持久卷；启动所需控制内容保持最小化。
- `CommandOutput`（命令输出）只创建一次，由进程输出句柄、增量解码器、进度窗口、结果回读共同使用。读写双方不再各自拼目录。
- 优先独立程序/参数与输出句柄，不为探测拼 `cmd`（命令解释器）脚本；真正需要脚本时，使用任务私有文件、可靠引用及原生测试。
- 逐个替换 `rewrite_s_root` 的调用点，最终不再用字节字符串替换来表达卷路径。不是只给该函数增加注释就算完成。
- 普通进度可临时缓存；格式化意图、状态、失败点、退出证据和清理责任必须持久化。临时盘容量不足或持久日志失效须进入受控失败，不得让已启动进程失管。
- 控制请求须携带任务 ID、请求 ID、协议版本和计划/载荷关联；请求 ID 防重复，不是身份认证。写权限及任务确认仍需保护。

### 3.4 原生三态探测

拟接口 `probe_file(root, relative) -> ProbeResult`（文件探测结果）：存在且可读取、确实不存在、未知并带原始错误。

1. 先证明根卷身份正确、卷根可访问；必要时以句柄确认规范路径未通过重解析点逃到其他卷。
2. 用元数据、打开/读取接口保留系统错误；检查对象类型，不把同名目录当所需文件。
3. `NotFound`（未找到）只在已确认卷和祖先路径可访问、没有逃逸或竞争异常时表示明确缺失；不是每个未找到错误都能直接当非系统卷。
4. 访问拒绝、离线、未知设备、祖先损坏、多候选、解析失败一律是未知；记录错误码和上下文。
5. 系统文件存在是内容证据，不是卷角色授权；系统内容的必要文件集按意图/架构决定，PE 安装与完整 Windows 系统不同。
6. `discover_drives` 当前是按盘符筛选的界面枚举，不是完整安全角色枚举。它的 `.is_file()` 展示也需三态化；无盘符卷不显示在普通列表本身不等于缺陷，但底层授权必须看得到它们。

## 四、现场身份与写许可：不可拆开的发布门槛

### 4.1 解析器不等于现有卷列表

复用 `volume_identity_at_path` 等已有能力，但不能声称增加几十行即可完成全部定位：这些接口先读取文件系统信息，未格式化分区可能无法通过；`mountvol`（卷挂载工具）列的是可枚举卷，不是所有物理分区。

拟 `VolumeResolver`（卷解析器）需有卷枚举与物理磁盘/分区枚举两个层次。支持未格式化目标时采用明确分支；尚未支持时在预检报错，绝不回退到任务旧编号。匹配磁盘/分区 GUID（全局唯一标识符）、类型、偏移和大小；克隆冲突、动态/跨盘布局或其他未支持设备报错。

### 4.2 写许可覆盖实际写入

1. 以不可变计划定位唯一目标，生成 `ResolvedVolume`（现场卷），取得本次磁盘号/分区号/工具所需路径。
2. 核验角色、镜像/索引、容量、运行环境和目标绑定确认，生成短寿命 `WritePermit`（写许可）。
3. 将意图和本次尝试号持久化后，再于命令启动前重验。命令参数只能来自该许可，不得另取旧盘符或旧编号。
4. 对检查后拔插/重新枚举，使用可行的句柄/锁保护并检查变更事件；失去绑定即撤销许可。若外部工具不能提供足够绑定保证，限制到已验证且稳定的设备场景，不声称消除了所有检查使用竞态。
5. 格式化、应用、引导修改分别核验适用许可；引导写入的是另一对象，不能沿用格式化目标的许可。
6. 格式化后重新定位同一物理分区，验证文件系统、可访问性、新序列号及本次操作证据。仅序列号变化不证明安全擦除；未格式化目标单独处理。

可以分提交实现，但**所有可达的破坏性入口完整接入前不发布为已修复版本**。仅增加日志说明“编号未核验”不是可接受的过渡保护。

## 五、状态、失败、备份及启动收尾

### 5.1 一个权威状态，区分意图和结果

- `task.json` 是不可变计划；`runtime.json` 是唯一权威运行状态；`status.json` 是可重建展示缓存。
- 权威记录绑定计划摘要、修订号、尝试号、实际动作证据和资源所有权。跨进程锁覆盖读校验写的全过程。
- 武装流程为“武装意图落盘 → 修改明确 BCD 对象 → 回读 → 已武装落盘 → 请求重启”。不能把“已武装”提前写入后再把排序问题当作事务解决。
- 每个外部副作用都可能落在“已执行但未记结果”的窗口。重入时按该动作现场对账，不取更大阶段，不从失败一律重跑格式化。
- 单文件替换仍需在实际文件系统验证刷新/断电行为；上一份可信状态只能辅助恢复，不自动证明未记录的外部动作没有发生。
- 旧任务先备份、列出、不自动升级执行。正在用旧载荷的任务不能被新版程序静默换协议。

### 5.2 失败不能继续，也不能下次无条件重跑

采用 W09 的 `StepResult`（步骤结果）：`Verified` 已验证、`NotApplicable` 契约不适用、`Failed` 失败、`Indeterminate` 无法判定。只有前两种且计划允许时才可继续。

失败后停止新的写操作与自动重启，保留现场；但不只是“不改名 .done”。原请求须变成已领取/失败待处理状态，重启扫描不能因请求仍在就重新执行第一行格式化。`.done` 只是终态派生标记，不拥有调度权。

格式化后的根目录不要求字面为空：合法文件系统元数据/系统目录可能存在。测试卷可用哨兵验证清空，生产不随意给用户卷写哨兵。系统还原内容检查、引导回读、系统真实启动分别记录，不以“几个文件存在”宣布全链路可启动。

### 5.3 候选备份与校验

所有入口在任务私有候选上捕获、追加、删除索引、同步副档；原件保留至发布已验证。最终候选摘要共享给所有副档，同一受保护复制流可合并旧摘要计算；不省掉跨重启后必须承担的严格校验。

缺失副档走真实第三方镜像预检，损坏/不可读副档不当缺失。仅大小保持已有默认但说明边界；“用户接受当前镜像”记录本次真实摘要，不能继续带旧副档摘要或用零值伪装。

多文件发布使用持久清单、旧代保留、读入口门禁与可重复对账，不宣称天然原子。空间不足停止，不改成就地覆盖。批量副档和输出路径也须防别名、重解析点和外部替换。

### 5.4 启动事务与取消

命令后端保留现有进程树治理成果，并补长命令、流式输出、取消、子进程与受委派服务现场收敛。准备/恢复/PE 各入口均接同一后端；工具从可信运行系统目录定位，不写死 `C:\Windows`。

任务载荷私有、持久活动任务记录与跨进程锁共同控制串行。准备失败按所有权补偿；其他程序后来修改的启动配置不覆盖。回滚启动配置不等于还原已格式化的数据。

采纳 W05 的保守约束：不将 `/store … /import …` 当作已证明可用的离线 BCD 回滚路径；精确存储的副本、锁定、日志一致性和文件系统替换另行验证。对方已引 [微软 BCDEdit 说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/bcdedit)；本次联网复取受工具访问限制，未独立重验网页，实施前还需结合目标版本帮助与隔离存储测试。

自动重入必须验证实际启动入口可达。保持不随意改变默认项；不把一次性启动成功当作断电后无人值守恢复已解决。

## 七、撤销的旧判断与修订理由

| 旧说法 | 校准 |
|---|---|
| “把 contains 改成精确匹配会将 NOSYS 判为系统” | 逻辑相反：精确匹配会排除 NOSYS。联合修复的理由是路径、错误分类、角色与后置条件共同完整，不是该错误因果 |
| “cmd 重定向只绑 else” | 2026-10-05 已在正常 Windows 11 原生命令中确认：真分支 stdout 有 SYS，但结果文件未生成；PE 环境尚未验证 |
| “cmd 一律不支持卷路径重定向” | 2026-10-05 实测实际卷路径重定向退出 0，文件内容正确；该笼统说法被否定，不外推所有环境均支持 |
| “is_system 恒 false、旧文件永远不存在、AUTO 恒空” | 仅在对应读回路径不存在/失败等条件下成立；可能有陈旧或其他生产者文件，必须防止读错代 |
| “pe-click 所有历史验收失效；2.0.4 必因 pe-task 成功” | 只确认历史卷根生产者与当前子目录消费者不匹配，不能推断所有实际部署与具体闭环入口 |
| “schedule_pe_task 写失败仍自动重启” | 代码实际以 `code.is_success() && write_ok` 限制自动重启；缺陷是任务写失败后仍尝试武装，可能留下影响以后重启的启动序列 |
| “编号漂移时格式化后核验必然通过” | 后置核验也比较磁盘/分区号，可能发现漂移，但发生在破坏之后；它不能替代事前绑定与本次格式化完成证据 |
| “默认项或全部加载器列表决定主系统/完整保护集合” | 主系统身份须在计划中确定，其他关键角色独立解析；加载器列表可能缺失、损坏或指向虚拟磁盘 |
| “确认具体身份就可覆盖 ESP 或放过角色未知” | 确认不豁免角色禁区与必需证据；格式化许可和 BCD 写许可必须分开 |
| “先上预检，完整写许可另开轮次” | 可分阶段开发，但实际可达写入口完整接入前不发布为安全修复 |
| “一次快照验证旧程序并部署新 PE、再返回系统” | 不符合项目快照边界；每个新的启动/部署事务、PE 内再次手工变更或返回，都按规则新建并核验 |
| “不改名 .done 就能安全续跑” | 缺少领取/失败状态会导致下次重复动作，必须由权威状态裁决 |
| “仅 task.json 做可变权威即可”“先写已武装再操作” | 最终采用不可变计划 + runtime 权威；外部动作前记意图，结果经回读后再记 |

本次不覆盖两份并行审计原文的历史叙述，纠正结论统一列在这里并同步导航，防止下一个实施者再引用已撤销规则。

| 局部测试 | 期望证据 |
|---|---|

| P07：临时路径不是 X:、S: 被他卷占用、输出有旧文件 | 同一输出对象跨写入/解码/进度/回读，未使用陈旧输出；关键状态持久化 |
| P08：任务文件拒写 | 写失败后设置启动序列次数为零；也不请求重启 |
| P09：两次独立启动/部署变更 | 各自有新快照 ID 与核验证据；快照失败第二次变更不执行 |

格式化旧程序不是只读观测。旧逻辑优先用源代码抽出的纯函数、临时文件夹和无写入动作替身复现；真机破坏性用例必须在专用测试卷与对应授权范围内进行。

快照最多保留最近两份、清理限已确认项目资源。若不能同时满足新快照、归属和保留规则，停止该项实机验收。证据放已忽略的 `.test-artifacts/`；本轮没有进行上述实机动作。
