## 三、★ D4 修复在 A 入口首次实机验证（独立恢复分区重接）

10-19 A 入口曾因 D4（`reconnect` 把「恢复环境在独立恢复分区」当异常拒接）导致任务 failed、
恢复环境被禁用。本轮日志（`H:\BRImages\Recovery.log`，UTC）完整记录修复后的正确路径：

```
00:26:17 WinRE registration target=C loader={2ef03cd4…} location=\\?\globalroot\device\harddisk0\partition4\recovery\windowsre
00:26:17 capturing C:\Windows\System32\reagentc.exe /info /target C:\Windows …
00:26:17 disk0/partition6 在现场没有盘符（按设备路径核对）
00:26:17 已启用 WinRE 位于独立恢复分区 \\?\globalroot\device\harddisk0\partition6\recovery\windowsre（现场盘符 None），恢复原件齐备，按独立分区重接
00:26:18 running bcdedit.exe /store Z:\EFI\Microsoft\Boot\BCD /set {2ef03cd4…} recoverysequence {264caa29-cb14-11f1-8997-e9cfd361e402}
00:26:18 running bcdedit.exe /store Z:\EFI\Microsoft\Boot\BCD /set {2ef03cd4…} recoveryenabled Yes
00:26:18 WinRE existing registration reconnected to repaired system loader
00:26:20 WinRE registration verified: Enabled; target location, recoverysequence, ramdisk and original hashes match
```

**机理备注**：镜像自带的 `C:\Recovery\WindowsRE` 让 register 起初记 partition4（同分区），
但 `/enable` 后 `reagentc /info` 报实际启用位置是机器原装的 **partition6 独立恢复分区**——
`recovery_payload()` 按设备路径核对 `winre.wim`+`boot.sdi` 原件齐备后走独立分区重接，
两个启动配置数据存储都补上 `recoverysequence`/`recoveryenabled`，终检哈希不变。
与 10-19 手工 `reagentc /enable` 补回的 `{264caa29-…}` 是同一个对象——原装恢复环境注册位完好复用。

## 四、镜像「带回旧状态」效应（新知识点，务必记住）

**现象**：还原后 C: 的一切都回到**镜像拍摄时刻（10-18 17:49）** 的状态——
包目录 `C:\Users\Public\backupRestore-package` 里是 **v2.6.19** 二进制、
任务 `02138f14` 是 **Capturing**（可续跑态），于是每次自启图形用户界面都弹待续跑框。

**教训**：
1. 还原系统盘会连「程序部署位」一起回滚——**还原后必须重新部署当前版本二进制**
   （本轮已补：包目录 + H:\brwork 两处均回到 `CD401F92…` v2.6.24）。
2. 镜像里处于可续跑态的任务会复活成弹框；用
   `abandon-task <包目录根> <task-id>` 收口（root 是包目录本身，内部再拼 `tasks\`）。
3. H: 工作卷不受还原影响（镜像只覆盖 C:），`H:\brwork` 的二进制与任务目录原样保留。
