## 1. exit 5 精确根因（决定性实验，2026-10-16 16:30-17:04）

> 此前的"覆盖式应用撞上 pagefile/hiberfil"是**未证实推测**。以下是 PE 控制台内的实测。

**实验条件**：同一 PE（DISM `10.0.28000.1`）、同一镜像 `c-full-20261014.wim` index 2。

| # | 目标 | 结果 |
|---|---|---|
| 1 | **C:**（已有完整 Windows） `/ApplyDir:C:\` | **秒退 `Error: 5 Access is denied`** |
| 2 | **F:**（此前写过一份系统） `/ApplyDir:F:\` | **100% 成功** |
| 3 | 对 F: 再来一次（非空覆盖） | **再次 100% 成功**（排除"非空即失败"） |

→ 变量**只剩目标卷**：不是 DISM 版本、不是镜像、不是 PE 环境。

**DISM 自身日志**（`X:\windows\Logs\DISM\dism.log`，PE 内可读）**精确到函数名**：

```
Warning  Directory metadata: C:\Program Files\WindowsApps\Microsoft.DesktopAppInstaller_1.29.289.0_arm64__8wekyb3d8bbwe (HRESULT=0x80070005)
Error    RestoreDirMetadata:(2418): Access is denied.
Error    WIMCreateDirectory:(3216): Access is denied.
Error    RestoreDirTree:(3468): Access is denied.
Error    WIMApplyImageInternal:(939): Access is denied.
```

**旁证（PE 内实测）**：
- 在 `C:\Program Files\WindowsApps\` 下 **`md` 建新目录成功**、可正常 `rd` 删除 → **普通数据写入允许**；
- 被拒的**只有"改写既有受保护目录的元数据"**这一步。

**机理**：DISM 覆盖式应用时，除写入文件外还要**还原目录的安全描述符/owner**（`RestoreDirMetadata`）。`C:\Program Files\WindowsApps` 里的 MSIX 应用包目录 owner = `NT SERVICE\TrustedInstaller`、带 app-package SID 与 `TrustedInstaller:(I)(F)` → 操作系统拒绝对这类目录改 owner/ACL → `0x80070005` → DISM 立即整体放弃。

**为什么格式化能通过**：格式化清空 C:，`WindowsApps` 等受保护目录一并消失，DISM 只需**新建**目录（允许）而非**改写**既有受保护目录元数据 → V1 成功。

**结论**：
1. 「跳过格式化 + 还原到系统卷 C:」在本机**确定性走不通**；
2. 与 RE/在线/PE 环境无关（PE 同样失败）；
3. 与 DISM 版本无关（PE 用 10.0.28000.1 照样失败）；
4. `--skip-format` 对**数据卷**有效（`20261014-2345` 已验证），对**已含 Windows 的系统卷**无效。

## 3. 本轮方法论（值得复用）

- **交叉编译绿灯要验真**：`#[cfg(windows)]` 代码在 macOS 不编译。本轮在新代码里**故意注入一个类型错误**，确认 `cargo check --target aarch64-pc-windows-msvc` 立刻报 `error[E0308]`，证明绿灯是真通过。
- **clippy 零新增靠 diff**：`git stash` 前后各跑一次 clippy、`comm` 比对警告文案，才敢说"零新增"；只看总数会被"消失的告警"骗过。
- **假设要能被实验推翻**：本轮先用在线态实验**推翻**了"非空卷必然失败"（F: 两次都成功），才逼出"必须去 PE 里看 DISM 日志"的正确方向。
- **PE 内可读 DISM 日志是解题钥匙**：RE 里 DISM 日志落内存盘 `X:\`（重启即丢）；PE 里同一路径**磁盘常驻**且可 `type`，是拿到 `RestoreDirMetadata` 精确函数名的关键。
