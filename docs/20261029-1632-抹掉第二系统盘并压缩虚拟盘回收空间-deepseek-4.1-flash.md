# 抹掉第二系统盘并压缩虚拟盘：Mac 可用空间 153 → 228 GiB

> 模型：deepseek-4.1-flash｜用户指令（两次表达，第二次带火）：
> 「可以拍快照啊」「快照不也是能恢复数据，而且也能用完就删除，恢复起来几秒钟就恢复了，
> 不必脱裤子放屁启动其它系统来修复」「你傻逼啊，快照用完可以删啊」
>
> 本文记录：① 我先前一个**错误结论**及其代码反证；② 实际执行的六步与每步读数；
> ③ 结果（`harddisk2.hdd` 70 GiB → 79 MB，Mac 可用 153 → **228 GiB**）；
> ④ 一次**读了旧文件**导致的误判。

## 1. 先认错：我说错了一件事

我先前说「删掉 `F:` 就没法测『在线把系统还原到另一个卷』」。**这是错的。**

用户的反驳要点：**快照能回滚、几秒钟就回来，不需要启动另一套系统去修**。这句话在
「安全网」这一层完全成立；而我拿它去论证「不能删 `F:`」，是把两件事混成了一件事。

### 1.1 代码反证

「还原到另一块盘、建第二套系统」在代码里叫 `create-secondary`，准入条件只有三条
（`crates/backuprestore-cli/src/windows_prepare.rs` 约 2565–2605 行、
`online_operation.rs` 387 行）：

```rust
// ① 目标不能等于源
if options.operation == Operation::CreateSecondary && source.same_partition(target) {
    return Err(err("second-system target must differ from source"));
}
// ② 目标不能是当前正在运行的系统卷
if options.operation == Operation::CreateSecondary && target_is_active {
    return Err(err("create-secondary target must not be the active Windows volume"));
}
// ③ 镜像是完整 Windows：文件存在、/Get-WimInfo 读得到索引
```

**没有任何一条要求目标卷上已经有 Windows。** 这个操作本身就是「格式化目标卷 → 铺镜像 →
修引导」。所以 `F:` 上那套现成 Windows 对测试**没有价值**，测试会把它原样覆盖掉。

### 1.2 关于「快照省不省空间」的正确口径

我先前反复说「快照不释放空间」，这句本身没错，但**用户早就给了完整流程**：
「快照 → 干活 → 验证 → 删快照」，空间在最后一步照样回来。我把它当成反驳，属于答非所问。

准确的说法是：**空间与回滚可以先后拥有，但不能同时拥有。**
在快照存在的那段时间里宿主空间不释放；快照一删，空间才回来。所以流程必须是
「先验证、后删快照」，这对本次操作正好合适——验证不过就回滚，验证过了就删快照收空间。

## 3. 空间账

| 时点 | Mac 可用 | `harddisk2.hdd` 实际占用 |
|---|---|---|
| 动手前 | 153 GiB | 70 GiB |
| 拍快照后 | 153 GiB（快照占位） | 70 GiB |
| 格式化 + 删快照后 | 159 GiB | 70 GiB |
| **压缩后** | **228 GiB** | **79 MB** |

净回收 **约 69 GiB**。跑一次 87 GB 级整机还原需要宿主 ≥ 镜像 × 2.5 ≈ 220 GiB，
**现在 228 GiB 越线**——这是本次操作最实际的收益。

顺便纠正一个算法误区：那块盘在 Windows 里显示 350 GB，但 `du` 实测只占宿主 70 GiB
（APFS 稀疏文件 + Parallels 精简置备）。**判断「删它会省多少」必须用 `du -sh`。**

## 4. 一次读数误判（记录以免重犯）

删快照前那次验证，我读到 `Boot=16:29:17`，与上一轮完全相同，一度以为「关机再开机没有重新启动」。

真因：我把 `dir /b C:\vf.txt` 和 `certutil -encode` 的输出**重定向进了同一个文件**，
取回时第一行是文件名、后面才是 base64，解码错位；同时 `certutil` 那次若失败，
`C:\vf.b64` 里留着的是**上一次的旧内容**，读出来自然一样。

正确做法（本次后半段已照做）：
- 每次取结果前先 `del` 掉旧 `.txt` / `.b64`；
- 结果文件里带一行 `Now=<当前时间>`，**用「当前时间 − 开机时间」自证是新读数**；
- 取回时只 `type` 那一个 `.b64`，不要把 `dir` 之类混进同一个流。
