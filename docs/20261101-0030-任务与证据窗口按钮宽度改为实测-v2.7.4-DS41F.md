## 1. 为什么要改

2.7.3 把同一窗口的**标签**宽度从写死 80 改成按实测文本算，但当时明确留了尾巴：
**那一排按钮仍然是写死的 100/150/130/66，连 x 坐标也是写死的 238/346/504/642。**

18 号中文下实测：

| 按钮 | 文本 | 实测宽 | 原写死宽 | 余量 |
| --- | --- | --- | --- | --- |
| 刷新列表 | 4 字 | 待填 | 100 | 待填 |
| 清理工作树 | 5 字 | 待填 | 150 | 待填 |
| 打开任务目录 | 6 字 | 待填 | 130 | **待填** |
| 关闭 | 2 字 | 待填 | 66 | 待填 |

也就是说「打开任务目录」早就该被切了——它没被切，只是因为按钮框比控件框宽一点点，
属于「恰好还够」。这正是本项目已经吃过两次亏的那种写法（2.6.68 改文案治标、2.7.3 标签被切）。

## 2. 改法

从「左边起按固定 x 依次摆」改成「先算宽、再从右边界往左排」：

```rust
const BUTTON_GAP: i32 = 8;
const BUTTON_RIGHT: i32 = 708;          // 与详情框右边缘对齐，窗口尺寸不用变
let mut cursor = BUTTON_RIGHT;
for index in (0..buttons.len()).rev() {
    let width = fit_width(buttons[index].1, buttons[index].2);   // 实测文本 + 12，且不小于原宽度
    widths[index] = width;
    cursor -= width;
    xs[index] = cursor;
    cursor -= BUTTON_GAP;
}
// 按原顺序创建：WS_TABSTOP 的键盘遍历顺序 = 创建顺序
```

要点：

- **floor 沿用原来的宽度**（100/150/130/66），所以任何字号下都不会比现在更窄；
- **右边界仍是 708**，窗口尺寸、其它控件位置都不用动；
- **创建顺序不变**，否则 `WS_TABSTOP` 的 Tab 顺序会被倒过来（这类改动最容易忽略的副作用）。
