## ① 设置项（失败次数 / 失败后行为）—— 端到端闭环达成

用户需求原文：

### 代码链路（`failure_policy.rs` 为单一来源）
- GUI 顶栏「设置…」→ `ask_settings_dialog` 弹模态窗 → `FailurePolicy::save_to_dir` 写程序目录 `BackupRestore.settings.ini`。
- `create_task` 拼 prepare 参数时追加 `--fail-threshold` / `--fail-action` / `--ui-language` → 落进 `RecoveryTask.env` 的 `FAILURE_THRESHOLD` / `FAILURE_ACTION` / `UI_LANGUAGE`。
- RE 启动时 `main.rs::recover_env_interactive` 读取该策略执行。**任务一旦创建策略即固定，事后改设置不影响已有任务。**

### 本轮新修的真 bug（沙箱 key：GUID 带引号匹配）
- **`FindWindowExW` 传 PowerShell `$null` 标题 → marshal 成 `""`**，导致找不到标题为"程序设置"的对话框（早先那个 apply 脚本一直"找不到窗口"就是这个原因）。改用 `EnumWindows` 按类名查找，问题解决。
- **旧 `br-settings-apply.ps1` 报"文件不存在"的真正根因**：计划任务用 `Start-ScheduledTask` 跑的是 `powershell.exe` 裸名，`lastResult=2`（ERROR_FILE_NOT_FOUND）被误读成脚本失败。改用**全路径** `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe` 后立刻跑通，且 `lastResult=0`。教训：脚本自身的 `exit 2` 会伪装成任务失败码，别只看 `lastResult`。

### 设置窗口端到端验证（全绿）
种子 ini = `7/pause` → 提权注入打开设置窗口回显 `threshold=7 pause=1`（**读取** ✓）→ 改 `9` + 点「自动清理」单选 → 保存 → 对话框关闭 → ini 被程序重写为 `threshold=9 auto-escape` 且带程序中文注释头，GUI 日志 `settings saved: threshold=9 action=auto-escape`（**写入** ✓）。

### 两个失败策略的 RE 行为（此前已实测）
- `auto-escape`：连撞 N 次后自动 disarm + 标 `Failed`（保留现场）+ 重启回 Windows。
- `pause`：达阈值后弹框停在 RE，等用户按「是」手动执行同一套清理；按「否」继续重试（**阈值不重新计数**，超阈值后每次失败都弹——与 React 语义不同的有意设计）。暂停 40 秒无输入验证：不自动重启。

### 踩坑：UIPI 与键盘注入
- `prlctl exec` 注入 Session 1 的进程是**中等完整性**，`PostMessageW` 到提权 GUI 被 UIPI 静默丢弃。唯一可行提权通道 = **计划任务 + RunLevel Highest + LogonType Interactive**（与 `restart-gui-h.ps1` 同一套）。
- `vmkey.sh` 走 Parallels HID 不受 UIPI 影响，但**必须先用 Alt+Tab 让 VM 窗口拿到焦点**，否则 `win` 键能唤菜单、而设置窗口收不到 Tab/退格。且键盘输入会乱序（`ctrl+a` 未选中、`5` 追加成 "53"）——精确文本输入不可靠，**文本框精确值一律用 `WM_SETTEXT` 注入**，别用键盘。

## ② BCD 深度清理 —— 已清，但发现"固件条目清不掉"

### 快照（用户明确要求"提前拍摄快照"，做了两层）
1. `bcdedit /export` → `.test-artifacts/BCD-before-deep-clean-20261016.bcd`（606,208 B，双份留存）。
2. **Parallels 整机快照** `before-bcd-deep-clean-20261016`（`{93d2c502-...}`）—— 比 BCD 导出更强的兜底。

### 清理动作
- 593 → **22** 个对象。删 571 个：77 个无引用 resume 孤儿 + 491 个未引用固件应用条目 + 3 个设备选项孤儿，**0 失败**。
- 保留清单精确到 21 个：`{bootmgr}`、默认启动项 `{72447cbc}` 及其 resume、WinRE 加载器 `{0cec537a}`+设备选项 `{0cec537b}`、memtest、9 个设置单例、`{fwbootmgr}` 的 7 个当前固件项。

### ⚠️ 关键结论：固件应用条目是"清不掉"的
重启后对象数从 22 **回长到 513**（498 固件应用条目原样回来）。根因：`bcdedit /enum FIRMWARE` 能立刻列出含 `{76601301-...}` 等标准固件 GUID 的条目 —— 这些是 **UEFI 固件 NVRAM `Boot####` 变量的实时视图**，由固件在每次开机重新同步进 BCD。`bcdedit /delete` 只能删当下，下次开机固件又会照 NVRAM 重建。
→ **498 条不是本程序产生的 BCD 垃圾，是这台 VM 设备固件自身累积的历史固件启动菜单**。本程序能清的是它自己创建的任务专属条目（每任务 2 个 BCD 对象 + bootsequence），这部分已由 `abandon-task` 终态收口负责，不会累积。
