## 一、本次改动概要

本次提交集中落地了第一阶段的三项 P0 任务：

1. **B-2693 闭环：`choice_dialogs.rs` 消除写死宽度**
   - 两个模态弹窗（`BackupRestoreSystemDriveChoice` 系统盘离线处理方式、`BackupRestoreInvalidPathChoice` 镜像路径非法引导）消除写死的 `CONTENT_W = 400`；
   - 改为通过 `measure_text_width` 遍历候选按钮文案实测算宽，按最大宽度 + 左右安全 padding（40 像素）与最小基准宽度（400 像素）动态取大；
   - 正文折行高度与整体窗口尺寸自适应绑定 `content_w`，彻底消除大字号（18号）及长英文文案下的贴边与裁切隐患。

2. **WinRE 零 Panic 防线：`recovery_progress.rs` 消除全部 42 处 unwrap**
   - 痛点：恢复宿主运行在 WinRE/PE 极简环境中，多线程协作下若有辅助线程（日志轮询/UI 刷新）因 I/O 抖动 panic，`Mutex` 进入毒化（poisoned）状态，后续主线程的任何 `lock().unwrap()` 会连锁触发二次 panic，直接导致进程终止，使关键的 `bcd_rollback` 钩子无法执行；
   - 方案：引入私有扩展 trait `SafeLock<T>`，在遇到 `PoisonError` 时通过 `poisoned.into_inner()` 提取内部数据继续保障主流程，绝不二次 panic；
   - 全文件 42 处 `Mutex::lock().unwrap()` 全部替换为 `.safe_lock()`，并增加单测验证线程持锁 panic 后的状态自愈提取。

3. **跨平台编译与死代码告警清零**
   - 精准修正 `main.rs:230` 处由 `#[cfg(windows)]` 门控引发的 `unused_mut` 告警；
   - 为 `collect_orphan_tasks` 的非 Windows 桩函数补充 `#[allow(dead_code)]`；
   - 为非 Windows 视角下仅作类型检查的模块（`cli_json`, `capture_heartbeat`, `i18n`, `image_admin`, `task_admin`, `status_receipt`, `failure_receipt`, `log_root`）规范标注 `#[cfg_attr(not(windows), allow(dead_code, unused_imports))]`；
   - 实现 macOS 本地 `cargo check --workspace` 与 `cargo test --workspace` **0 警告**。

4. **PE 镜像预检门禁错误码契约化**
   - 新增正式契约错误码：`BR-PE-059`（`PeImageMissingShellConfig`，缺少 `winpeshl.ini` 引导配置）与 `BR-PE-060`（`PeImageShellTargetNotFound`，所指前台程序在镜像中不存在）；
   - 在 GUI 提示弹窗与日志中完整透出 `[BR-PE-059]` / `[BR-PE-060]`，支持结构化判据与问题归因；
   - `python3 tools/gen-error-codes.py` 刷新 `docs/ERROR-CODES.md`。
