# 2.3.0 日志弹窗键盘焦点修复与实机验收（Fable 5）

时间：2026-10-11 19:00–19:40。本轮做两件事：**复核另一 AI 的 2.2.9 验收报告**，以及**修掉它没能测出来的一个真实缺陷**。

## 一、复核结论：报告的根因判断不成立

该报告称 2.2.9 验收失败的根因是「`FindWindowW(类名, $null)` 里 PowerShell 把 `$null` 绑成空字符串，
于是条件变成类名匹配且标题为空，必然找不到」，并建议改用 `EnumWindows + GetClassNameW` 修复。

**实测推翻了这个判断。** 在客体用三种传参各调一次 `FindWindowW`：

| 传参 | 返回 |
|---|---|
| `$null` | 0x0 |
| `[NullString]::Value`（保证传真 NULL 指针） | **0x0** |
| `''`（空字符串） | 0x0 |

传真 NULL 同样失败，所以"空字符串绑定"不是原因。进一步探测拿到决定性证据：

| 探测项 | 值 |
|---|---|
| `prlctl exec` 通道会话 | **Session 0** |
| 通道窗口站 | **`Service-0x0-3e7$`**（服务窗口站） |
| 通道桌面 | `Default` |
| GUI 进程 | pid 7544，**Session 1**，通道侧读到 `MainWindowHandle = 0x0` |

真正原因是**窗口站隔离**：通道运行在服务窗口站 `Service-0x0-3e7$\Default`，
GUI 窗口在交互窗口站 `WinSta0\Default`。`FindWindowW` 与 `EnumWindows` **都只枚举
调用方自身窗口站 + 桌面上的窗口**，跨窗口站结构性不可见。

**因此报告提出的修复（改 `EnumWindows`）同样会失败。** 对方声称
"同一进程 EnumWindows 能枚举到该窗口"，应是在 Session 1 里手工跑的探测脚本，
与 `prlctl exec` 通道不是同一环境，两次不同环境的结果被当成了同一条链路的证据。

**正确做法**：验收不要在客体内枚举窗口，改用宿主侧
`prlctl send-key-event` + `prlctl capture` + macOS Vision OCR 驱动与判读。
这条路不受窗口站限制，本项目此前测 F3 弹窗时已经跑通。

> 附带：`tools/acceptance/br-229-accept.ps1` 与 `br-findprobe.ps1` 建立在上述被推翻的前提上，
> 经 `prlctl exec` 调用时结构性不可能成功，**未入库**。

## 三、新发现的真实缺陷（2.2.9 遗留）

详细日志弹窗的编辑框：

- **没有 `WS_TABSTOP`**；
- 整个 `recovery_progress.rs` **没有任何 `SetFocus` 调用**（grep 计数 0）。

所以编辑框永远拿不到键盘焦点，按键全被弹窗窗口过程吞掉。

**后果**：在 WinRE 这种可能没有鼠标的环境——而这正是当初加 L 热键的全部理由——
用户能打开详细日志，却**完全无法滚动它**。底部吸附逻辑本身实现正确，
但没有鼠标时用户永远滚不离底部，这个特性等于摸不到。

这也解释了 2.2.9 第三项为何"无法验证"：不是测法不对，是功能确实够不着。

### 修复

- 弹窗编辑框样式加 `WS_TABSTOP`；
- 首次创建与复显弹窗时均 `SetFocus(GetDlgItem(window, ID_LOG_EDIT))`。

## 六、经验（建议固化）

1. **客体内窗口枚举在 `prlctl exec` 下结构性不可用**。通道是 Session 0 服务窗口站，
   GUI 在 Session 1 的 `WinSta0`。`FindWindow`/`EnumWindows`/`Get-Process.MainWindowHandle`
   全部拿不到交互桌面的窗口。GUI 验收一律走宿主侧 `send-key-event` + `capture` + OCR。
2. **Win32 控件要能被键盘操作，`WS_TABSTOP` 与 `SetFocus` 缺一不可**。
   只加热键打开窗口是不够的——窗口里的控件如果拿不到焦点，纯键盘环境下依然是死的。
3. **截图 SHA-256 比对是 UI 行为的可靠判据**。"看起来没变"容易主观，
   逐像素哈希能把"根本没响应"和"响应后恰好相同"区分开——2.2.9 的 PageUp 失效
   正是靠前后哈希完全相同才确认的。
