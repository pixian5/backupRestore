## 本轮实机结果

- **Windows ARM64 原生回归 165 项通过**（125 CLI + 40 core，2.1.9 为 156 项），6 项破坏性夹具按预期忽略。
- 部署 2.2.1 到客体包目录与 `H:\brwork`，四份文件 SHA-256 与宿主一致。
- **新载荷路径实机确证**：`boot-entry.json` 记录 `H:\BackupRestoreRE\<任务ID>\Winre.wim`，
  机器凭此真实启动进任务 WinRE 并完成恢复。2.1.9 的断电证据取自旧共用路径，本轮是新路径首次确证。
- **restore-existing 链路通过（数据卷契约）**，终态 `success` / 100%：真实 `diskpart` 格式化
  （disk 0 / partition 5 / NTFS）、`dism /Apply-Image` 跑到 100%、哨兵文件消失、
  还原内容可回读（含 20MB/10MB 大文件）。
  **注意：本次目标无 SYSTEM 配置单元，日志 `skipping BCDBoot`，引导修复这一步未被验证。**
- **重试窗口实机交互通过**：`MB_RETRYCANCEL` 默认按钮为重试，注入 `error-once` 后发 Enter 成功续跑。
  准确计数是**镜像应用一次、格式化两次**（在 `TargetErased` 阶段重入会再次格式化已擦除的目标，
  属设计行为）；初稿写成"只发生一次格式化"有误，已在验收文档更正。
- **清理彻底**：BCD 终态与基线**逐字节零差异**，两个任务 BCD 对象已删除，
  `BackupRestoreRE` 父目录一并回收；WinRE 注册零差异；恢复原件 `Winre.wim`/`boot.sdi` 哈希未变。
- 2.2.1 的 `ImageAcceptance` 行为符合设计：正常镜像 `imageAcceptance=None`，不写例外。
