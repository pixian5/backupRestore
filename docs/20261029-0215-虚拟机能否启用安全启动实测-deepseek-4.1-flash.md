# 这台虚拟机怎么开安全启动：直接开不行，先重建固件存储就成功

> 时间：2026-10-29 02:15（**02:24 补充 §六：已成功开启**）　模型：deepseek-4.1-flash　版本：**不升版本**（纯虚拟机固件实验，零代码改动）
>
> **最终结论（2026-10-29 02:22 实测）**：这台虚拟机能开，但**直接开不行** ——
> 必须先把固件存储（`NVRAM.dat` + `NVRAM.tnvs`）删掉让它重建，再打开安全启动。
> 重建后固件成功写入微软证书白名单，系统正常启动，`Confirm-SecureBootUEFI=True`，**连续两次重启都成立**。
>
> 失败经过（§一~§四，仍有价值：它解释了这个故障长什么样、怎么回退）：
> `prlctl set "Windows 11" --efi-secure-boot on` **命令成功**，但虚拟机启动后被固件判定「安全启动违规」
> **直接停机**（不弹窗、不报错，看现象只是「启动几十秒后状态变回已停止」）；
> 根因是固件**写不进白名单证书库**，白名单是空的，于是任何引导程序都不被信任。

## 二 根因：白名单写不进去，所以白名单是空的

固件启动时的日志（`Windows 11.pvm/parallels.log`）把原因写得很清楚（以下为原文摘录，两次尝试分别对应
「直接开」与「重置后开」）：

```
第一次（02:07:58）
[SecureBoot] Initializing: PK=ok(clear) KEK=ok(clear) DB=ok(clear) DBX=ok(clear)
[SecureBoot] PK =e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
[SecureBoot] KEK=e3b0c442…（同上，空）  DB=e3b0c442…  DBX=e3b0c442…
[SecureBoot] Create PK var
[SecureBoot] Create KEK var
[SecureBoot] Error allocating memory for new data to SetVariable KEK
[SecureBoot] Create db var
[SecureBoot] Error allocating memory for new data to SetVariable db
[SecureBoot] Create dbx var
[SecureBoot] Error allocating memory for new data to SetVariable dbx
02:07:59  Sending warning PRL_ERR_SECURE_BOOT_VIOLATION   → 虚拟机停机
```

`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` 是**空数据**的 SHA-256。
也就是说：**主密钥、密钥交换密钥、允许清单（db）、禁止清单（dbx）全都是空的**。
安全启动的规矩是「只放行清单里的签名」，清单空 = 谁都不放行 = 微软签名的 `bootmgfw.efi` 也被拒。
Parallels 检测到这个违规后不是报错弹窗，而是**直接把虚拟机停机**（所以看到的现象是「启动 45 秒后自己关了」）。

`reset` 那次有一点进展：

```
第二次（02:09:15）
[SecureBoot] Resetting: PK=ok KEK=lost DB=lost DBX=lost
[SecureBoot] PK =485aca0cb5f875572c905e6f19ec0a249cf438b005a3e27257ac4bd3f56777bd
              （主密钥这次有内容了，其余三项仍是空值）
[SecureBoot] Error allocating memory for new data to SetVariable KEK / db / dbx
02:09:16  Sending warning PRL_ERR_SECURE_BOOT_VIOLATION   → 虚拟机停机
```

说明**不是「没有证书」，而是「写证书那一步分配内存失败」**，这是固件/虚拟机管理程序侧的缺陷，
不是我们哪里配错了。

### 补充证据：这台虚拟机从来没有过白名单

虚拟机目录里留着四个历史固件存储副本（含 9-13 那次「只剩 UEFI Shell」事故前后的备份），
逐个按字节查微软证书名（`Microsoft Windows Production PCA 2011` 等），**五个文件全部没有**。
所以 9-13 之前配置里那个「安全启动=开」，很可能从来没真正生效过 —— 这也是当时引导菜单里只剩
「UEFI Shell」的一个合理解释。

### 开之前我以为能过，但那三条都不管用

| 我核过的事 | 结论 | 为什么没能救场 |
| --- | --- | --- |
| ESP 上三个引导文件签名 | 全部「有效 · 微软签名」 | 白名单空着，签名再正规也没人认 |
| 虚拟 TPM | 在（类型 crb） | TPM 管的是密钥与度量，不是放行名单 |
| 磁盘加密 | 四个卷全未加密 | 只影响「会不会要恢复密钥」 |

Parallels 官方文档确实写了 Apple 芯片上的 Windows 11 虚拟机支持安全启动，官方知识库也记录了
「安全启动阻止操作系统启动」这个故障（该问题号称在 26.3.3 / 20.4.2 修好，本机是 27.1.0，属于更新的版本，
症状却以另一种形态出现）。所以**不能把它当成「Parallels 不支持」一句话结论**，准确说法是：
**这台虚拟机当前的固件存储（NVRAM）无法建立安全启动白名单**。

## 五 一句话给以后的自己

**「签名有效」≠「会被放行」**。安全启动是**白名单**机制：白名单为空时，微软签名的引导程序一样被拒。
判断能不能开，先看固件信任库（日志里 `PK/KEK/DB/DBX` 的哈希是不是 `e3b0c442…` 那个空值），
而不是先查文件签名。

## 六 成功路径（2026-10-29 02:20，用户选「重建固件存储」后实现）

### 做了什么（四步，可复现）

1. 确认虚拟机已关机、没有进程占用固件存储（`lsof` 查 `NVRAM.dat` 为空）；
2. `prlctl set "Windows 11" --efi-secure-boot on`（先记下 `EfiSecureBoot=1`）；
3. `rm -f NVRAM.dat NVRAM.tnvs`（**这两个文件就是「固件存储」，删掉由固件按默认值重建**；
   备份在 `/Users/x/Parallels/brvm-backup-20261029/`）；
4. `prlctl start "Windows 11"`。

### 结果（关键：这次日志里没有 allocate 失败）

```
02:20:37 [SecureBoot] Initializing: PK=ok(clear) KEK=ok(clear) DB=ok(clear) DBX=ok(clear)
02:20:37 [SecureBoot] Create PK var / Create KEK var / Create db var / Create dbx var
         ← 上一次在这里刷「Error allocating memory for new data to SetVariable KEK/db/dbx」，这次一条都没有
02:20:38 系统启动完成
```

客体内核对（这是最终判据，不看日志猜）：

| 判据 | 结果 |
| --- | --- |
| `Confirm-SecureBootUEFI` | **True** |
| 注册表 `…\Control\SecureBoot\State` 的 `UEFISecureBootEnabled` | **1** |
| 白名单 `db` 内容 | 含 `Microsoft Windows Production PCA 2011`、`Windows UEFI CA 2023`（**签 Windows 引导程序的那两张**） |
| `PK` 变量 | 1575 字节（固件自己的平台密钥） |
| 能不能进系统 | 正常，客体通道可用 |

**持久性复验**：02:22 再关机重启一次 —— `secureboot=True`、`boot=02:22:49`，仍成立，不是「只在第一次启动时碰巧」。

### 两个额外收获

1. **「删掉固件存储会丢引导项、要新建虚拟机修复」这条老经验不成立**（至少对这台机器）。
   固件重建后自己扫出了启动项：`bcdedit /enum firmware` 里出现了
   `Windows Boot Manager`（`path \EFI\Microsoft\Boot\bootmgfw.efi`、`device partition=S:`），
   系统直接进来了。9-13 那次之所以要新建虚拟机，原因应该在别处，不在「NVRAM 被删」。
2. **`Microsoft UEFI CA 2011` 不在 `db` 里**（这张是给第三方引导器用的，比如 Linux 的 shim、
   部分 U 盘启动工具）。所以这台虚拟机现在**能启动 Windows 与微软签名的 PE，但会拒绝非微软签名的引导器** ——
   这恰好就是我们要测的那种「真机安全启动」环境。

### 现在的现场

- 虚拟机：`running`，**安全启动开**，`EfiSecureBoot=1`，系统正常；
- 若要临时关掉（例如做会改引导的实验）：`prlctl set "Windows 11" --efi-secure-boot off` + 重启即可；
- 回退到「重建前」原状：关机后把 `/Users/x/Parallels/brvm-backup-20261029/` 里的
  `NVRAM.dat`、`NVRAM.tnvs` 拷回虚拟机目录（`config.pvs` 也一起拷回可连配置复原）。
