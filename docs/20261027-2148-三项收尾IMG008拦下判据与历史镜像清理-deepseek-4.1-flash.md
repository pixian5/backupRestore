## 1. `BR-IMG-008`：从「只验不误拦」到「也验拦下」

### 1.1 之前为什么只验了一半

不是漏写测试，是**结构导致的**：判定 `if free < floor` 在两条链里**各写了一遍**——
`windows_prepare::ensure_backup_image_capacity`（离线准备）与
`online_operation::capture`（在线捕获）。一个在两处各自实现的不等式，
测试只能测到**阈值函数**（`backup_space_floor`）本身，测不到「会不会真的拦」。
于是 `BR-IMG-008` 长期只有「空间够时放过」这一半。

### 1.2 改法：把判定收成 core 的单一函数

```rust
pub fn backup_space_shortfall(available_bytes: u64, source_used_bytes: u64) -> Option<u64> {
    let floor = backup_space_floor(source_used_bytes);
    (available_bytes < floor).then_some(floor)   // Some(下限) = 拦下；None = 放行
}
```

两处调用点都改成 `if let Some(floor) = backup_space_shortfall(…) { 报 BR-IMG-008 }`，
不等式只此一份。边界语义写死在函数里：**`available == floor` 放行**（是 `<` 不是 `<=`），
与「低于硬闸才拒绝」的文档一致。

### 1.3 判据与变异

新用例 `backup_space_gate_blocks_below_floor_and_allows_at_floor`：

| 分支 | 断言 |
|---|---|
| ① 拦下 | 可用 = 下限 − 1 字节 → 必须 `Some(下限)`（回报的正是那个下限） |
| ② 边界 | 可用 = 下限 → `None`（放行） |
| ③ 充裕 | 200 GiB 可用 / 100 GiB 源已用 → `None` |
| ④ 同语义 | 5 组 `used`（0 / 1 / 10 / 249 / 4096 GiB）各验「floor−1 拦、floor 放」 |

变异（两条各自变红，恢复后转绿）：

- `<` 改成 `<=` → 边界断言红（说明「恰好等于下限」这个语义真的被钉住了）；
- 拆掉 `.max(1 GiB)` 绝对下限 → 两个用例都红（小源卷必须仍要求 1 GiB）。

验收：core **57**（+1）+ cli **306** 全绿；`./build-win.sh` 零新增告警、**产物字节数不变**
（纯重构没有新增代码规模，旁证改动只是把不等式搬了个位置）。

### 2.2 ★ 宿主回收：停机那一刻就回收了 42 GiB

按项目铁律「VM 内删文件不释放宿主」，先记了宿主 `df`：**182 GiB** 空闲（删除前后没变）。
随后停机准备 compact，**停机完成的瞬间宿主就变成 226 GiB** —— 三步实测结论：

1. `harddisk1.hdd` 是 `online-compact=on`，客体的 TRIM 已把删除的块标空，
   但**运行期间宿主文件不会缩**；**停机时才真正吐出来**（+42 GiB，比删掉的 34 GB 还多，
   因为顺带回收了历史碎片）。
2. 再跑 `prl_disk_tool compact --hdd harddisk1.hdd`：**46 G → 14 G**（.hds 体积）。
3. 重启后核验：`H:\BRImages` 内容齐全（`pe-boot.wim` 在）、`H:\brwork` 三件套在、
   **部署 exe 的 SHA 仍是 `fc7fc65c…`，与 `artifacts/` 和交付包完全一致** —— compact 没有损伤任何文件。
   `H:` 卷可用空间 146.8 GB → **178.2 GB**。

> 结论（写进经验）：**先停机看 `df`，再决定要不要 compact**。
> 本次停机已回收 42 GiB，compact 只是把稀疏块真正落到宿主文件上。

## 4. 三条可复用的教训

1. **「只听一半的守卫」通常是结构问题，不是测试懒**：同一个不等式写两遍，就注定只能测到阈值。
   把判定抽成一个返回 `Option<下限>` 的函数后，「拦下」才第一次成为可断言的承诺。
2. **删镜像先分清「产品组件 vs 历史证据」**：`pe-boot.wim` 是随程序发布的载荷，
   跟着「清理历史镜像」一起删掉就等于删了产品的一部分。
3. **VM 内删除与宿主释放是两件事，但顺序可以省一次 compact**：
   先停机量 `df`，再决定 compact——本次停机一步就拿到了大头。
