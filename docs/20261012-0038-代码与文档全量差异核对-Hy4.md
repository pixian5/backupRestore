### H2. PE 还原在 `boot()` 阶段还会调 WinRE 注册，失败时目标已被格式化并应用

`pe_operation.rs:748-753` —— `Engine::boot` 在 bcdboot 之后**继续调** `winre_registration::repair`。
而该函数的 `preflight` 强制要求：在 PE 内（MiniNT 键，`winre_registration.rs:275-281`）、
UEFI `PEFirmwareType=0x2`、目标须有 `reagentc.exe` + `SYSTEM` hive（301-307）。

**这正是 2026-10-11 发现的「纯 PE 作 `create-secondary` 会先擦除目标卷才失败」的根因**——
失败发生在 `format` 与 `apply` 之后。文档（含本轮 2.3.3 的全景文档）只写了"PE 会做 bcdboot 引导修复"，
**漏掉了后面这一步注册**，导致"擦除后才失败"的危险性被低估。

### H3. `{bootmgr}.resumeobject` 未恢复——**已修，文档过时**

`docs/20261011-1030-boot-matrix...` 第 64-93 行称「产品未恢复，建议增加字段」。

### H4. 在线路径不识别「另一个含 Windows 的卷」——**已修（2.3.6：改为在线格式化 + bcdboot）**

`online_operation.rs` 的 `restore-existing` 分支原本只比对 `%SystemDrive%`，**不判断目标是否含 Windows**：
双系统场景下把系统镜像在线还原到另一个 Windows 卷时，只写日志"不格式化、不修复引导"、**不做 bcdboot**。
2.3.5 先临时改为命中即**显式拒绝**；**2.3.6 按用户裁定改为完整还原**：命中 `pe_safety::target_is_windows_volume()`
后走 `restore_to_windows_volume()`，对齐 PE 入口做 diskpart 格式化 → DISM 应用 → bcdboot（`/d` 保留主系统默认项 +
bootmgr 快照前后比对 + 追加进启动菜单）。用户前提：第二系统中途断电只是不可启动、主系统仍在，重新还原即可，故不引入状态机。

## 五、关键结论：在线路径该不该加格式化与引导修复

用户提出「在线路径增加判断目标是不是另一个含 Windows 的卷，然后格式化、修复引导」。
核对代码后的**原结论是不建议在线做**（理由按严重度如下）；**但 2.3.6 用户裁定推翻该结论**，改为直接在线实现，见文末说明。

1. **无状态机，格式化是不可逆点。** 在线路径无 `Task`/`Stage`/`TaskStore`/`rearm`（读码确认）。
   格式化属于 `is_destructive_boundary()`，中途断电会留下「已格式化未应用」的目标卷 = **数据丢失**。
   RE 路径能做是因为它有 11 Stage 状态机 + 事务重放 + 每 Stage 一次续跑额度。
2. **WinRE 注册在线根本不可用。** `winre_registration::repair` 的 preflight 第一行查
   `HKLM\...\MiniNT` 注册表键，非 PE 环境直接报「离线 WinRE 注册只允许在 PE 中执行」
   （`winre_registration.rs:275-281`）。在线只能做 bcdboot，**做不了 reagentc 注册**。
3. **bcdboot 会改写真 ESP 的 bootmgr**，而在线路径**没有** `bcd-before-bootmgr.txt` 快照与
   `preserve_primary_boot_manager` 兜底（离线有，见 `main.rs:3049`）。这正是禁令清单第 1 条的高危操作。
4. **UAC 不提权**：`run_online_operation`（`native_gui.rs:5386`）不提权，而 diskpart/bcdboot 均需管理员。
5. **目标卷在线被挂载**，diskpart format 会失败；离线有 `verify_partition_identity_after_format` 复核，在线没有。

**推荐方案（分两步）**：

- **第一步（安全）**：在 `execute_inner` 探测目标是否含 `Windows\System32\config\SYSTEM`，
  命中则**显式拒绝**并提示改用「进入 Windows RE」离线链。这样堵住 H4 的坑，不引入任何破坏性能力。
  ✅ **已于 2.3.5 实施**：判据抽为 `pe_safety::target_is_windows_volume()`（复用 `probe_file`，
  继承拒绝重解析点穿越的保护；放在 `pe_safety` 是因为 `online_operation` 是 `#[cfg(windows)]`、
  本机不可测，而 `pe_safety` 是 `#[cfg(any(windows, test))]`），
  `online_operation.rs` 的 `restore-existing` 分支在解析索引前先调用并拒绝。
  单测 `windows_volume_detected_only_with_system_hive` 锁住判据（本机通过）。
- **第二步（已按用户裁定实施，非原推荐）**：用户裁定——第二系统中途断电无实质影响（主系统仍在，重新还原即可），
  **不强制走 RE 链**，直接在在线路径实现格式化 + bcdboot。2.3.6 已落地 `restore_to_windows_volume()`：
  diskpart 格式化 → DISM 应用 → `bcdboot /d` + bootmgr 快照前后比对（保留主系统默认项、追加新系统进菜单）。
  仍不调用 `winre_registration::repair`（拒绝非 PE），目标 WinRE 注册留待其首次启动后 `reagentc` 完成。

> **该结论已被 2.3.6 用户裁定推翻**：原"不建议在线做"的四条顾虑仍成立（无状态机 / `repair` 拒绝非 PE / bcdboot 改 bootmgr / 需提权），
> 但用户判定对**第二系统**而言这些风险可接受——断电最坏只是该卷不可启动、主系统仍在，重新还原即可，不值得为它引入状态机或强制走 RE。
> 因此 2.3.6 改为在线补格式化 + bcdboot，并复用 PE 的 bootmgr 快照比对（`/d` 不改主系统默认项）把引导风险压到最低；
> 仅 WinRE 注册仍交由目标系统首次启动后的 `reagentc` 完成（W09 收敛项）。
