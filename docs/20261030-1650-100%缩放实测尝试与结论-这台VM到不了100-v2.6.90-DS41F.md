# 100% 缩放的实测尝试与结论：这台 VM 到不了 100%

> 模型：DS41F。时间：2026-10-30 16:50。
> 代码零改动，不升版本。这是**验证覆盖范围**的记录，不是功能改动。

---

## 1. 为什么非要试这个

2.6.79 之后所有界面几何都由 `dpi::scale()` 驱动（`s()` 放大、`unscale()` 还原），
而**这一整轮（2.6.80~2.6.90）的几何与文字宽度判据全部只在 200% 下跑过**。
100% 下 `s()`/`unscale()` 退化为恒等、字体是 14px（不是 28px），
文字的排版/取整行为不同——从来没验过，是个实打实的空白。

## 2. 先说一个差点误导我的坑：读 DPI 必须声明 DPI 感知

第一版探针读 `GetDeviceCaps(LOGPIXELSY)` 得到 **96**，我一度以为「本来就是 100%」。
原因是那个 PowerShell 进程**没有声明 DPI 感知**，读到的是虚拟化值。
加上 `SetProcessDPIAware()` 后才读到真值 **192**。
`dpi.rs` 里那句注释（「声明感知后 GetDeviceCaps 返回的就是真实系统 DPI」）就是这个意思。

## 3. 四条路都试过，全部失败

| 尝试 | 结果 |
|---|---|
| `HKCU\Control Panel\Desktop\LogPixels` 改 96（+ `Win8DpiScaling=1`） | 改完立即读是 96，**重启后仍是 192** |
| `SystemParametersInfo(SPI_SETLOGICALDPIOVERRIDE, 0)` | 返回 **True**，但 `GetDpiForSystem` 前后都是 192 —— Win10/11 上这个老 API 已不改桌面缩放 |
| 设置 → 显示 → 缩放（UI 自动化） | 见 §4，控件被禁用；且它是**滑块式**下拉，改完要**注销**才生效 |
| `prlctl set --high-resolution-in-guest off` + 重启 | 客户机 DPI **仍 192**，分辨率仍 2350×1938 |

结论：**这台虚拟机的 200% 是 Parallels 显示管线直接给客户机的**，
Windows 内部的三个传统开关都压不过它。

## 4. 设置页里那个禁用的下拉框，暴露了真实机制

页面顶部有一条提示：「**自定义缩放比例已设置。关闭自定义缩放并注销**」，
而「缩放」下拉框是**禁用**的。也就是说：

- 这个 VM 早就设过一个**自定义缩放**（不是我设的，第一次截图就有这条提示）；
- 自定义缩放**必须注销才生效**，生效前 Windows 把常规的那个下拉框禁掉；
- 我点了「关闭自定义缩放并注销」→ 注销 → 重启自动登录 → 回到「推荐 200%」，
  但**下拉框依然不可用**，UIA 的 `Expand()` 报 `ElementNotEnabled`；
- 一次误操作还把它推到了 **250%**（那个下拉其实是个滑块，`Select()` 只有一项），
  已改回（`LogPixels=192`、`PerMonitorSettings\...\DpiValue=0`、`high-resolution-in-guest=on`、重启确认 DPI=192）。

**顺带一个可复用的教训**：写给我自己看的判据脚本里有中文，而 PowerShell 按 ANSI 读文件时
中文会乱码，导致 `-match '设置'` 永远不成立——第一版 UI 自动化脚本就因此报
`SETTINGS_WINDOW_NOT_FOUND`（其实窗口就在那儿）。改成**只用 ASCII、按 `%` 或 `AutomationId` 匹配**
就正常了。

## 5. 因此这一项的结论是

**100% 缩放下没有实测过，也不会在这台 VM 上实测。**
现有几何判据的覆盖范围应当如实写成：

> 2.6.79~2.6.90 的界面几何与文字宽度判据，**仅在 200% 缩放（DPI 192）下验证**。
> 100% 与中间档（125/150/175%）**未验证**。

风险有多大：`s()`/`unscale()` 是对同一个 scale 做乘法/除法，等比缩放下相对几何不变；
真正的差异在**字体 14px 时的排版与取整**（宽度实测、折行、行距），
所以 100% 下最可能出现的是「标签/按钮文字余量比 200% 下更紧」这类问题，
而不是布局错乱。要验它，需要一台能真正设成 100% 的机器。

## 6. 环境状态

- `high-resolution-in-guest` 已恢复 `on`；`LogPixels` 已恢复 192；`PerMonitorSettings` 的 `DpiValue` 回到 0；
- 重启后 `GetDpiForSystem` = **192**，与动手前一致；
- 判据脚本新增 `setdpi.ps1`（以 DPI 感知方式读真实 DPI，可复用）。
