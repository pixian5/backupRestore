- 基线 commit：`2b9d1222`（v2.6.14 弹窗引导改造之后）→ 本文提交 `efd8d7ce`（部署 SHA256 前缀）
- 验证时间：2026-10-18 03:35~03:40（VM "Windows 11" 实机）
- 证据边界：本文所有「已验证」结论均来自当轮实机操作（截图 / 日志文件 / 事件查看器 / 进程枚举），未验证项单独标注。

## 一、用户要求与问题

用户 2026-10-18 原话：「日志应该放到一个不是 PE、不是目标分区的一个地方。」

触发点：v2.6.14 验收时发现 GUI 日志实际写在
`C:\Users\Public\backupRestore-package\logs\gui.log`，而此前几轮一直读的是
`H:\brwork\logs\gui.log`（旧实例路径）——**同一功能两个落点，排障时按旧经验去翻会扑空**。

旧行为（所有日志一律 `<exe>\logs`）的三个问题：

1. **C: 可能是还原目标分区**。A 入口还原到 C:（离线）时，日志正写在「即将被
   重写」的卷上——还原成功之时正是日志消失之刻；
2. **PE/WinRE 里 `<exe>` 是内存盘** `X:\Windows\System32`，重启即失；
3. `<exe>\logs` 随程序目录搬迁而漂移，用户要的「一个固定的地方」不存在。

## 二、新策略（`crates/backuprestore-cli/src/log_root.rs`，新建）

进程内只解析一次（`OnceLock`），所有日志站点共用，**写方与读方永远同源**
（`launcher-errors.log` 由 CLI 进程写、GUI 进程读，两边各解析一次，
策略确定性保证结果一致）。按优先级取第一个可用的：

1. **`H:\brwork\logs`** —— 本项目磁盘布局约定的事务工作卷
   （`H:\brwork` + `H:\BRImages`；还原目标是 C:/E:/T:/P:，Y: 是 WinRE）。
   既不是 PE 也不是任何目标分区，路径固定。只认**已存在**的 `H:\brwork`，
   不在陌生机器上凭空造目录；
2. **卷探测** —— `C:`~`Z:` 逐个试建目录 + 写探针，跳过系统盘与程序所在盘
   （PE 里程序盘就是内存盘，跳了才躲开重启即失）。**第一轮只认「卷根已有
   `brwork`」的工作卷**（按内容认出它，不死磕 H: 这个字母）；都没有再按
   字母序取第一个可写卷，建 `<卷>\BackupRestore-logs`（与 `session_log`
   的镜像目录同名）。探测时建出来又没被选中的目录会清掉，不留垃圾；
3. **`<exe>\logs`** —— 最后兜底，保证日志永远有地方写。

解析结果写进 `<根>\log-root.txt`（一行：时间 + 路径 + 来源）——**日志自己
说明自己住在哪**。

## 三、顺带结清的两个旧坑（同属 v2.6.14~2.6.15 验收链）

### 3.1 tooltip `tool_count=0`：自有 `ToolInfoW` 多一个 `reserved` 字段

实机枚举：`tooltips installed: added=34 missing=0 tool_count=0` ——
`TTM_ADDTOOLW` 调用了 34 次，comctl32 一个都没收。

根因不在 windows-rs，而在项目**自己**的 `ToolInfoW` 结构体比 C 的
`TOOLINFOW` 多一个 `reserved: usize` 字段（x64 下 72 vs 64 字节），
comctl32 校验 `cbSize` 不匹配，全部拒收。

修复：新建 `#[repr(C)] struct ToolInfoFFI`，按 C 头文件逐字段对齐
（cbSize+uFlags 两个 u32 打头 → HWND 8 字节对齐 → uId → RECT 四 i32 →
hinst → lpszText → lParam，共 64 字节），`add_tooltip` 改用它。
同时补 `TTM_GETTOOLCOUNT` 常量、安装日志（added/missing/tool_count）、
`TTS_BALLOON` 气球样式。

### 3.2 验收脚本「卡死」：`SendMessage(BM_CLICK)` 是同步的

点按钮后 `SendMessage` 要等按钮处理函数（弹出模态框）整个返回才返回，
agent 侧永久挂起。改用 `PostMessage` 异步投递即解。

**教训**：对可能触发模态 UI 的控件，自动化点击一律 `PostMessage`。

### 3.3 agent 侧老坑复述（本次各踩一次）

- agent 只捕获 PowerShell 输出流，**C# `Console.WriteLine` 不到** ——
  必须 C# 返回 `List<string>` + PS `Write-Output`；
- agent 是常驻 runspace，**同名 `Add-Type` 第二次编译报「已存在」** ——
  换类名或先判 `("CDxx" -as [type])`；
- `FindMain()` 调用曾在编辑中丢失，`Main=0` 时先查是不是根本没调用，
  别急着改枚举逻辑。
