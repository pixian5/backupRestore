## 1. 这个项目是干什么的

Windows 下的「整机备份 / 还原」工具，支持三种还原入口：
- **A 还原系统到 C 盘**（本位还原）
- **B 数据到非 C 盘**
- **C 系统到非 C 盘**（如还原到 F:，双系统并存）

核心难点在 **BCD（启动配置数据）管理**：还原后要让电脑正常启动、且默认启动项（`{bootmgr}.default`）
指向「本次新还原出来的系统」。这条规则在 v2.6.1 从旧行为**翻转**（推翻 0725 文档的旧规则 2），
是近期最重要的行为变更，涉及 5 处代码。

## 4. 验收铁律（**最重要，别踩**）

1. **macOS `cargo test` 绿灯对 `#[cfg(windows)]` 模块零证明力。**
   涉及这些模块的改动必须在 **Windows VM 内重跑**。相关 cfg(windows) 模块（非穷举）：
   `online_operation` / `native_gui` / `windows_prepare` / `windows_command` /
   `recovery_progress` / `pe_operation` / `boot_entry` / `recovery_fault`。
2. **弱信号不算验收**：截图、EventID 1000、WerFault 都不能当「通过」证据。
3. **部署后必须核对二进制内含新代码**（见 §5 步骤 3），避免复制了旧产物。启动成功 ≠ 备份还原成功。
4. **改启动链前必须可回滚**：优先 `bcdedit /export <普通路径>`（提权通道即可用，见 AGENTS.md）；
   确需整机快照才拍，且全程最多 1 个（CoW 增量模型，估算「写入量 × 保留层数」）。
5. 跑 87GB 级还原前宿主空闲 ≥ 镜像 × 2.5；跑完立刻 `df -h /System/Volumes/Data` 检查。

## 6. 环境坑（血泪，务必记）

1. **`prlctl exec` 管道遇中文会断**：VM 内跑全量 `cargo test` 时，`#[ignore]` 的中文原因会
   中断管道（症状=输出截断在原因串中间、无结果行）。故 §5 步骤 2 必须 `--skip` 那 6 个用例，
   且 **`--skip` 要写在 `--` 之后**（`cargo test -- --skip X`；直接 `cargo test --skip X` 被 cargo 拒）。
2. **子进程输出别假设 UTF-8**：中文 Windows 上 `cmd /c` 在超时/负载时会写 GBK 错误
   （「系统找不到指定的路径。」）；读这类落盘文件一律 `fs::read` + `String::from_utf8_lossy`，
   不要 `read_to_string`（v2.6.3 修过一个因此偶发失败的用例）。
3. **PowerShell 5.1 脚本必须带 UTF-8 BOM**：无 BOM 的 .ps1 按系统代码页（简体中文=GBK）解码，
   中文字面量全乱（症状=「字符串缺少终止符」）。放客体的脚本先加 `EF BB BF`。
4. **判 CRT 静态/动态必须解析 PE 导入表**（数据目录 index 1，PE32+ 在 optional header +120）；
   `findstr /c:"VCRUNTIME140"` 在静态产物上会误报。
5. **`findstr` 搜不了二进制里的中文**：核对产物含新代码要用 UTF-8 字节比对，不是 findstr。
6. macOS 是 `sed -i ''`（BSD 语法）；本机是 MacBook M5 / macOS，与 VM（Windows ARM64）环境不同，别混。

  `decide_default` 的 WARN 只覆盖「原 default 没被探测进最终菜单」，且只在读**旧版落盘方案**
