# 虚拟机里堆了 828 个孤儿终端窗口——收工检查一直漏掉的一类残留

- 时间：2026-10-31 23:57
- 版本：**无改动**（`VERSION` 仍 2.7.3；本轮只动 `tools/vm/postflight.sh`，零个 `.rs`）
- 性质：残留清理 + 新增一条收工判据（修复一个会撒谎的复查项）
- 起因：用户看到 Parallels 窗口里一叠黑窗，截图问「怎么打开了这么多终端」

---

## 1. 我一开始查错了地方

先查宿主 Mac：只有一个 `Terminal` 进程（已跑 2 天 13 小时）、底下只有 2 个活会话
（`ttys000` 2 天、`ttys002` 1 天，都早于本次工作）；VS Code / Trae CN 底下 0 个 shell；
虚拟机里 `tasklist /fi "imagename eq powershell.exe"` 也是 0。于是判断「没有真窗口」。

**这个判断是错的**，错在判据的取样面：我只问了「有没有 powershell 进程」，
而窗口的宿主根本不是 PowerShell。

用户随后发来截图，画面是 Parallels 里层叠的深色窗口 + 右下角转圈光标——位置在**虚拟机里**。

## 2. 真正的现场

按控制台宿主去数（Windows 11「默认终端 = Windows Terminal」下，每个控制台会话会产生
一对 `conhost.exe` + `OpenConsole.exe`）：

```
CONHOST_TOTAL=829
CONHOST_ORPHAN=828      ← 父进程已在进程表里查不到
OC_TOTAL=828
WT_COUNT=1
SESSIONS=4,0
```

**828 对孤儿控制台宿主**，分布在 session 4（用户会话，看得见）和 session 0（SYSTEM，看不见）。

创建时间分布把肇事者指认得很清楚：

| 时段 | 数量 | 当时在干什么 |
| --- | --- | --- |
| 2026-10-31 01 | 275 | G4/G5 判据那一轮（大量提权探测） |
| 02 | 18 | 收尾 |
| 08 | 6 | G2 端到端实测 |
| **22** | **432** | **四个辅助窗口接入 GUI 矩阵**（每组合要开窗/量/关窗，每次探测一次提权） |
| 23 | 98 | 收尾复测 |

## 3. 根因：每次提权探测都漏一对控制台宿主

`tools/gui-check/ps/runas.ps1` 用 `Start-Process cmd.exe -Verb RunAs` 提权跑判据脚本。
在 Windows Terminal 做默认终端时，控制台要「交接」给 WT 托管；进程退出得太快时交接失败，
`conhost`/`OpenConsole` 成了**没有父进程的孤儿**，窗口却留在桌面上。

- 一次 GUI 矩阵 ≈ 200~400 次探测 → 一两小时就攒出几百个窗口；
- 这些窗口全是空壳（里面没有任何 shell），所以 `tasklist` 查 `powershell.exe` / `cmd.exe` 永远是 0；
- 单个占用不大，但几百个叠起来：屏幕糊满 + 每次开新窗口更慢。

## 4. 处置

### 4.1 当场清掉

只杀「父进程已不存在」的 `conhost.exe` / `OpenConsole.exe`（活着的会话一律不碰）：

```
KILL_TARGETS=828
AFTER_CONHOST=1        ← 只剩当前这条查询自己的
AFTER_OC=0
AFTER_WT=0
```

截图复核：虚拟机桌面**一个窗口都没有**了（只有桌面图标和任务栏）。

### 4.2 变成收工判据（这才是真正的修复）

`tools/vm/postflight.sh` 新增 `ITEM=orphan_console`：

```
ITEM=orphan_console status=pass count=0
```

- 判据：`conhost.exe` / `OpenConsole.exe` 里，**父进程 PID 在进程表中不存在**的数量。
- 有孤儿 → `status=fail`（不是 warn：这是残留，会让你看见一屏黑窗），并附
  `oldest_min=`（最早那个活了多久）与 `sessions=`（在哪个会话），`POSTFLIGHT=leftovers` 退出 1。
- `clean` 模式会只杀孤儿、然后**复查归零**；杀了没死（进程僵住）→ `reason=orphan_console_survived`。

### 4.3 顺带修掉一个「会撒谎的复查项」

跑 `clean` 模式时看到：

```
ITEM=clean_verify status=fail ghost_after=  mounted_after=0
```

明明干净却报 fail。根因是老代码只对 `state` 剥了 `\r`，`after`（清理后的复查读数）没剥：
`GHOST=\r` 让 `[ -z ... ]` 判空永远为假。**同一个坑只堵了一半。**

而且它 `status=fail` 却不影响最终结论——又是一个「判据不判」。两处一起改：
剥 CR；复查不通过就 `left=1`，真的变成 `POSTFLIGHT=leftovers`。

## 5. 验证

| 步骤 | 结果 |
| --- | --- |
| 清理前 | `conhost=829 / orphan=828 / OpenConsole=828` |
| 清理后 | `CH=1 OC=0 WT=0`，截图桌面无窗口 |
| `postflight.sh`（check） | `orphan_console status=pass count=0`，`POSTFLIGHT=clean` 退出 0 |
| `postflight.sh clean` | `clean_verify status=pass ghost_after=none mounted_after=0 orphan_after=0` 退出 0 |
| **变异**（把父进程判据改成恒真） | `orphan_console status=fail count=1 oldest_min=0 sessions=0` → `POSTFLIGHT=leftovers` **退出 1** |

变异那一枪同时证明：判据**读的是真进程表**（恒真时立刻数到当前探测自己的那个 conhost），
而且 `fail` 真的会让整体变红。

## 6. 没做的事（记进 BACKLOG）

- **没有根治泄漏**。根治方向是「复用单个提权进程」：现在每量一个窗口就提权一次，
  天然每次都可能漏一对。改成常驻助手（一个提权进程读命令、回结果）能同时解决两个问题：
  不再漏窗口，探测也快得多（现在每次提权要等 ~1 秒）。
- 没给 `runas.ps1` 加 `-WindowStyle Hidden`：能挡住视觉堆积，但**问题只是藏起来**，
  进程照样漏，反而更难被发现。宁可漏得看得见、由 postflight 报出来。
- 没动 GUI 矩阵脚本本身（不改变测量路径，避免把已验证的判据搅乱）。
