# 开工前检查报警，是「读数侧抽风」而不是「部署过期」——顺带扫出全仓 7 处多字节变量名地雷

- 时间：2026-10-31 23:18
- 版本：**无改动**（`VERSION` 仍 2.7.3；本轮只动 `tools/` 下的脚本，零个 `.rs`）
- 性质：工具加固 + 静态守卫新增一条判据
- 起因：上一轮收工后按规矩跑 `tools/vm/preflight.sh`，报 `ITEM=deploy_exe status=error reason=probe_failed` / `PREFLIGHT=error`（退出码 2），而部署其实是最新的

---

## 1. 现象与初判

```
ITEM=vm status=pass name=Windows 11
ITEM=deploy_exe status=error reason=probe_failed
PREFLIGHT=error
```

紧挨着的前一次运行还是 `status=present mtime=2026-10-31 23:13:10` / `deploy_version status=pass want=2.7.3`。
两分钟内既没有提交也没有重新部署，所以**不可能是真的过期**；而 `error`（退出码 2）按脚本自己的定义
就是「仪器或通道故障」。

重跑一次即 `PREFLIGHT=pass`。结论：`prlctl exec` 那约 1/8 的**静默不执行**抽到了这一次。

## 2. 但这不该报警——单发探测是全脚本唯一的抖动放大器

翻脚本发现一个刺眼的不对称：三处探测，两处带重试，一处单发。

| 探测 | 原实现 | 抖动时的后果 |
| --- | --- | --- |
| VM 可达 | 3 次重试 | 判 error（正确） |
| 部署件 mtime/尺寸/哈希 | **单发** | **判 error（把抖动当成了结论）** |
| 版本号串 | 3 次重试 | 判 warn |

而这条规则项目里早就写下来过：**「空输出分不清『真没有』与『命令没跑』」**。单发探测正好踩在上面。

## 3. 修法

### 3.1 三处探测统一走带哨兵的重试

```bash
run_ps()  {  # 要求回显 __END__ 才算真跑过，最多 3 次
  local script="$1" out
  for _ in 1 2 3; do
    out=$(prlctl exec "$VM" powershell -NoProfile -Command "$script" 2>&1)
    case "$out" in *__END__*) printf '%s' "$out"; return 0 ;; esac
    sleep 2
  done
  oneline "$out"     # ★ 失败时把原始回显当**标准输出**交回调用方
  return 1
}
```

### 3.2 `error` 与 `fail` 彻底分开，且 error 必须带 `raw=`

```
status=error reason=probe_failed attempts=3 raw=[channel_flaked: The operation was canceled.]
  >> 这是**读数侧**故障（通道没执行），不代表部署过期，别据此重构建；重跑本脚本即可。
```

`status=fail` 才是判据真的不满足（部署件比 HEAD 旧 / 版本号搜不到）。**没有 raw 的 error 等于没报**。

### 3.3 warn 不许被 `pass` 盖掉

版本号串本来就是次要信号（mtime 对 HEAD 才是主判据），通道抽风时判 warn 不该让整体变红；
但光写 `PREFLIGHT=pass` 又成了「通过但什么都没验」。改成：

```
PREFLIGHT=pass warn=deploy_version_probe_failed
```

## 4. 两个「死诊断」——修的过程中撞出来的

### 4.1 `$( )` 里调用的函数，给全局变量赋值等于没赋

第一版把原始回显写进全局 `LAST_RAW`，结果 `raw=[]` **永远是空**：`probe=$(run_ps ...)` 里的
`run_ps` 跑在**子 shell**，函数返回时赋值就丢了。这和之前那个 `WORST_SLACK=-999` 哨兵写反同族
——**看着有诊断，其实从不触发**。改成「函数用标准输出把 raw 交回去」才对。

### 4.2 ★★ `$VAR` 紧跟中文/全角字符，bash 3.2 会把首字节吞进变量名

变异 M3（把要搜的版本号换成必然不存在的串，逼脚本走「搜不到」分支）一跑就崩：

```
/tmp/pf-m3.sh: line 150: want_ver?: unbound variable
```

第 150 行是 `say "  >> 部署件里搜不到 VERSION 的 $want_ver：基本可以确定是旧版本。"`。
那个中文冒号是多字节，macOS 自带 bash 3.2 **按字节**解析变量名 → 名字变成 `want_ver<0xEF>`：

| 情形 | 后果 |
| --- | --- |
| 脚本带 `set -u`（本项目脚本都带） | 直接 `unbound variable` **崩掉**，后面的 `PREFLIGHT=` 一行都打不出来 |
| 不带 `-u` | 值被**静默吞掉**，只少一个数字，肉眼极难发现 |

两条都**只在失败分支触发**，所以长期没人碰见。实测最小复现：

```
$ bash -c 'set -u; v=abc; echo "前 $v：后"'      → unbound variable
$ bash -c 'set -u; v=abc; echo "前 ${v}：后"'    → 前 abc：后
```

**全仓按字节扫（`LC_ALL=C grep -E '\$[A-Za-z_][A-Za-z0-9_]*[^ -~]'`），命中 7 处，全部在报错路径上：**

| 文件 | 位置 | 触发条件 |
| --- | --- | --- |
| `tools/vm/preflight.sh` | 版本号搜不到时的说明行 | 部署件是旧版本时 |
| `tools/test/ignored-acceptance.sh` | 基线判据自身故障 | 基线判据坏了时 |
| `tools/test/ignored-acceptance.sh` | 故障标记目录读不到 | 仪器故障时 |
| `build-win.sh` | 缺 SDK libs 目录 | 工具链不全时 |
| `build-win.sh` | 部署 SHA-256 与基线不一致 | 部署校验失败时 |
| `build-win.sh` | GUI_CHECK 未通过 | 门禁变红时 |
| `tools/release/pack-dist.sh` | 找不到 exe | 打包前没构建时 |

「等于一报错就没报错」。七处全部改成 `${var}`。

## 5. 从「我记得」变成「门禁会红」：`source-guard.sh` 新增 D 节

仓库里其实早就有这条经验——`tools/test/source-guard.sh:122` 的注释就在讲它，但**只有注释、没有判据**，
所以那七处活了很久。现在补成第四节：

```bash
multibyte_hits=$(LC_ALL=C grep -rn -E '\$[A-Za-z_][A-Za-z0-9_]*[^ -~]' \
        --include='*.sh' --exclude-dir=target --exclude-dir=.git --exclude-dir=dist \
        "$ROOT" 2>/dev/null | grep -v -E ':[0-9]+:[[:space:]]*#' || true)
```

- `LC_ALL=C` 是必须的：要的就是**字节**语义，和 bash 3.2 的解析方式对齐。
- 注释行豁免——`source-guard.sh:122` 和 `br-smoke.sh:72` 本身就在讲这个坑。

## 6. 验证（全部实跑，不是推断）

### 6.1 preflight 五条分支各自可辨

| 变异 | 造法 | 输出 | 退出码 |
| --- | --- | --- | --- |
| M1 读数侧（通道）故障 | 让 powershell 探测永远返回无哨兵的回显 | `status=error reason=probe_failed attempts=3 raw=[channel_flaked: …]` | **2** |
| M2 部署件不存在 | 探测返回 `EXE=missing` | `status=fail reason=missing path=…` | 1 |
| M3 版本号搜不到 | 把要搜的串换成 `zzzznope` | `status=fail reason=version_string_absent` + 说明行**正常打出 2.7.3** | 1 |
| M4 版本探测没跑通 | 把哨兵改名 `__NOPE__` | `status=warn reason=probe_failed raw=[VER_HIT __NOPE__]` + `PREFLIGHT=pass warn=…` | 0 |
| M5 部署比 HEAD 旧 | 把 `-ge` 取反 | `status=fail reason=deployed_older_than_HEAD` | 1 |

★ M3 是这一轮最有价值的一次变异：**它把一条从来没执行过的 `say` 打崩了**。而且崩掉之后退出码
恰好也是 1（看着像「按预期失败了」），只是 `PREFLIGHT=` 那行没打——**只验 happy path 的变异，
等于只验了仪器在好消息下不撒谎。**

### 6.2 守卫本身也变异过

- 干净树 → `OK no_var_multibyte_collision` / `RESULT=PASS`
- 植入 `printf "退出码 $rc：坏了\n"` → `VIOLATION=var_followed_by_multibyte tools/test/_mut_probe.sh:4:…` / `RESULT=FAIL`（退出码 1），随后删除植入文件，`git status` 只剩两处正常改动
