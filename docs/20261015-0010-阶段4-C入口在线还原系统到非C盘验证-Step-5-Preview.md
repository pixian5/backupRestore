## 1. 阶段 4 是什么

C 入口 = tab「还原系统到非 C 盘」，内部操作键 `restore-system-other`，
**CLI 层映射为 `create-secondary`**（`native_gui.rs:1197`）。

它有两种通道（界面单选，`ID_CHANNEL_ONLINE=1212` / `ID_CHANNEL_OFFLINE=1213`，默认在线）：

| 通道 | 行为 |
| --- | --- |
| **在线**（本次验证） | **不重启**，在当前会话内 格式化 → 应用镜像 → 修复引导 |
| 离线 | 重启进 PE/RE 执行（此前那位 AI 只跑过这条，日志 `channel selected: offline`） |

在线分支在 `online_operation.rs:398` `"create-secondary" => restore_to_windows_volume(...)`。

**本次是这条在线通道的首次实机验证。**

## 2. 为什么必须用 GUI 真实驱动

在线通道 GUI 专属（CLI 只有 `prepare` 离线链），且用户要求「通过程序本体操作、真实确认链」。
因此全程用 VM 内 TCP agent 的**真实键鼠**驱动，未用 `--test-hook`。

## 7. 踩坑记录（GUI 自动化，本轮新增）

1. **每次点击前必须确认 GUI 在前台**。窗口被资源管理器抢焦点时，点击静默失效
   （日志无任何反应，极易误判成"按钮坏了"）。用 `SetForegroundWindow` + `GetForegroundWindow` 回读校验，
   **且不要用 `SW_RESTORE=9` 激活**（会把最大化窗口还原成默认尺寸，坐标全变）。
2. **zsh 的 `echo` 会把 `\c` 解释成「抑制后续输出」**：`echo "text H:\BRImages\c-full-…"`
   实际只发出 `H:\BRImages`（11 字符）。**写 batch 文件一律用 `printf '%s\n'`，不要 echo**。
3. **中文 `bcdedit` 输出把 `identifier` 本地化成「标识符」**，按 `^identifier` 匹配必然落空。
4. **选 combo 项不能用 `CB_SETCURSEL`**（不发 `CBN_SELCHANGE`，程序收不到）；
   可靠做法是点击 combo 获得焦点后按方向键（本轮索引选择即如此）。
5. **填完菜单名后索引 combo 会被界面刷新重置回索引 1**，须重选后再点创建任务。
6. 当前 GUI 跑的是 `C:\Users\Public\backupRestore-package\BackupRestore.exe`，
   日志在**同目录的 `logs\gui.log`**（不是 `H:\brwork\logs\gui.log`）——排障前先确认进程路径。
7. 在线日志落在**运行进程的 `%TEMP%`**：`C:\Users\x\AppData\Local\Temp\BackupRestore-online-<pid>-<ts>\Online.log`。
