# 把每次组合的 4~7 次探测合并成 1 次：泄漏再降一个数量级（B-2694 第二条）

- 时间：2026-11-01 01:35
- 版本：**无改动**（`VERSION` 仍 2.7.4；只动 `tools/gui-check/`，零个 `.rs`）
- 前情：`docs/20261101-0005`（三次订正，泄漏源是 `prlctl` 起的客户端进程）、`docs/20261101-0035`

---

## 1. 为什么

上一轮定论：**每调用一次 `prlctl exec --current-user powershell` 就漏一对** `conhost`/`OpenConsole`。
那么最直接的减排手段就是**少调用**。而矩阵当时的调用数是：

| 路径 | 原调用次数 | 拆解 |
| --- | --- | --- |
| 主窗口一个组合 | **7** | set-combo / launch / click(提权) / overlap / dlg-fit / fit-bottom / tipaudit |
| 一个辅助窗口 | **5** | aux-open(提权) / dlg-fit / overlap / fit-bottom / aux-close(提权) |

## 2. 做法：一个批处理脚本 + `-NoNewWindow`

新增 `ps/batch.ps1`：在**一次** prlctl 调用里顺序跑多个探测脚本，每个子进程用
`Start-Process powershell -NoNewWindow` **继承批处理自己的控制台**——不新建控制台，
就没有可漏的东西（和 `helper.ps1` 同一个原理，只是这里连常驻都不需要）。

```
主窗口：  7 次  →  4 次   （四个测量合并成 1 次）
辅助窗口：5 次  →  3 次   （三个测量合并成 1 次）
```

## 3. ★ 踩的坑：这个通道会**破坏参数里的特殊字符**

第一版把任务列表编码进**一个**参数，用 `@@` 分隔：

```
-Jobs "overlap-all.ps1|-Class X@@dlg-fit.ps1|-FontSize 18 -Class X"
```

结果 `BATCH=1`——三个任务静默变成了一个。加诊断打印实际收到的参数才看清：

| 分隔符 | 实际到达的内容 |
| --- | --- |
| `@@` | 整个消失（`x.ps1\|y.ps1\|z.ps1\|`） |
| `~~` | 变成**空格**（`x.ps1\| y.ps1\| z.ps1\|`） |

也就是说：**这不是我的解析写错，是通道在传参时改写了参数内容**。而参数长度本身是对的
（`RAW_LEN=22` 与原文一致），所以「长度对」不能证明「内容对」。

**改法：干脆不用分隔符**——每个任务一个独立参数 `-J1 … -J5`，各自带 `|` 分隔脚本名与参数：

```bash
vmps_batch() {
  local args=() i=0 spec out
  for spec in "$@"; do i=$((i+1)); args+=("-J$i" "$spec"); done
  prlctl exec "$VM" --current-user powershell ... -File "${DST}\\batch.ps1" "${args[@]}"
}
```

## 4. 验收

1. **数值不变**：`--quick` 前后逐项对照（这批数字是回归的锚点）：

| 项 | 批处理前 | 批处理后 |
| --- | --- | --- |
| 主窗口 font=14 zh tab=1101 | overlap=0 clipped=0 margin=514 | **overlap=0 clipped=0 margin=514** |
| 设置窗口 | clipped=0 margin=49 | **clipped=0 margin=49** |
| 备份文件管理 | clipped=0 margin=18 | **clipped=0 margin=18** |
| 查看日志 | clipped=0 margin=42 | **clipped=0 margin=42** |
| 任务与证据 | clipped=0 margin=77 | **clipped=0 margin=77** |

2. **完整矩阵**（2.7.4 上实跑）：`combos=40 clipped=0 overlaps=0 below=0 untipped=0 skipped=0`、
   `GUI_CHECK_AUX checked=16 clipped=0`、`RESULT=PASS`；耗时 **16:48**（改造前 18:49）。

3. **泄漏量（这才是重点）**：

| 场景 | 改造前收尾清扫的目标数 | 改造后 |
| --- | --- | --- |
| 一轮 `--quick` | **41** | **0**（`sweep=none`） |
| 一轮完整矩阵 | **65** | **3** |

   完整矩阵的 3 个属于「偶发」，不是「每次调用必漏」——批次把调用次数从每组合 7 次压到 4 次，
   泄漏量跟着掉了一个数量级。

## 5. 没做

- 提权那两次（`click` / `aux-open` / `aux-close`）没有合并进批次：它们需要 High 完整性，
  和普通批次不是同一个进程。要再省，得让 `runas.ps1` 支持「一个提权批次跑多步」——
  留作后续（`BACKLOG` B-2694 仍未关闭）。
- 根治仍是「让 prlctl 不起控制台」；本轮只是把次数压下来。
