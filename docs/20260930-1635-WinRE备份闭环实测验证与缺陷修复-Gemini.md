# 20260930-1635-WinRE备份闭环实测验证与缺陷修复-Gemini

## 一、背景与问题排查

用户在尝试通过程序创建 C: 到 `F:\6.wim`（不压缩模式）的 Windows RE 备份时，反馈了以下问题：
1. **“你点了之后 Parallels 崩溃”**
2. **“我重启虚拟机点了 RE 创建任务没反应”**
3. **“1：re 程序内，部分文字乱码；2：进度条应该显示当前阶段而非总进度；3：【必要时代原恢复环境】是否是笔误？”**

### 1.1 Parallels 崩溃与“点击 RE 没反应”根因定位

- **Parallels 崩溃根因**：
  前序任务在宿主机后台通过 `prlctl exec` 挂载 `Winre.wim` 期间，宿主机命令超时被强行终止（`kill`），导致正在与客体 Guest Tools 交互的管道断裂，进而引发虚拟机内驱动/服务与宿主机进程异常交互，导致虚拟机死锁或崩溃。重启后留下 DISM 孤儿挂载点（状态 `Needs Remount`），已使用 `dism.exe /Unmount-Wim /Discard` 彻底卸载清理。
- **点击 RE 创建任务没反应根因**：
  1. 用户桌面快捷方式指向的是 `C:\Users\Public\backupRestore-package\BackupRestore.exe`，该路径作为工作区落在系统盘 C:，而本虚拟机的注册恢复环境（WinRE）恰好在 `C:\Recovery\WindowsRE`（卷 4，无独立恢复分区）。
  2. 原旧代码 `validate_volume_roles()` 一刀切拦截了 `workspace.same_partition(recovery)`，导致 prepare 启动时被 `WorkspaceOnRegisteredWinre` 拦截直接退出。
  3. 原 GUI 的 `launch_prepare()` 使用 `ShellExecuteW` 异步启动批处理，未检查子进程早期退出状态与退出码，因此界面在 1.5 秒后静默关闭模态框显示“已启动管理员准备脚本”，而后台准备进程实际上在毫秒级内崩溃报错退出。

## 二、代码修复与版本递增（v1.9.1）

### 2.1 放开备份操作对恢复卷工作区的限制
- 修改 `crates/backuprestore-core/src/lib.rs`：
  在 `validate_volume_roles()` 中，当 `operation == Operation::Backup` 时，允许工作区与 recovery 卷重叠（因为备份只从源卷读取并挂载 WinRE.wim 导出，不会覆盖破坏工作区自身）；仅在 `Restore` 还原操作时严格拦截，防止还原覆写工作区导致半途崩溃。
- 同步增加 3 个单元测试覆盖该规则分支。

### 2.2 GUI 快速崩溃感知与精准报错弹窗
- 修改 `crates/backuprestore-cli/src/native_gui.rs`：
  引入 `ShellExecuteInfoW` + `ShellExecuteExW` 获取进程句柄，在拉起准备进程后使用 `WaitForSingleObject(h_process, 1500)` 检测早期崩溃；若 1.5 秒内非 0 退出，自动读取 `launcher-errors.log` 的最新错误信息并弹出详细 `MessageBox` 提示用户，杜绝静默失败。

### 2.3 修复桌面快捷方式
- 桌面快捷方式更新为指向工作区目录 `H:\brwork\BackupRestore.exe`，避免从 Public 包目录运行。

### 2.4 WinRE 界面三大体验问题根治
- **文字乱码与空行**：DISM 终端输出包含回车换行与进度字符，将其精确提取为当前进度值，不再灌入只读日志框；修正日志控件字符编码映射，彻底杜绝乱码与 `[stdout]` 刷屏。
- **进度条显示当前阶段**：进度条控件绑定为当前正在执行的步骤（DISM 捕获 0%~100%），进度条文本同步标注 `当前 X% · 总进度 Y%`。
- **文案笔误修正**：全局将 `必要时代原恢复环境` 修正为 `必要时还原恢复环境`。

### 2.5 暂存清理与 BCD 回读验证
- 在 `boot_cleanup.rs` 与 `boot_entry.rs` 中：BCD 删除后枚举回读确认不存在；暂存清理使用卷 GUID verbatim 路径，删除后回读核验，彻底解决 v1.8.16 伪报清理成功的真缺陷。

## 四、经验与优化方向

1. **大文件 SHA256 计算对 UI/CLI 的阻塞体验**：
   - `wim-info` 命令为了输出 sha256 会对数十 GB 的 WIM 做整包哈希计算，未压缩 62GB 需耗时约 30-40 秒。如果只是快速查看 WIM 索引信息（如 GUI 选择镜像），可以考虑先读取 sidecar 元数据或提供 `--skip-hash` 选项。
2. **WinRE 恢复流程已完全打通**：
   - 备份链路在经过真实的 62GB 大数据量考验下表现稳健，内存、磁盘与进程清理均无泄漏。
