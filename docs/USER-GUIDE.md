# BackupRestore 用户手册

> **适用版本：v2.6.53（2026-10-26）**。本手册是**活文档**（与 `ERROR-CODES.md` 同属命名例外的常青文件），
> 描述最终用户可见的行为；开发/验收细节见 `docs/` 下各轮文档，报障对照见 [`ERROR-CODES.md`](./ERROR-CODES.md)。
> 行为与源码不一致时**以程序实际行为为准**，并请把差异反馈给维护者。

---

## 1. 这是什么

BackupRestore 是一个 Windows 一键系统备份还原工具（开发测试版）。它能做四件事：

| 能力 | 一句话说明 | 破坏性 |
|---|---|---|
| 探测（仅检查） | 只校验系统、恢复环境与各卷身份，不写盘、不重启 | **否（全程无破坏）** |
| 备份 | 把选中的分区制作成 WIM 镜像文件 | 否（只读源卷，只写镜像文件） |
| 还原系统到 C 盘 | 把镜像写回当前系统盘并重建引导 | **是（覆盖系统盘全部数据）** |
| 还原数据到非 C 盘 | 把镜像在线还原到其他分区 | **是（覆盖目标卷数据）** |
| 新增非 C 盘第二系统 | 把完整 Windows 装到另一分区并加入启动菜单 | **是（覆盖目标分区）** |

另有一个「安装 PE」入口：制作/安装预安装环境（WinPE），是另一条简化路径。

**支持边界**：Windows 10/11、UEFI + GPT、NTFS 系统分区。**明确不做**：增量/差异镜像、网络备份、
Legacy BIOS（MBR）、自动修改 BitLocker。MBR 磁盘上的第二系统盘符绑定走不通，是硬边界。

## 2. 运行前提

1. **必须以管理员身份运行**。程序会自检；非管理员启动会因读不到卷身份而无法创建任务。
2. **从 `H:\brwork\BackupRestore.exe` 启动**（部署五件套都在 `H:\brwork`：`BackupRestore.exe`、
   `Recovery.exe`、`winpe-winpeshl.ini`、`wimlib-imagex.exe`、`libwim-15.dll`）。
   任务记录、日志也都在 `H:\brwork` 下——**不要只把 exe 拷到别处单独运行**，那会换一套任务视角。
3. 镜像（.wim）保存到一个**不是**被备份/还原目标的卷上。

## 3. 图形界面使用

### 3.1 界面一览

启动后主窗口（标题栏显示版本号，如 `BackupRestore - Rust GUI v2.6.53`）：

- **操作模式**（一排单选入口）：`备份` / `还原系统到 C 盘` / `还原数据到非 C 盘` / `新增非 C 盘第二系统` / `安装 PE` / `探测（仅检查）`
- **顶栏按钮**：`查看日志…`（列出最近修改的日志文件，可用记事本打开，也能直接打开日志目录）、
  `备份文件管理…`（列出镜像卷下的 WIM 与索引，可删除最旧索引只保留最近 N 个）、
  `取消待重启任务…`（放弃一个等待重启续跑的任务）、`设置…`、`语言`（中文/English，重启后保持）
- **主区域**随入口切换，通常有：源卷下拉、镜像路径（`浏览…`选择）、压缩率、索引名、保留最近 N 个、
  `格式化目标分区` 复选框（还原类入口）、`读取镜像`（解析选中的 .wim，自动带出索引信息）
- **底部按钮**：`刷新环境`（重新识别系统/恢复环境/各卷身份，**首次使用先点它**）、`读取镜像`、`创建任务`、`刷新任务状态`
- 每个入口下方有一块说明区，写清这个入口读什么、写什么、要不要重启——**动手前先读它**。

### 3.2 第一次使用：先「刷新环境」

点 `刷新环境`，确认：当前 Windows、恢复环境（WinRE/PE 入口）、各卷身份都被正确识别。
身份按「磁盘+分区 GUID」校验，不依赖盘符，所以盘符变化不影响识别。

### 3.3 第一次使用：再跑一次「探测」

选 `探测（仅检查）` 入口 → 点 `创建任务`。它只做**环境自检**：刷新并校验当前 Windows、恢复环境
（WinRE / PE 入口）与各卷身份（按「磁盘+分区 GUID」，不依赖盘符），并生成任务文件与恢复环境载荷以
验证这套搭建是否正确。

- **不会备份、不会还原、不会格式化、不会改启动项、不会重启**（走 `--no-reboot`）；
- 完成后看 `刷新任务状态` 与日志：准备成功即自检通过，之后再用备份/还原入口就心里有底；
- 探测任务不会变成「等重启续跑」的任务——它本来就不重启，不会堵住下一次操作。

### 3.4 备份

1. 选 `备份` 入口；源卷默认当前系统分区（可改选其他分区）。
2. 镜像路径填一个**绝对路径**（如 `H:\BRImages\my-backup.wim`）；镜像已存在时自动追加为新索引。
3. 压缩率：`压缩`=fast（速度体积平衡，默认）、`不压缩`=最快但文件最大。
4. 索引名默认取「系统版本+启动时间」，可改；`保留最近 N 个`填 N 可自动清理旧索引（0=不清理）。
5. 点 `创建任务` → 破坏性确认框（备份的确认框只说明要读哪个卷、写哪个镜像）→ 确认后：
   - **数据卷**：在当前 Windows 里在线直接完成，进度走完即成功；
   - **系统卷**：自动重启进入恢复环境离线捕获，完成后自动返回 Windows。
6. 成功后任务记录与日志留在 `H:\brwork`（见 §7）。

### 3.5 还原

三个还原入口按目标分叉，共同点是**都会覆盖目标上的数据**，都有确认框：

- `还原系统到 C 盘`：目标锁定为当前运行的系统盘；`格式化目标分区`默认勾选（先格式化并校验成功才写镜像，
  取消勾选 = 覆盖式应用，旧文件会残留）。走恢复环境，结束后自动修复引导并重启回 Windows。
- `还原数据到非 C 盘`：在线执行，目标自选；同样可勾选格式化。
- `新增非 C 盘第二系统`：把完整 Windows 装到另一分区，结束后加入启动菜单（双系统）。

还原成功的一等判据（程序内部会逐条校验，任一不过拒绝报成功）：目标卷序列号变化、
启动菜单项齐全、默认启动项指向本次还原的系统、恢复环境注册完好。

### 3.6 卡住了怎么办

- 恢复环境里可以按 `P` 暂停/继续、按 `B` 回退启动配置数据、按 `L`/`M`/`K` 查看日志等
  （进度窗上有按钮，也有快捷键）；关闭窗口前程序会等当前步骤到边界。
- 顶栏 `取消待重启任务…`：放弃一个「等重启续跑」的任务（保留全部证据，只清一次性启动项）。
- 无人值守时失败达到阈值（默认 3 次）会自动清理并重启回 Windows，不会把机器留在恢复环境里。

## 4. 命令行用法

`H:\brwork\BackupRestore.exe <命令> [参数]`。不加参数打印完整命令表。

| 命令 | 用途 |
|---|---|
| `online --operation backup\|restore-existing\|create-secondary --source-drive <字母> [--target-drive <字母>] [--image-path <绝对路径>] [--index <n>] [--compress <fast\|none>] [--image-name <名>] [--keep-indexes <n>] [--format-target] [--ui-language <zh\|en>]` | 在线链：数据卷备份/还原、第二系统。`--compress` 不填 = fast |
| `prepare --operation probe\|backup\|restore-existing\|create-secondary --source-drive <字母> [--target-drive <字母>] [--image-path <路径>] [--wim-index <n>] [--boot-menu-name <名>] [--skip-format] [--fail-threshold <1-20>] [--fail-action <auto-escape\|pause>] [--ui-language <zh\|en>] …` | 准备期：校验、写任务、注入恢复环境载荷、设一次性启动 |
| `resume <task-root> <task-id>` | 续跑/清理一个已有任务（`<task-root>` 是**工作区根**，如 `H:\brwork`，不是 tasks 目录） |
| `recover <task-root> <task-id> [--dry-run] [--efi-root <挂载的 EFI 根>]` | 恢复环境/PE 内手工续跑通道 |
| `wim-info <绝对路径> [--skip-hash]` | 只读解析镜像索引与元数据 |
| `status <task-root> <task-id>` / `hash <文件>` / `list-volumes` / `inspect-environment` | 查任务状态 / 算文件 SHA-256 / 列卷 / 环境自检 |
| `--json` | 任何命令加它：结论打成**一行 JSON**（`command/operation/success/task_id/log_path/error/error_code`） |

**自动化请用 `--json`**：判据只认字段（`success`、`error_code`），不要解析日志文案——日志文案有多语言版本。

**语言**：优先级 `--ui-language` 旗标 > 环境变量 `BACKUPRESTORE_LANG` > 设置文件 `ui_language` > 中文。
例：`set BACKUPRESTORE_LANG=en` 后任何命令的日志与结论都走英文。

## 5. 恢复环境流程会发生什么

以「还原系统到 C 盘」为例，从点「创建任务」开始：

```text
Windows 里 prepare：校验 → 保存 BCD 快照 → 注入独立 WinRE 载荷 → 设一次性启动项
   → 自动重启进恢复环境 → Recovery.exe 自动拉起
      → 离线应用镜像（DISM 主力，失败自动降级 wimlib 重试一次）
      → bcdboot 修复引导 + 回读校验（默认项/菜单/resumeobject 全对才报成功）
      → 清理本任务临时启动项与载荷副本
   → 重启回正常 Windows
```

- 中途失败：按设置的失败策略重试（默认 3 次）；恢复环境里可手动 `P` 暂停、`B` 回退 BCD。
- 「自动降级 wimlib」不是故障：DISM 超时/失败时程序自动换 wimlib 通道重试，日志里有 `自动降级` 行，
  任务仍以成功结算。
- 全程不动恢复环境本身以外的系统组件；任务记录（`task.json`/`status.json`/日志）全部保留在 `H:\brwork\tasks\<任务号>\`。

## 6. 失败自助：看错误码

所有运行期失败的文案都带**稳定错误码**，格式 `[BR-域-序号] 文案`：

1. **找码**：日志里 `grep -a "[BR-"`（PowerShell: `Select-String -Pattern '\[BR-'`），
   或命令行报错行 `error:` 后的方括号前缀；`--json` 则直接看 `error_code` 字段。
2. **查码**：对照 [`ERROR-CODES.md`](./ERROR-CODES.md)（213 条，中英双语）。**码是契约，不会变**，
   报障时报码即可精确定位。
3. **命令行用法错误**（如参数写错）**故意不带码**——英文原文即标识；带码的才是运行期失败。

常见失败速查：

| 现象/码 | 含义 | 怎么办 |
|---|---|---|
| 目标容量不足（`BR-PE-048`） | 目标卷放不下镜像展开后的体积 | 换更大目标卷，或勾选格式化后重试 |
| 文件被占用（日志分类「占用」） | 目标卷上有程序占着文件 | 关闭占用程序重试；恢复环境内通常不出现 |
| 镜像损坏（日志分类「镜像损坏」+ `BR-APL-001/004`） | 镜像文件本身坏了，**不会**自动降级 | 换一份镜像；别把坏镜像当备份 |
| DISM 超时（日志分类「超时」） | DISM 卡住超上限 | 程序自动降级 wimlib 重试；可在设置里调 `dism_timeout_secs` |
| 副档不匹配（`BR-PE-047`） | 镜像旁的 `.index-N.metadata.json` 与镜像对不上 | 别手改副档；重新备份或删掉过期副档 |
| wimlib 缺件（`BR-APL-002/003`） | 程序目录缺 `wimlib-imagex.exe` 或 `libwim-15.dll` | 把两个文件放回 `H:\brwork` |
| `BR-IO-001` | 文件/系统调用失败（文案随系统语言） | 看文案里的路径：多半是路径不存在/被占用/权限 |

日志位置见 §7。**报障时请附：错误码 + `H:\brwork\logs` 下对应时间段的日志**。

## 7. 设置项与日志

### 7.1 设置（`设置…` 按钮 → 写 `H:\brwork\BackupRestore.settings.ini`）

| 键 | 含义 | 默认 |
|---|---|---|
| `failure_threshold` | 恢复环境内连续失败多少次后自动清理重启回 Windows（1–20） | 3 |
| `failure_action` | 达阈值后的动作：`auto-escape`（自动清理重启）/ `pause`（弹框停机等待人工） | auto-escape |
| `failure_pause_max_wait_secs` | `pause` 策略的无人值守总等待上限（秒，0=不限制） | 0 |
| `dism_timeout_secs` | DISM 等待上限（秒，0=不限制） | 0 |
| `ui_language` | 界面语言 `zh`/`en`（也可用顶栏「语言」下拉切，重启保持） | zh |

设置对**之后创建**的任务生效；已在跑的任务沿用创建时的设置。
（维护者注记：该文件由多个模块共享，写它必须合并写，只替换自己那行。）

### 7.2 日志在哪

| 内容 | 位置 |
|---|---|
| 统一日志根 | `H:\brwork\logs\`（在线任务 `BackupRestore-backup-*` / `BackupRestore-restore-*`） |
| 每个任务的证据 | `H:\brwork\tasks\<任务号>\`（task.json / status.json / 日志，**全部保留**） |
| 恢复环境主日志 | 镜像同目录 `Recovery.log`（如 `H:\BRImages\Recovery.log`） |
| GUI 操作审计 | `H:\brwork\logs\gui.log`（每次点击都有记录，排障时看这里） |

想直接翻日志不用记路径：顶栏 `查看日志…` 会列出日志根目录下**最近修改的 20 个**日志文件
（本轮任务的日志排在最前），选中一个点「用记事本打开」，或点「打开日志目录」进资源管理器。

## 8. 已知边界（再次强调）

- 只支持 UEFI + GPT + NTFS 系统分区；MBR 盘做不了第二系统。
- 没有增量/差异备份、没有网络备份、不自动处理 BitLocker。
- 覆盖式还原（不勾选格式化）会保留旧文件残留；要干净就勾选格式化。
- 「保留访问控制列表」是默认行为（属主/ACL 逐字节还原），覆盖式通道同样保留。
