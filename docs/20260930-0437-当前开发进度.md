## 已完成并有实机证据

- 新 PE 式离线通道已完成测试卷备份、还原闭环；还原后测试卷内容与镜像逐字节一致，项目 BCD 项清理，注册 WinRE 未变。
- 真实 C: 系统卷还原已按用户授权实机完成，包含 DISM Apply-Image、BCDBoot、BCD 指向核验并成功回到 Windows。还原后 WinRE 曾 Disabled，已通过 `reagentc /enable` 恢复并核验。
- `power-loss-image-applied` 故障点断电续跑在测试卷闭环通过：任务重新武装、重启进入 PE、继续执行至 success，恢复数据与镜像大小一致。
- 断电续跑期间发现并修复 payload 哈希刷新与 SOURCE 序列号校验两个缺陷，详见 [断电续跑验收记录](20260930-032000-power-loss-resume-loop-passed.md)。
- 用户确认「进入 PE」和「进入 Windows RE」表达可选择的两种离线处理环境；产品应保留两个选项。任务 RE 使用注册 Winre.wim 副本构建，名称不要求限定为微软原版恢复环境。

## 当前 GUI 选择故障

此前实机日志出现按钮点击记录 `choice=2`，但对话框结果返回 `0`，导致程序按取消处理。源码已修改为通过局部结果盒读取选择，不再在窗口销毁后访问 HWND；同时增加按钮选择、返回值、确认结果及 ShellExecute 返回码日志，并将 prepare 控制台设为显示。

源码现有版本为 1.8.9 的未提交改动。此前虽部署过相关构建，但尚无可靠证据证明当前客体运行的是最新包，也尚未通过真实 GUI 点击或等效消息注入证明 `choice=2` 完整流转。因此该故障只能标记为**代码已修、实机复验待完成**。`--test-hook` 自动设置 choice 会绕过选择对话框，不足以作为按钮修复验收。
