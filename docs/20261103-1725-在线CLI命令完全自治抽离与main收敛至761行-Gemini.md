## 一、背景与设计动机

在 `v2.8.0`（巨石模块大解耦）、`v2.8.1`（测试用例高内聚归位）与 `v2.8.2`（全仓生产代码 0 unwrap & 0 expect 双零防线落地）之后，CLI 主入口 `crates/backuprestore-cli/src/main.rs` 已经由最初的 6,287 行大幅缩减至 888 行。

然而，在 `main.rs` 中仍残留着原 `online_cli` 命令的冗长参数解析循环（491-616 行，共 127 行），处理包括 `--format-target`、`--operation`、`--source-drive`、`--target-drive`、`--image-path`、`--index`、`--compress`、`--image-name`、`--keep-indexes`、`--ui-language` 等大量在线操作专有的命令行参数。这违背了高内聚与各功能模块完全自治的演化原则（此前 `image_admin` 与 `recovery_engine` 均已完成命令解析收拢自治化）。

## 二、重构核心改动

### 1. `online_operation.rs` 承载完整在线 CLI 驱动

在 `crates/backuprestore-cli/src/online_operation.rs` 中提供公有自治入口：
```rust
#[cfg(windows)]
pub(crate) fn cli_online(args: Vec<String>) -> Result<(), TaskError>
```
将原本属于在线备份/在线还原/在线克隆的全部命令解析逻辑自治化封装在模块内部：
- 提取 `--format-target`（在线还原格式化目标卷开关）；
- 提取 `--operation`、`--source-drive`、`--target-drive`、`--image-path`、`--index`、`--compress`、`--image-name`、`--keep-indexes`；
- 提取 `--ui-language` 并通过 `crate::i18n::set(language)` 设置本进程国际化文案；
- 构造 `OnlineOpParams` 并调用 `online_operation::execute`；
- 统一处理 `--json` 模式下的结构化日志路径与错误码分流（保持错误码与文案的契约化输出）。

### 2. `main.rs` 彻底清除 127 行冗余解析

在 `crates/backuprestore-cli/src/main.rs`：
- 分发路由处简化为单行调用：
  ```rust
  #[cfg(windows)]
  Some("online") => online_operation::cli_online(args.collect()),
  ```
- 物理删除 491-616 行 `online_cli` 函数实现，`main.rs` 源码行数从 888 行直接骤降至 **761 行**。
