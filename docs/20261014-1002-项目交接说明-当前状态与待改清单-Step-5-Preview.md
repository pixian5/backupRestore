## 3. 操作手册（接手方必读）

### 3.1 构建与部署

```bash
./build-win.sh --deploy        # 宿主机交叉编译 + 部署到 H:\brwork（同时刷自启包）
```

- 产物真名 `backuprestore-cli.exe`，部署前用 `Get-FileHash` 核对，`findstr` 查中文/二进制不可靠。
- **版本三处同步**：`VERSION`（根目录，`build-windows.ps1` 读它）+ `crates/backuprestore-cli/Cargo.toml`
  + `crates/backuprestore-core/Cargo.toml`（`PROGRAM_VERSION` 来自 `CARGO_PKG_VERSION`）。
- **验证二进制里的中文文案**：Rust 字符串字面量在二进制里是 **UTF-8**（不是 UTF-16）：
  `[Text.Encoding]::UTF8.GetString([IO.File]::ReadAllBytes($p))` 再 Contains。
- 改完立即 `git commit` + `git push origin main`，**不要问用户要不要提交**（项目铁律）。

### 3.2 VM 与 GUI 自动化

- VM 名 `Windows 11`（Parallels）。`prlctl exec "Windows 11" cmd /d /c "..."`（不加 `--current-user`）= SYSTEM+管理员。
- **GUI 界面自动化唯一可靠路线** = VM 内 TCP agent `tools/win-clicker/br-agent-tcp.sh`
  （提权 + Session 1 + 高完整性，真实键鼠）：`click x y / key 0xVV / chord mod,key / text 字符串 / exec 本地.ps1 / shot / batch / windows`。
  - **消息级注入（SendMessage / BM_CLICK）不可行**：GUI 是高完整性进程，被 UIPI 拦；BM_CLICK 对自绘按钮也无效。
  - **exec 与 agent 同进程**：脚本里写 `exit` 会**杀死 agent**（现象：连接重置、零输出）。一律用 `return`。
  - **激活窗口勿用 `ShowWindow(SW_RESTORE=9)`**：会把最大化窗口恢复成默认 1020×760，布局坐标全变、点击全落空。用 `SetForegroundWindow`，要最大化用 `SW_MAXIMIZE=3`。
  - **combo 回读**：项数 `CB_GETCOUNT=0x0146`（**勿用 `0x014B`=RESETCONTENT，会清空列表**）、选中 `0x0147`、项文本 `0x0148`；`WM_GETTEXT` 的 wParam 必须传缓冲区字符数。
  - **可靠全选** = `End(0x23)` + `Shift+Home`（标准 EDIT 本身不支持 Ctrl+A，这不是注入问题）。
- **控件 ID**：创建任务 `1003`、源卷 combo `1202`、镜像路径 `1203`。
  **屏幕坐标（1254×954 最大化态）**：创建任务 (340,489)、源卷 (705,133)、路径框 (660,383)；确认框「是」(660,579)、「否」(756,579)。
- ⚠️ **`--test-hook` 会自动接受所有确认框**（`TEST_AUTO_CONFIRM`）。要验收真实确认链必须用纯净 GUI：
  `tools/win-clicker/restart-gui-plain.ps1`（计划任务 Interactive+Highest，无参数）；`restart-gui-testhook.ps1` 切回钩子版。

## 4. 待改清单（P0 → P6，按建议优先级）

### P0 · 【安全漏洞】create-secondary 可以格式化当前活动系统

- **现象**：`prepare --operation create-secondary --source-drive T --target-drive C` 会被接受 → 重启进 RE 后 diskpart **格式化当前正在运行的系统盘**。GUI 里同样能构造（源卷选 T:、目标选 C:）。
- **根因**：
  - GUI 智能分流 `native_gui.rs:4983` 是 `matches!(operation, "backup" | "restore-existing")`，**create-secondary 不在内** → 不过 `%SystemDrive%` 检查；
  - prepare 侧 `assert_environment`（`windows_prepare.rs:2298`）只查 **source** 的 SYSTEM hive；target 只查 `is_reserved_partition`；
  - 唯一挡着的是 `source != target`（`core/lib.rs:807`），把 source 选成 T: 即绕过。
- **改法**：在 `windows_prepare.rs` 的 `RestoreExisting | CreateSecondary` 分支（约 1977 起）
  **只对 CreateSecondary** 加：取 `%SystemDrive%` 的 `volume_identity`，若 `target.same_partition(...)` 则拒绝并给明确错误。
  ⚠️ **不能一刀切**：restore-existing 的目标 = `%SystemDrive%` 是**合法场景**（重建唯一系统，GUI 会弹窗走 PE/RE 离线链）。
- **验证**：①create-secondary target=C 应被拒；②`restore-existing --source-drive C --target-drive C` 应正常走离线确认链。
- **风险**：低，约 10 行。

### P1 · 离线 restore-existing 到「非活动 Windows 卷」的收尾是错的

- **现象**：离线还原完整 Windows 镜像到 C 以外的 Windows 卷时，格式化 + BCDBoot 都做了（观感 = 装好第二系统），但收尾缺三样
  → **抢走主系统默认启动项** + **第二系统盘符绑定错乱** + **WinRE 注册不对**，产出「能启动但会崩、且主系统每次开机被劫持」的半成品。
- **根因**：`main.rs` 里这些收尾只在 `target.role == NewWindows`（即 create-secondary）执行：`/d /addlast`(2700-2725)、
  `secondary_registry::repair`(2685)、`assert_boot_default_preserved`(2677 靠 `previous_boot_manager`)、
  `winre_registration::repair_secondary`(2731)、`set_secondary_boot_menu` + `preserve_primary_boot_manager`(2737-2745)。
  而 STEP 3/4 的分支条件只是「目标卷有 SYSTEM hive」（2640-2646），**与 role 无关**。
  **对比**：在线路径 `online_operation.rs:300` 遇到 Windows 卷目标反而走 `restore_to_windows_volume`
  （有全套 `/d /addlast` + `secondary_registry::repair`）——**两条通道自相矛盾，在线的那套才是对的**。
- **改法**：把收尾判定从「操作类型」改为「操作类型 + 目标性质」：
  `target_is_windows_volume(target_root) && !target.same_partition(当前活动系统卷)` → 按 NewWindows 收尾。
  需要把「目标是否为当前活动系统」带进 RE（prepare 时在 task 里记一个布尔字段，RE 内读取）。
- **验证**：用一个非活动的 Windows 卷（E: 或 P:，**别用 C:**）做离线还原，检查三项：BCD `default` 没变、新系统能正常进桌面、菜单项名正确。
- **风险**：改 BCD 写入，必须实机验证。

### P2 · `wim_full_windows_probe` 硬拒数据卷镜像（待办修复项⑤）

- **现象**：`windows_prepare.rs:1988` 对 `RestoreExisting | CreateSecondary` **都**调 `wim_full_windows_probe`。
  DISM `/Mount-Wim` 可用时，缺 `reagentc.exe`/`SYSTEM` 标记的**数据卷镜像被硬拒**。
  本机因挂载报 87 走了「镜像名启发式放行」才通过 → **换台机器，数据卷的离线还原会被直接拒绝**。
- **改法**：`RestoreExisting` 分支下判定为数据卷镜像时放行（恢复期本就有 data-volume 分支，日志会打
  `data-volume restore: target has no SYSTEM hive; skipping BCDBoot`）。判据可取自副档 metadata 或放宽 probe 的 outcome 处理。
  ⚠️ **CreateSecondary 必须保持硬拒**（装第二系统必须是完整 Windows）。
- **风险**：中。判据取错会让「拿数据卷镜像装第二系统」漏过。

### P3 · `source` 字段三义 + `require_windows_volume` 名不副实

- **事实**：
  - backup：source = 被捕获的卷，**执行层真用**（`main.rs:2237` `/CaptureDir`）；
  - restore-existing：source = **target 的别名/锚点**（强制 `source == target`），RE 里挂载后**无人使用**（`main.rs:1067` 挂载，还原流程只读 target）；
  - create-secondary：source = 「保留的系统」，**执行层同样无人使用**，唯一作用是 `target != source` 这条约束；
  - `core/lib.rs:378 validate_volume_roles` 传了 `source` 但**函数体没用它**；
  - `windows_prepare.rs:2329 require_windows_volume` **只查「非保留分区 + NTFS」，根本不查有没有 Windows**（T: 数据卷秒过）。
- **改法（低风险）**：
  ① restore-existing 的 GUI 标签 `native_gui.rs:1600`「源卷（当前系统）」→「源卷（须与目标相同）」，tooltip（1766/1782）同步；
  ② create-secondary 的 tooltip 去掉 "current Windows to keep" 暗示（代码没这个校验）；
  ③ `require_windows_volume` 改名 `require_ntfs_nonreserved`——**不能真加 Windows 检查**（会破坏数据卷备份/还原）。
- **风险**：纯文案，零风险。

### P4 · 字面 `'C'` 技术债

- `native_gui.rs:3721`：`if drive_char == 'C' || drive_char == 'S' || drive_char == program_drive` —— 用**字面 C** 代替系统盘判据（PE 安装的目标校验）。
- **危害**：系统盘不是 C: 的机器（双系统从 E: 启动、PE 环境、盘符重排）会误判——要么错误拒绝，要么放行到真的系统盘。
- **额外背景**：程序现在有**三套「系统盘」判据**在混用：`%SystemDrive%`（4984/2802/3322/1397，当前运行）、
  `drive.has_windows_installation`（3738，任何装了 Windows 的卷）、字面 `'C'`（3721）。改之前先明确要用哪个语义。
- **改法**：改用 `%SystemDrive%`（4984 有现成写法）。

### P5 · `winre_registration` 硬要求 `reagentc.exe`，失败即整体失败（历史 5 项之①）

- `winre_registration.rs:315-320`：目标缺 `Windows\System32\reagentc.exe` 或 `config\SYSTEM` →
  `Err("目标缺少离线注册组件")` **整体失败，没有降级**。
- **历史后果**：2026-10-13 实测 create-secondary 因此失败，而此时 bcdboot 已把 `{bootmgr}.default`
  改到半成品系统上（用户每次开机被拖进去，只能离线改 BCD 才能救）。
- **改法**：改成「跳过 WinRE 注册 + 记警告」而非整体失败；或者把该检查**提前到擦除前预检**
  （在还没动 BCD 的时候就失败，代价为零）。
- **风险**：涉及注册状态机，需实测。

### P6 · 「单系统还原」拆成「还原系统盘 / 还原其他盘」（用户提议，**未授权**）

- **用户诉求**：拆两个入口；「还原 C 盘」锁定目标不用选，新手友好，还能省校验、避免出错。
- **已给出的评估结论**：
  - ✅ 收益真实：消除 `source == target` 这个反直觉约束、消除「误选目标盘」这个最危险误操作。
  - ❌ **「省掉校验」是错觉**：能省的只有 target 的点选和 `source==target` 那条约束。镜像完整性、副档大小/哈希、
    索引有效性、容量预检、BitLocker、保留分区、身份重绑定 —— **一条都省不掉**；
    而且**容量预检在锁定态更要加强**（用户失去了「换个更大的盘」这条纠错路径）。
  - ⚠️ **「C 盘」不能按字面实现**：必须锁 `%SystemDrive%` 的 `volume_identity`（disk/partition/GUID/serial），
    界面显示实际盘符「当前系统盘 (D:)」——系统盘非 C 的机器按字面锁会**锁错盘并格式化它**。
  - ⚠️ 拆成 5 个 tab 会让新手更晕；**建议不拆 tab**，而是在「单系统还原」tab 内加一行模式单选：
    ⦿ 当前系统盘（默认，锁定） ○ 其他分区（手动选）。
  - ✅ 顺带的事实：默认行为已经近似「还原系统盘」（备份默认源 = 系统盘，切到还原时 GUI 自动把 target 同步成 source），
    所以新手真正的痛点其实是那个**误导性标签**，而不是缺少入口。
- **状态**：等用户拍板。**未授权，不要擅自动手**。

## 6. 关键机制速查（别重踩坑）

| 主题 | 要点 |
| --- | --- |
| **盘符绑定** | 盘符**不是分区的物理属性**，存在每套 Windows 自己的 `HKLM\SYSTEM\MountedDevices`；同一物理分区在两套系统里可叫不同字母，「两个都自认 C:」不冲突。判定镜像自认字母的唯一依据 = 离线 SOFTWARE hive 的 `SystemRoot`。本项目策略 = **迁就镜像**（`secondary_registry::repair()`，不改写 SystemRoot）。详见 `docs/20261014-0945-…` |
| **BCD 不依赖盘符** | 启动阶段用设备路径/分区 GUID；盘符只在内核读完 SYSTEM hive 后建立 |
| **ramdisk 规格** | 一律写**设备路径** `ramdisk=[\Device\HarddiskVolumeN]\...`（`boot_entry.rs:421-431`）。数据卷上写盘符形式 bootmgr 解析不了 → **静默丢弃一次性 bootsequence**（不报错，看着像没重启） |
| **数据卷 vs 系统卷** | 判据是目标卷有无 `Windows\System32\config\SYSTEM`。没有 → 只应用、不碰引导（全通道一致）；有 → 格式化 + BCDBoot 全流程 |
| **WinRE 里没有 reagentc.exe** | 要操作注册位必须全路径调用**离线目标 OS 自带**的 `<目标>:\Windows\System32\reagentc.exe` |
| **镜像副档** | `<wim名>.index-N.metadata.json`：容量预检 + 防冒充。⚠️ 副档的 `name` 字段固定显示 `Windows Backup (index N)`，WIM **实际索引名**才是 `--image-name` 的值（DISM `/Name` 生效） |
| **RE 启动模式** | **ramdisk 内存模式**：WIM 暂存镜像卷，bootmgr 载入成 RAM 盘 X:；注册恢复分区全程只读。旧通道（v1.7.11 前）才是写回注册分区的「独立分区」模式 |
| **在线 vs 离线** | GUI 分流用 `%SystemDrive%`（**不是「任何含 Windows 的卷」**）：受影响卷 == 当前活动系统 → 弹窗选 PE/RE 走离线；否则在线直接执行、不重启 |
