# 主界面「镜像绝对路径」那一行顶部被状态框压住（v2.6.85）

> 模型：DS41F。时间：2026-10-30 12:50。
> 版本：**2.6.85**（改行为 +0.0.1）。
> 关联：`docs/20261030-1017-设置界面过小-窗口尺寸与文字块高度两层缺陷-v2.6.82~v2.6.84-DS41F.md`
> （同一类缺陷的第三个化身：**高度改了，靠它算出来的下游坐标没跟着改**）。

---

## 1. 用户报的现象

2.6.84 交付后用户回了一句：

> 「镜像绝对路径这一行顶部被稍微遮挡了。」

说的是**主界面**（不是设置窗口）中间那一行：左边标签「镜像绝对路径」、中间输入框、右边「浏览…」按钮。
字的**上沿**被上面那个大块状态提示框（`说明：系统分区必须在离线环境备份……`）压住一条。

## 2. 真因

主界面每一行的 y 都是在 `layout_operation()` 里按上一行累加出来的。这一行是：

```rust
let status_y = last_details_y + 16 + pe_extra_y;
let image_y = status_y + 168;        // ← 罪魁
```

168 这个数不是随便来的：2.6.79 时状态框高度是 **148**，加上 20 的空隙正好 168。

但 **2.6.80 把界面基准字号从 12 提到 14**，状态框高度换成按行距算：

```rust
let status_height = crate::dpi::text_block_height(9, 25);   // 9 × 17 + 25 = 178
```

178 − 168 = **10 个基准像素**（200% 缩放下 20 物理像素）——状态框的下沿盖在下面这一行上。

实机量的数字（中文、14 号字、200%，`.test-artifacts/dpi-2679/main-rects.ps1`）：

| 控件 | 上沿 | 高 | 下沿 |
|---|---|---|---|
| 状态框 `id=1300` | 705 | 356 | **1061** |
| 镜像路径输入框 `id=1203` | **1041** | 48 | 1089 |
| 「镜像绝对路径」标签 `id=2004` | 1045 | 48 | 1093 |

输入框上沿 1041 比状态框下沿 1061 **小 20 物理像素** → 顶部被压 20 像素。
标签因为本身比输入框低 4 像素，被压 16 像素，所以看起来只是「稍微遮挡」。

**为什么一直没被发现**：被压的是这一行的**上边缘**，标签文字本身（14 号字约 20 像素高）还能露出大半，
不像「最后一行被切成半截」那么刺眼。是用户对着截图看出来的。

## 3. 改动

`crates/backuprestore-cli/src/native_gui.rs` 的 `layout_operation()`：

```rust
// 状态提示框的高度：9 行文字 + 边框与余量，随字号变。
let status_height = crate::dpi::text_block_height(9, 25);
let status_y = last_details_y + 16 + pe_extra_y;
// 状态框与下一行之间的空隙。原来是 20（= 168 − 148）；现在按实测高度算，
// 8 已经够呼吸，也少往下推一些，免得整窗底部贴到屏幕边。
let status_gap = 8;
let image_y = status_y + status_height + status_gap;
```

三处配套：
1. `status_height` 从「reposition 状态框那一行」提前到函数上半段（原来在那儿现算），
   下面几行的 y 全部改用它，不会再有第二个 168；
2. 「探测」页那个分支 `else { status_y + 168 }`（没有镜像行时按钮直接跟状态框）
   同样是错的，一并改成 `status_y + status_height + status_gap`；
3. 原来在 reposition 处的那句 `let status_height = …` 删掉（值一样，留着容易两处走岔）。

空隙从 20 降到 8：状态框自己有边框，8 已经能分开；更重要是**下面的行只下移 18 个基准像素**
（178+8−168），而不是 30（178+20−168），避免整窗底部贴近屏幕边。

**判据方式**：`main-rects.ps1` / `status-gap.ps1` 枚举主窗口子控件矩形，直接比

所以不存在 2.6.84 里那种「判据自己量错」的空间。视觉另用截图确认。

### 4.1 全部页签 × 全部字号（200% 缩放，物理像素）

| 页签 | 14 号：状态框下沿 / 镜像行上沿 | 18 号：状态框下沿 / 镜像行上沿 |
|---|---|---|
| 备份 | 1061 / 1077（16） | 1213 / 1229（16） |
| 还原系统到非 C 盘 | 1177 / 1193（16） | 1329 / 1345（16） |
| 还原数据到非 C 盘 | 1177 / 1193（16） | 1329 / 1345（16） |
| 新增第二系统 | 1177 / 1193（16） | 1329 / 1345（16） |
| 安装 PE | 1241 / 1257（16） | 1393 / 1409（16） |

间隙恒为 16 物理像素是因为 `status_gap = 8` 写在 96dpi 基准空间里，200% 下正好 16——与字号无关，
所以 18 号字下**不会**因为行高变大而重新压上（这条是这轮复核才确认的：原来只抽查了 3 个页面）。

### 4.2 复核：怎么证明这 10 个数字不是同一个页面的 10 次重复

第一版判据（`overlap-all.ps1`）有个盲区：**如果点击没生效，5 个页签会测到同一个页面**，
而 `OVERLAPS=0` 照样是绿的。复核时补了两项自证：

1. **页面指纹**：打印每页可见控件的 id 集合。五页互不相同（29 / 27 / 29 / 31 / 32 个，
   指纹哈希各异），而且各自带着该页特有的控件——
   备份页有源卷标签 `2003`、压缩率 `2014` 而**无**目标卷 `1204`；还原系统页反过来；
   还原数据页多出通道单选 `1212/1213`；新增第二系统页再多出 `1207/2008`；安装 PE 页是 `1410~1418` 整组。
   这些可见性差异与代码里的 `source_visible` / `target_visible` / `channel_visible` / `index_visible`
   逐一对应，所以「确确实实切到了 5 个不同页面」。
2. **窗口底边**：18 号字下窗口底边 1855 物理像素，五个页面最底可见控件在 1493~1597 之间，
   余量 258~362——**没有任何控件被窗口底边切掉**（此前只比过「屏幕高 1938」，口径偏松，这次换成窗口实际底边）。

**顺带发现一个「读不到」的陷阱**：想用「哪个页签按钮处于选中态」当第二重自证，
读出来五个全是 0。这不是「五个都没选中」，而是**跨进程读不到**——GUI 是提权进程，
中等完整性进程发的这条查询被拦了。
按项目规矩，**「读不到」与「判据不满足」必须分开报告**，所以判据里把它标成
`CHECKED_UNREADABLE=1`，不转成红灯，改用可见控件集合当指纹。

### 4.3 顺带算出：这个 bug 在大字号下严重得多

状态框高度 `text_block_height(9, 25)` 随字号变：

| 字号 | 行距 | 状态框高度 | 与旧的 168 相比 |
|---|---|---|---|
| 14（默认） | 17 | 9×17+25 = **178** | 压 10 基准（20 物理） |
| 18 | 21 | 9×21+25 = **214** | 压 **46 基准（92 物理）** |

也就是说用户把字号调到 18 时，「镜像绝对路径」这一行会被盖掉将近一半——
用户看到的是 14 号下的「稍微遮挡」，实际最坏情况远不止「稍微」。


## 5. 这类缺陷的通用形状（第三次了）

| 版本 | 高度发生了什么 | 谁没跟着改 | 症状 |
|---|---|---|---|
| 2.6.80 | 基准字号 12→14，行距 14→17 | `details_height` / `status_height` 三处创建高度 | 多行文本最后一行被切半截 |
| 2.6.83 | 说明文字高度改成实测 | 每块文字高度与下一个控件的 y | 第三行画到控件外、被下一个控件盖掉 |
| **2.6.85** | **状态框高度 148→178** | **`image_y = status_y + 168`** | **下一行顶部被压 10 基准像素** |

同一个形状：**某个高度变了，靠它算出来的坐标是常量。**
所以改高度时应当 `grep` 一遍「所有用旧高度推出来的 y」，而不是只改高度本身。
现在这个文件里已经没有 `168` / `148` 这类魔数（只剩注释里提到它们）。

## 6. 遗留

1. `status_gap = 8` 是从 20 调下来的经验值。若将来状态框改成「按实际文案行数自适应高度」，
   这个空隙要重新看一眼（现在是「按最坏 9 行固定高度」，所以下面的行位置是稳定的）。
2. 状态框在「安装 PE」页会靠 `WS_VSCROLL` 滚动——那是**故意**的（宁可滚，也不切半行），
   与本次改动无关。
3. 100% 缩放仍未实测（与本轮改动无关，属历史遗留）。
