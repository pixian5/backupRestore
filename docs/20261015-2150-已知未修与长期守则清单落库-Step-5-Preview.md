## 2. 跨版本仍有效的守则（.workbuddy/memory/MEMORY.md 库内镜像）

### 2.1 构建与部署
- 一律宿主机交叉编译 `./build-win.sh --deploy`（产物 `target/aarch64-pc-windows-msvc/release/backuprestore-cli.exe`）；**改完即 commit+push origin main，不要问**；版本三处同步（`VERSION` + 两 crate `Cargo.toml`，`Cargo.lock` 由 `cargo` 自动同步）。
- **构建路径唯一化**：用户 2026-10-15 拍板「编译完全走 VM 内 Windows」（`docs/20261015-0844`）；macOS 侧仅限本地 `cargo test` / `cargo check` 快速回归，**产物不得部署、不作发布依据**。
- `+crt-static` 不能漏：漏了进不了精简 WinRE/PE（退出码 0xC0000135，症状=零输出零副作用）。VM 内 `build-windows.ps1` 已幂等内置。

### 2.2 文档与工作纪律
- 入口 `docs/20261011-2350-项目全景与知识浓缩-Hy4.md`；新文档 `docs/YYYYMMDD-HHMM-<标题>-<模型名>.md` + README/文档索引同步；**写「当前行为」前回源码核对**。
- **弱信号不算验收**：功能可用须 ①截图 ②EventID=1000 无崩溃循环 ③WerFault≤1。
- **「分析/检查/看看」= 只读**，一个字节都不改；想改先列清单问用户。
- 引用历史文档前先查 `经验/07-墓碑与争议清单.md`（文档说法与经验库冲突时以经验库为准）。

### 2.3 还原验收与现场清理
- **哨兵法**：还原前目标卷根放 `BR-时分秒.txt`，还原后必须消失；**序列号变化 + 哨兵消失**才是铁证（DISM Apply 保留 WIM 内时间戳，目录时间不能证明重写）。
- **还原成功后删快照**：`prlctl snapshot-list` 有残留立即 `snapshot-delete -i <id>`。
- **测试分区用后即删**：**该项若是当前 default 先 `bcdedit /default {主系统}`**——`/delete` 掉 default 项会把 `{bootmgr}.default` **一并清空**（2026-10-15 实测）→ 再 `displayorder /remove` → `/delete {guid} /f` → `format X: /FS:NTFS /Q /Y`。
- **快照纪律（CoW，修正版）**：快照=相对父快照的增量，拍摄几乎不占空间；一次修改只付一次、不随层数翻倍；真正代价=各层增量累积、删前不释放。纪律：该拍就拍 → 还原前先删旧快照 → 验证通过即删 → 不长期挂多层。
- **改 BCD 用 `bcdedit /export` 代替拍快照**（在线态提权即可用，实测定论见 `docs/20261015-0708`）；ESP 原文件任何身份都拷不走。

### 2.4 VM 操作
- `prlctl exec "Windows 11" cmd /d /c "…"` = SYSTEM+管理员。**路径反斜杠一律双写**（UNC 单写静默失败）；`-File` 不吃 UNC。
- `-Command` 禁转义双引号，管道/花括号被扰；`wmic`/GBK 输出过 `strings` 会滤空 → `iconv -f GBK`。
- GUI 自动化：TCP agent `tools/win-clicker/br-agent-tcp.sh`（exec 禁 `exit` 用 `return`）；点击前 `br-focus-gui.ps1` 聚焦回读；**跨进程读文本只有 UIA 可靠**。
- WinRE 内无 `prlctl exec` 会话；看屏 `prlctl capture --file`。
- **VM 内跑测试**：源码走共享盘 `\\Mac\backupRestore`，cargo 在 SYSTEM profile
  （`C:\Windows\System32\config\systemprofile\.cargo\bin\cargo.exe`）。
  **全量 `cargo test` 必须 `--skip` 掉 6 个 `#[ignore]` 用例**（中文 ignore 原因会中断
  `prlctl exec` 管道，症状=输出截断在原因串中间、无 panic 无结果行）；或输出重定向到客体文件再
  `type` + `iconv -f GBK` 读回。用例名见
  `docs/20261015-2220` §4'。
  **cargo 的 `--skip` 要写在 `--` 之后**（`cargo test -- --skip X`）：直接 `cargo test --skip X`
  会被 cargo 自己拒掉（unexpected argument）。
- **子进程输出别假设 UTF-8**：中文 Windows 上 `cmd /d /v:off /c` 在超时/负载时会把 GBK 错误
  （「系统找不到指定的路径。」）写进落盘文件；测试与工具读这类文件一律
  `fs::read` + `from_utf8_lossy`，不要 `read_to_string`（2026-10-15 修过一个因此偶发失败的用例）。
- **PowerShell 5.1 脚本必须带 UTF-8 BOM**：无 BOM 的 .ps1 会被按系统代码页（简体中文=GBK）解码，
  中文判据全变 mojibake（症状=解析报「字符串缺少终止符」）。放进客体的脚本先加 `EF BB BF`。
- **构建/部署只走 VM 内** `build-windows.ps1 -Architecture arm64 [-CargoTargetDir C:\br-build] -Deploy`
  （`& '\\Mac\backupRestore\windows\build-windows.ps1'`，UNC 可用 `-Command` 调）；
  `Publish-Build` 会自行 `Stop-Process` 旧程序再复制并逐文件核对 SHA-256。
- **核对二进制内含新代码**：判据从源文件抽取后按 **UTF-8 字节**在产物里搜
  （`.test-artifacts/verify-new-code-in-binary.ps1`）；`findstr /c:"中文"` 匹配不了二进制里的中文。
- **判 CRT 静态/动态必须解析 PE 导入表**（数据目录 index 1，PE32+ 在 optional header +120）；
  `findstr /c:"VCRUNTIME140"` 在静态产物上会误报。
- **跑 87GB 级还原前宿主空闲 ≥ 镜像大小 × 2.5**；编译产物绝不能放还原目标卷。

### 2.5 测试边界与磁盘
- C: 可作测试源/目标；在线入口仍拒绝活动系统盘当在线目标；未点名真实目标时默认测试环境。
- H:=`H:\brwork` + `H:\BRImages`；F: 第二系统已删；E: 大目标 / T: 5G 卷 / P: 测试 / Y: WINRE 别碰。
- A/C 入口验收从 H: 卷起 GUI（`restart-gui-h.ps1`）：程序卷==目标卷触发自毁保护。

### 2.6 default 归属（现行规则，v2.6.1 起）
- 还原后 `{bootmgr}.default` **一律指向本次新还原出来的系统**（0725 旧规则 2「保持原主系统」已废除）；bcdboot 不带 `/d`；在线/PE 终检=「default 指向目标卷」；原系统仍钉在菜单里。
- 决策唯一权威：`boot_menu::DefaultPolicy` 注释；纯逻辑在 `boot_menu::decide_default`（有单测护栏）。
- 备份索引名默认「系统版本+年月日」（`Windows 11 26200.9550 20261015`）；**主版本按 build 判定**（≥22000=Win11，`ProductName` 会撒谎）；源卷非系统盘降级 `Windows (F:) 日期`。
- **备份与在线还原共用 `online_operation` 模块**（按 `operation=="backup"` 分叉）：备份目录也叫 `BackupRestore-online-*`；核对现场看 `dism.exe` 命令行判型（`/Capture-Image`=备份 vs `/Apply-Image`=还原）；`durationSecs` 是挂钟差，VM 挂起会虚高，判卡死看进程+进度推进。
