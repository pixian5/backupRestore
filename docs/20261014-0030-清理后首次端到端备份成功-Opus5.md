# 清理后首次端到端备份成功（2026-10-14 00:30，v2.4.7）

> 模型：Opus5｜用户指令："重新编译，并且执行一次备份"
> 用户选定：源盘 **T: 5G 数据卷**，镜像落 **`H:\BRImages`**（按 10-13 23:55 的新约定）

## 1. 前置：重新编译部署

```
./build-win.sh --deploy
>> 产物：2505216 字节
>> DEPLOYED SHA256=1b39a1e280f09530bd51a1c773e957e625983345d6e48c99088041e909a09315
```

源码相对上一版无改动，cargo 直接命中缓存（`Finished in 0.09s`），产物哈希与上一版一致。
构建输出里 `LNK4099 ... libvcruntime.arm64.pdb` 仍是 SDK 静态库缺 PDB 的固有警告，无害。

## 2. 坑：未终结任务会阻止新建任务（必须先解锁）

首次执行 `prepare` 直接被拒：

```
error: invalid task: 检测到尚未终结的任务，未创建新任务或修改启动配置。
请先继续原任务，或明确放弃并清理旧任务：
id=0d8f1ed5-30f5-44de-8297-dfa01339a1fe operation=Backup stage=BootRequested
```

- 该任务是 10-13 20:42 那次，卡在 `BootRequested`（当时报 `Recovery.exe 载荷 sha256 不符`）。
- 它的载荷目录已随 `F:\BackupRestoreRE` 删除、`{bootmgr}` 上也**已无 `bootsequence`**（一次性启动已消费）。
- 处置：**删除任务目录** `H:\brwork\tasks\0d8f1ed5-…\` 即可解锁（另外两个 `852c0dad`=failed、
  `ae3dac88`=success 是终态，不挡路，保留作证据）。
- **排查口诀**：`prepare` 报"检测到尚未终结的任务" → 先 `bcdedit /enum {bootmgr}` 确认无残留
  `bootsequence`，再删对应的 `tasks\<id>\` 目录。

## 3. 备份执行

```
H:\brwork\BackupRestore.exe prepare --operation backup --source-drive T \
    --image-path H:\BRImages\T-drive-backup.wim --wim-index 1
```

**未加 `--no-reboot`**（用户明确禁止），走完整闭环：准备 → 重启进 RE → 捕获 → 清理 → 重启回桌面。

```

  new boot channel: staging directory …\BackupRestoreRE\577b8f7e-… removed and verified

```

**两点值得记：**

1. **载荷确实落在镜像卷 H:**（`staging …\BackupRestoreRE\<id>`，`recorded_letter=H`）——
   这是 2.4.7 定案的现场印证：载荷**不再**放系统卷 C:，而是随镜像卷（见
   `docs/20261014-0003-载荷必须在系统卷的说法已作废-机理与更正-Opus5.md`）。
2. 收尾做了**双重"removed and verified"**：BCD 自建对象 + 载荷暂存目录都删掉并复核。

捕获本身：`dism /Capture-Image` → `/Get-WimInfo` 复核 Index 1 = `Windows Backup`、
Size 16,777,397 bytes，`duration=1s`。

## 5. 收尾校验（回桌面后）

- `{bootmgr}`：**无 `bootsequence`**，`default={12e3701c-…}`、`timeout=10`、`displayorder` 两项 → **BCD 已自动回基线**。
  （`device partition=S:` 是 RE 视角的盘符显示，桌面视角为 `\Device\HarddiskVolume2`，同一对象。）
- 载荷清理：`C:\BackupRestoreRE` 不存在、`H:\BRImages\BackupRestoreRE` 不存在，H: 卷根只剩 `BRImages`、`brwork` → **无残留**。
- 客户机代理恢复（`prlctl exec` 可用）→ 机器已回到桌面。

## 6. 结论

**v2.4.7 端到端备份闭环在清理后的环境上通过**：准备 → 重启进自建 RE → DISM 捕获 → 写元数据副档 →
清理 BCD 与载荷 → 重启回桌面，全程无人工干预，`stage=success`。
