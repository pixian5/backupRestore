# 取消「恢复环境降级跳过」：缺组件必须失败（v2.6.73）

> 用户 2026-10-28 两个决定：
> ① 缺恢复环境组件时 **要「任务失败并说明原因」**，不要「成功但残废」；
> ② 镜像哈希 **不强制校验**（默认仍只比大小）。

* * *

## 一、先说一个「查代码才发现的设计变样」

我原本按 `经验/07 §3` 的清单，准备去修「优先级 5：缺 reagentc/SYSTEM 时擦除后才失败」。
读代码后发现清单**过期了**：

1. 擦除**之前**有 `pe_operation::check_image` → `wim_full_windows_probe`；
2. 它挂载镜像做**权威判定**，查的正是 `Windows\System32\reagentc.exe` 与
   `Windows\System32\config\SYSTEM`（`windows_prepare.rs` 的 `wim_mount_markers`）；
3. 也就是说，正常路径下**格式化之前就拦住**了。

但顺着往下读，发现了清单没写的一件事：**`Preflight::Skip` 不是死代码**。
目标卷缺这两个组件时，真实后端会返回 `Skip`，于是任务**报成功**、日志写「按裁定跳过」，
而新系统**根本没有恢复环境**。

这比「擦除后失败」更糟：用户看到「还原成功」，以为以后能进恢复环境检修，真出事时进不去。

★ 顺带一条教训：我第一遍只看了 `preflight` 的前半段就断言「Skip 是死代码」，
   是 `grep` 出全部 3 处 `Preflight::` 才纠正过来。**「我以为」不算证据。**

## 二、改了什么

按用户裁定，把整条「降级跳过」通路拆掉——不是加个开关，而是**让这种状态在类型上不存在**：

| 删除 | 原作用 |
| --- | --- |
| `enum Preflight { Proceed, Skip(String) }` | 前置检查能返回「跳过」 |
| `pub(crate) enum RegistrationOutcome { Registered, Skipped(String) }` | 调用方要区分「注册了」和「跳过了」 |
| `run()` 里的 `if let Preflight::Skip(..)` 分支 | 跳过时提前返回成功 |
| `pe_operation` / `main` 里两处 `Skipped(reason)` 处理 | 复述「已跳过」 |

现在 `preflight() -> Result<(), TaskError>`、`repair() -> Result<(), TaskError>`：
**只有成功，或带码失败**。调用方想「假装成功」都写不出来。

新增错误码（码是契约，只增不重排）：

```
BR-RE-047  WinreComponentsMissing
目标卷缺少恢复环境注册组件（{0}），无法注册恢复环境；
系统虽可启动，但日后无法从恢复环境检修，按裁定拒绝继续
```

失败点是**干净的**：`preflight` 在 `run()` 最前面，缺组件时**一次注册写入都不会发生**
（用例断言 `calls == ["preflight"]`）。

## 三、判据（两条变异，各自单独变红）

新用例 `registration_fails_when_components_missing` 钉三条不可退让的性质：

1. 返回 **Err**（不是 Ok）；
2. 错误码是 **BR-RE-047**（界面/日志靠它定位）；
3. **一次注册写入都不许发生**（`calls` 只有 `preflight`）。

| 变异 | 结果 |
| --- | --- |
| 替身改回「缺组件也返回 Ok」 | 红：`缺组件必须失败，而不是『跳过算成功』: ()` |
| 把错误码改成 `BR-RE-999` | 红：`错误码必须可定位，实际：[BR-RE-999] …` |
| 还原 | 绿 |

★ 第二条变异证明的是「判据真在查码」，而不是「碰巧 Err」——这条区别很要紧，
否则将来有人把码改掉、用例照样绿。

## 四、关于镜像哈希：记录决策，不改行为

用户裁定**不强制校验**。所以：

- 默认行为保持「仅比大小」，`--verify-hash` 才比 SHA256；
- 决策写进 `经验/07 §3`，并**把风险写在旁边**：同大小、内容不同（损坏/半写入/被替换）时，
  可能应用到一半才发现系统起不来，而备份阶段本来就有 SHA256。
  —— 写下来是为了将来有人问「为什么这么设计」时能立刻答上，而不是重新讨论一遍。

- `.fault-<name>.triggered 跨任务只触发一次` → 仍待处理，见下。

**下一轮**：故障注入标记那一条。我读代码后的修正判断是——根因不是「标记位置错」，
而是**任务目录被复用**（我们的验收夹具就固定同一个 task id），陈旧标记把注入吃掉。
所以方向应当是「注入被陈旧标记抑制时必须**大声记日志**」+「门禁跑前清掉夹具根下的标记」，
而不是去改标记位置（改了反而会让「同一任务只触发一次」的语义失效）。
