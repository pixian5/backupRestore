# RE 进度窗新增「打开命令提示符」按钮与 K 快捷键（v2.5.6）

> 模型：GLM-5｜版本 **2.5.5 → 2.5.6**｜用户需求：RE 内恢复程序增加启动 cmd 的功能（按钮+快捷键），方便现场运行命令修复。

## 1. 实现

- `recovery_progress.rs`（RE/在线恢复的进度窗口）：
  - 新按钮 `ID_CMD_BUTTON=9`「**打开命令提示符(K)**」，常显（不依赖任务阶段），排在按钮行第三位（详细日志(L)/引导修复/命令提示符）；布局 `tail_width` 相应让出三份按钮宽。
  - **快捷键 K**（VK_K=0x4B）：消息循环全局拦截，与既有 L（详细日志）同机制——WinRE 下鼠标未必可用的纯键盘通路。代价与 L 相同：焦点在文本控件时无法输入字母 K（进度窗自身无可编辑文本，仅影响日志弹窗/引导修复编辑器，可接受）。
  - `open_cmd_prompt()`：调 `windows_command::spawn_detached_interactive("cmd.exe")`（新增 pub(crate) 函数）：**分离启动、不等待、不捕获输出、不挂作业对象**（cmd 与恢复流程并行存活，绝不被收尾连带终止）；启动结果写 Recovery.log。
- 关键决策：进程启动放 `windows_command.rs` 复用其既有 CreateProcessW 声明（避免同 crate 内两份不同签名的 extern 声明冲突告警）。

## 2. 验证（真 RE 环境，三件套全过）

借一次 C 入口离线任务的 RE 执行窗口（进度窗存在约 5 分钟）验证：

| 项 | 结果 |
| --- | --- |
| 按钮渲染 | ✅ RE 进度窗按钮行三个按钮并排：「详细日志(L)」「引导修复」「**打开命令提示符(K)**」 |
| **K 快捷键** | ✅ `prlctl send-key-event -s 75` → **黑色 cmd 窗口弹出**（与进度窗层叠），恢复流程（STEP 2/4 87%）继续跑不受干扰 |
| 按钮点击 | ✅ Tab×4 导航到按钮 + 回车 → 第二个 cmd 弹出（两 cmd 与进度窗共存） |

编译+单测 138/43 全过；部署四处 SHA256 一致 `f9e1fa1c…`；二进制含按钮文案。
