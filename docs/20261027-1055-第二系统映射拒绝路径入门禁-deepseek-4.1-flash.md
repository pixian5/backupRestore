# 第二系统映射：把「永远不跑」的破坏性用例拆出只读拒绝路径

**日期**：2026-10-27 10:55 ｜ **版本**：仍 **2.6.68**（只加测试与门禁用例，产品代码零改动）
**前置**：`docs/20261027-0205-ignore安全测试门禁化与拆分`（同类手法）、N3 第一步
**本步范围**：`ignored-acceptance.sh` 的 `pass` 从 **3 → 4**，SKIP 仍 5，但**最该常态化的安全属性进了门禁**。

---

## 0. 为什么先做这一条

N3 原计划是「把 3 条依赖真实第二系统的用例改成 VHD 夹具」。读代码后发现更划算的切法：
`secondary_registry::repair()` **前面有三道纯拒绝的守卫**，它们一个字节都不写，
根本不需要第二系统分区——而这三条恰恰是最该天天跑的安全属性：

| 守卫 | 条件 | 错误码 |
|---|---|---|
| ① 卷身份不符 | `verify_binding(expected, actual)` 比对 GUID/几何 | `BR-PE-004` |
| ② 目标是当前系统盘 | `SystemDrive == {letter}:` | `BR-VOL-014` |
| ③ 目标缺 hive | 缺 `Windows\System32\config\{SYSTEM,SOFTWARE}` | `BR-VOL-015` |

原来的 `offline_secondary_mapping` 只验**成功路径**（真去改配置），F: 删除后它退化为
「永远不跑」——**最危险的写操作没有任何自动化覆盖，而它的护栏反倒没人验**。

---

## 1. 做法：拆成两条，共用同一份前置

新增 `secondary_mapping_rejections`（`#[ignore]` 但理由写准：「需要 Windows 管理员与一个
非系统卷，默认 `H:`，可用 `BR_REJECT_DRIVE` 覆盖」），三条断言：

```rust
// ① 身份不符 → BR-PE-004
wrong.partition_guid = "{00000000-0000-0000-0000-000000000000}";
// ② 空临时目录（身份对、但没有 hive）→ BR-VOL-015
// ③ SystemDrive 自己（身份对、hive 也在，但这是自己的配置）→ BR-VOL-014
```

原 `offline_secondary_mapping` 原样保留（成功路径依旧需要真实第二系统），
两者共用同一份 `repair()` 入口，不存在「另写一份被测逻辑」。

---

## 2. 一条假红：把「不该存在」当成「不该新增」

第一版最后一条断言是「备份目录 `BackupRestore-secondary-original` 不得存在」，
结果 FAIL——而这台机器上**本来就有**这个目录（历史第二系统测试留下的）。

「不写」的正确判据是**前后不变**，不是「不存在」：

```rust
let existed_before = backup_probe.exists();
... 三次调用 ...
assert_eq!(backup_probe.exists(), existed_before, "拒绝路径不得改动备份目录");
```

★ 与项目既有纪律一致：**判据必须先证明自己量的东西是对的**。把环境既有状态当成
「不该出现」的现象，会得到一条与产品完全无关的红判据。

---

## 3. 变异验证

拆掉产品里「拒绝修改当前系统盘」那道守卫（`if false && running.eq_ignore_ascii_case(...)`）：

```
CASE=secondary_mapping_rejections=FAIL
SUMMARY pass=0 fail=1 skip=0 ran=1
```

恢复后 `PASS`；`git diff` 确认 `repair()` 一个字节没变（只多了测试与脚本事例）。

---

## 4. 门禁现状

```
CASE=no_write_on_reject=PASS
CASE=online_capture_indexes=PASS
CASE=wimlib_log_replay=PASS
CASE=secondary_mapping_rejections=PASS     ← 新增
CASE=secondary_registry_map=SKIP reason=missing_env: BR_SECONDARY_MAPPING_*
CASE=winre_offline_reg=SKIP reason=missing_env: BR_WINRE_TEST_*
CASE=secondary_menu_repair=SKIP reason=missing_env: BR_ACCEPTANCE_*
CASE=boot_entry_fault=SKIP reason=missing_env: BR_ACCEPTANCE_SNAPSHOT BR_ACCEPTANCE_ROOT
CASE=boot_failure_rollback=SKIP reason=requires_windows_pe_or_re
SUMMARY pass=4 fail=0 skip=5 ran=4
```

`pass` **3 → 4**，`ran` **3 → 4**，`skip` 不变（5 条仍缺环境，理由逐条点名）。

---

## 5. 剩下 3 条 SKIP 的可行性判断（下一轮依据）

| 用例 | 需要什么 | VHD 夹具可行吗 |
|---|---|---|
| `secondary_registry_map`（成功路径） | 一个真实存在的第二 Windows（有 hive、能跑 bcdedit 映射） | **难**：要真 hive；只做「空 hive 文件」会走到 ③ 的拒绝分支，等于重复上面那条 |
| `winre_offline_reg` | **PE + reagentc** + 独立注册目标 | **难**：`/copy` 作用在**活动 BCD 存储**上，VHD 不改变这一点；且 reagentc 必须 PE |
| `secondary_menu_repair` | 已完成第二系统任务 + EFI 挂载 + 快照 | **中**：可只验「任务未核验 → 拒绝修菜单」这类前置拒绝（同本轮思路），**不必真改菜单** |

**建议下一轮**：照本轮的切法，把 `secondary_menu_repair` 的前置拒绝路径也拆出来
（「未核验任务拒绝修改启动菜单」），继续走「先只验拒绝/回滚」路线；
真正要验成功路径时再考虑重建第二系统分区（宿主需 ~350 GB，目前 190 GiB）。
