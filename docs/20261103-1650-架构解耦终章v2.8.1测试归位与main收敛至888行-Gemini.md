# 架构解耦终章 v2.8.1：测试用例按职责归位与 main.rs 收敛至 888 行

## 1. 演进背景与问题

在 `v2.8.0` 里程碑中，CLI 入口 `main.rs` 成功剥离了镜像管理与恢复引擎适配层，源码大幅精简至 1,249 行。
然而深入代码审计后发现：
1. **测试用例职责倒挂**：
   `main.rs` 底部仍保留着 410 行历史遗留的单测。这些单测不仅包含对 `diskpart_format_script`（卷格式化）、`bcd_identifier_from_line` / `parse_boot_manager_state` / `secondary_boot_order`（BCD 引导项）、`parse_recover_options` / `annotate_chain_failure`（恢复引擎）、`claim_boot_resume_attempt`（挂起引导任务）、`parse_prepare_options`（准备规划）等外部模块私有/内部逻辑的测试，而且迫使 `main.rs` 引入大量冗余的深层内部符号导入。
2. **缺乏模块自治与高内聚**：
   当开发者修改 `recovery_volume.rs` 或 `recovery_bcd.rs` 时，相关的单元测试却留在 `main.rs` 底部，破坏了 Rust 模块的局部封装与自包含原则。
3. **纯函数单测盲区补齐**：
   在 `v2.8.0` 中刚实现跨平台通用化的 `format_size`（二进制容量格式化纯函数，支持 B/KiB/MiB/GiB/TiB 阶梯换算）尚未建立边界用例保护。

---

## 2. 核心实施方案

### 2.1 模块单测全景归位
将 `main.rs` 底部的测试逐一按功能内聚性拆解并移入对应的子模块中：
1. [`crates/backuprestore-cli/src/process_runner.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/process_runner.rs)：
   - 移入 `dispatch_failure_carries_its_code_even_without_json`，锁死通用子进程非 0 退出时携带 `BR-APL-010` 错误码契约；
2. [`crates/backuprestore-cli/src/recovery_volume.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/recovery_volume.rs)：
   - 移入 `diskpart_format_script_uses_verified_target_numbers`，保护 diskpart 脚本对磁盘号、分区号的强校验；
3. [`crates/backuprestore-cli/src/recovery_bcd.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/recovery_bcd.rs)：
   - 移入 `secondary_menu_omits_deleted_objects_and_requires_primary`；
   - 移入 `secondary_menu_repair_rejections` 与 `secondary_menu_repair_native`；
   - 移入 `bcd_identifier_parser_ignores_localized_field_labels`；
   - 移入 `secondary_loader_selection_ignores_resume_object`；
   - 移入 `boot_manager_state_parser_accepts_guid_and_alias_only`；
   - 移入 `boot_manager_state_parser_preserves_resume_object_and_loader_mapping`；
   - 移入 `boot_menu_does_not_absorb_tools_or_later_guid_fields`；
4. [`crates/backuprestore-cli/src/recovery_engine.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/recovery_engine.rs)：
   - 移入 `recovery_boot_menu_gate_matches_finalize_routing`；
   - 移入 `recover_options_accept_explicit_efi_root` 与 `recover_options_reject_unknown_or_incomplete_flags`；
   - 移入 `chain_failure_note_only_for_bcd_rollback_sessions`；
5. [`crates/backuprestore-cli/src/pending_task.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/pending_task.rs)：
   - 移入 `automatic_boot_resume_is_limited_to_once_per_durable_stage`；
6. [`crates/backuprestore-cli/src/windows_prepare.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/windows_prepare.rs)：
   - 移入 `prepare_options_reject_missing_image_or_invalid_drive`；
   - 移入 `prepare_fault_options_require_efi_only_for_efi_faults`；
7. [`crates/backuprestore-cli/src/main.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/main.rs)：
   - 仅保留自身定义的纯逻辑测试：`workspace_path_allows_directory_named_tasks` 与 `interruption_resume_accepts_only_staged_nonterminal_tasks`。

### 2.2 补齐 `format_size` 边界测试
在 [`crates/backuprestore-cli/src/image_admin.rs`](file:///Users/x/code/backupRestore/crates/backuprestore-cli/src/image_admin.rs) 中新增 `format_size_handles_units_and_boundaries` 用例，完整覆盖：
- 0 字节、512 字节、1023 字节（"B" 单位与下界）；
- 1024 字节（"1.0 KiB"）、1536 字节（"1.5 KiB"）；
- 1 MiB（1048576 字节）、1 GiB（1073741824 字节）、1 TiB 进位边界。

### 2.3 `main.rs` 历史性收敛至 888 行
- 清除跨模块内部函数的长串导入，`main.rs` 仅保留对外路由与纯顶层分发逻辑；
- `main.rs` 行数从 1,249 行降至 **888 行**（相比初始 6,287 行净减 5,399 行，**累计瘦身幅度达 85.9%**）。
