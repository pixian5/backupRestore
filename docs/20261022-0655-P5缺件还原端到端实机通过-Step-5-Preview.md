## 五、本轮附带发现（两处日志落点问题，非阻塞）

### 5.1 预安装环境主日志不在任务目录，而在「镜像同目录 Recovery.log」
- `recover_env` 里 `let mut log = store.log_path(&task_id)` 指向 `任务目录\recovery.log`，
  但注释与实测都表明：**挂载镜像卷后会切到「镜像同目录 Recovery.log」**，方便用户在镜像旁看。
- 实测：`H:\BRImages\Recovery.log` 已 **75,805,556 B**，且是**累积**的（里面还含 10-13、10-14 的会话）。
- 后果：①任务目录的 `recovery.log` 只有 prepare/resume 的 3 行（262 B），单看任务目录**查不到
  恢复环境里的任何 STEP 日志**；②大文件累积无轮转，已 75 MB。
- 建议（待拍板）：恢复环境内的主日志改为「任务目录优先 + 镜像目录镜像一份」，或按 task id 分文件、
  加简单轮转。**注意**：本轮所有关键判据都是从 `H:\BRImages\Recovery.log` 里 grep 出来的，
  如果以后有人只看任务目录会误判「日志缺失」。

### 5.2 `recovery_fault::checkpoint` 默认不落日志
- `checkpoint("registration-skipped")` 只在**故障注入**（`--test-fault`）激活时才写
  `fault-{point}.json` marker；正常流程里它是空操作。
- 所以「靠 checkpoint 判断走了 Skip 分支」这个判据**不成立**，真正的判据是
  `reagentc.exe` 缺失时 preflight 写的两行日志（`WinRE registration skipped:` + `恢复环境注册已按裁定降级跳过：`）。
- 上轮交接文档 §七写「checkpoint `registration-skipped`」作为判据，**表述不准**，本文件为准。

## 七、本轮踩到的坑（补进纪律）

1. **`abandon-task` / `resume` / `recover` 的 root 参数是「工作区根」**，不是 `…\tasks`。
   `TaskStore::task_dir` = `root.join("tasks").join(id)`，传 `H:\brwork\tasks` 会拼成
   `H:\brwork\tasks\tasks\<id>`。上轮交接文档 §五路线 A 的写法是错的。
2. **`%time%` 在 `for /L` 循环体内不会重新求值**（静态展开）→ 时间戳全一样。必须
   `setlocal enabledelayedexpansion` + `!time!`。
3. **`schtasks /create` + `/run` 在 SYSTEM 通道下报「系统找不到指定的文件」**，
   用 `start /min C:\x.cmd` 起后台更省事。
4. **恢复环境里点弹框只能用 `tools/win-clicker/vmkey.sh <键名>`**（Parallels keycode，`n=57`、`esc=9`）；
   手写 `--scancode` 必错（PS/2 scancode 与 Parallels keycode 两套）。
5. **恢复环境内工作卷盘符与 Windows 侧不同**（本轮预安装环境里 WORKSPACE=E:、IMAGE=C:、TARGET=F:），
   日志里出现的 `E:\brwork\tasks\…` 就是 Windows 侧的 `H:\brwork\tasks\…`，**别以为是两个任务**。
