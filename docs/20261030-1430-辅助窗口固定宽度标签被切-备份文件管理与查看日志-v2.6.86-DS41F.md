# 两个辅助窗口的固定宽度标签被切（v2.6.86）

> 模型：DS41F。时间：2026-10-30 14:30。
> 版本：**2.6.86**（改行为 +0.0.1）。
> 关联：`docs/20261030-1017-…v2.6.82~v2.6.84-DS41F.md`（设置窗口的文字宽度）、
> `docs/20261030-1250-…v2.6.85-DS41F.md`（主界面高度改了坐标没改）。
> 本篇是同一句「检修全部类似问题」的第四站：**另外三个窗口的内部控件**。

---

## 1. 怎么找到的

主界面查完之后，接着把「备份文件管理」和「查看日志」这两个窗口也按同样的标准量了一遍——
它们此前只修过**窗口尺寸**（2.6.82），从没查过**内部控件**在 18 号字下装不装得下文字。

判据还是那套：枚举子控件矩形，对每个**单行** `STATIC` 比较「控件宽」与「独立重建字体量出的文字宽」。
这轮把判据从只看 `STATIC` 扩展到也看 `BUTTON`——按钮上的字被切掉是同一类缺陷，之前漏判了。

## 2. 查到的问题（分两批，第二批是第一批修完才露出来的）

### 2.1 中文 18 号字

| 窗口 | 控件 | 控件宽 | 文字需要 | 差 |
|---|---|---|---|---|
| 备份文件管理 | `个索引：` | 70（140 物理） | 72 | −2 基准（−4 物理） |
| 查看日志 | `日志文件：` | 90（180 物理） | 90 | 0（判据要求 ≥2 物理余量，判红） |

两处都是**写死宽度**：

```rust
"个索引：", 0, 150, 388, 70, 20, 0      // 宽 70，14 号字下够用
"日志文件：", 0, 16, 50, 90, 20, 0      // 宽 90，14 号字下够用
```

14 号字下 `个索引：` 只要 56 基准像素、`日志文件：` 只要 70，写死的 70 / 90 都富余；
字号一到 18，前者要 72 > 70（切），后者正好 90 = 90（贴边，全角冒号随时掉半个）。

### 2.2 英文 18 号字（第一批修完后再量才露出来）

| 窗口 | 控件 | 控件宽 | 文字需要 | 差 |
|---|---|---|---|---|
| 备份文件管理 | `WIM image:` | 90 | 110 | **−41 物理像素** |
| 备份文件管理 | `Delete old indexes...` | 160 | 184 | **−48 物理像素** |
| 查看日志 | `Open in Notepad` | 160 | 156 | 仅剩 3.5 基准，太紧 |

中文比英文短，所以先修中文那两处时**看不出英文的问题**——这也是为什么
「按语言 × 字号两维全量跑」不能省。顺带说明：`WIM image:` 这个标签在截图里
被切的是最后那个冒号，`Delete old indexes...` 被切的是末尾三个点，都属于
「看着像正常标点、其实少了几个像素」的类型，不量根本发现不了。

## 3. 改法

统一成设置窗口那套：**宽度按当前字号实测，默认字号下取值不变**。

```rust
// 标签：左右各留 4，旧值当下限
let image_label_width = (measure_text_width(image_label) + 8).max(90);
// 按钮：左右各留 12（文字居中要有呼吸），旧值当下限
let btn_w = |text: &str, min: i32| (measure_text_width(text) + 24).max(min);
```

`(实测 + 内边距).max(旧值)` 这个写法是关键：
- 默认字号（14）+ 中文下，实测值本来就在旧值以内 → **宽度一个像素都不变**，外观与旧版完全一致；
- 只有真的装不下时才变宽，不会因为换算法就把所有控件重新排一遍。

配套三处：
1. 「镜像：」+ 下拉框、「日志文件：」+ 下拉框：**标签变宽后把下拉框往右挤**，
   但**下拉框右缘固定**（606 基准），挤出来的宽度从下拉框自己的宽度里扣，整行不会顶出窗口。
2. 「保留最近 [N] 个索引：」这一行：三个控件改成**顺序排布**
   （标签 → 数字框 → 标签，间隙 0 / 6），不再写死 x=150。
3. 两个窗口的按钮行都改成**顺序排布**（间隙 8），不再写死 104 / 272 / 420 这些 x。

## 5. 通用结论（第四次了）

| 版本 | 缺陷形状 |
|---|---|
| 2.6.80 | 行距变了，按行距算的**高度**没改 → 最后一行切半截 |
| 2.6.83 | 文字高度改成实测，**下一个控件的 y** 没改 → 第三行画到框外 |
| 2.6.85 | 状态框高度变了，**下一行的起算偏移**没改 → 顶部被压 |
| **2.6.86** | **字号变大，写死的控件宽度**没改 → 标签末尾被切 |

前三次是「纵向」的，这次是「横向」的，但根源是同一句话：
**凡是由「字号 × 语言」共同决定的尺寸，写死就一定会在某个组合上出错。**

所以判据也必须按这两维全量跑：中文 14（默认，回归看外观没变）、中文 18、英文 18。
只跑中文会漏掉英文长词，只跑 14 号会漏掉全部。

## 6. 遗留

1. 这两个窗口的**窗口尺寸仍是固定的**（不随内容/字号变），字号调到 18 时窗口内仍有富裕，
   但更长的文案（比如将来加一条更长的提示）可能顶到右下角——届时应当像设置窗口那样按内容定尺寸。
2. 清单正文（`文件大小 / 索引` 那些行）在英文界面下仍是中文，属于另一个问题（内容未本地化），不在本轮范围。
3. 100% 缩放仍未实测（历史遗留，与本轮无关）。
