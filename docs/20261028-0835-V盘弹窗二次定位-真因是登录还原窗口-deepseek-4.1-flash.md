# 「V 盘无法访问」二次定位：真因是**资源管理器登录还原窗口**（v2.6.70 环境侧修复）

> 用户 2026-10-28 08:17 报「我看到仍然有 v 盘弹窗啊」。
> 结论：我 10-27 那两轮判断（幽灵盘符 / 测试夹具）都**不是这次弹窗的来源**。
> 真正的机制是 **explorer.exe 在登录时还原上次打开的文件夹窗口**，而那个窗口
> 停在早已消失的 `V:\` 上。与我们的进程无关（当时 GUI 根本没在运行）。

* * *

## 一、先看现场，不要先查注册表

上一轮我一直在查 `HKLM\SYSTEM\MountedDevices`。这次第一件事改成**截图**：

```
标题：位置不可用
正文：无法访问 V:\。
      拒绝访问。
按钮：确定
```

两条关键差别，直接推翻了前两轮的方向：

| 观察 | 含义 |
| --- | --- |
| 标题是 **「位置不可用」** | 这是 **Shell（explorer.exe）自己的对话框**，不是 Win32 严重错误框（那种是 `V:\ 无法访问。设备未就绪。`） |
| 正文是 **「拒绝访问」** 而不是「设备未就绪」 | 说明打不开的原因是路径语义，不是卷没就绪 |
| 注册表里**已经没有任何** `\DosDevices\V:` | 幽灵盘符理论当场失效 |
| `tasklist` 里 **BackupRestore.exe 没在运行** | 不是我们的进程弹的 |
| 任务栏有一个标题为「位置不可用」的**资源管理器窗口** | 有一个 Explorer 窗口正卡在 `V:\` |

## 二、认窗口的主人

`Shell.Application.Windows()` 在 `--current-user` 下枚举不到窗口（窗口站问题，
本项目老坑）。改用已有的提权会话仪器 `tools/win-clicker/br-s1.sh` 跑一个只诊断的
body（`tools/win-clicker/_v-dialog-diag.ps1`，输出 `H:\brwork\_v-diag.txt`）：

```
SESSION=1  USER=x
WIN pid=2144 explorer title=位置不可用        ← 主人是 explorer.exe
EXPLORER pid=2144 start=2026-10-27 23:27:29
EXPLORER pid=6564 start=2026-10-27 23:26:17   ← 开机时间 23:25:58
PROBE V: exists=False / Could not find a part of the path 'V:\'
```

两个 explorer 进程的启动时间都落在**开机后 20 秒内**。也就是说：**这个窗口是登录那一刻
被「还原」出来的**，不是有人在用的时候点开的。

## 三、真因链

1. 更早（10-27 白天/晚上跑门禁时）机器上确实出现过 `V:` 卷（测试夹具的 VHD），
   期间留下了一个停在 `V:\` 的资源管理器窗口。
2. VHD 卸载、分区消失，窗口还在（只是内容失效）。
3. Windows 默认开启 **「登录时还原上次打开的文件夹窗口」**
   （`HKCU\...\Explorer\Advanced\PersistBrowsers`，**该值原本不存在 = 默认 1**）。
4. 每次登录 → 还原那个窗口 → `V:\` 不存在 → 「位置不可用 / 拒绝访问」→ 一直挂在屏幕上。
5. 用户看到的就是「经常弹出 V 盘无法访问」。

★ 这也解释了为什么它**清完注册表还会回来**：复发的载体不是盘符记录，是**窗口还原清单**。

## 四、修复（环境侧，不动产品代码）

| 动作 | 值 | 作用 |
| --- | --- | --- |
| `HKCU\...\Explorer\Advanced\PersistBrowsers` | `0` | 登录不再还原文件夹窗口 —— **掐掉复发机制** |
| `HKLM\...\Policies\Explorer\NoDriveTypeAutoRun` | `0xFF` | 所有驱动器类型禁用自动播放/自动打开 |
| `HKLM\...\Policies\Explorer\NoDriveAutoRun` | `0xFFFFFFFF` | 所有盘符禁用自动运行 |
| 关闭残留窗口 | `taskkill /f /im explorer.exe` + 以用户身份重新拉起 | 清掉当前那个卡住的窗口 |

前两条是**这次的关键**；后两条是我顺带把「卷出现 → 自动开窗口」这条同类路径也关掉，
因为本机反复挂载/卸载 VHD，属于典型受害者场景。

注意执行细节：从 SYSTEM 通道改用户设置必须走 `HKU\<SID>\...`（`prlctl exec` 的 HKCU
是盲区，本项目老坑）；杀 explorer 后它**不一定自动重启**，实测屏幕变黑，需要用
`run-in-session.ps1 -SessionId 1` 以用户身份重新拉起 `explorer.exe`（不要提权拉起）。

## 五、判据

| 项 | 结果 |
| --- | --- |
| 重启 VM 后截图 | **没有任何 V 盘窗口**，桌面/任务栏正常；GUI 自启且标题栏为 `V2.6.70`（部署件仍是新的） |
| 再跑一轮 `no_write_on_reject`（会给 VHD 挂 `V:`，6.01s PASS） | 跑完**没有**新的资源管理器窗口（窗口列表只剩 GUI 与输入体验） |
| 跑完后 `MountDevices` | 只剩 `C/D/F/H/S/Y`，**无 `V:`** |

## 六、我前两轮错在哪（必须写清，否则下一个人还会走同一条路）

1. **只查注册表、不看现场。** 「幽灵盘符」在 10-27 是真的（6 条确实指向不存在的分区），
   但它解释不了 10-28 这次——那天早上注册表里一条 `V:` 都没有。
   **现象还在，就先看现象本身（截图 + 窗口归属），不要沿用上一轮的因果。**
2. **把对话框的类型认错了。** `SetErrorMode(SEM_FAILCRITICALERRORS)` 只能压住
   Win32 严重错误框；`位置不可用` 是 Shell 弹的，产品怎么设错误模式都管不了它。
   代码里那条改动本身仍然正确（防的是另一类框），但**它不是这次的原因**，不能算「修好了」。
3. **「清完就完事」是错的。** 清理只能清当前实例；**复发的载体**（这里是窗口还原清单）
   不处理，下次登录必然重来。判断一个 bug 有没有修好，要问「它靠什么复发」。

## 七、顺带修的门禁仪器

这轮反复被同一个仪器问题打断，索性抽成函数 `vm_launch_verified`：

> 约 **1/8** 的 `prlctl exec` 调用**根本不执行**命令（不是失败，是没跑）。
> 症状是「结果文件连创建都没有」，而脚本会白等到超时，再把「仪器没工作」判成 FAIL。
> 重启后几十秒内（VM 忙）比例明显更高。

抽成一个函数后，STEP 1 编译、复制测试二进制、`--ignored --list`、每条用例四次复用同一套
「发出 → 探测是否生效 → 最多重发 3 次」逻辑。**判据仍是那一行 `test result`**，
没有把失败改判成通过。

## 八、状态

- 产品代码**未改**（本轮只改环境与门禁工具）→ 版本仍是 **2.6.70**。
- 环境已改：`PersistBrowsers=0`、`NoDriveTypeAutoRun=0xFF`、`NoDriveAutoRun=0xFFFFFFFF`。
  ★ 这三条是**测试 VM 的基线**，换机器/重建 VM 时要重做，否则同类弹窗会重现。
