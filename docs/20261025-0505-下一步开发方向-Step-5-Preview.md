## 3. 候选开发方向（详细设计）

### E1（P1·首推）：用户手册 + 错误码速查（产品文档，零代码风险）

- **动机**：仓库有 220 余篇开发文档，但没有一篇是给最终用户看的。错误码体系已就绪（212 条 CLI 双语码 + `docs/ERROR-CODES.md`），缺「用户视角」的串联：四个任务怎么选、恢复环境流程会发生什么、失败了怎么按 `BR-域-序号` 查、设置项各是什么。这是「开发测试版」变成「敢交给别人用」的前置条件。
- **方案**：新建 `docs/USER-GUIDE.md`（**活文档**，与 `ERROR-CODES.md` 同属命名例外的常青文件；先中文，英文版随 GUI 语言成熟度补）：
  1. 快速开始：从 `H:\brwork` 起 GUI / 命令行三入口（`prepare` / `resume` / `recover`）各能做什么；
  2. 四任务决策表（备份 / 还原到原分区 / 第二系统 / 数据卷）+ 破坏性分级；
  3. 恢复环境流程（文字版）：prepare → 重启 → `Recovery.exe` → BCDBoot → 清理 → 回 Windows，每步用户会看到什么；
  4. 失败自助：`grep '\[BR-'` 捞日志 → 对照 `ERROR-CODES.md` → Top10 常见失败（磁盘满 / 句柄占用 / 镜像损坏 / DISM 超时降级）的处置建议；
  5. 设置项说明（`failure_policy` 四项 + `dism_timeout_secs` + `ui_language`），附「settings.ini 必须合并写」的维护者注记（不进用户章节）。
- **工作量**：中（纯写作 150–250 行）。**风险**：零（不动产品代码）。**验收**：按手册能在 T: 5G 卷独立完成一次备份+还原（新人视角走查，不依赖任何口头补充）。

### E2（P1）：备份完整性「最后一公里」——捕获侧独立自检

- **动机**：还原侧已带 `/CheckIntegrity /Verify`（`pe_operation.rs:730`、`online_operation.rs:199/1354/1843`）+ sidecar sha256 比对；**备份侧的收尾质量没人系统盘点过**。已核实：在线链捕获后整档算 sha256 并写 sidecar、发布前重验原镜像、legacy 簿记回读（`online_operation.rs:1438-1476`）；但 **RE 离线捕获链（`main.rs` 的 capture 路径）收尾是否对成品镜像做「只读重开 + 结构校验」未核实**——坏镜像只会在还原时才炸，那时用户的源盘可能已经没了。
- **方案**：① 盘点（1h，两条捕获链各读一遍收尾路径）；② 若缺独立校验，在备份收尾加「只读重开成品 + `/CheckIntegrity`（或 wimlib 侧等价只读校验）」一步，失败即任务失败并发 `BR-IMG-*` 码；③ 判据防误报：正常路径零新增失败（先跑 T: 备份对照），且校验本身要受 `dism_timeout` 上限约束，别把「校验」做成新卡点。
- **工作量**：盘点 1h；实现小–中。**风险**：低（只读）。**验收**：T: 备份 success 且日志有校验行；人造截断镜像副本 → 备份后自检失败且带码（不静默放过）。

### E3（P1·架构决策）：主备反转评估——wimlib 提默认 apply 引擎？

- **动机**：10-24 方向文档定的远期项，当时设的证据门槛已基本满足：v2.6.25 集成 → v2.6.27 ACL 8/8 逐字节 → v2.6.37 DISM 失败降级主力（79GiB 成功）→ v2.6.44 RE 主链降级首次端到端实证（TimedOut → wimlib 79GB/4min49 → success/100%）。「DISM 默认 + 失败降级 wimlib」的格局已稳定运行，该做正式对比供用户拍板了。
- **方案**：纯评估轮（不改产品代码）：同一 T:/F: 卷、同一镜像，DISM vs wimlib 对照——耗时 / 退出码 / ACL 判据 8 项 / 进度行质量 / 失败模式分类；产出一页对比表 + 反转建议（维持 or 反转 + 若反转的默认值改动点清单）。**「无证据不反转」的门槛不变。**
- **工作量**：中（1–2 轮 VM）。**风险**：低（评估不动产品）。**验收**：双通道三项判据（哨兵 / 序列号 / success-100）齐 + 用户一句话拍板记录在案。

### E4（P2·流程）：冒烟套件接入 deploy 门禁 + 判据扩容

- **现状**：`br-smoke.sh` 全链 6/6，但 `build-win.sh --deploy` 末尾**不调用**（grep 零命中）——每次发版跑不跑全看人，而最近 5 个版本每个都改了 apply 主链或判据层。
- **方案**：① deploy 末尾加 `--smoke` 可选开关（默认关，避免每次部署多等 ~15 分钟；用户拍板后可改默认开）；② 判据扩容：失败路径判 `--json` 的 `error_code` 字段（v2.6.48 已就位）、还原后回读 `default` 指向。
- **工作量**：小–中。**风险**：低。**验收**：一键 `--deploy --smoke` 输出判据汇总行（含 error_code 期望值表）。

### E5（P2·体验）：GUI 侧错误码可见性与失败定位

- **盘点问题**：GUI 失败回执是否展示 `[BR-xxx]` 前缀（`Display` 已含，估计自动受益，需实测一次失败路径确认）；日志弹窗能否一键定位日志目录；失败时用户下一步动作是否明确。
- **工作量**：盘点 1h + 视情况小改。**风险**：低。

## 7. 本轮操作记录与三条新坑（2026-10-25 05:00）

1. **证据目录迁移**：`move C:\Users\Public\BackupRestore-actual-20261005-0724 H:\BRImages\evidence\` 跨卷报「拒绝访问」；改 `robocopy <src> <dst> /E /MOVE /R:1 /W:1 /NFL /NDL` 一次成功（64 文件 / 6,419,483 B / 0 失败，源目录消失）。**robocopy 退出码 1 = 复制成功**（0 = 无需复制，≥8 才是失败），别把 1 当错误。
2. **cmd 混合写法坑**：`if exist X (echo A) else (echo B) & robocopy ... && echo OK || echo FAIL` —— **后半段被 cmd 整个吞掉**（只回显了 if 分支的结果，robocopy 根本没执行）。if/else 块不要和 `&` 命令链写在同一行，分开跑。
3. **prlctl 通道单引号坑**：PowerShell 字符串里的**单引号会被通道剥掉**——`Write-Output ('TARGET_FILES=' + $_.Count)` 进 VM 变成 `Write-Output (TARGET_FILES= + $_.Count)`，报「无法识别为 cmdlet」。进 VM 的 PowerShell 只用双引号，或把结果写文件再 `cmd /c type` 回读。
4. **`dir` 判存坑**：`dir C:\a\b`（b 不存在）会按「列父目录 + b 作掩码」解释，输出父目录头和匹配项；判「目录是否还在」要看它是否作为**条目**出现，不能只看有没有报错文本。
