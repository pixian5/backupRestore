## 四、缺陷清单（需要你裁定修法）

### 1. 离线数据卷还原走不通（C5-3）

- **现象**：「还原数据到非 C 盘」把通道选成离线、点「进入 Windows RE」，用户连点三次「是」之后，
  弹出「任务准备失败（退出码 1）：invalid task: restore-existing target must be the active Windows volume」。
- **根因**：界面的离线数据还原路径（10-14 写入）下发的命令是 `prepare --operation restore-existing` 加数据卷目标；
  而准备期在 10-18 加了一道安全闸（提交 `08ec341`），规定「还原到原卷」的目标必须是当前活动系统卷。两者互相矛盾。
- **影响**：这条路径自 10-14 以后再没有实机记录，也就是至少从 10-18 起就是死路。失败是干净的（无任务、无写入、无重启）。
- **附带**：该拒绝走的是「用法错误」一类的出口，`error_code` 为 `null`，用户无从按码查表。
- **修法两选一**：
  - 让准备期接受「界面离线数据还原」这一种数据卷目标（需要显式区分于「源和目标都误选成数据盘」那种情况）；
  - 或者界面对数据卷不再提供「进入 Windows RE」选项，只保留 PE。

### 2. 「还原数据到非 C 盘」的目标卷默认选中光驱

- **现象**：虚拟机光驱里挂着光盘时，目标卷下拉框默认选中的是 `D: | UDF | 卷标 无卷标 | 总容量 383.0 MiB | 可用 0 B`
  （证据 `C5-tab1105.png`）。规则是「不能选当前系统盘或已有 Windows 的分区」，排在最前的非系统卷——光驱——被自动选中。
- **影响**：用户不留神就会对着光驱点「创建任务」。目前会被准备期拒绝，不会造成破坏。
- **建议**：数据卷候选与默认选中应排除光驱、可移动介质和非 NTFS 卷。

### 3. 离线数据还原的处理方式选择框文案不随「格式化」变化

- 不勾「格式化目标分区」时实际是覆盖式应用，但选择框固定写「目标卷将被格式化并写入镜像」
  （`choice_dialogs.rs` 第 56–66 行是静态字符串）。

## 五、观察与优化建议（不是缺陷）

1. **镜像哈希计算慢 12 倍以上**：备份的第 3/4 步「校验」花了 12 分钟（03:24:55 → 03:37:02），
   而系统自带的 `certutil` 算同一个 40G 文件不到 60 秒。
   原因是 `sha256_file` 用的是纯软件实现的 `sha2` 库（`backuprestore-core/src/task_store.rs:133`），没有用处理器的硬件加速。
   改用系统加密接口（或给算法库开硬件加速）后，每次备份可省约 11 分钟。
   **⚠️ 订正（2026-11-24，v2.10.7 已优化）**：「瓶颈是纯软件哈希」成立，但「12 分钟」是**异常值不是常态**——
   同一个旧程序 10 月份在恢复环境里算 30 GB 只要 68 秒，这一次 727 秒的直接原因**没有钉死**；
   「每次备份可省约 11 分钟」只对最坏情况成立。优化后恢复环境里 40 GB 约 25–31 秒。还原路径在应用镜像之前不做整档哈希，所以不受影响。
2. **副档里的系统版本信息缺失**：`windowsEdition`、`windowsBuild`、`EditionId` 都记为 `unknown`，界面索引下拉框显示「版本未知」。
3. **用户主动取消的任务没有记录原因**：按 B 回退后选「取消」的那个任务，状态文件里 `error` 是空串、`errorCode` 是 1。
   界面「刷新任务状态」因此没有可显示的原因和错误码。建议记成「用户选择取消」。
4. **不提权运行命令行会给出误导性的结论**：`inspect-environment` 不提权时退出码为 0，
   结论字段是空的卷列表加 `winreAvailable:false`，各卷读取失败的原因只出现在错误输出里。
   自动化若只看退出码或结论字段，会把「没权限读」当成「恢复环境不可用」。建议明确报「需要管理员」并返回非零。
5. **校验步骤与捕获时长相当**：40G 镜像的捕获 26.5 分钟、校验 12 分钟；修掉第 1 条后总时长可缩短近三成。
   （订正同上：12 分钟是最慢一次的读数，校验一步的常态是一两分钟；优化后是半分钟。）

## 十、对测试计划本身的订正

计划执行中有四处与预想不符，如实记下：

1. **「两个夹具缺失不阻塞四条免环境用例」是错的**——门禁第 0 步是六项全过才放行。
2. **「带快照的走法甲」在本机不可行**——镜像比以往大（40G 而不是 30G），再加上快照增量，没有不动用户数据的办法凑够空间。
3. **系统盘还原先用命令行通道、图形界面放到第二轮**——为了先拿到最干净的必过证据。
4. **两次「通道挂死」不是通道问题**——是虚拟机被自动暂停。

计划里读代码预判的那处缺陷（离线数据卷还原）被实测坐实。
