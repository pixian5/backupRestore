# 还原校验选项框按需对比哈希与快速比对大小实现

- **日期**：2026-09-30 19:20
- **版本**：v1.9.9
- **执笔模型**：Gemini

---

## 一、需求背景与设计考量

用户提出：
> “改为增加一个校验选项框，不勾选时仅对比大小，勾选时对比哈希”

### 1. 痛点分析
- 当进行还原（`restore-existing`）或新增第二系统（`create-secondary`）时，WIM 镜像往往达到几十甚至上百 GB（如 58GB）。
- 若在主 UI 线程或准备阶段默认流式读取完整镜像计算 SHA-256，耗时可达 1~2 分钟，容易引起主窗口未响应（卡死）错觉，极大影响操作流畅度。
- 然而部分用户在关键还原场景下，确实希望通过 SHA-256 严格保障镜像未发生位翻转或隐蔽损坏。

### 2. 解决方案
- **UI 界面新增复选框**：在还原选项的“镜像索引”右侧增加 `严格对比哈希（默认仅对比大小）` / `Verify hash (default: size only)` 复选框（Win32 `BS_AUTOCHECKBOX`）。
- **默认行为（未勾选）**：毫秒级仅比对 WIM 文件的物理字节大小（`file_meta.len() == metadata.image_size`）。大小一致即认定通过，不产生任何 I/O 等待，即点即开始。
- **勾选行为（按需严格比对）**：
  - 前端 UI 在点击开始后，流式计算镜像 SHA-256 并与 sidecar 元数据比对；
  - 启动提权准备进程时追加 `--verify-hash` 参数，后端在提权准备校验中执行严格哈希比对。

## 二、具体实现细节

### 1. 控件与布局管理 (`crates/backuprestore-cli/src/native_gui.rs`)
- 定义控件 ID `ID_VERIFY_HASH: usize = 1211` 与 Win32 消息常量 `BS_AUTOCHECKBOX`、`BM_GETCHECK`。
- `Controls` 结构体增加 `verify_hash: Hwnd`。
- 多语言与工具提示支持：
  - 中文：`严格对比哈希（默认仅对比大小）`，Tooltip 提示说明默认仅比对大小，勾选后将流式校验整包完整性。
  - 英文：`Verify hash (default: size only)`。
- 动态可见性：与索引下拉框同步，仅在还原系统（`restore-existing`）或新增系统（`create-secondary`）时显示。
- 布局自适应：
  - 单系统还原：放置在索引下拉框右侧同排（`secondary_y`）。
  - 新增第二系统：由于右侧已有启动项名称输入框，自动排布于下方下一行（`secondary_y + 32`），绝不重叠。
- 任务执行分流：
  - 读取 `BM_GETCHECK` 状态。
  - 若未勾选，且文件物理大小与档案一致，则直接判定通过；
  - 若勾选，调用 `backuprestore_core::sha256_file(&image_path)` 进行完整比对。
  - 组装提权准备命令时，若勾选则追加 `--verify-hash`。

### 2. 准备阶段严格比对支撑 (`crates/backuprestore-cli/src/windows_prepare.rs`)
- `PrepareOptions` 增加 `verify_hash: bool` 字段。
- 命令行参数解析：支持 `--verify-hash` 开关。
- `validate_operation_inputs` 校验逻辑：
  - 始终首先比对文件物理大小 `file_size != metadata.image_size`。
  - 仅当 `options.verify_hash` 启用时，才计算 `sha256_file(path)` 并比对 `metadata.image_sha256`。
