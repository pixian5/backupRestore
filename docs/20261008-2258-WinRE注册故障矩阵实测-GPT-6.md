# WinRE 注册故障矩阵实测

2026-10-08，新加坡时区；模型 GPT-6；版本 2.1.6，基线 4b4ff67。

## 范围与方法

延续 2.1.5 的系统恢复验收，补充离线注册模块的拒绝路径。真实故障发生在 P: 专用夹具；不格式化、不还原 C:。使用已有只读系统镜像复制 Windows 目录，完整组件约 40 GB，不能把它称为完整可启动系统。

新增 `winre_registration_fault_tests.rs`，接入已有显式忽略测试。常规单元测试不写 BCD（启动配置数据）。真实测试必须提供快照确认、夹具标记、分区 GUID（全局唯一标识符）及主系统盘，并确认当前处于 PE（预安装环境）。同一次测试事务包含自动进入、夹具注册/失败注入/清理和返回 Windows。

| 场景 | 必须观察到的结果 |
|---|---|
| 目标分区 GUID 不符 | 身份校验拒绝 |
| Winre.wim 两个合法位置都缺失 | 原件缺失拒绝 |
| Winre.wim 为空 | 空原件拒绝 |
| boot.sdi 两个合法位置都缺失 | 原件缺失拒绝 |
| boot.sdi 为空 | 空原件拒绝 |
| 指定 BCD 副本与活动 BCD 的目标加载器不同 | 存储不一致拒绝，副本的全部对象与字段不变 |
| 目标加载器关联到了主系统的恢复对象 | 冲突拒绝，不覆盖已有关联 |
| 恢复对象设备不是目标 WIM（Windows 镜像） | 真实工具返回成功后，最终状态回读拒绝 |
| 内存盘启动文件路径错误 | SDI（系统部署镜像）路径校验拒绝 |

各场景要求命中指定错误，前后活动 BCD 文本完全一致。前置闸门要求没有 setreimage/enable 命令；损坏恢复对象可由工具报告 Disabled，此时必须证明注册与启用命令均执行成功、前后状态仍为 Disabled，而程序最终核验明确拒绝。所有失败日志都不能出现注册已验证成功。原件通过同卷重命名暂存和摘要回读恢复；冲突对象仅修改测试新建对象，并在每个场景后立即恢复。故障 BCD 副本在任务盘普通目录内，不覆盖 ESP（EFI 系统分区）。

## 回归与静态检查

本机 100 CLI（命令行）+ 35 core（核心）测试通过；Windows ARM64（64 位 ARM 架构）114 CLI + 35 core 通过，3 个环境依赖用例默认忽略。真实注册用例另行显式运行。

本机及 Windows 目标的严格 Clippy（静态检查）均通过；Windows 检查最初暴露 21 处历史警告，已修正冗余借用、分支与错误传播写法、UTF-16（16 位统一字符编码）分块以及文档注释空行。运行顺序、失败传播及业务条件不变。两个目标重新检查并执行常规测试；发布构建通过，外部 SDK（软件开发工具包）PDB（程序数据库）缺失警告仍存在。

## 夹具和证据

沿用已知系统镜像，仅复制 Windows 目录；6 个应用执行别名按已核验的精确路径排除，不放宽其他错误。复制 235872 个文件，跳过 19 个，失败/不匹配均为零，源镜像必须成功卸载才允许重启。

证据目录 `.test-artifacts/re216-faults-20261008/`，包含构建、常规测试、快照、失败场景日志、原件摘要和最终基线比较。证据压缩后交付，不复制系统 WIM 到程序压缩包。

## 首次测试暴露的判据与清理问题

首次实测在第 6 个拒绝场景后失败：测试把 BCD 副本的文件摘要不变作为判据。独立控制实验仅执行两次 bcdedit /store ... /enum all /v，文件均为 98304 字节，但两次分别有 2013、1508 个字节变化，枚举出的所有对象和字段完全相同。不能从文件字节变化直接推出产品修改了启动对象或字段；尚未逐字段解释配置单元内部变化。修正为完整逻辑内容比较，保留每个失败场景的活动 BCD 全文比较与禁止注册写命令检查。恢复 WIM/SDI 的原件摘要核验仍保持不变。

首次测试的断言异常还绕过了测试外围清理，留下 3 个本次创建对象（临时启动器、设备选项、夹具加载器）。已在新快照保护下按新增 GUID 与名称逐个清理，活动 BCD 全文恢复到初始基线。新增故障助手的判定改为返回错误，让外围统一清理仍执行；这属于测试脚手架修正。

第二轮执行到第 7 个拒绝场景后，故障脚本写死正常 Windows 的 P:，而 PE 中该卷为 E:，因此 bcdedit 返回错误。外围清理已正常执行，仅剩供返回后清理的 2 个启动对象；已改用现场测试卷盘符，并对最终测试程序重新完整验收。

第二轮返回后全量 BCD 比较发现：克隆加载器继承了主系统的 resumeobject，reagentc 给该主系统休眠恢复对象补了 recoveryenabled=Yes。默认项和主系统恢复文件摘要未改变；已按新快照保护和精确字段差异回滚，验证完整 BCD 与原件摘要恢复基线。测试加载器现删除继承的 resumeobject，并新增整份 BCD 全文一致断言，不再只比较启动管理器。

第三轮已通过完整原有 BCD 一致性检查。错误 WIM 设备使 reagentc /info 报 Disabled；setreimage 与 enable 均返回 0，之后仍 Disabled，产品最终核验正确失败。测试原先只允许写注册前拒绝，现对损坏恢复对象明确增加这一可观察的虚假成功路径，要求两个命令执行、两次 Disabled、整体返回失败、BCD 和原件不变；不能接受其他报错替代。

第四轮前 8 个场景通过，但测试助手使用了小写比较值恢复 device，导致路径从 `\Recovery\WindowsRE\Winre.wim` 变为小写。新增原始字段读取，完整保留路径大小写；仍以严格全文一致验收，不改成忽略大小写。所有原有 BCD 对象保持初始基线，测试新建对象按快照保护清理。

## 实测结果

第五轮完整通过：`1 passed; 0 failed; 116 filtered out; finished in 467.60s`，退出码 0。9 个场景中，8 个在注册写命令前拒绝；错误 WIM 设备场景由真实工具虚假成功后的回读拒绝。首次注册、重复执行的幂等性、丢失关联后的重接也由同一用例再次通过，日志含 3 次完整注册核验成功。测试内部清理完成后，所有原有 BCD 对象全文一致，并自动返回正常 Windows。

## 验证边界与后续

本轮 9 个场景覆盖前置拒绝与恢复工具虚假成功后的回读拒绝，不能代替真实 reagentc（恢复环境管理工具）启用命令中途失败、原件修复失败、断电后状态对账等测试。首次注册、幂等和恢复关联重接由同一真实用例重新执行。

2.1.5 的 C: 全新备份、格式化还原、标准恢复环境启动与返回证据仍保留；本轮不会将它标成 2.1.6 的新一次 C: 还原。Windows x64（64 位 x86 架构）、第二系统、完整图形界面和预装 PE 系统恢复链路仍待独立验收。

优化机会：Windows 条件编译模块的严格静态检查应成为固定验证项，本机检查不能覆盖这些模块。离线注册夹具重复复制仍约 40 GB；后续可以建设专用可复用夹具，但不得削弱真实组件和完整系统启动验收。
