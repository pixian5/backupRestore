# 下一步待实现（2026-09-30）

## 1. 复验离线环境选择按钮

- 核对工作树版本、构建产物和客体安装包版本及 SHA-256，结束旧 GUI 实例后再启动新包。
- 保留 PE 与 Windows RE 两个选项，不因任务 RE 基于 Winre.wim 副本而移除其中之一。
- 使用不干扰宿主桌面的 VM 自动化方式触发对话框按钮，分别确认 PE 选项与 Windows RE 选项的点击、返回值、确认对话框、提权启动和后续 prepare 行为。
- 明确区分真实按钮/消息测试与 `--test-hook`。后者直接设置 choice，不能证明模态框结果读取正确。
- 先以不触发启动事务的诊断方式核实分支，再按快照约束执行会改 BCD 或重启的完整任务；只使用测试卷。

## 2. 闭环测试任务 RE 分支

- 选择 `Windows RE` 后检查 GUI 详细日志、prepare 返回码、任务文件、BCD 私有条目、ramdisk 路径和一次性启动序列。
- 若启动进入恢复环境，核对离线日志、任务状态、BCD/暂存目录清理、注册 WinRE 状态以及自动返回 Windows。
- 备份与还原均使用测试卷，严禁因启动成功就标记为备份/还原成功；必须核实镜像可读、数据一致及最终状态。

## 3. 复验 PE 步骤进度窗口

- 使用最新构建的 PE/Recovery 载荷进入 PE，确认步骤清单、当前步骤、步骤内进度、总进度百分比和进度条都实际显示并随日志更新。
- 保存关键截图及对应日志到 `.test-artifacts/`，不将测试证据散落在系统分区或 ESP 根目录。

## 4. 后续断电矩阵与清理

- 修复故障注入防重入标记按共享日志路径而非 task_id 定位的问题，再验证 `power-loss-target-erased` 和 `power-loss-boot-repaired` 两个尚未闭环的断电点。
- 每轮保留最小可复核证据后，按项目范围清理本轮生成的旧测试任务、日志和一次性 marker；不得删除用户文件、系统恢复镜像、工具链或已有快照。
