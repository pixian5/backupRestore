## 一、修复顺序（按实测严重度重排）

### 第 1 位：写盘前预检 + 失败即停（归 W02/W04/W09）

实测已证明"先格式化、后发现镜像不存在、再报完成"会真的毁数据，这条必须先修，且两半缺一不可：

1. **写盘前预检**：第一次破坏性命令之前验证镜像存在、DISM 可读、所选索引存在、镜像与目标不同卷、容量足够。任一不满足即拒绝，不进入格式化。
2. **失败即停**：`execute_pe_task_line` 返回结构化结果；任一步失败则不执行后续写盘、不弹"还原完成"、不提供重启。「完成」只能由统一成功判定产出。

验收：注入"镜像不存在""镜像损坏""索引不存在"三种输入，确认格式化调用次数为零、无成功提示；再注入"格式化成功但应用失败"，确认不报完成、不重启。

### 第 2 位：路径同源 + 本地化解码（归 W01/W08）

三条一起改，单改任何一条都不够：

1. **探测文件写读同源**：17 组配对由同一个函数产出路径。本轮实测 `format-check`/`bcdboot-check`/`find-system` 三组确认不同源。
2. **`NO MOUNT POINTS` 改为非文本判据**：不要解析本地化字符串。用卷枚举 API 判断是否有挂载点，或按分区类型 GUID（`c12a7328-f81f-11d2-ba4b-00a0c93ec93b`）+ 卷内是否有 `EFI\Microsoft\Boot\BCD` 来认 ESP。同时删掉代码里"固定串不随本地化变"的两处错误注释。
3. **命令输出统一走解码层**：禁止对工具输出用 `std::fs::read_to_string`，改用项目已有的 `decode_console_bytes`（UTF-16 → UTF-8 → 系统代码页）。

验收：中文系统上 ESP 定位成功；探测结果能读回；DISM/DiskPart 的中文输出能正确读出并进入判定。

### 第 3 位：探测三态 + 受保护卷集合（归 W01/W02）

路径修好后，`format-check`/`bcdboot-check` 才会真正返回值，此时必须同批完成：

- 三态化：存在 / 不存在 / 探测失败；探测失败按角色取安全默认（格式化拒绝，引导修复跳过并标失败）。
- 删掉 `contains("SYS")`（`NOSYS` 含 `SYS`）。
- 第二系统入口的判据改为受保护卷集合，不能用"含 Windows hive"，也不能只看 BCD 默认项。

### 第 4 位：退出码与身份（归 W08/W01）

- `mountvol` 退出码不作判据，改为回读实际挂载结果。
- 盘符不作执行期身份：本轮实测 PE 内盘符漂移四个卷。格式化前按分区 GUID 现场派生磁盘号/分区号。
