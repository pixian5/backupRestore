## 二、撞见的两处界面缺陷（本轮修掉）

### 2.1 备份的破坏性确认冒充「还原目标」

在备份页把源卷选成 `T:`、点「创建任务」后，弹窗是：

> 模式：备份 / 源卷：T / 镜像绝对路径：H:\BRImages\br-tdata-2629.wim /
> **目标卷：C** / WIM 索引：1
> **目标分区将被覆盖，确认继续？**

**备份没有「还原目标卷」**——它的目标是镜像文件。`目标卷：C` 取自隐藏的目标下拉
（备份页该控件不可见，默认停在 `C:`），既是无用信息，又会让用户以为 `C:` 会被写坏。

**修法**：抽出纯函数 `failure_policy::destructive_confirm_parts(operation, language, target_drive)`：

- `backup` → 不输出目标卷行，警示语换成「将把源卷捕获进镜像（镜像已存在则追加新索引），确认继续？」；
- 其余 operation → 保持原样（目标卷行 + 「目标分区将被覆盖」）。

纯函数放在 `failure_policy.rs`（跨平台模块）而不是 `native_gui.rs`（`#[cfg(windows)]`，
macOS 单测够不着）——**这是本轮踩的一次结构性坑**：函数最初加在 `native_gui.rs` 的测试模块里，
macOS 上 `cargo test` 根本 collected 不到，白写。

单测 `destructive_confirm_parts_drop_the_target_for_backup`：备份双语都不能出现目标卷行与
「覆盖」字样、不能带 `C:` 盘符；还原必须两者俱在。

### 2.2 `--tab` 帮助文本与真实编号差一位

`--help` 写 `--tab <1..=5>（1=backup 2=restore-A …）`，但代码把数字**直接当 0 基的
`operation_index` 用：`--tab 1` 实际打开的是 **A 页（还原系统到 C 盘）**，不是备份页。
本轮就是这么撞见的——`--tab 1` 启动后界面显示「目标卷（当前系统盘 C:）」与 A 页说明。

**修法**：帮助文本改成 `--tab <0..=4>（0=backup 1=restore-A to C: 2=restore-B to non-C:
3=second system 4=install PE）`；`native_gui.rs` 两处 `(0..=5)` 收窄为 `(0..=4)`。
**没有改映射本身**——`--tab 3` = 第二系统入口是现有脚本与文档依赖的行为，改了会连锁破坏。

### 2.3 实机复验

修正后重开备份页（`--tab 0`）+ 选 `T:` + 点创建任务，弹窗变成：
