# 【已推翻】第二系统启动验收：桌面无法启动，图形子系统崩溃循环

日期：2026-10-12 14:05
模型：GPT-5

> ⚠️ **本文档推翻同日 13:50 的 `20261012-1350-第二系统实际可启动验收通过-GPT-5.md`。**
> 那份文档的结论是错的，我用错了判据。保留它是为了留下误判痕迹，不要照它做判断。

## 真实的失败现象

第二系统（E:）能启动到内核、能响应 `prlctl exec`、`SystemDrive=E:`，
**但桌面起不来**：`dwm.exe`（桌面合成器）与 `LogonUI.exe`（登录界面）
每3–5 秒交替崩溃一次，构成无限崩溃循环。

事件日志（Application / EventID=1000）：

```
13:53:03  LogonUI.exe  崩溃  KERNELBASE.dll  异常 0x8000ffff
13:53:07  dwm.exe      崩溃  KERNELBASE.dll  异常 0x8000ffff
13:53:09  LogonUI.exe  崩溃
13:53:12  LogonUI.exe  崩溃
13:53:20  dwm.exe      崩溃
13:53:24  LogonUI.exe  崩溃
13:53:31  LogonUI.exe  崩溃   （持续到 13:54:33）
```

系统里挂着 **7 个 WerFault.exe**（Session 1 六个 + Session 0 一个），WerFault 自身也崩，
所以用户看到的是「WerFault.exe 应用程序错误」弹窗反复出现。

**连带效应**：崩溃循环把 shutdown 服务也拖死——
`shutdown /r /t 0 /f` 在第二系统里无效（`SystemDrive` 仍是 `E:`），
`prlctl stop --acpi` 也失败，最终只能 `prlctl stop --kill` 强制断电才能回到主系统。

## 我犯的错：判据选错

我在 13:50 用三个信号判定"启动成功"：

| 信号 | 是否充分 | 说明 |
|---|---|---|
| `prlctl exec` 可用 | ❌ 不充分 | 只证明内核+服务控制管理器活着 |
| `SystemDrive=E:` | ❌ 不充分 | 只证明 BCD 指向正确、系统盘选对了 |
| `dwm.exe` 进程存在 | ❌ **致命错误** | **崩溃中的进程也会短暂存在** |

**正确判据（桌面可用）**：
- `explorer.exe` 在 Session 1 正常驻留（内存 ~200MB 且稳定）
- 任务栏出现、能截图看到完整桌面
- 无 WerFault 崩溃循环（最多 1 个常驻）

这正是 AGENTS.md 里写着的「启动成功不等于备份还原成功」——同一轮我自己违反了它。

## 方案 C 的对照实验：镜像本体没问题

把镜像放回原位置 C: 启动，对照结果：

| 检查项 | 主系统 C:（镜像原位置） | 第二系统 E:（还原目标） |
|---|---|---|
| `explorer.exe` | ✅ 201,668 K | ❌ 未启动 |
| `dwm.exe` | ✅ 96,772 K稳定 | ❌ 每 3–5 秒崩溃 |
| WerFault 数量 | 1（系统常驻） | **7（崩溃循环）** |
| 桌面画面 | ✅ 任务栏/Chrome/BackupRestore GUI 正常 | ❌ 黑屏 + 弹窗 |

**结论：镜像内容本身没问题**（COPY 源、副档哈希都校验过，原位置能正常进桌面）。
故障发生在**还原到非原位置之后的启动环境**。

## 尚未定位的根因（线索）

1. **版本号不一致**：
   - 崩溃的 `LogonUI.exe` / `dwm.exe` 文件版本 = `10.0.26100.9549`
   - `systeminfo` 报告的 OS = `10.0.26200 (Build 26200)`
   - 说明 E: 上的注册表/组件版本与实际文件对不上，怀疑还原后注册表处理或
     servicing 状态不完整。

2. **显示驱动**：`pnputil /enum-devices /class Display` 与 `sc query dwm`
   在崩溃态下都返回空输出，**这条线索没验证成功**（可能是崩溃态下查询本身失效，
   也可能是显示栈真的没起来）。需要在能进命令行的环境下重查。

## 待验证的下一步

- 进 E: 的安全模式或 WinRE 命令行，读显示适配器状态与 `dwm` 启动失败的具体原因
- 检查 E: 的 `SYSTEM`/`SOFTWARE` hive 与 `E:\Windows` 文件版本是否匹配
- 确认 `bcdboot` 是否需要额外的注册表处理（如 `bcdboot` 后跑一次
  `sysprep /generalize` 或重新生成 `BCD` 的 `{current}` 绑定）
