## 5. 备份 macOS 的两条路线（这才是目标）

### 路线 A：Time Machine（推荐）
- **目标盘容量**：Apple 建议 ≥ 数据量的 2 倍。当前 855G → **建议 2T 起**；最低也要 900G+。
- **可大幅缩小备份体积的排除项**（在「系统设置 → Time Machine → 选项」里加）：
  `~/code/*/target`、`~/.npm`、`~/.cache`、`~/Library/Caches`、`Docker.raw`、
  `~/Parallels`（172G，若接受重装 VM 的话）、`~/Downloads` 里的大 ISO。
  排除后单次备份体积可降到 **200G 量级**。

### 路线 B：整盘克隆（CCC / SuperDuper）
- **目标盘 ≥ 900G**，且备份期间不能有大量写入。
- 优点：可直接启动；缺点：占空间固定，无法像 TM 那样保留多版本。

### 共同前提
**先把 A 档清掉**（≈128G）：备份体积、备份时间、以及「目标盘要不要买更大」三件事同时改善。
清理后剩余空间约 **166G**，仍不足以在本机放一份完整备份——但足够支撑 TM 增量 + 外置盘。

### 8.3 ★ 关键前提：删了不等于宿主变瘦

Parallels 的磁盘是**只增不减**的稀疏盘：在虚拟机里删文件，`.hdd` 不会自动缩小。要真正在 macOS 上回收，必须：

1. 虚拟机内删干净 → 2. **把虚拟机完全关机**（不是挂起）→ 3. 宿主上执行

```
prl_disk_tool compact --hdd "/Users/x/Parallels/Windows 11.pvm/harddisk2.hdd"
```

（注意项目经验：是 `--hdd`，**不是** `--disk`；有快照时 compact 无效——本机已确认无快照。）

4. compact 是**原地重写整个盘**，几十 GB 可能要十几分钟到半小时，期间别断电；完成后开机验证。

### 8.4 与本项目的取舍

- `F:`（第二系统）与 `H:\BRImages`（测试镜像）是**本项目实机判据的测试台**。
  删它们不会影响代码与单测，但会让「还原到非 C 盘 / 第二系统」这一类实测需要重建环境。
- `C:\BackupRestorePE`、`H:\brwork`（部署五件套）属于**当前工作台**，删了下次跑判据要重新部署。

### ★ 还差最后一步：宿主 compact

此刻 macOS 上 `.pvm` **仍是 172G**——虚拟机内删文件不会缩小稀疏盘。要真正回收必须：


### 9.1 ★ 订正：**不需要 compact，关机即自动回收**（2026-11-05 20:33 实测）

我在 §9 写的「还差最后一步：宿主 compact」**是错的**。用户判断正确——Parallels 关机时自动回收了：

| 磁盘文件 | 清理前 | 关机后 | 回收 |
| --- | --- | --- | --- |
| `harddisk2.hdd`（F:，已格式化） | 64G | **80M** | −64G |
| `Windows 11-0.hdd`（H:，删了 29G 镜像） | 32G | **2.6G** | −29G |

**结论**：本机 Parallels 配置了关机时自动回收（`prl_disk_tool compact` 是**手动**手段，不是必需步骤）。

若哪天关机后 `.hdd` 没变小，再考虑手动 compact。
