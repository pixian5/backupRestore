## 5. 备份 macOS 的两条路线（这才是目标）

### 路线 A：Time Machine（推荐）
- **目标盘容量**：Apple 建议 ≥ 数据量的 2 倍。当前 855G → **建议 2T 起**；最低也要 900G+。
- **可大幅缩小备份体积的排除项**（在「系统设置 → Time Machine → 选项」里加）：
  `~/code/*/target`、`~/.npm`、`~/.cache`、`~/Library/Caches`、`Docker.raw`、
  `~/Parallels`（172G，若接受重装 VM 的话）、`~/Downloads` 里的大 ISO。
  排除后单次备份体积可降到 **200G 量级**。

### 路线 B：整盘克隆（CCC / SuperDuper）
- **目标盘 ≥ 900G**，且备份期间不能有大量写入。
- 优点：可直接启动；缺点：占空间固定，无法像 TM 那样保留多版本。

### 共同前提
**先把 A 档清掉**（≈128G）：备份体积、备份时间、以及「目标盘要不要买更大」三件事同时改善。
清理后剩余空间约 **166G**，仍不足以在本机放一份完整备份——但足够支撑 TM 增量 + 外置盘。

## 6. 建议执行顺序（等你确认后我再动手）

1. **第一批（零风险，≈90G）**：A1 `target`、A4 npm 缓存、A5 `codex-runtimes`、A7 brew、A8 废纸篓
   → 清完 `df` 复核（预期可用空间 38G → 128G 左右）。
2. **第二批（低风险，≈35G）**：A2 `.test-artifacts` 只删 10 天前的、A3 `pass/target`、A9 旧 toolchain、A10 重复 dmg。
3. **第三批（要你逐项点头）**：B1 Docker、B2/B3/B4 Downloads、B5 pass 重复副本、B7 artifacts。
4. **最后**：按路线 A 或 B 做备份，并配置排除列表。

### 安全做法（我会严格遵守）
- 删除一律走**废纸篓**（`osascript` 丢进 Trash）或工具自带清理命令，**不用 `rm -rf`**。
- 每批最多 10 项，**每批做完 `du`/`df` 复核并报告**。
- 有疑虑的一律先移到 `~/Desktop/_待删_20261105/` 观察一周，而不是直接删。
