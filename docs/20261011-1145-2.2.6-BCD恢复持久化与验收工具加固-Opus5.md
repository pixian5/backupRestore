# 2.2.6 BCD 恢复、状态持久化与验收工具加固（2026-10-11，Opus 5 / Fable 5）

## 用户已确认的收口项

用户明确要求：

1. 加 `{bootmgr}.resumeobject` 恢复逻辑；
2. 清理替换第二系统留下的孤儿 `Windows Resume Application` 对象；
3. 终态状态文件增加 `FlushFileBuffers` 防断电撕裂；
4. 验收工具三项小加固。

## 已实现

### 1. `{bootmgr}.resumeobject` 恢复

`BcdBootManagerState` 新增 `resume_object`。准备阶段从任务前 BCD 快照解析 Boot Manager 的 `resumeobject`；BCDBoot 完成后，`preserve_primary_boot_manager` 在恢复 `default` 前后同时恢复该字段，并回读校验。

旧 BCD 没有 `resumeobject` 时保持没有，不凭空创建。比较使用 GUID 大小写不敏感匹配。新增跨平台解析回归测试。

### 2. 孤儿 resume 对象精确清理

快照解析同时记录每个 Windows loader → `resumeobject` 的映射。BCDBoot 后、菜单恢复校验通过后：

- 只检查快照中原有 loader 的映射；
- 如果原 loader 已不存在，且其 resume GUID 不再被任何现存 BCD 对象引用，则删除该 resume 对象；
- 仍被引用或 loader 仍存在则保留；
- 不按描述文字、不按“所有未引用对象”盲删。

每次删除都有详细日志，删除失败会使事务失败，不静默吞错。

### 3. `FlushFileBuffers` 状态持久化

`write_json_atomic` 在 `MoveFileExW(..., MOVEFILE_WRITE_THROUGH)` 安装最终 JSON 后，以共享读写删除方式重新打开最终文件，调用 `FlushFileBuffers`，再关闭句柄。这样 `task.json`、`status.json` 和事务文件在返回成功前都经过显式文件刷新。

### 4. 验收工具三项加固

`tools/acceptance/run.py`：

- `--fault` 先经过集中白名单校验；
- `--boot` 拒绝持续型 `:error` 故障，避免无人值守地把客体卡在无限失败循环；
- 新增 `--root-relative`，允许每轮显式指定客体工作卷相对目录，并拒绝绝对路径/危险字符；默认行为不变。

`tools/acceptance/system.ps1`：

- `created` 核验新增 `{bootmgr}.resumeobject` 前后存在性和值一致断言；
- 与 `default`、`timeout` 一样，变化会报告具体 before/after 值。
