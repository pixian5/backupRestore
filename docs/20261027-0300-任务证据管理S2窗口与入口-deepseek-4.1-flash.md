## 2. 入口：改造 `ID_REFRESH_TASK`，不新增按钮

```rust
ID_REFRESH_TASK => {
    refresh_task_status(state);              // 2.6.64 的行为保留
    let language = selected_language(state);
    show_task_admin(state.root, language, &state.executable_dir);
}
```

三个理由：
1. 顶栏刚在 2.6.59 修过 **6 对控件重叠**，加按钮就要重算整行宽度；
2. 这个按钮的语义本来就覆盖新窗口，两个入口会让用户困惑；
3. **主窗口 148 条控件基线一条不动** → 几何判据天然仍绿，回归风险最小。

同时保留「先刷新状态框」：`_t-refresh-status.ps1` 的四结局用例依赖它，
这样 S2 不会把 2.6.64 的验收打掉。

## 3. 三个实现细节（都是踩过的坑的直接应用）

1. **锁不能跨 `SendMessageW`**：`task_admin_reload` 先把所有要显示的文字算好、
   释放互斥锁，再碰控件。持锁调 `SendMessageW(combo, CB_SETCURSEL)` 会触发
   `CBN_SELCHANGE` → 回调里再锁同一把锁 → 死锁。
2. **`px` 与 `CBN_SELCHANGE` 类型**：项目里 `CBN_SELCHANGE` 定义为 `usize`，
   而 `WM_COMMAND` 的 `code` 我一开始写成了 `u32`，编译直接报
   `no implementation for u32 == usize`。统一成 `usize`。
3. **不处理 `WM_DESTROY`**：本窗口与主窗口同线程，`PostQuitMessage` 会把整个程序的
   消息循环打掉（「软硬件信息」窗口踩过同一个坑）。
4. **模态循环**照抄「软硬件信息」窗口：`PeekMessageW` 轮询 + 每轮查 `IsWindow`；
   `WM_QUIT` 必须 `PostQuitMessage` 还回去，否则关这个窗口会把程序一起退掉。

## 4. 冒烟：模态窗口会阻塞后续用例（本轮改动之一）

`_t-refresh-status.ps1` 原有 4 个用例，每个点一次 1004。**现在每点一次就弹一个模态窗口**，
不关掉的话后续用例全部失效，而且对用户来说等于程序卡死。

改造后每个用例：

```
点 1004 → sleep 1200 → 找 BackupRestoreTaskAdmin → 读 CB_GETCOUNT
        → 断言 (窗口存在 && 项数>0) → WM_CLOSE 关闭 → 读状态框 → 判 CASE_RESULT
```

`finally` 里也兜底 `Close-TaskAdmin`：异常退出不能把模态窗口留在屏幕上。

**这同时把 S2 的实机判据做进去了**——原来的四结局断言 + 新增的「窗口出现且非空」。

## 5. 实机结果

```
TASK_WINDOW=1 COMBO_ITEMS=50      ← 4 次，全部一致
CASE_RESULT=S1_OK_WITH_CODE=PASS  outcome=ok/ok code=BR-PE-039/BR-PE-039 flags=1
CASE_RESULT=S2_OK_NO_REASON=PASS  outcome=ok/ok code=none/none flags=1
CASE_RESULT=S3_MISSING_FILE=PASS  outcome=missing/missing code=none/none flags=1
CASE_RESULT=S4_MALFORMED=PASS     outcome=malformed/malformed code=none/none flags=1
结果：PASS=20 FAIL=0
```

- **`COMBO_ITEMS=50`** 与 `H:\brwork\tasks` 里的目录数**完全一致**（同一个时间点用 `dir /b /ad` 数过 50）
  ——这不是「窗口出现了」这种弱判据，而是「它读到了全部任务」。
- 主窗口冒烟 **20/20 全绿**：改造 `ID_REFRESH_TASK` 没有破坏任何既有用例。
- 部署 `DEPLOYED SHA256=f9aa22d1…`；交叉编译产物从 3,216,896 增到 **3,340,288** 字节
  （+123 KB），证明新代码确实进了二进制——若还是原大小，说明函数被链接器当死代码剥掉了。

## 6. 一段没做成的验证（如实记录）

想截图肉眼看一眼布局，`prlctl capture` 第一次拍到**全黑**（VM 屏幕休眠，这是已知的仪器问题），
第二次拍到了主窗口——但我那个临时脚本的 hook 没生效（`H:\brwork\gui-token-body.txt`
里还是上一个用例的脚本名），所以**窗口根本没被打开**。

结论：**布局目前只有坐标计算，没有肉眼或几何验证**。
坐标是算过的（§1），但「算过」不等于「屏幕上对」——这类事本项目栽过（裁图切字误判、
`availH` 不等于可见高度）。**归入 S3 的几何判据**，届时用
`_t-layout-rects.ps1 -WindowClass BackupRestoreTaskAdmin` 跑那 5 条。
