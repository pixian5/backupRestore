# 「载荷必须在系统卷」的说法已作废：机理与更正（2026-10-14 00:03）

> 模型：Opus5｜触发：用户问"载荷为什么必须在系统卷"

## 0. 一句话结论

**"载荷必须在系统卷"是 2.4.5 的权宜结论，2.4.6 起已作废。** 真正的变量不是**卷**，而是
**BCD 里 ramdisk 规格的写法形态**：

| 写法 | 数据卷（H:/F:/T:） | 系统卷（C:） |
|---|---|---|
| 盘符形式 `ramdisk=[F:]\…\Winre.wim,{devopts}` | ❌ bootmgr 解析不了 | ✅ |
| **设备路径形式 `ramdisk=[\Device\HarddiskVolume11]\…\Winre.wim,{devopts}`** | ✅ | ✅ |

现版本（2.4.7）**一律写设备路径形式**，载荷**留在镜像卷**（不再搬去 C:）。

## 1. 当年为什么会得出"必须在系统卷"

### 1.1 现象（2026-10-12 受控实验）

新启动通道在 BCD 里建一条一次性启动项，`device`/`osdevice` 写成
`ramdisk=[X:]\BackupRestoreRE\<任务ID>\Winre.wim,{设备选项对象}`。实验矩阵：

- 载荷放 **C:**（系统卷）→ 成功进 RE（19:16 截图为证）
- 载荷放 **H: / F: / T: / P: / E:**（数据卷）→ **全部失败**，且失败得很安静

### 1.2 机理：bootmgr 处在"盘符还不存在"的极早期

1. **盘符不是磁盘的属性，是 Windows 内核挂载后分配的。** `C:`、`F:` 这套映射来自注册表
   `MountedDevices`（联机后由内核按卷挂载顺序确定，所以项目里反复踩"盘符会重排"的坑）。
2. **bootmgr 运行在内核加载之前**：UEFI 固件 → bootmgr（读 BCD、画启动菜单）→ winload → 内核。
   bootmgr 手里只有固件给的最小设备栈和 BCD 本身，没有完整卷枚举，也没有那份"盘符→设备"映射表。
3. 于是 BCD 里 `ramdisk=[F:]…` 这种**盘符形式**规格，bootmgr 只能对它**已经知道的那个卷**
   （它自己启动链上的系统卷）做替换；对数据卷，它拿不到 `[F:]` 到真实设备的对应关系 → **解析失败**。
4. 解析失败的后果是**静默**的：winload 拿不到 ramdisk 源 → 启动该项失败 → bootmgr **丢弃一次性
   `bootsequence`** → 回落 `{bootmgr} default`（桌面）。**不弹错、不报错**，看着就像"根本没重启过"。
   项目里曾据此误判为"载荷在重启前被外部删除"，白查了数小时。
5. 旁证：10-11 同一个 `[H:]` 暂存**能引导**，10-12 就不行（疑 Windows 更新改变了 bootmgr 行为）——
   说明这是 bootmgr 侧的解析行为差异，不是我们写错路径。

## 2. 为什么这条结论不成立（2026-10-13 19:36 对照实验 + 单变量矩阵 A/B/C）

`docs/20261013-1936` 那轮做了单变量矩阵，把"卷"和"写法形态"拆开：

- 同结构、同一数据卷上，**只把规格从盘符形式换成设备路径形式 → 从失败变成功**。
- 结论：能引导的不是"系统卷"，而是"**设备路径形式**"。系统卷只是恰好在盘符形式下也能work。

**误判根源（关键坑）**：`bcdedit` 的**显示层把两种形态都规范化成 `[X:]`**——
存储层一个是盘符、一个是 `\Device\HarddiskVolumeN`，回读出来长得一模一样。
所以当年从 `bcdedit /enum` 和 prepare 日志里**根本看不出差别**，
看到 `[C:]` 成功、`[H:]` 失败就自然归因为"卷"，得出了错误结论。

## 3. 现版本（2.4.7）实际怎么做

- `boot_entry.rs:271-308` `dos_device_of()`：用 `QueryDosDeviceW` 把盘符现场转成 NT 设备路径
  （`F:` → `\Device\HarddiskVolume11`）；转换失败就**拒绝写盘符形式**（不静默退化）。
  另有一段坑记录：返回值必须以首个 NUL 截断，否则命令参数里带 NUL 字节会被拒（E2E 实测报
  "nul byte found in provided data"，对应任务 `852c0dad`）。
- `boot_entry.rs:421-431`：写 `ramdisk=[\Device\HarddiskVolumeN]<卷内路径>,{devopts}`，
  `ramdisksdidevice` 也写 `partition=\Device\HarddiskVolumeN`。
- `windows_prepare.rs:840`：`re_staging.volume = image_volume`——**载荷回到镜像卷**。
  2.4.5 把载荷搬到 C: 的做法**已回退**，原因写在源码注释里：污染 C:，且 `restore-existing`
  一旦断电，格式化目标卷会把自己的续跑载荷一起抹掉。
