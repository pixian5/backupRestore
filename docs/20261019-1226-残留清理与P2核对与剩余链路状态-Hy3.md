## 3. P2 数据卷硬拒核对

判定点：`windows_prepare.rs:2510` 的 `overlay_restore_on_windows_volume_error(target_is_windows, format_target)`，硬拒条件是 **「目标含 Windows 且取消格式化（覆盖式应用）」**；放行条件含 **数据卷（按目标卷的 SYSTEM hive 探测，而非仅活动系统卷）**、**勾选格式化**。

**单元证据（pe_safety.rs 4 例，平台无关可在 macOS 跑）**：
- `rejects_overlay_restore_onto_windows_volume`：windows+skip-format → 拒（文案含 WindowsApps/TrustedInstaller/格式化目标分区）
- `allows_format_on_windows_volume`：windows+format → 放
- `allows_overlay_restore_onto_data_volume`：data+skip-format → 放（2026-10-14 T: 已实机）
- `allows_format_on_data_volume`：data+format → 放

**接线证据**：`windows_prepare.rs:2485-2489` 的 `target_is_windows` 用 `target_is_active || probe_file(目标卷\SYSTEM hive)`——这正是 P2 修正点（数据卷按自身内容判定，不被活动系统卷的「必有 Windows」误伤）；2510 行 `if let Some(message) = ... { return Err(err(message)) }` 在任务创建前短路。

**实机烟雾受阻说明**：想用 `prepare --operation restore-existing --target-drive F --skip-format` 直接触发硬拒，但先撞 `restore requires --allow-destructive` 闸门（正常安全闸），加上 `--allow-destructive` 后本应抵达 2510；但当前 **F: 已被改造成数据卷（标签 BRTARGET，无 Windows 目录）**，不再是「非活动的 Windows 卷」，无法孤立该路径。结论：**逻辑 + 单元 + 接线三层已闭环；纯 CLI 端到端需要一台「非活动 Windows 卷」作目标，本机未现成具备（F: 已转为数据卷），不另造。**
