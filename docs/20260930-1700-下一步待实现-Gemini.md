## 一、下一步核心任务规划

在 WinRE 备份闭环完全跑通并彻底完成界面/文本交互精炼重构（v1.9.2）之后，接下来的工作重点如下：

### 1. 离线 WinRE 还原（Restore）端到端实机验证
- **目标**：验证在 WinRE 下将备份好的 WIM 镜像完整还原回目标卷，并成功修复引导启动。
- **阶段策略**：
  1. **小卷/非系统卷测试先行**：先在独立的测试分区（如 scratch 卷）上执行还原，验证格式化、DISM 应用镜像（`/Apply-Image`）、步骤标题/时间戳展示、BCD 修复引导全流程；
  2. **系统卷真实还原**：在宿主机磁盘空间充足及用户明确授权的前提下，执行真实系统卷还原验收。

### 2. 实测验证本轮 UI 改造效果
- **镜像路径交互**：在虚拟机 Windows 桌面 GUI 中，输入空或非法路径后点击【创建任务】，检查弹出的【选择镜像位置】与【取消】双按钮对话框表现，以及点击后按钮文字的联动切换；
- **WinRE 恢复界面**：在后续任务中实机观察精炼后的四阶段标题、各阶段后追加的 `[HH:MM:SS]` 时间戳、右上角靠右显示的时间信息及单一当前进度百分比。

### 3. wim-info 性能优化建议（供用户裁定）
- **背景**：当前 `wim-info` 会对整个大容量 WIM 镜像计算 SHA-256，62GB 镜像耗时约 30~40 秒。
- **优化方向**：默认优先读取同目录下的 sidecar 元数据（`*.metadata.json`），毫秒级直接呈现；仅在用户需要显式重校验时再流式计算整包哈希。

### 4. 启动项自检与孤儿清理机制产品化
- 在应用启动时自动检测并清扫因异常掉电或意外终止遗留的孤儿 BCD 条目与载荷暂存目录，进一步增强自愈能力。

### 5. 快照管理纪律保持
- 严格维持 Parallels 虚拟机最近不超过 2 个快照的约束，每次启动项变更前新建并核验快照，及时清理旧快照。
