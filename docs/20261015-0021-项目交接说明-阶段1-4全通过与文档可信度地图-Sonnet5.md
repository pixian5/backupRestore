### 2.2 被证伪的三个「缺陷」——别按它们改代码

- **A**：`assert_boot_default_preserved` **本来就是回读+自愈+再回读**（main.rs ~3266），只在自愈失败时才报错。19:46 那次 RE 日志有「BCDBoot /d 已生效：默认启动项仍指向原主系统」——自愈正常工作的直接证据。
- **B**：**default 从未留在半成品 F: 上**。三份独立证据：RE 日志 `/set {bootmgr} default {12e3701c}` 返回成功；失败前校验回读 default=主系统；实时 BCD 同。
- **C**：「bcdboot 后主动回读」= 缺陷 A 的函数本身，已实现。

### 2.3 两个真实的 bug 与一个重要陷阱（可信结论）

1. **resumeobject 不对称**（2.5.5 修，主因）：快照无 `resumeobject` 字段而 BCDBoot 为新系统凭空加一个（与新 loader 是兄弟 GUID）时，旧代码既不删除、三项联合校验又把 `(live=Some, 快照=None)` 判失配 → BootRepaired **确定性失败**。
2. **cleanup 容错缺失**（2.5.7 修，第二卡点）：删已不存在的孤儿 resume object 返回 exit 1，`?` 把它当致命错误 → 实质全成功的任务被判失败。
3. **resume 验证陷阱**：`resume` 只重新武装启动项，**复用 prepare 时暂存的旧载荷 WIM**——改了 RE 侧代码后用 resume 验证必然是旧代码假象，必须全新 prepare。

## 5. 操作手册（累积版，含 10-15 最新坑）

### 构建部署

```bash
./build-win.sh --deploy   # macOS 交叉编译 + 部署两处（SHA 校验）
# 版本三处同步：VERSION + 两个 Cargo.toml；纯文档/验证轮不升版本
# 部署后 UTF-8 字符串比对确认二进制含新代码
```

### VM 与通道

- `prlctl` 用**完整路径** `/usr/local/bin/prlctl`（后台 shell PATH 会丢）。
- **复合长脚本过 prlctl 会神秘挂起且 0 字节输出——拆成单步命令逐个验证**。
- RE 里 prlctl exec 不可用；判断 RE 是否真在干活 = 看宿主 `.pvm` 快照层 `.hds` mtime。
- **截图拿到就立刻看**（多轮教训：只算哈希不看图，报错画面干等）。本会话 Read 工具对 1024×768 PNG 反复失效，退化用 PIL 主色统计判断画面类型。
- prlctl exec 间歇抖动重试即可；GBK 乱码不是文件坏了。

### GUI 自动化（阶段 4 新增坑，全部实测）

1. **每次点击前确认 GUI 在前台**（`SetForegroundWindow` + `GetForegroundWindow` 回读）；**勿用 `SW_RESTORE=9`**。
2. **zsh `echo` 把 `\c` 解释成抑制输出**——写 batch 用 `printf '%s\n'`。
3. 中文 bcdedit 输出 `identifier` 本地化成「标识符」。
4. combo 选项**不能 `CB_SETCURSEL`**（不发通知），点击获焦后按方向键。
5. 填菜单名后索引 combo 会被刷新重置，须重选。
6. GUI 日志在**运行进程所在目录**的 `logs\gui.log`；在线日志在运行进程的 `%TEMP%`。

### 任务/BCD 运维

- `Prepared/BootRequested/RecoveryStarted/Preflight` 可 `abandon-task`；**`BootRepaired` 起不可**，只能 resume 或人工（备份目录 → status/task json 改 `failed`）。
- BCD 手术：先摘引用（`/deletevalue`）再删对象（`/delete {guid} /cleanup`）；删前 `/enum all /v` 存证；`/cleanup` 连带清从属对象（报「找不到」属正常）。
- 引导类改动前抄 `{bootmgr}` 三行；`bcdedit /export`/`/import` 联机态不可靠。
- 测试前拍快照（全程最多 1 个）；RE 卡住绝不反复强停（触发系统还原挂起）。
