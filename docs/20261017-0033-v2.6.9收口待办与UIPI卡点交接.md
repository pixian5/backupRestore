## 5. 关键卡点：UIPI（用户界面特权隔离）

### 5.1 现象

冒烟脚本 `tools/smoke-settings-4inputs.ps1` 经 `prlctl exec "Windows 11" --current-user` 跑时：

- 能 `EnumWindows` 找到主窗口（类名 `BackupRestoreNativeGui`，可见）；
- 能 `GetDlgItem(main, 1007)` 拿到「设置」按钮句柄（返回非零）；
- 但 `SendMessage(btn, BM_CLICK)` 后再次 `EnumWindows` 找 `BackupRestoreSettingsWindow` 返回 **0** —— 设置窗口没弹出来。
- 输出：`windows-seen=94 / main-window=393346 / settings-button=131884 / settings-window=0 / FAIL: settings window did not open`

### 5.2 根因

GUI 以**提权态**运行（`gui.log` 启动行记 `elevated native Rust window initialized`）。  
`--current-user` 通道是**非提权**（Medium IL）的交互用户进程。UIPI 规则：**低 IL 进程不能向高 IL 窗口发消息**——`BM_CLICK` 被静默丢弃（`SendMessage` 返回 0，但不报错）。`GetDlgItem` 只是查询，不受限，所以能拿到句柄；`BM_CLICK` 才是被拦的那个。

### 5.3 解法（已定位可行路径，但尚未执行验证）

要让冒烟脚本能驱动提权 GUI，冒烟进程必须与 GUI **同 IL 且同会话同桌面**（会话 1 / `winsta0\default`）。两条路：

**A. 借 GUI 自己的令牌起一个提权子进程（推荐，已写好脚本未跑）**  
`tools/launch-as-gui-token.ps1`：以 SYSTEM 通道运行 → `OpenProcess(GUI pid=3008)` → `OpenProcessToken(TOKEN_DUPLICATE|TOKEN_QUERY)` → `DuplicateTokenEx` 转 primary → `CreateProcessAsUser` 在 `winsta0\default` 起冒烟脚本。因为借的是 GUI 自己的提权令牌，子进程天然 High IL、会话 1、同桌面，`BM_CLICK` 不再被 UIPI 拦。

**B. 失败过的旧路（留作教训，别再走）**  
`tools/launch-in-session-elevated.ps1` 用 `WTSQueryUserToken` + `GetTokenInformation(TokenLinkedToken=18)` 取提权令牌，再 `CreateProcessAsUser`。实测 `DuplicateTokenEx(linked→primary)` 报 **err=6 (ERROR_INVALID_HANDLE)**——`TokenLinkedToken` 读出的句柄此处不可用。即使用 `hLinked` 直传也因非 primary 而 `CreateProcessAsUser=False`。

### 5.4 已知 PowerShell / 自动化坑（避免重复踩）

- **FindWindow(cls, `$null`)** 在 PS 里 `$null` 被编组为空串 → 匹配「标题为空」窗口，恒返回 0。改用 `EnumWindows` + 类名匹配，或 `FindWindow(cls, 真实标题)`。
- 原生 `EnumWindows` **回调里的 `Write-Output` 会被吞**：收集到 script 级 `ArrayList`，枚举后统一打印。
- 回调里读不到**函数参数**（`$script:` 只认脚本级变量）：先把参数赋给 `$script:xxx`。
- 字符串 hwnd 转 `IntPtr` 须 `[IntPtr]([int64]$str)`，不能直接 `[IntPtr]$str`。
- **投进 VM 的 `.ps1` 一律纯 ASCII**：中文（UTF-8）会被 PS 按 GBK 解析，破坏引号配对导致整脚本静默不执行。本会话已把 `smoke-settings-4inputs.ps1` 重写为 ASCII（原带中文注释）。
- **实机输出通道**：`prlctl exec` 输出是 GBK 与 UTF-8 混合，单独 `iconv` 会报 `Illegal byte sequence`。最可靠是让 VM **写共享盘 → 宿主 Read**（`.test-artifacts/` 即在共享盘上）。
- `prlctl exec "Windows 11"`（不加 `--current-user`）= **SYSTEM 通道**，看不到会话盘符 `X:`，要用 UNC `\\Mac\backupRestore\...`；`--current-user` = 交互用户（会话 1），能看到 `X:` 但非提权。

## 6. 版本号 bump 精确位置（v2.6.8 → v2.6.9）

GUI 标题来自 `crates/backuprestore-cli/src/native_gui.rs` 的  
`&format!("BackupRestore - Rust GUI v{PROGRAM_VERSION}")`（line 9638 等）。  
而 `PROGRAM_VERSION = env!("CARGO_PKG_VERSION")`，定义在  
`crates/backuprestore-core/src/lib.rs:66`。

即**版本号由 Cargo.toml 的 `version` 字段驱动**，不是硬编码字符串。需改：

1. 仓库根 `VERSION` 文件：`2.6.8` → `2.6.9`
2. 各 `Cargo.toml` 的 `version = "2.6.8"`（至少 `crates/backuprestore-core/Cargo.toml`，因为 `PROGRAM_VERSION` 来自它；另有 workspace 根与 `backuprestore-cli` 等，按上一轮记录是「VERSION + 两个 crate Cargo.toml 三处同步」）。  
   `grep -rn '^version = "2.6.8"' --include=Cargo.toml .` 一次性找全。
3. `cargo` 构建会自动更新 `Cargo.lock`（无需手改）。
4. 标题里 `v2.6.8` 这种字面只在**探针/文档**出现（`tools/probe-findwindow.ps1:13` 的搜索串、各 `docs/*.md`），不影响二进制，可顺手改或不改。

> 历史参考：v2.6.7→v2.6.8 时同步了 `VERSION` + 两个 crate `Cargo.toml`（`docs/20261016-2027-...` §开头）。
