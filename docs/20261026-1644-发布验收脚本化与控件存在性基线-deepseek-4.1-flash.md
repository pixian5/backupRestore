### 判据里最值钱的第 6 条

**包内 exe == 实机部署 exe**。它同时证明「产物→包」和「产物→部署」两条拷贝都没串——
手工核对时最容易被别的绿光掩盖（其它 8 条全绿，只有这条能说明「你打的包就是把正在跑的那个」）。

### 三种状态，不是两种

`PASS` / `FAIL` / **`SKIP`**。VM 没开、`strings` 不存在、找不到构建产物 → 记 SKIP 并**在摘要里点名**：

```
结果：PASS=8 FAIL=0 SKIP=1 —— 交付包可发布
      注意：跳过 1 条，见上方 SKIP
```

**把通道抽风记成红判据，会训练人忽略红判据**——本仓已经吃过这个亏（2026-10-26
`probe-entry-check.txt` 明明有内容，读回空串就报 FAIL）。

### 变异验证

| 变异 | 结果 |
|---|---|
| 解包后把包内 `VERSION` 改成 2.6.61 | `FAIL 版本不一致 repo=2.6.62 pkg=2.6.61` |
| 包内 `USER-GUIDE.md` 追加一行（不动清单） | `FAIL SHA256SUMS 9/10` + `FAIL 手册与仓库不同源（zh=0 en=1）` |
| 恢复好包 | `PASS=9/10 FAIL=0`，退出码 **0**；坏包退出码 **1** |

> 顺带一个 bash 坑：`$VERSION（strings 未命中）` 会被当成变量 `VERSION（`——
> **变量后面跟全角字符必须写成 `${VERSION}`**。脚本里一次性全量加了花括号（3 处）。

### 用法

## 2. `MISSING_CONTROLS` + `control-baseline.txt`

### 为什么几何判据看不见「少了东西」

前 5 条判据回答的都是**「现有的东西摆得对不对」**：不重叠、不越界、不截断、装得下、不塌缩。
一个控件**根本不存在**时，这五条全绿——没有东西可重叠、可越界、可截断。这正是
「删了入口忘删接线」和「加了控件忘创建」这两类缺陷的藏身处。

### 真值来源：签入仓库的基线，不是解析源码

考虑过「脚本解析 `native_gui.rs` 的 `CONTROL_NAMES`」，否决了：依赖仓库路径、
而且**删了控件却忘了删脚本时两边一起错**，等于自己给自己盖章。

改成 `tools/win-clicker/control-baseline.txt`（148 条，`page|id|class`）：

```
# 主窗口控件存在性基线（page|id|class）。由 _t-layout-rects.ps1 自动生成。
# 用途：MISSING_CONTROLS=0 需要它作真值。删/加控件后请重新生成并 review diff。
backup|1001|BUTTON
backup|1002|BUTTON
…
```

基线文件不存在时**自动生成**，但输出 `MISSING_CONTROLS=-1` + `BASELINE_AUTO_CREATED=148`——
用 `-1` 而不是伪造一个 `0`，否则「基线丢了」会看起来像「全部都在」。

### 两个方向都验证过

| 变异 | 输出 | 含义 |
|---|---|---|
| 基线里加一条界面上不存在的 `backup|9999|BUTTON` | `MISSING_CONTROLS=1` + `MISSING backup|9999|BUTTON` | 控件消失了 |
| 基线里删掉真的 `backup|1010|BUTTON` | `MISSING_CONTROLS=0` + `BASELINE_STALE=1` | 界面多了没登记的东西 |

### 一处自我纠正

第一次做「删掉基线条目」的变异时，脚本报 `MISSING_CONTROLS=0`，我一度以为判据失效。
**实际是两个错叠在一起**：

1. python 用 `replace('…\n')` 删行，但文件是 **CRLF**，替换根本没命中（我却打印了「removed」，
   因为没检查返回值）；
2. 即使删成功，方向也是反的——删基线一行 = 界面比基线**多**，该报 `BASELINE_STALE`，不是 `MISSING`。

教训：**打印了"做完了"不等于做成了**，`replace` 之后必须断言计数变化。

## 5. 可复用的钉子

1. **判据要三态（PASS/FAIL/SKIP），不要两态**。把「读不到」记成 FAIL，等于训练人忽略 FAIL。
2. **「有真值」比「会计算」重要**：`MISSING_CONTROLS` 的难点不是写比较，是找到一份
   不会自我盖章的真值。基线的价值在于**可 diff、可 review**。
3. **自动生成要显式标记**（`MISSING_CONTROLS=-1`、`BASELINE_AUTO_CREATED`），
   别让「没有真值」伪装成「全部通过」。
4. **`replace` 之后断言计数变化**——这次 CRLF 让删除静默失败，而我打印了成功。
5. **bash 里 `$var` 后面跟中文/全角标点必须写 `${var}`**，否则被当变量名吞掉。
6. **变异方向要想清楚**：删基线一行 ≠ 控件消失，是「界面多东西」。
