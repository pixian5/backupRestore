## 1. 独立测试系统卷的完整恢复

先检查并备份 P: 现有恢复资产，准备有真实系统文件、可启动的专用测试系统卷及独立镜像，核对容量与副档约束。不能把 C: 历史镜像的分区大小副档改小来绕过预检，也不能用合成 SYSTEM 文件充当可启动系统。

每个新部署、BCD（启动配置数据）或启动事务前建立并核验新快照。验证真实 RE 捕获、格式化应用、引导修复、恢复后系统实际启动、原主系统仍可启动及最终清理。C: 的系统备份/还原仍仅在用户明确指定后进行。

## 2. RE 与其他写入入口统一

按现有 D01～D10 决策落实到 RE、在线执行和硬盘 PE 安装器，沿用稳定身份、保护角色、输出同源、索引/内容预检、失败即停及持久领取。保留详细中文诊断日志。

优先复核 RE 以 `.is_file()` 判断系统分支的边界，以及 `TargetErased` / `ImageApplied` 续跑时重复格式化、应用的行为。正常数据卷成功不能证明身份未知、磁盘错误、重解析点或断电场景可安全放行。

## 3. 故障与界面验收

- 正常 Windows 界面选择“进入 RE”的备份/还原触发与错误反馈。
- 缺失/损坏镜像、错误索引、摘要失配、容量不足、身份变化、任务篡改、磁盘空间耗尽。
- DISM（部署映像服务和管理）失败、BCDBoot（引导文件修复）失败及回滚失败传播。
- 明确阶段的真实断电和恢复，检查是否重复危险写入、误报成功或提前清理证据。
- 第二系统加入菜单、实际进入第二系统、返回主系统与默认项保护。

## 4. 环境恢复改进

本轮实测 BCD `/import` 会新增固件重复项。后续优先评估已有原始 BCD 快照回滚路径，分别验证文件内容、枚举结果、固件变量及实际启动，避免把“导入退出码为 0”当作环境完全恢复。实施前保留回滚副本并按现有快照要求执行，不自行扩大清理范围。
