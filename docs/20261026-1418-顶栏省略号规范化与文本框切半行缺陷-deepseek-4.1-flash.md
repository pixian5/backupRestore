# 顶栏省略号规范化 + 两个文本框「切半行」缺陷（2.6.60）

> 2026-10-26 14:00 起。用户一句：「为什么这么多按钮上有省略号啊？第一排上这些按钮」。
> 查证过程里顺手撞出第二个真缺陷——**详情框/提示框的高度装不下自己的内容**。

## 1. 省略号：谁该带、谁不该带

Windows 的约定是：按钮/菜单项带 `…` 表示**点下去还要再给信息**（弹窗收集参数），不是立刻执行。
按这条把顶栏过一遍：

| 按钮 | 点下去实际做什么 | 该带 `…` |
|---|---|---|
| `设置` | 打开设置对话框，收集参数 | ✅ |
| `备份文件管理` | 打开镜像管理窗口，内有选择/删除 | ✅ |
| `浏览` | 打开选文件对话框 | ✅ |
| `查看日志` | 只弹一个**纯展示**的日志清单 | ❌ |
| `取消待重启任务` | 只弹一次「放弃这个任务？」**确认框** | ❌ |

规范里「确认框」不算收集信息——资源管理器的「删除」会弹确认但不带省略号；「关于 Windows」只展示也不带。
所以后两个的省略号是空转的，只让整排看起来更花。

**另一个真实的不一致是语言**。`gui_text.rs` 实测：

```rust
// 中文：全部 U+2026
(Language::Chinese, "settings") => "设置…",
(Language::Chinese, "cancel_pending") => "取消待重启任务…",
// 英文：四个用三个句点，只有 browse 用 U+2026
(Language::English, "settings") => "Settings...",
(Language::English, "browse")   => "Browse…",
```

同一个窗口、同一排控件里两套写法。

### 改法

- 去省略号：`查看日志…` → `查看日志`、`取消待重启任务…` → `取消待重启任务`（中英各一）；
- 统一省略号字符：英文四个 `...` → `…`（`Settings…` / `Backup files…`）；
- 同步 `docs/USER-GUIDE.md`（4 处）、`docs/USER-GUIDE.en.md`（6 处）、`tools/smoke/gui-clicks.sh` 两处用例标题。

**影响面为零风险**：验收脚本按**控件 ID**（`1010`/`1009`/`1007`/`1008`）找按钮，不认文案；单测里没有任何 `contains`
断言这几个标签。历史文档里的 49 处引用属记录，不改——改写过的历史才是错的。

## 2. 顺手撞出的缺陷：文本框高度装不下内容

改完文案截图复查时，发现「源卷详情」框最后一行（`卷 GUID：…`）**被边框切掉一半**，提示框最后一条也被切。
2 倍放大后先怀疑是「行距小于字高」，写了 `_diag-details-metrics.ps1` 把数字量出来，结论跟猜测**不完全一样**：

```
DPI=96 AWARENESS=0
source_details id=2012 client_h=112 lines=9 tmHeight=12 extLead=2 face=SimSun lfHeight=-12
  per_line_available=12.4 vs font_line=14
status        id=1300 client_h=64  lines=8 tmHeight=12 extLead=2
  per_line_available=8.0  vs font_line=14
```

- **字体是 `SimSun 9pt`（`lfHeight=-12`），行高 14 px**（`tmHeight 12 + extLead 2`）。中文字形几乎占满字身，
  所以两行之间只有 2 px 空隙——**放大看像「压住」，其实没压住**。这一条我一开始判断错了，靠数字纠正。
- **真问题是高度**：详情框 112 px 要装 9 行（需 126 px），提示框 64 px 要装 8 行（需 112 px）。
  `per_line_available` 只有 12.4 / 8.0，都小于 14 → 最后一行必然被切。

而 `set_text()` 早已调用 `text_parsing::normalize_edit_newlines`（LF→CRLF，幂等），所以**不是换行符问题**。
我曾据此把两个格式串改成 `\r\n`，量完数字后**撤回**——源码里留一个「看起来在修什么」的冗余改动，
比不修更误导人。

### 改法

| 控件 | 改前 | 改后 | 依据 |
|---|---|---|---|
| 源卷/目标卷详情框 | 112 | **130** | 9 行 × 14 = 126，留 4 px |
| 提示/状态框 | 64 | **126** | 9 行整：backup(8) / probe(6) / restore(9) 全可见 |
| 提示框下方行距 | `+84` | `+146` | 状态框高 126 + 20 间距 |
| 创建时初始高度 | 70 / 90 | 130 / 126 | 与 layout 一致，避免两个数字互相矛盾 |

★ **原则：多行 EDIT 的高度必须按行高整行取整**。差 4 px 不是「挤一点」，而是**最后一行被切成半截**，
看起来像控件坏了；比它更长的内容靠 `WS_VSCROLL` 滚动——**宁可滚，也不要切半行**。

## 3. 验收

| 判据 | 实测 |
|---|---|
| 详情框 `client_h` / `lines` | 130 / 9 → `per_line_available=14.4 ≥ 14` |
| 提示框 `client_h` / `lines` | 126 / 8 → `15.8 ≥ 14` |
| 截图（2× 放大） | 详情框 9 行全见、`卷 GUID` 尾部 `}\` 完整；提示框 8 行全见、无滚动条 |
| 六个页签几何 | `OVERLAP_COUNT=0`、`PAGES_CHECKED=6`（含 PE 页，提示最长） |
| 冒烟 | **10/10 PASS** |
| 部署 SHA | `47229062…`（2.6.60 最终） |

## 4. 可复用的钉子

1. **省略号只给「还要收集参数」的按钮**；只展示、只确认的不带。同一窗口里省略号字符必须统一（`U+2026`）。
2. **「看着像行距压住」先量再改**：`tmHeight + tmExternalLeading` 是权威行高，`GetClientRect / EM_GETLINECOUNT`
   是权威可用空间。数字对得上就说明是缩放视图的错觉，改代码只会制造新问题。
3. **多行 EDIT 高度按整行取整**，宁可靠滚动条也不要出现半行。
4. **改高度要连带改下方行距**（`image_y = status_y + 84` 这种「高度 + 间距」的魔数），否则压到下一行。
5. **诊断脚本要输出可直接判读的数字**（`client_h` / `lines` / `tmHeight` / `per_line_available`），
   而不是让人盯着截图猜——这次三次判断有两次是被这些数字纠正的。
