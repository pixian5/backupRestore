- 日期：2026-10-06，时间按新加坡时区；模型：GPT-6；版本：**2.1.4**。
- 用户明确授权：“验证：系统引导修复及恢复后的 Windows 系统启动；对 C: 做备份还原”。
- 产品逻辑沿用 `cf933e6` 基线，本轮更新版本、执行真实系统验收并记录结果，未修改产品执行逻辑。

## 结论

**本轮 C: 全新备份 → 真实格式化还原 → BCDBoot（引导文件修复）→ 恢复后的 Windows 启动 → 再次普通重启，全部通过。**

这是 Parallels 虚拟机中的 Windows 11 ARM64、UEFI（固件启动环境）与 GPT（GUID 分区表）的正常单系统恢复场景。未执行故障注入、第二系统或断电测试。

另发现：恢复前临时启用的 WinRE（Windows 恢复环境），在系统还原后回读为 `Disabled`。原恢复镜像完整，Windows 正常启动，但**不能据此认定恢复环境已自动恢复为可用状态**。该注册收尾问题单独列为后续修复项，未用手工再次启用掩盖。

## C: 真实还原和引导修复

先在独立测试目录修改 `restore-me.txt`、删除 `nested\restore-deleted.bin`，新增 `must-disappear.txt`，再建立新的还原快照。

```text
BackupRestore.exe prepare --operation restore-existing --source-drive C --target-drive C --image-path H:\BRRE-C214-20261006\images\system.wim --wim-index 1 --verify-hash --allow-destructive
```

- 还原任务 `aadc2382-7dbf-4a4b-8800-6ce675e50d75`，最终 `success`。
- 日志明确选择磁盘 0 分区 4，真实格式化后再次核验分区身份。
- 实际执行 `/Apply-Image /Index:1 /ApplyDir:C:\`，成功应用约 278 秒。
- 实际执行 `bcdboot.exe C:\Windows /s Z:\ /f UEFI /v`；Z: 是本次挂载的真实 EFI 系统分区。
- BCDBoot 日志包含启动文件复制到 `EFI\Microsoft\Boot`、更新 ARM64 的 `EFI\Boot\bootaa64.efi` 和创建启动对象；程序回读验证 `device/osdevice` 指向 C:。
- C: 的 NTFS 卷序列号由 `B61F1F3D` 变为 `2E94C362`，分区 GUID 不变。证明进行了真实格式化并恢复到原分区。
- 没有进入“数据卷跳过 BCDBoot”分支。完成后产品清理临时条目和载荷，自动重启。

## 恢复后的系统启动验证

第一次进入 Windows 后和第二次普通重启后，均运行独立核验脚本：

1. 实际系统盘为 C:，Windows 路径为 `C:\Windows`，版本为 `10.0.26200`，分区 GUID 与目标一致。
2. 3 个原测试文件大小和 SHA-256 一致；被修改文件恢复、被删除文件重新出现，新增哨兵消失。
3. `winload.efi`、`ntoskrnl.exe` 及原恢复镜像/启动辅助文件与测试前摘要一致。
4. 当前 Windows 加载器为 `{78803174-c0e6-11f1-b1ba-80680e4613cd}`，`device`、`osdevice` 指向 C:，路径是 `winload.efi`。
5. 默认启动项与当前加载器一致，没有 `bootsequence` 一次性启动配置，任务临时对象及载荷目录均消失。
6. 事件日志、WMI（系统管理接口）、任务计划服务运行，`explorer.exe` 桌面进程存在。
7. 第二次普通重启未修改 BCD、未手动选择系统；操作系统启动时间确实改变，上述检查再次全部通过。

证据中的桌面自动打开的是已有旧版程序，不能用于判断本次执行版本；本次版本由独立目录部署摘要、注入清单和镜像副档共同证明。

## WinRE 注册与未覆盖边界

开始时 WinRE 为 `Disabled`。为执行本轮系统备份，快照后临时启用，注册位置为 C: 的 `Recovery\WindowsRE`。备份及还原过程中，产品使用独立镜像副本；原 WinRE SHA-256 一直为：

```text
1060a552be3b6f2f190e9e50f0ee5fe9b183f97ef62083f61b92b1a9b52b9dd5
```

还原和第二次启动后，WinRE 回读为 `Disabled`，与最初状态一致，但与捕获前临时启用的状态不同。本轮没有证明“恢复后可立即再次从系统进入 RE”，也没有自动重注册的修复。该问题需要针对格式化后卷身份、BCDBoot 新加载器与注册关联继续定位。

第二系统、错误镜像/容量不足、引导故障注入、真实断电恢复，以及 Windows 图形界面选择 RE 的完整交互，本轮均未测试。不能把正常 C: 恢复通过扩展为全部故障场景通过。
