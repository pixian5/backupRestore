# 备份排除表增加「程序部署件」——实机落地与端到端验证

- 时间：2026-10-24 10:50
- 模型：Step-5-Preview
- 版本：v2.6.32 → **v2.6.33**
- 用户指令：「备份排除表 修改」（承接同日「不再往 C: 部署 exe」）

## 1. 动机

「镜像带回旧状态」效应还剩最后一条尾巴：备份一个卷时，DISM 会把**程序自身的部署件**
（`BackupRestore.exe` / `Recovery.exe` / `wimlib-imagex.exe` / `libwim-15.dll` /
`winpe-winpeshl.ini`）一起打进镜像；还原该卷时二进制随镜像回滚成旧版
（10-24 07:5x 实测：还原后自启 GUI 标题 v2.6.31 而 H: 是 v2.6.32）。

同日已完成：TaskStore 搬离 C:（任务状态不回滚）、不再往 C: 部署 exe（分发副本消失）。
本轮补上第三块：**排除表显式排除程序部署件**，让「还原后程序目录里没有二进制」成为常态。

## 2. 设计（两条边界，都有出处）

| 排除对象 | 范围 | 理由 |
|---|---|---|
| 程序部署件（5 个文件名） | **只排文件、不排目录** | 同目录的 `tasks\`（任务证据）与 `logs\` 必须留在镜像里——2026-10-24 用户拍板「证据全留」；二进制是可再生产物 |
| 历史分发目录 `\Users\Public\backupRestore-package` | 整目录固定排除 | 2026-10-24 起已不再部署，deploy 的 rmdir 会清残留；旧镜像还原后会把它带回来，排除=还原后不复发，与 rmdir 双保险 |

「同卷才排」：exe 目录与源卷同卷时才生成条目（跨卷无对应路径，不加项）；
exe 就在卷根时不加（排整个卷没有意义）。

## 3. 实现

**core（`crates/backuprestore-core/src/lib.rs`）**
- `build_capture_exclusions(source_root, self_exe_dir: Option<&Path>)`：新增参数；
  固定项表加 `\Users\Public\backupRestore-package`；同卷时按
  `SELF_DEPLOY_FILES`（5 个文件名）逐条生成 `\<相对路径>\<文件>`。
- 新增两个 helper：`volume_key`（盘符，大写）与 `relative_to_volume_root`
  （卷内相对路径）。**手写前两字符解析而不用 `Component::Prefix`**——后者只在
  Windows target 上产生，而单元测试常在 macOS 宿主跑（本项目交叉编译），必须行为一致
  （第一版用 Component，测试当场失败，已改）。
- `write_capture_exclusion_config` 同步加参数；三个捕获入口（CLI / GUI 在线 / RE 内）
  共用同一函数，避免某条路径漏接 `/ConfigFile`（历史上 GUI 在线备份漏接过一次，
  `\Mac disk` 进镜像、还原撞 0x80070020）。

**调用点（关键分叉，本轮实测踩出的真 bug）**
- `main.rs`（RE 内 `recover_windows`）：传 **`Some(store.root)`**——store.root 就是
  Windows 侧运行目录（RE 内由 `resume <task-root>` 参数带进来）。
  **不能传 `current_exe()`**：RE 内 current_exe 是恢复环境里的暂存路径，与捕获卷
  不同卷，动态排除项会永远不生成（实测：五个部署件全被打进 T: 镜像）。
- `online_operation.rs`（在线捕获）：传 `current_exe().parent()`——在线场景它就是
  运行目录（H:\brwork），正确。

**测试**：3 个既有调用加 `None`；新增
`capture_exclusions_skip_self_deploy_files_same_volume`（同卷 5 条 / 不整目录排 /
跨卷不加 / exe 在卷根不加，用 Windows 风格假路径，macOS 上也能跑）；
`capture_exclusions_without_users_keeps_fixed_list` 的判据从 `\Users\` 改为
`AppData\`（固定项本身含 `\Users\Public\...`，原判据会误失败）。
`cargo test -p backuprestore-core --lib` **45 全过**。

## 4. 实机验证（T: 5GB 测试卷，全链路）

**场景构造**：`T:\brwork-test\` 放五件套 + `tasks\sentinel-evidence.txt` +
`logs\marker.log` + `user-data.txt`；从该目录起 CLI（模拟「程序装在源卷上」）。

**① 备份（CLI `prepare --operation backup`，全链在 WinRE 执行，STEP 2/4 捕获 100%）**

镜像 `br-excl-test.wim`（2,146,059,229 B）内 `\brwork-test\` 顶层实测：

| 条目 | 在镜像里？ |
|---|---|
| `BackupRestore.exe` / `Recovery.exe` / `libwim-15.dll` / `wimlib-imagex.exe` / `winpe-winpeshl.ini` | **全部不在**（排除生效） |
| `tasks\sentinel-evidence.txt`、`logs\marker.log`、`user-data.txt`、`last-task.json` | **在**（证据+用户数据全留） |
| `tasks\e9d51aeb…\`（task.json/status.json/recovery.log/stage\Winre.wim 全套） | **在**（任务证据全留） |

> 第一次实测排除**未生效**（五个部署件全在镜像里）——根因即 §3 的 RE 内
> `current_exe` 问题。改传 `store.root` 后重测通过。

**② 还原端到端（在线，`--format-target` 格式化后只落镜像内容）**

```
T:\brwork-test\ 还原后 = .backuprestore-*.bcd.LOG + last-task.json + logs\ + tasks\ + user-data.txt
五个部署件：一个都没有
sentinel/marker/user-data：逐字完好
```

**「镜像带回旧 exe」效应彻底消除**（格式化还原后程序目录无任何二进制）。

**③ 顺带验证**
- 自毁保护对数据还原同样生效：从 `T:\brwork-test` 起还原 T: 被明确拒绝
  （"the program directory is on T:, which is the restore target"，零任务零 BCD 零重启）。
- CLI 备份/还原入口备忘：备份=`prepare --operation backup`；在线数据还原=
  `online --operation restore-existing --source-drive X --target-drive X
  --image-path … --index 1 [--format-target]`；`prepare restore-existing` 的
  target 必须是活动 Windows 卷（A 入口语义），数据卷在线还原必须走 `online`。
