# A 档结构收敛：盘符租约成为唯一入口（v2.6.71）

> 用户问「是否以后能彻底避免这类问题？」→ 我把它拆成三档（A 我方代码残留 / B 机器已有残留 /
> C 用户 Windows 行为），用户选 **A 档：结构收敛**。本文只讲 A 档做完的那三件事。

* * *

## 一、要解决的是什么

`mountvol <letter>: <卷>` 与 diskpart `assign letter=` 写的都是**持久**记录
（`HKLM\SYSTEM\MountedDevices`）。只要有一条代码路径「挂了不撤」，盘符就永久留下；
等那个分区被删掉，Windows 会为这个不存在的卷反复弹「X:\ 无法访问」。

10-27/28 两轮事故的 6 条幽灵盘符、测试夹具每跑一次留一条，全部属于这一类。
此前的防线是**注释**里写着「用完必须卸掉」——**约定靠人记，一定会漏**。

## 二、三件事

### 1. 把那扇门关掉（编译期保证）

删掉 `pub(crate) fn ensure_volume_mounted`（不返回租约的那个），全库只留：

```rust
pub(crate) fn ensure_volume_mounted_leased(
    identity: &VolumeIdentity, preferred: char, log: &Path,
) -> Result<(char, MountLease), TaskError>
```

拿到盘符就一定拿到租约；租约离开作用域自动 `mountvol /D`。
**新代码想「挂了不管」在 API 层面已经写不出来**——这是编译器替我们守的。

12 个调用点全部迁移，按生命周期分两类：

| 类型 | 判据 | 处理 |
| --- | --- | --- |
| 用完即弃 | 字母的全部使用都在同一个函数/闭包内 | 租约活到作用域结束（**提前撤销，更干净**） |
| 字母会逸出 | 写进持久化方案、被拼进返回的路径字符串、存进结构体字段 | `lease.hold_for_process()`（见下） |

`efi_bcd_store_path` 的返回类型从 `Option<char>` 改成 `Option<MountLease>`，
原来调用方手写的那两段 `mountvol /D` 收尾代码直接删掉——租约替它做。

### 2. `hold_for_process()`：有边界的逃生口

字母真会逸出的地方有 3 处（`grep hold_for_process` 一眼能数清）：

- `boot_entry::copy_into_staging` —— 返回的绝对路径把 `R:` 拼进去了；
- `boot_menu` 生成方案 —— `entry.drive_letter` 随 `SavedPlan` 落盘；
- `windows_prepare::ReStaging` —— `boot_sdi` 把盘符拼进路径存进结构体。

这些地方不能立刻撤（撤了后面的步骤就断），但也不能不管。所以：

- 字母进**进程级集合**，`main()` 收尾统一 `mountvol /D`；
- 进程被强杀/崩溃 → Drop 不会跑 → 靠**磁盘登记 + 下次启动按 PID 清扫**（见 3）。

★ 它是显式的、可 grep 的、数量可控的——比「到处都可能有裸挂载」强一个量级。

### 3. 崩溃兜底：按 PID 清扫，不猜时间戳

- 分配时在 `logs/mount-leases.txt` 追加一行 `<盘符> <PID>`；正常撤销时划掉该行。
- 每次进程启动先跑 `release_dead_owner_leases()`：逐行判活，
  **只清理「登记还在、但登记它的进程已经不在了」的那些**。

判活走 `OpenProcess` + `GetExitCodeProcess`（`STILL_ACTIVE`），不猜时间戳——
因为 GUI 会派生 CLI 去准备，两个实例并存是常态，用时间戳一定会误伤。

### 4. 静态守卫：绕开入口会被提交门禁拦下

`tools/test/source-guard.sh`（接进 pre-push 第 7 步）：

| 规则 | 内容 |
| --- | --- |
| A | `assign letter=` / `Command::new("mountvol.exe")` 只许出现在白名单文件（`windows_prepare.rs` 实现、`main.rs` RE 内挂载、`pe_operation.rs` 测试夹具）；**新文件出现即 FAIL**（棘轮：只许减不许增） |
| A' | 夹具里 assign 了哪个字母，就必须 remove 同一个字母（**按字母配对**） |
| B | `windows_prepare.rs` 必须仍有 `ensure_volume_mounted_leased`，且**不得**再出现不返回租约的 `pub(crate) fn ensure_volume_mounted(` |
| C | 打印 `hold_for_process()` 清单（信息项） |

## 四、未覆盖（不掩饰）

1. **「正常收尾释放 hold」没有单独实测。** 触发它需要在 prepare 流程里真挂一次载荷卷
   （要走一次完整备份）。它复用的是同一个 `release_mounted_letter`，风险集中在
   「调用时机」这一点上，不是实现本身。
2. **`main.rs` 的 RE 挂载仍走裸 `mountvol`**，作为白名单放行——RE 的 hive 是内存盘
   （`Winre.wim` 解压出来的 X:），挂载不入库、不跨重启。这是**有理由的例外**，不是遗漏。
3. B 档（机器上已有的幽灵盘符）与 C 档（Shell 窗口停在消失的卷上）**没有做**，
   按用户选择只做 A 档。

## 五、这轮踩到的两个判据坑（比代码本身值钱）

1. **又踩了一次「空集通过」。** 守卫里按字母配对的那段 awk，偏移少减 1，取到的是字母后面
   那个 `\`，于是一个字母都提不出来；而「空集」让配对检查**全部跳过**，报了个干净的 PASS。
   —— 现在加了硬闸：文件里明明有 `assign`、却解析不出任何字母 → **`ERROR=…` 并 exit 2**，
   不许当成通过。**判据的输入也是判据的一部分。**
2. **变异做错了也会「绿」。** 第一次做「删掉 remove letter=」的变异，我先写成了
   `Xremove letter=V`——它仍然**包含** `remove letter=` 这个子串，于是判据照绿。
   教训：**变异本身也要能判**（要么改变量、要么改变字母），不能只改前缀。
